# Alpha101 参考实现说明

代码：`src/ashare/factor/alphas/reference/alpha101_ref.py`（101 条，每条一个函数，上方注释是 `sources/alpha101.jsonl` 的原文，测试逐字核对），算子在 `alpha101_ref_ops.py`。测试在 `tests/reference_alpha101/`，冒烟脚本 `smoke_alpha101_ref.py` 在同一目录（不进 pytest）。

写的时候只读了任务书允许的文件：`CONVENTIONS.md`、负责人裁决（2026-11-13）、`REFERENCE_INPUTS.md`、`sources/` 下的原文、`inputs.py`、`verify.py` 的参考实现接口、`qlib_alpha158.py` 的文件组织方式。没有读也没有调用 `dsl`、`ops`、`alpha101.py`、`panelops`。

## 1. 接口

- `REFERENCES = {"alpha101_001": 函数, …}`，函数签名 `f(data, **params) -> DataFrame`，与 `data["close"]` 同索引同列。
- `compute_many(frames, names, argmax="days_ago")`：一批共享 `adv{d}` 缓存。
- D-13：`references(argmax="days_ago" | "position")` 返回整张表；`ARGMAX_DEPENDENT` 列出受影响的 001、057、060、096、098、100，这 6 个函数也直接接受 `argmax=` 参数。读法 A（`days_ago`）：距今天数，今天 0，并列取最近；读法 B（`position`）：窗口内位置，最早一天为 1，并列取最早。

## 2. 口径落实（照 CONVENTIONS 与裁决）

| 项目 | 写法 |
|---|---|
| 窗口 | 天数先 `math.floor`；窗口必须满，窗口里任一输入 NaN 结果为 NaN，前 d−1 行 NaN（D-09、D-15） |
| `rank` | `DataFrame.rank(axis=1, pct=True)`，平均秩 / 有效个数（D-11） |
| `ts_rank` | 当天值在窗口内的平均秩 / d（D-12） |
| `correlation` | 两遍算法（先减均值）；任一侧窗口逐值相等时 NaN |
| `stddev`、`covariance` | 分母 d−1，两遍算法；常数窗口的标准差精确为 0 |
| `decay_linear` | 权重 1..d（今天最大）除以权重和 |
| `scale` | x / Σ\|x\| × a，Σ\|x\| 为 0（含整行缺失）时 NaN |
| `indneutralize` | 当天同组有效值减组均值；三个层级都用申万一级（D-06）；组缺失或 x 缺失为 NaN；单只成组为 0 |
| `adv{d}` | 成交额 d 日均值（D-05） |
| 逐元素 | `/`、`log`、`^`、`SignedPower` 的非有限结果为 NaN；比较、`\|\|`、三目遇 NaN 为 NaN；序列对序列的 `max/min` 逐元素，NaN 传播（Q-A-01）；029 的 `min(…, 5)` 是时序 |
| 照抄 | Q-A-02（059、066、082、089 的 `x·w + x·(1−w)`）、Q-A-03、Q-A-04（100 的两次 `indneutralize`）、Q-A-05 都按字面算，不化简 |

滚动算子用 `sliding_window_view` 把窗口摊到最后一维再归约，按列分块（每块窗口数组约 48 MB）；每个归约都有朴素循环版本在测试里对拍（随机面板含并列、NaN、常数列、整段常数、非整数窗口），另有分块压到每块 1 列的结果逐位不变的测试。

同一个子式在公式里出现两次（024 的比值、046/049/051 的斜率差、083 的价差比）时只算一次：输入和运算完全相同，结果逐位相同，不算化简。

## 3. 原文疑点（约定和裁决里没有的）

## 4. 冒烟结果

数据：面板 `2d0319f0…`，最近 300 个交易日 × 5923 只（`warmup=0`），另跑了一次核对区间规模 750 + 260 = 1010 日计耗时。「有效格比例」= 有限值格 / 有行情的格（close 有值）。

- **报错**：无。
- **全 NaN**：无。
- **全常数**：096（两种读法，原因见 R-A-01：全区间只有 1 个有效格）。
- **有效比例很低**（1010 日上 < 60%）：096（0）、097（0.16%）、088（43.7%）、071（38.6%）、079（53.5%），原因都是 R-A-01；300 日上还有 019、039、048、052（250/240 日窗口）以及 032、036、037、061、063（200 日以上的窗口），这些在 1010 日上恢复正常。
- **近似常数**：007（R-A-02）、021、027（两值因子：原文就是三目输出 ±1）。

**耗时**（1010 日 × 5923 只，单线程，机器负载约 8）：101 条加读法 B 的 6 条共 182 s。最慢：048（9.3 s，两个 250 日窗口）、037（6.0 s，200 日相关）、032（5.9 s，230 日相关）、036（3.9 s）、081、100、098（各约 3.8 s）。都在一分钟以内。

## 5. 运行环境的变动

写到一半时，`src/ashare/factor/public/` 下除 `reference/` 以外的文件（含 `inputs.py`、`verify.py`）一度从工作区里移走（看起来在迁去当时的私有仓库），之后 `inputs.py`、`verify.py` 又出现了。为了不受这类搬动影响：

- 参考实现本身只依赖 NumPy / pandas，不受影响；
- 测试自带合成数据，不再用 `conftest.py` 的 `source` 夹具和 `inputs`（`pytest --noconftest` 也能跑）；
- 冒烟脚本优先用 `inputs.reference_frames`，取不到时照 `REFERENCE_INPUTS.md` 第 2 节自己从 `ashare.data` 换算（全量冒烟时 `inputs` 不在，走的是自带换算，版本串带 `+own-loader`；之后用 `inputs` 复跑 001、096，有效比例与之相同）。迁移完成后请顺带把本文件、两份代码和测试目录一起搬过去，并改 import 路径。
