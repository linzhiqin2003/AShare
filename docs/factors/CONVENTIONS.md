本文件把 Alpha101、国泰君安 191、Qlib Alpha158 三套公式里的输入数据和运算口径落到本仓库的面板和算子上，并列出原文疑点的处理意见。翻译规范（给翻译的人看）在 `DSL_REFERENCE.md`，算子缺口和补法在 `OPERATOR_GAPS.md`，参考实现的输入约定在 `REFERENCE_INPUTS.md`，原文在 `sources/`。

**状态**：负责人 2026-11-13 已裁决全部条目（第 7 节是汇总）。没有单独改动的条目按原先的「建议」执行；本文里标「已裁决（2026-11-13）」的地方写的就是最终口径。代码按此实现，以后改口径只需要改公开仓库 `src/ashare/factor/formula/dsl.py`（Alpha101、国君）或 `qlib.py`（Alpha158）里对应的一处，翻译不用重做。

数据版本：本文的实测数字取自面板 `2d0319f0…`，最近 810 个交易日（2023-07-11 至 2026-11-12）。

### 1.3 已知代价：截面比较价格水平

后复权价的水平取决于每只股票自己的分红送转历史，同一天不同股票之间的后复权价水平没有经济含义。原文里有直接对价格或成交量水平做截面排名的写法（例如 Alpha101 003 `rank(open)`、国君 062 `RANK(VOLUME)`），在后复权口径下这些排名会被复权历史扭曲。可选的「窗口内动态前复权」（以当天为基准把窗口内价格换算到同一股本）不能表示成一张固定面板，现有算子做不到。**D-08 已裁决（2026-11-13）：按建议**：建议先按 D-01/D-02 统一后复权，复现后对这类条目单独看一次与「不复权」口径的秩相关，差异大的再决定。

## 2. 缺失值

### 2.1 什么时候是 NaN

- 停牌日（上市但无日线）、上市前、退市后：开高低收、vwap、量额全部 NaN，不前向填充（数据层就是这样存的；最近 810 日上市但无行情 9448 格，占上市格 0.22%；有行情时量、额、复权因子、vwap 都不缺）。
- 所有逐元素运算：任一操作数 NaN 结果为 NaN；结果不是有限数（除以零、对数非正数、负数开非整数次方、溢出）一律为 NaN。Qlib 原代码遇到除以零给出 ±inf，核对时 ±inf 按 NaN 处理（3.3）。
- 截面运算：NaN 不参与排名、去均值、缩放，自身输出 NaN。

### 2.2 滚动窗口里的 NaN（每套各定一个）

| 套 | 口径 | 依据 |
|---|---|---|
| Alpha101 | **窗口必须满**：窗口内 d 行都有有效值才出数，否则 NaN；所以一只股票停牌一天，之后 d−1 天的 d 日窗口统计都是 NaN；面板最前面 d−1 行也是 NaN | 原文没写。通行实现（pandas `rolling(d)` 默认 `min_periods=d`）就是这样。本仓库写作 `min_periods=window`。**D-09 已裁决（2026-11-13）：按建议**；备选：放宽到八成有效（与 `default_registry` 一致）。实测影响见 2.1 的停牌比例。 |
| 国君 191 | 同 Alpha101 | 同上（研报没写；聚宽实现基于 pandas）。 |
| Alpha158 | **至少 1 个有效值就出数**（`min_periods=1`），窗口按行数计（停牌的 NaN 行占位但不计入统计） | Qlib `Rolling._load_internal` 原文 `series.rolling(self.N, min_periods=1)`。 |

其他窗口相关的约定（三套一致，都已对着 `panelops` 实现核实，测试见公开仓库 `test/factor/formula/test_formula_dsl.py`）：

- 窗口含当日：第 t 行的 d 日窗口是第 t−d+1 到第 t 行。
- `delay(x, k)` 取 k 行之前的值（向过去），`delta(x, k) = x − delay(x, k)`，两端都要有值。按行数计，跨停牌不跳过停牌日。
- 时序回归（`REGBETA(A, SEQUENCE(n), n)`、Qlib `Slope`）的自变量是原始行位置，停牌的空行占位置。
- 递推类（国君 `SMA`）：从第一个有效值起递推，遇到 NaN 保持状态（不衰减），**D-10 已裁决（2026-11-13）：按建议**：建议输出在当天输入为 NaN 时也给 NaN（与「停牌日为 NaN」一致，状态仍然保留），并要求自开头起至少 n 个有效值才出数。结果依赖数据起点：正式计算从面板第一天（2007-01-04）算起；核对时候选和参考用同一段数据，所以可比。

## 3. 算子口径

### 3.1 Alpha101 和国君 191

| 项目 | 口径 | 依据 |
|---|---|---|
| 截面排名 `rank` / `RANK` | 百分位 = 平均秩 / 当天有效个数，取值 (0, 1]；并列取平均秩；NaN 不参与，输出 NaN | **D-11 已裁决（2026-11-13）：按建议**。与 pandas `rank(pct=True)`、yli188 代码、Qlib main 的 `Rank` 同一口径。备选：`(秩−1)/(个数−1)`，取值 [0, 1]（`panelops.cs_rank(normalize=True)` 的口径）。两者对单个截面是同序的线性变换，但会改变 `rank(x) − 0.5`、`rank(x) < ts_rank(y)` 这类写法的数值。 |
| 时序排名 `ts_rank` / `Ts_Rank` / `TSRANK` | 当天值在窗口内的平均秩 / 窗口内有效个数，取值 (0, 1]；当天 NaN 时为 NaN | **D-12 已裁决（2026-11-13）：按建议**。WorldQuant 平台的 `ts_rank` 取值在 [0,1]；Alpha061、075、095 等把截面百分位和时序排名直接比较，只有同为 (0,1] 才有意义。备选：1 起的平均秩（yli188 用 `rankdata(x)[-1]`，取值 1..d）。在 2.2 的全窗口口径下有效个数恒等于 d。 |
| `ts_argmax` / `ts_argmin`（Alpha101） | 距今天数：最大（小）值出现在几天前，今天为 0；并列取最近一次 | **D-13 已裁决（2026-11-13）：默认读法 A，可切到读法 B**（`alpha101_registry(argmax="days_ago" | "position")`，核对工具 `--argmax`；翻译只写 `d.ts_argmax`）。001、057、060、096、098、100 在元数据里标「两读」。原文「which day ts_max(x, d) occurred on」。读法 A（默认）：距今天数，依据是 WorldQuant 平台对 `ts_arg_max` 的说明。读法 B：窗口内位置，从最早一天数起为 1，并列取最早（yli188：`rolling(d).apply(np.argmax) + 1`）。两者满足 B = d − A（并列时不同），**在 `rank` 之下方向相反**，影响 001、057、060、096、098、100 的符号。两种都能精确表达（B 需要新加的「并列取最早」选项）。 |
| `HIGHDAY` / `LOWDAY`（国君） | 距今天数，今天为 0，并列取最近一次 | 原文「最大值距离当前时点的间隔」。研报定义表 `LOWDAY` 也写成「最大值」，按名字取最小值（Q-G-D2）。并列取最近一次与 TA-Lib 的 Aroon 一致；**D-14 已裁决（2026-11-13）：按建议**（备选：并列取最早）。 |
| `correlation` / `CORR` | 窗口内成对有效的 Pearson 相关；任一序列窗口内方差为 0（逐值完全相等）或不足 2 对时为 NaN | panelops 口径。pandas 在零方差时给 NaN 或因舍入给出 ±inf；yli188 把 inf 换成 0。建议 NaN。 |

| `decay_linear` / `DECAYLINEAR` | 权重从最早到今天为 1, 2, …, d，除以权重和；窗口必须满 | 原文「weights d, d−1, …, 1」指从今天往回，与此相同。 |

### 3.2 Alpha158 的 `Rank`

取 Qlib main 分支的口径：`rolling(N, min_periods=1).rank(pct=True)`，即当天值在窗口内的平均秩 / 窗口内有效个数，取值 (0, 1]；当天 NaN 为 NaN。v0.8.6 的写法是 `percentileofscore(x1, x1[-1]) / len(x1)`（`percentileofscore` 本身已是 0–100 的百分数，再除以个数，数值口径不同，明显是旧版的错误），不采用。

- 三套因子的公式、参考实现在 `ashare.factor.alphas`，原文和本文件在 `docs/factors/`（2026-11-14 起随仓库公开，此前放在本地私有包里）；机制在 `ashare.factor.formula`（翻译用语言 `dsl`、组合算子 `ops`、Qlib 表达式转换 `qlib`、取数 `inputs`、核对工具 `verify`、外部因子包的加载入口）。三套因子作为内置因子集注册，别的因子包仍经 Python 入口点组 `ashare.factors` 挂上来，见 `docs/DESIGN.md` 6.2.1。

- 三套各有一个注册表（`alpha158`、`alpha101`、`gtja191`，由 `ashare.factor.formula.load_registry(名字)` 取得），名字为 `alpha158_kmid`、`alpha101_001`、`gtja191_001` 这样的格式，不混进 `default_registry`。`alpha101` 有一个选项 `argmax="days_ago" | "position"`（D-13）。

- **元数据标记**：每个因子带 `notes`（可多个），每个标记是 `(标记, 编号)`，标记共十一种：`笔误已改`、`两读`、`补参数`、`照抄`、`量纲混用`、`行业层级降级`、`缺失口径自定`，Alpha101 参考实现交稿后补充的 `有效格极少`、`有效率偏低`、`分母可为零`（4.4 节），以及逐条核对后补充的 `输入退化`（R-A-09、R-G-06）；编号是本文件里的疑点或决定编号。「条目 → 标记」表在 `ashare.factor.alphas/notes.py`，注册表构造时按条目编号自动挂上，翻译的人不用登记。`registry.with_note("两读")` 列出带某个标记的因子。

## 6. 核对工具的判定阈值

`python -m ashare.factor.formula.verify` 对每个因子比较候选（本仓库表达式）和参考实现（独立的 pandas 写法），只比较核对区间（默认最近 750 个交易日；之前另取一段预热数据，两边都在同一段数据上算）。设参考值为 b、候选值为 a，记 `err = |a − b| / (1 + |b|)`：

| 结论 | 条件 | 依据 |
|---|---|---|
| 一致 | NaN 掩码逐格相同，且所有两边都有限的格子 `err ≤ 1e-12` | 两边是不同的浮点算法（补偿求和与 pandas 的在线算法、直接相乘与重排的结合顺序），同一数学量的舍入差在几十到几千个 ulp（1e-14 到 1e-12）；超过这个量级就不是单纯的舍入顺序。 |
| 仅浮点差 | 掩码逐格相同，且 `err ≤ 1e-6` | 方差、相关、回归在近乎常数的窗口里是病态的：`N·Σx² − (Σx)²` 这类差在后复权价（10¹–10⁴ 元）上会把 1e-16 的相对舍入放大 (均值/标准差)² 倍；pandas 的滚动标准差在大值滑出窗口后留下残差（常数窗口给出很小的非 0 值，量级随数值大小变化）；Qlib 的 `Slope/Rsquare/Resi` 用不带补偿的累加和递推，误差随序列长度累积。1e-6 足以容纳这些差，又远小于因子在截面上的区分度。 |
| 不一致 | 其余情况（含掩码有任何一格不同） | 掩码不同说明缺失或定义域规则不同，不是浮点问题。 |

每天的截面秩相关（两边在同一天共同有效的格子上的 Spearman 相关）只报告最小值，**不参与判定**：在 `err ≤ 1e-6` 的前提下，排序只可能在相差不到 1e-6 的格子之间变动，而这正是浮点差的典型形态——例如一边给出精确的 0（若干只股票并列）、另一边给出极小的残差（并列被拆开），截面小时 Spearman 会因此掉到 0.99。用它判定会把纯浮点差报成不一致。

阈值附近的翻转（例如 Qlib 的「标准差 ≤ 2e-5 置 NaN」两边各算的标准差恰在 2e-5 两侧）会表现为少量掩码不同，按「不一致」报出，逐条查明后写在第 8 节。

**已知例外**（2026-11-13 裁决）：负责人认定「候选按约定就该与参考不同」的情形，登记成一条例外：编号、条件（一个表达式，与候选在同一份数据上求值）、候选在这些格子里必须给出的值。例外只对同时满足三条的格子生效：条件为真（有限且非零）；按正常规则不过关（掩码不同或 err > 1e-12）；候选逐位等于声明值。这些格子从统计里拿掉，单独计数并列出样例；条件成立但候选值不对的格子照样不一致；不许整条因子豁免。带例外的结论写成「一致（已知例外 N 格）」「仅浮点差（已知例外 N 格）」，汇总时与纯粹的「一致」「仅浮点差」分开计数。现在只有一条：Q-Q-06（WVMA5/10/20/30/60，条件是窗口内 `|收益|×成交量` 的最大值为 0，候选值 0）。
