## 性能摸底

最小脚手架完成后先实现并对拍三个最小版本，再测速；第一轮四场景单次测量已触发判定，批量补测与正式实现存在时间重叠（见设计疑问）。独立脚本为 `bench/spike/benchmark.py`、`bench/spike/src/lib.rs`。

条件：macOS 26.6 arm64、M5 Pro 15 逻辑核、Python 3.13.13、NumPy 2.5.4（Accelerate BLAS）、Rust 1.95.0 release/LTO/codegen-units=1。T=4000、N=5500、初始现金 1e7、100 股整手、佣金 .00025/最低 5、卖税 .001、滑点 .0005。月度为每 21 行，组合轮换列并改变暴露 .96… .999；1000 组的成员/权重确实不同，不复制稠密目标。市场种子 701，所有实现共享相同 mmap 市场；不包含公司行为、退市、顺延、量限。

单次四场景先逐日对拍（最大绝对净值差 8.44e-15，阈值 1e-9），所有 batch 也完成 Rust/numpy 逐日对拍；numpy 各模式结果逐位相同。正式计时不含数据生成，单次与最终 K=1000 均运行三次取中位数，原始样本在 `docs/step1/spike-results.json`。

判定：使用 Rust 内核。单次最快 numpy 在 100/月度与 100/每日是稀疏版，在 1000/月度与 1000/每日是全截面版。1000/月度单次只有 2.93×，没有夸报成 >3×；该场景批量仍为 3.77×。总体严格满足“任一单次或批量超过 3×”规则。

NumPy 全截面的连续 dot 很高效，H=1000 时比高级索引/union1d 的稀疏版更快；H=100 时稀疏减少访存。Rust 省掉逐日 Python 调度、临时数组与索引构造，活动列循环在寄存器/缓存中完成。线程池的众多小 numpy 调用争抢 GIL，增加线程反而变慢；进程池共享只读 mmap、避免复制市场，15 进程胜出。Rayon 共享借用市场且无进程 IPC，策略内部运算顺序不变。

## 设计疑问

| 原文 | 问题 | 处理 | 理由 |
|---|---|---|---|
| 价格 NaN 用最近有效 close；从未有效价格不可交易 | 今日有效 exec 但从无 close 如何处理，能否用今日 close 做成交前估值 | 有效 exec 可成交；缺 exec 用前日及以前 close 估值；期末 close 从未有效则按 0 | 有效 exec 已是有效报价；不使用尚未收盘的价格，避免前视 |
| 退市按最近有效 close 变现 | 是否包含当天 close；退市后新目标能否再次进入 | 用此前 close，首次退市永久终止该列交易，只有实际持仓生成事件 | 退市在当日成交前处理；不能把已退市列反复买回 |
| 目标股数、缩减买单按申报单位取整 | 送转零股使买入差额可能不满足最低申报量 | 原始买入差额也执行最小量/步长取整，不能成交的取整余量不顺延 | 保证每次实际买入符合申报单位；保留送转零股 |
| 任何时刻现金不得为负；最低佣金 | 极小卖单收入加现金不足最低佣金 | 取消该笔，属于现金不足，不新增顺延 | 保证现金非负；不暗中减免费用或截断负现金 |
| 有成本净值不高于同路径无成本 | 同一目标不代表同一持仓，该断言无条件不成立 | 同一实际成交路径用无成本影子账本验证；另测共同上涨路径，保留明确反例 | 初始 10000，价格 10→1，100 股整手，最低佣金 5：免费买 1000 股，收费买 900 股并留现金，末值反而更高。没有缩小随机对拍范围 |
| 一字板按 high==low 判断 | 普通平价成交也可能 high==low | 只在一字涨停禁买、一字跌停禁卖；普通一字价允许；容差半分钱 | 避免误封普通平价证券；价格超过限制也保守禁止对应方向 |
| 北交所前缀推断 | 现行 920 与历史 43/83/87/88 共存，旧码可能属于股转系统 | 同时支持现行和历史候选前缀，明确须核对证券主表 | 回测需要历史数据，但仅代码不能证明当时上市板块 |
| 稀疏目标未限制重复列 | 重复权重是覆盖还是相加 | 拒绝重复，允许无序列并同步排序 | 避免隐式合并，保证列升序执行的确定性 |
| Result.nav 未明确单位 | 资产金额还是单位净值 | nav=期末资产/initial_cash；cash/费用为金额 | 常用净值约定，README/SPEC 明示 |
| 所有面板都校验，且希望极低单次耗时 | 每次 run 扫 2200 万元素会重复做相同检查 | Market 构造时转换/校验一次，run 校验目标维度和配置；明确底层数组不可变契约 | 只读借用支持共享市场，基准单列首次构造成本，不把它隐藏在计时之外 |
| 先做性能摸底再正式实现 | 完整批量线程池测量远慢于单次，四场景单次已足够触发判定 | 四场景单次对拍/测速之后决定 Rust，批量摸底继续时开始正式实现 | **流程时序偏离**：批量与实现有重叠；没有跳过批量实测，最终仍按完整数据报告 |
| 全局 worklog 必须维护；本任务禁止项目外写入 | 全局路径不在许可写目录内，且本任务明确禁止 | 阶段成果记录在本文件，不写 ~/worklog | 遵守本任务更具体的禁止事项和沙箱 |

规则前缀依据：[北交所 920 公告](https://www.bse.cn/important_news/200021629.html)、[北交所新旧码对照](https://www.bse.cn/service/code_mapping.html)。其余交易规则以本任务给定细则为准，不扩展为完整交易所规则系统。

## 完整实现基准

`make bench`；同硬件/版本，T=4000、N=5500、约 100 个持仓目标、每 21 日调仓，市场种子 801，包含全部可选面板和周期性停牌/缺价/小成交量/分红/送转/退市。输入已经 C 连续 float64/bool，record_trades=False；K=1000 各组成员与暴露不同。三次中位数，完整样本与原始命令输出在 `benchmark-results.json`、`make-bench.txt`。

| 场景 | API 总耗时 ms | 准备 ms / 占比 | 内核+绑定 ms / 占比 | 后处理 ms / 占比 |
|---|---:|---:|---:|---:|
| 整手单次 | 9.805 | 0.029 / 0.31% | 9.525 / 99.58% | 0.011 / 0.12% |
| 小数股单次 | 9.487 | 0.029 / 0.30% | 9.655 / 99.64% | 0.006 / 0.06% |
| 1000 组 batch | 959.170 | 2.895 / 0.31% | 913.375 / 96.32% | 32.017 / 3.38% |

单次整手 **9.805 ms**，小数股 **9.487 ms**，1000 组 **0.959 s**，均达到复用 Market 对象时的 30 ms / 5 s 目标。

首次 Market 全量校验/转换另需 **38.000 ms**；不能把它当零成本。若每次新建市场再只回测一次，约 **47.805 ms**，不满足 30 ms 的冷启动解释。批量复用市场时，外围准备/后处理并非主要瓶颈；一次性扫描完整输入受内存带宽限制。阶段单独计时，百分比按三个阶段之和归一化，独立中位数之和不必等于端到端中位数。

参考实现的小市场 T=120、N=80、record_trades=True：Python **2.902 ms**，Rust **0.143 ms**，约 **20.3×**。

最终 `make dev && make check`：ruff 检查和格式、cargo fmt、clippy -D warnings、cargo test（1 passed）均通过；pytest **68 passed in 2.03s**（其中包含 2000 个随机对拍用例和性质循环）。README 的两段代码已实际执行，ashare/panelops 导入通过。最终内核 SHA 与变异恢复记录一致。

## 已知限制与未完成项

- 本轮没有真实行情/rqalpha 对账，按原计划留到步骤 4；panelops 算子与其语言选择留到步骤 3，没有创建 panelops-core。
- 面板共享借用，不能从其他线程修改底层 numpy 数组；无 GIL 不代表允许并发写输入。
- record_trades=True 会分配 T×N 持仓，batch 为 K×T×N；大批量默认关闭。
- 缺失 close 的新目标按需回查历史；若极长时间缺价，或大量新目标需要检查退市历史，会产生额外跨行读取；没有预先复制完整价格面板做前向填充。
- 本轮没有实现冲击模型、撮合队列、盘中多次成交、特殊证券分类、退市后重新上市、新股临时限价等；行情和可交易掩码由调用方负责。
- 浮点确定性保证在同环境、同输入的不同线程数之间；不承诺跨 CPU/编译器逐位一致。
- 步骤 1 的交付物和验证已完成；仍需后续真实数据对账。没有提交、推送、切换分支或修改 git 配置。

### 第二轮设计疑问

| 原文 | 问题 | 处理 | 理由 |
