# 事件驱动交付笔记（`ashare.events`，第 1 批，2026-11-13）

设计摘要在 `docs/DESIGN.md` 6.6。本笔记写定义、口径、已知的坑、验证、真实例子和留给负责人的问题。真实数据只读（数据版本 `2d0319f0…`，面板 4825 × 5923，20070104–20261112），没有联网、没有调用 Tushare。

## 1. 用法

```python
import ashare.data as ad
import panelbt
from ashare.events import extract, event_study, to_targets
from ashare.events.market import load

ds = ad.open(); m = load(ds, start="2015-01-05")
ev = extract.forecasts(ds).filter(forecast_type="预增", is_revision=False)
study = event_study(ev, m.returns, m.market_return, m.dates, m.symbols, window=(-20, 60))
print(study.test(1, 20))            # 朴素 t、按事件日聚类、自助法并排
plan = to_targets(ev, m.dates, m.symbols, m["can_buy_open"], holding=20, max_positions=50)
bt = m.backtest
result = panelbt.run(bt.market, plan.targets, bt.costs(), bt.config())
```

模块：`table.py`（事件表、对齐、去重、覆盖时点）、`_calendar.py`（信号日到成交日，私有）、`extract.py`（四类内置事件）、`targets.py`（事件转目标）、`study.py`（事件研究）、`market.py`（读面板、建回测行情，照 `ashare.backtest.market_from_panel` 写的私有副本）、`examples.py`（两个真实例子）、`bench.py`（性能基线）。

## 2. 事件表与时点

必需列 `symbol`、`date`（公告日历日 YYYYMMDD）、`kind`、`timing`；其余列原样保留。

- **默认 `after_close`**：Tushare 的公告日只到天、没有时刻。交易所的披露在收盘后（晚间）或次日开盘前，这两种都不晚于「公告日收盘后」，所以按收盘后可知、最早在公告日之后的第一个交易日开盘成交，**不会前视，最多晚一天**。代价在例子里看得见：大幅预增事件在公告日当天（第 −1 天）就有 +1.40% 的异常收益，说明相当一部分预告在公告日开盘前或盘中已经披露，这部分按默认口径吃不到（见 6.1）。
- **`pre_open`**：确知开盘前已披露时用，最早在不早于公告日的第一个交易日成交。按类型覆盖：`with_timing(ev, {"forecast": "pre_open"})`。
- **公告日不是交易日**：两种口径都顺延到其后第一个交易日（周六的公告周一成交）。
- **错位函数**：信号日 = 公告日当天或之前最后一个交易日（`pre_open` 为公告日之前最后一个交易日），成交日 = 信号日 + 1，经包内私有的 `execution_days`。它与主干新合入的 `ashare.backtest.timing.execution_days(signal_days, t, *, lag=1, tail="drop")` 同参数名、同语义（严格递增、末尾没有成交日的丢弃），由一条测试守住；合入后删掉私有副本、改为导入公共函数，`first_trade_index` 不变（`_calendar.py` 顶部有 TODO）。
- **对齐**（`align`）：丢弃证券不在面板的、公告日早于面板第一天的、可成交日超出面板的，各计数在 `dropped`。
- **同一只股票同一天多条**：提取函数各自先按「同一证券、同一报告期、同一公告日」去重（下表）；不同报告期的同日公告（如年报预告和一季报预告同一天）保留为两条。要合并成一条用 `dedupe(ev, by=列, keep="max")`，并留下 `n_same_day`。事件转持仓里同日同股的多条按重叠规则处理（延长/忽略/叠加）。
- **更正公告**：业绩预告的修正是独立事件（`is_revision`、`revision` 序号）；业绩快报的更正只用最早一条（`versions` 记条数），更正后的数字晚于事件日才可知，不回写。
- **公告日晚于实际影响日**：只按可知时点建事件，不把生效日挪到可知之前。真实影响早于可知时点的（指数调样、分红决议之前的预案）在事件研究里表现为事件前走势，结论只能是「可知之后还剩多少」，各类型下面分别写明。

### 3.1 业绩预告 `extract.forecasts`

- 事件日 = 预告公告日，`after_close`。
- 字段：`forecast_type`（预增/略增/扭亏/续盈/预减/略减/首亏/续亏/增亏/减亏/不确定/其他，去掉首尾空白）；`change_low`/`change_high` 归母净利润同比变动幅度下限/上限（%）；`change_mid` 两端平均或只有的一端；`net_income_low/high`、`prior_net_income` 预计净利润与上年同期（源是万元，换算成元）；`first_date` 该报告期首次预告日；`is_revision` = 公告日晚于首次预告日；`revision` = 第几次（0 为首次）。
- 坑：①「预增」在交易所规则下是同比增长 50% 以上，同一类型里幅度差别很大（预增的下限中位 87%，最大到几十万 %，上年同期接近 0 时幅度没有意义），按幅度筛选前先看上年同期；②只给一端的约 8%；③源 `first_ann_date` 缺失 0.07%，用本表该报告期最早一条代替；④同一证券、报告期、公告日的重复只出现在换码股票（新旧代码各报一次，4 组），留更新标识为 1 的一条；⑤修正公告在 2022 年后明显变少（制度变化），按年份比较修正事件要小心。

### 3.2 业绩快报 `extract.expresses`

- 事件日 = 快报公告日，`after_close`。
- `net_income` 快报净利润（与利润表归母净利润在 1% 内一致的占 63%：快报是未经审计的初步数，口径大体是归母）；`revenue`。
- 超预期两种口径：`yoy` = 快报净利润 / 上年同期归母净利润 − 1，上年同期取公告日当天及以前已公告的最新版利润表（之后的重述不用；上年同期 ≤ 0 为空，85% 的快报有值）；`vs_forecast` = (快报净利润 − 最近一次预告中点) / |上年同期|，预告只取同一报告期、公告日**严格早于**快报的（同日公告不算「之前」），预告只给变动幅度时中点 = 预告里的上年同期 × (1 + 幅度中点)；`forecast_position` 是在预告区间里的位置；`has_forecast`（67% 的快报之前有预告）。
- 坑：快报大多在已有预告之后，市场的「意外」主要已经在预告里兑现（例二的结果印证了这一点）；同一报告期多条快报 20 组，只用最早一条。

### 3.3 分红 `extract.dividends(ds, stage)`

**先核实了本地分红表各日期的含义**（全部是实测）：

- 表里几乎只有「实施」行：实施 55,842 行，股东大会通过 40、预案 31、预披露 3。所以**没有真正的预案记录可用**。
- 实施行的 `ann_date` **不是预案公告日，也不是董事会决议日**：与同一报告期利润表首次公告日比，晚 21–29 天居多（中位 24 天，峰值 21、22 天；早于报告日的 794 条、同一天的 1,153 条，共 46,359 条可比）。年度股东大会须在召开 20 日前通知，通知通常随年报一起发出，所以最短间隔正好是 21 天——这一列是**股东大会决议日（或其公告日）**。21.96% 落在周六（周日 1 条），与「周五开会、周六见报」一致；原研究说的「27% 落在周六」本地实测为 22%，说它是「董事会决议日」与日期间隔不符。少量预案行的 `ann_date` 等于年报公告日（例：中国平安 2019 年年报 2020-02-21 的预案行），印证预案日 ≈ 报告日。
- `imp_ann_date` 是实施公告日，中位在决议日后 25 天；`ex_date` 除权除息日，中位在实施公告后 7 天。

三个 `stage`：

- `"report"`（默认，**预案日的代理**）：事件日 = 同一报告期定期报告的首次公告日。A 股利润分配预案由审议定期报告的同一次董事会提出、随报告披露。要求报告日不晚于决议日（否则丢弃）。代理的偏差：数值取最终实施的派现/送转（预案在股东大会被改的少数情况会前视）；**从未实施的预案不在表里**（只看「说到做到」的公司，有选择偏差，而且这个偏差靠本地数据无法量化）；季度之外的特别分红没有对应报告，丢弃。约 4,900 条因此丢掉。
- `"resolution"`：事件日 = 股东大会决议日。
- `"implementation"`：事件日 = 实施公告日。

字段：`cash_per_share` 税前每股派现（元）、`stock_per_share` 每股送转、`resolution_date`、`implementation_date`、`record_date`、`ex_date`、`report_date`。同一证券、报告期、除权日的重复行只留一条。

### 3.4 指数成分调整 `extract.index_changes(ds, "csi300" | "csi500" | "csi1000")`

- 原始库只有成分权重的月末快照（沪深 300、中证 500 各 239 期，2009-01 有一期在 01-23），没有调样公告。相邻两期比较：新出现的是调入（`index_add`），消失的是调出（`index_remove`）；事件日 = 新快照日，`after_close`。
- **推不出公告日，只能用生效之后的快照**：中证指数的定期调样一般 5 月底、11 月底公告，6 月、12 月第二个星期五的下一交易日生效；月末快照最早在生效后两到三周、公告后约五周才反映调整。所以这类事件**会低估甚至完全错过公告效应**，只能研究「生效并被快照记录之后」。`regular_review` 标记快照月是 6 月或 12 月（实测沪深 300 调入 861 条里 534 条在这两个月，其余是临时调整和快照间隔造成的）。`delisted_by` 标记调出时已退市（沪深 300 16 条）。
- 本地实测（剔除退市、相对中证全指、按事件日聚类）：沪深 300 调入在快照之前 40 天累计 +1.17%（聚类 t 1.32），快照后 40 天 −1.20%（t −1.48）；调出事件前 −1.79%（t −1.97），之后 +1.60%（t 2.25）。中证 500 方向相同，调出后 40 天 +2.01%（t 3.10）。快照之后的「反转」可能是真实效应，也可能是对公告和生效前价格压力的回吐，用这份数据分不清。要研究公告效应需要真实的调样公告日（见第 9 节）。

## 4. 事件转目标持仓 `to_targets`

规则（模块文档串有完整说明）：

- 决策日 = 可成交日 + `entry_lag`；开盘买入，持有 `holding` 个交易日，在买入日后第 `holding` 个交易日开盘卖出（`panelbt` 第 t 行就是第 t 日成交时的目标，错位在这里做完）。
- 买不进（`can_buy` 为假：停牌、开盘涨停、一字板）：`defer=0` 放弃；`defer=K` 在 K 天内第一个可买日买入，持有期从实际买入日算。
- 重叠（同股新事件的决策日早于原持仓卖出日）：`extend` 卖出日延到「新决策日 + holding」；`ignore` 忽略；`stack` 另开一份、权重叠加。正好落在卖出日当天的不算重叠，新开一份首尾相接，在回测里就是继续持有。
- 持仓数上限：按决策日先后、同日按 `priority`（默认 `value`，都没给时按证券代码顺序）处理，满了放弃。**名额在决策日占用，不看之后能否买到**：顺延期满仍没买到的名额在最后一次尝试的次日释放；同一证券还在顺延中的买单遇到新事件，新事件并入（`absorbed`）。最初的写法按「之后买不买得到」决定占不占名额，这会用到决策日之后的行情，被防前视测试抓到后改掉（变异 M6）。
- 权重：`equal` 当日所有持仓份额等权满仓；`value` 按事件数值占比满仓（数值须为正）；`fixed` 每份固定比例。之后单只截到 `max_weight`（多出的留现金），合计超过 1 时同比例缩到 1。按数值加权时，延长事件的新数值只从它的决策日起生效，把持仓切成前后两段（最初直接改整段持仓的数值，等于用未来事件改写过去的目标，同样被防前视测试抓到，变异 M7）。
- 只在持仓集合变化的日子写一行；那一行对所有持仓重新按规则给权重，所以等权会有少量再平衡交易（可以用 `Config(trade_band=...)` 抑制）。
- 输出 `EventTargets`：`targets`（`panelbt.Targets`）、`positions`（每份持仓的买入日、卖出日、数值、合并的事件数）、`events`（每个事件的 `status`：opened/deferred/extended/ignored/absorbed/not_buyable/capacity/after_panel_end）、`counts`。

## 5. 事件研究 `event_study`

- 第 0 天 = 可成交日；第 k 天的收益 = 第 `avail+k` 日收盘对前一交易日收盘的复权收益（`daily_returns`：缺行情日收益为 0、复牌日记跳空，未上市为缺失）。
- 异常收益三种口径：①减市场，默认中证全指（`000985.CSI`，**价格指数，不含分红**，相对它的超额每年约高估一到两个百分点的股息）；②减同行业同市值组合（`size_industry_groups`：前一日总市值五分位 × 申万一级行业；`group_benchmark`：组内**留一**等权，组内少于 5 只为缺失；行业含回填的历史分类，作基准可以接受，但不是严格当时口径）；③调用方给的 T×N 预期收益（例如风险模型的因子部分）。**风险模型的特质收益没有做**：`ashare.risk` 目前没有公开的逐日残差接口（残差只在内部滑动窗口里），而且尚未接真实行情，见第 9 节。
- 窗口不完整落在面板内的事件整条丢弃；窗口内缺失的异常收益记 0，`coverage` 记哪些格子是真数据。
- 检验并排三种：朴素 t（事件独立）、按事件日聚类的标准误（CR1，t 分布自由度 = 事件日数 − 1）、按事件日整块重抽的自助法（1000 次，双侧 p）。`cluster="month"` 或 `test(..., cluster=数组)` 可以换成按月聚类，用来覆盖相邻事件日窗口重叠造成的相关。
- 其他输出：`by_year()`、`caar(mask)`（含事件前走势）、`split(mask, a, b)`（例子里按第 0 天开盘能否买入分开统计）。

## 6. 两个真实例子

代码：`src/ashare/events/examples.py`（`python -m ashare.events.examples --root … --out report.json`，全程约 10 秒）。**参数在运行前定好，写在 `PARAMS` 里，没有按结果改过**：

- 样本 2010-01-04 至 2026-11-12；窗口 [−20, 60]；检验区间 [−20,−1]、[0,0]、[1,5]、[1,20]、[1,60]、[0,20]；市值分 5 组；自助法 1000 次。
- 回测：可成交日开盘买入（`entry_lag=0`），持有 20 个交易日，重叠延长，买不进放弃（`defer=0`），当日持仓等权，最多 50 只、单只不超过 5%（不到 20 只时有现金）；佣金万 2.5 最低 5 元、过户费万 0.1 双边、滑点 5 个基点、历史印花税；初始 1000 万；完整 A 股规则（开盘可买可卖掩码、整手、公司行为、退市）。比较基准是中证全指（价格指数），另报相对等权全 A（逐日等权平均收益，不含成本，是偏高的基准）。

### 6.3 聚类的影响（两个例子共同）

## 9. 交给负责人

需要决定或安排的事（每条附我的建议）：

1. **数据层公开列**：`Data.table` 对业绩预告只公开了净利润上下限，没有类型、变动幅度、上年同期、首次公告日；快报没有公开，分红没有公开股东大会决议日/记录日；利润表没有归母净利润；指数权重表只在面板里。我经数据层内部的 `Data._store.scan` 读原始表，源字段名只出现在 `extract.py`。**建议**：数据层把这些列加进 `catalog.PUBLIC_TABLES`（预告：type、p_change_min/max、last_parent_net、first_ann_date；快报：n_income；分红：div_proc、record_date；利润表：n_income_attr_p；index_weight 整表），之后 `extract.py` 改用 `Data.table`。另外 `Data.table("index_daily")` 可用（`market.py` 用的就是它）。
2. **缺的数据集**：①中证指数调样公告（公告日、生效日、调入调出名单），没有它指数事件只能研究生效后；②真正的分红预案记录（Tushare 分红接口按公告日或报告期查询能拿到「预案」进度行，本地按除权日分区下载，几乎只剩实施行）；③公告的披露时刻（盘前/盘中/盘后），决定默认口径吃不吃得到公告日当天的反应。**建议**：先补②（同一接口换查询方式，成本最低），①需要找来源，③目前没有现成来源。
3. **主干的公共函数**：合入时删掉 `_calendar.execution_days` 和 `market.market_from_panel` 两个私有副本，改为导入 `ashare.backtest.timing.execution_days` 与 `ashare.backtest.market_from_panel`（两处都有 TODO 注释，调用处不用改）。注意公共 `BacktestMarket.costs()` 直接调用 `ASHARE.costs`：费用档案从 2008-09-19 开始，更早的日期直接报错，2022-04-29 之前还要求显式给出过户费，所以从 2007 年或 2010 年开始的回测要调用方自己补。我的副本补了（2008-09-19 前按历史卖出印花税，过户费默认 1e-5 双边，有单测），换的时候要保留。**建议**：在公共版本里补上这两处。
4. **风险模型特质收益**：`ashare.risk` 没有逐日残差的公开接口。**建议**：风险模型接真实行情时顺便公开「第 t 天模型对第 t+1 天收益的残差」，事件研究直接当第三种口径（`event_study` 已经接受 T×N 基准）。
5. **名额满时的先后**：默认按证券代码顺序先到先得，是任意但确定的。**建议**：例子保持事先定的口径不变；以后的研究若用名额上限，预注册时写明 `priority`（例如按幅度或市值）。

我发现但没有解决的问题：

- 例一的结论对「收盘后可知」很敏感（公告日当天 +1.4%）。没有逐条披露时刻，无法确认多少公告其实盘前可交易。
- 分红预案日是代理，未实施的预案缺失造成的选择偏差无法用本地数据量化。
- 回测的比较基准：中证全指是价格指数；等权全 A 是逐日再平衡、不含成本的理论组合，两者都不是可投资基准。
- 事件研究的同行业同市值基准用的行业含 2014 年以前的回填分类（`industry_source = 3`），作为基准影响不大，但不是严格当时口径。
- 自助法只按事件日整块重抽，相邻事件日窗口重叠造成的相关只能靠按月聚类近似处理。
