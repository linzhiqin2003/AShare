# 事件驱动交付笔记（`ashare.events`，2026-11-13）

设计摘要在 `docs/DESIGN.md` 6.6。本笔记写定义、口径、已知的坑、验证、真实例子和留给负责人的问题。真实数据只读（数据版本 `2d0319f0…`，面板 4825 × 5923，20070104–20261112），没有联网、没有调用 Tushare。

## 1. 用法

```python
import ashare.data as ad
import panelbt
from ashare.events import extract, event_study, to_targets
from ashare.events.market import load

ds = ad.open(); m = load(ds, start="2015-01-05")
ev = extract.forecasts(ds).filter(forecast_type="预增", is_revision=False)
study = event_study(ev, m.returns, m.market_return, m.dates, m.symbols, window=(-20, 60))
print(study.calendar_time(1, 20))   # 首选：日历时间组合，Newey–West t
print(study.test(1, 20))            # 按事件：朴素 t、按月聚类、自助法并排
plan = to_targets(ev, m.dates, m.symbols, m["can_buy_open"], can_sell=m["can_sell_open"],
                  holding=20, max_positions=50, priority="change_low")
bt = m.backtest
costs = bt.costs(commission_rate=2.5e-4, commission_min=5.0, slippage=5e-4)
result = panelbt.run(bt.market, plan.targets, costs, bt.config())
```

模块：`table.py`（事件表、对齐、去重、覆盖时点）、`_calendar.py`（公告日到可成交日，调用公共的 `ashare.backtest.timing.execution_days`）、`extract.py`（四类内置事件）、`targets.py`（事件转目标）、`study.py`（事件研究）、`market.py`（在 `ashare.backtest.market_from_panel` 的面板上多读事件研究用的字段，算复权收益和指数收益）、`examples.py`（两个真实例子）、`bench.py`（性能基线）。回测行情、整手、开盘可买可卖掩码和费用（`panelbt` 的 A 股历史费率档案，见 `docs/ASHARE_FEES.md`）全部来自主干的公共实现，本包不再自带。

## 2. 事件表与时点

必需列 `symbol`、`date`（公告日历日 YYYYMMDD）、`kind`、`timing`；其余列原样保留。

- **默认 `after_close`**：Tushare 的公告日只到天、没有时刻。交易所的披露在收盘后（晚间）或次日开盘前，这两种都不晚于「公告日收盘后」，所以按收盘后可知、最早在公告日之后的第一个交易日开盘成交，**不会前视，最多晚一天**。代价在例子里看得见：大幅预增事件在公告日当天（第 −1 天）就有 +1.47% 的异常收益（同行业同市值口径），说明相当一部分预告在公告日开盘前或盘中已经披露，这部分按默认口径吃不到（见 6.1）。
- **`pre_open`**：确知开盘前已披露时用，最早在不早于公告日的第一个交易日成交。按类型覆盖：`with_timing(ev, {"forecast": "pre_open"})`。
- **公告日不是交易日**：两种口径都顺延到其后第一个交易日（周六的公告周一成交）。
- **错位**：信号日 = 公告日当天或之前最后一个交易日（`pre_open` 为公告日之前最后一个交易日），可成交日 = `execution_days(信号日, lag=1, tail="drop")`，全项目共用这一个函数（`docs/DESIGN.md` 4.3）。
- **对齐**（`align`）：丢弃证券不在面板的、公告日早于面板第一天的、可成交日超出面板的，各计数在 `dropped`。
- **同一只股票同一天多条**：提取函数各自先按「同一证券、同一报告期、同一公告日」去重（见第 3 节）；不同报告期的同日公告（如年报预告和一季报预告同一天）在事件表里保留为两条。规则：
  - 事件研究默认把「同一证券、同一可成交日、同一类型」的多条合并成一条（保留排在前面的一条，`dedupe=False` 关掉），合并条数在 `dropped["same_day_duplicates"]`。否则同一段收益会被算两次。
  - 事件转持仓里同日同股的多条按重叠规则处理（延长/忽略/叠加），不会重复买入。
  - 要按数值合并（例如取幅度最大的一条）用 `dedupe(ev, by=列, keep="max")`，会留下 `n_same_day`。
- **更正公告**：业绩预告的修正是独立事件（`is_revision`、`revision` 序号）；业绩快报的更正只用最早一条，更正后的数字晚于事件日才可知，不回写；「之后还会有几条更正」也是未来信息，不输出。
- **公告日晚于实际影响日**：只按可知时点建事件，不把生效日挪到可知之前。真实影响早于可知时点的（指数调样、分红决议之前的预案）在事件研究里表现为事件前走势，结论只能是「可知之后还剩多少」，各类型下面分别写明。

### 3.1 业绩预告 `extract.forecasts`

- 事件日 = 预告公告日，`after_close`。
- 字段：`forecast_type`（预增/略增/扭亏/续盈/预减/略减/首亏/续亏/增亏/减亏/不确定/其他，去掉首尾空白）；`change_low`/`change_high` 归母净利润同比变动幅度下限/上限（%）；`change_mid` 两端平均或只有的一端；`net_income_low/high`、`prior_net_income` 预计净利润与上年同期（源是万元，换算成元）。
- **首次与修正（一套规则）**：同一证券、报告期内按公告日排序；`first_date` = min(源记载的首次公告日, 本表该报告期最早的公告日)；`revision` = 本表里排在它前面的条数，若源记载的首次公告日早于本表最早一条（真正的首次预告不在表里，多是随定期报告披露），再加 1；`is_revision` ≡ `revision > 0`。原来「首次」与「修正」各用一条规则（一个看源字段、一个看本表），两者在 3,334 个报告期里不一致，37 个报告期的事件标错；统一后每个报告期的 `revision` 都是从 0 或 1 开始的连续整数（全量核对过），首次预告比原来少 39 条。
- 坑：①「预增」在交易所规则下是同比增长 50% 以上，同一类型里幅度差别很大（预增的下限中位 87%，最大到几十万 %，上年同期接近 0 时幅度没有意义），按幅度筛选前先看上年同期；②只给一端的约 8%；③源 `first_ann_date` 缺失 0.07%，用本表最早一条代替；④同一证券、报告期、公告日的重复只出现在换码股票（新旧代码各报一次），留更新标识为 1 的一条（两行数值不同时也取它，有测试）；⑤修正公告在 2022 年后明显变少（制度变化），按年份比较修正事件要小心。

### 3.2 业绩快报 `extract.expresses`

- 事件日 = 快报公告日，`after_close`。
- `net_income` 快报净利润（与利润表归母净利润在 1% 内一致的占 63%：快报是未经审计的初步数，口径大体是归母）；`revenue`。
- 超预期两种口径：`yoy` = 快报净利润 / 上年同期归母净利润 − 1，上年同期取公告日当天及以前已公告的最新版利润表（之后的重述不用；上年同期 ≤ 0 为空，85% 的快报有值）；`vs_forecast` = (快报净利润 − 最近一次预告中点) / |上年同期|，预告只取同一报告期、公告日**严格早于**快报的（同日公告不算「之前」），预告只给变动幅度时中点 = 预告里的上年同期 × (1 + 幅度中点)；`forecast_position` 是在预告区间里的位置；`has_forecast`（67% 的快报之前有预告）。
- 坑：快报大多在已有预告之后，市场的「意外」主要已经在预告里兑现（例二的结果印证了这一点）；同一报告期多条快报 20 组，只用最早一条。

### 3.3 分红 `extract.dividends(ds, stage)`

**先核实了本地分红表各日期的含义**（全部是实测）：

- 表里几乎只有「实施」行：实施 55,842 行，股东大会通过 40、预案 31、预披露 3。所以**没有真正的预案记录可用**。
- 实施行的公告日（公共表 `announcement_date`）**不是预案公告日，也不是董事会决议日**：与同一报告期利润表首次公告日比，晚 21–29 天居多（中位 24 天，峰值 21、22 天）。年度股东大会须在召开 20 日前通知，通知通常随年报一起发出，所以最短间隔正好是 21 天——这一列是**股东大会决议日（或其公告日）**。21.96% 落在周六，与「周五开会、周六见报」一致。
- 实施公告日中位在决议日后 25 天；除权除息日中位在实施公告后 7 天。

三个 `stage`：

- `"report"`（默认，**预案日的代理**）：
  - **年报期（1231）**：事件日 = 年报首次公告日。年度利润分配预案由审议年报的同一次董事会提出、随年报披露。要求年报日不晚于决议日（否则丢弃）。
  - **中报、季报及其他报告期**：分红大多在报告之后另行公告（三季报期 37% 的报告日比决议日早 30 天以上），用报告日会前视，所以**落到决议日**，`date_source="resolution"`（44,468 条用年报日、5,932 条用决议日）。这一条由测试守住：非年报期的事件日不早于决议日。
  - 代理的偏差：数值取最终实施的派现/送转（预案在股东大会被改的少数情况会前视）；**从未实施的预案不在表里**（只看「说到做到」的公司，有选择偏差，这个偏差靠本地数据无法量化）。
- `"resolution"`：事件日 = 股东大会决议日。
- `"implementation"`：事件日 = 实施公告日。

字段：`cash_per_share` 税前每股派现（元）、`stock_per_share` 每股送转、`resolution_date`、`implementation_date`、`record_date`、`ex_date`、`report_date`（只在 `"report"`）、`date_source`（只在 `"report"`）。

**同一证券、报告期、除权日有多条实施行时按进度分别取日期**（这类组 1,307 个）：决议日取最晚的一条（较早的那条常是年报日被记进了这一列，例如 600519.SH FY2024 的 20250403 与 20250520），实施公告日取最早的一条。原来按行整体去重、各进度取同一行，会让决议日落到年报日上。

### 3.4 指数成分调整 `extract.index_changes(ds, "csi300" | "csi500" | "csi1000")`

- 原始库只有成分权重的月末快照（沪深 300、中证 500 各 239 期），没有调样公告。相邻两期比较：新出现的是调入（`index_add`），消失的是调出（`index_remove`）；事件日 = 新快照日，`after_close`。
- **推不出公告日，只能用生效之后的快照**：定期调样一般在调整月之前约两周公告、调整月第二个星期五的下一交易日生效；月末快照最早在生效后两到三周、公告后约五周才反映调整。所以这类事件**会低估甚至完全错过公告效应**，只能研究「生效并被快照记录之后」。
- `regular_review` 标记快照月是定期调样月：**2013-11 之前是 1 月、7 月，之后是 6 月、12 月**（快照实测从 2013-12 起换到 6/12 月）。按此规则沪深 300 调入 861 条里 842 条落在定期调样月，其余是临时调整。`delisted_by` 标记调出时已退市（沪深 300 16 条）。

## 4. 事件转目标持仓 `to_targets`

规则（模块文档串有完整说明）：

- 决策日 = 可成交日 + `entry_lag`；开盘买入，持有 `holding` 个交易日，在买入日后第 `holding` 个交易日开盘卖出（`panelbt` 第 t 行就是第 t 日成交时的目标，错位在这里做完）。
- 买不进（`can_buy` 为假：停牌、开盘涨停、一字板）：`defer=0` 放弃；`defer=K` 在 K 天内第一个可买日买入，持有期从实际买入日算。
- 重叠（同股新事件的决策日早于原持仓卖出日）：`extend` 卖出日延到「新决策日 + holding」；`ignore` 忽略；`stack` 另开一份、权重叠加。正好落在卖出日当天的不算重叠，新开一份首尾相接，在回测里就是继续持有。
- **持仓数上限与先后**：按决策日先后；同一决策日按 `priority` 列从大到小（默认取 `value`）；再相同时按 `tie_key` = `crc32(f"{seed}|{symbol}|{公告日}")` 从小到大。这个键只由事件自己决定，与代码大小、事件表的行序、其他事件都无关（所以不破坏防前视），换 `seed` 可以检查结论对次序的敏感程度。原来再相同时按证券代码顺序，名额满得快的日子系统性偏向代码小的股票：例一里 000 开头的事件开仓 47%、603 开头 25%。
- **名额的占用与释放**：名额在决策日占用，不看之后能否买到；顺延期满仍没买到的名额在最后一次尝试的次日释放；同一证券还在顺延中的买单遇到新事件，新事件并入（`absorbed`）。卖出：给了 `can_sell`（例子里用 `can_sell_open`）时，名额在**计划卖出日起第一个可卖日**释放——跌停、停牌卖不出时 `panelbt` 会把卖单顺延（`Config.carry_blocked` 默认开），持仓实际多拿几天，名额也跟着多占几天；不给时在计划卖出日释放，这时卖不出的那几天实际持仓数可能超过上限（例一的开仓里约 1.9% 的卖出当天被挡）。这一判断只用到「到今天为止卖出过没有」，同样不前视（防前视测试把未来的可卖掩码一起改掉）。
- 权重：`equal` 当日所有持仓份额等权满仓；`value` 按事件数值占比满仓（数值须为正）；`fixed` 每份固定 `fixed_weight`（不给时取 `1 / max_positions`），只在持仓集合变化的日子按这个固定值重写，不按市值漂移再平衡。之后单只截到 `max_weight`（多出的留现金），合计超过 1 时同比例缩到 1。按数值加权时，延长事件的新数值只从它的决策日起生效，把持仓切成前后两段。
- 只在持仓集合变化的日子写一行；那一行对所有持仓重新按规则给权重，所以等权会有少量再平衡交易（可以用 `Config(trade_band=...)` 抑制）。
- 输入检查：`dates`、`symbols` 必须一维，`can_buy`、`can_sell` 形状必须是 (交易日数, 证券数)，否则报出期望和实际形状。
- 输出 `EventTargets`：`targets`（`panelbt.Targets`）、`positions`（每份持仓的买入日、计划卖出日、数值、合并的事件数）、`events`（每个事件的 `status`：opened/deferred/extended/ignored/absorbed/not_buyable/capacity/after_panel_end）、`counts`。

## 5. 事件研究 `event_study`

- 第 0 天 = 可成交日；第 k 天的收益 = 第 `avail+k` 日收盘对前一交易日收盘的复权收益（`daily_returns`：缺行情日收益为 0、复牌日记跳空，未上市和退市后为缺失）。
- 异常收益三种口径：①减市场，默认中证全指（`000985.CSI`，**价格指数，不含分红**，相对它的超额每年约高估一到两个百分点的股息）；②减同行业同市值组合（`size_industry_groups`：前一日总市值五分位 × 申万一级行业；`group_benchmark`：组内**留一**等权，组内少于 5 只为缺失；行业含回填的历史分类，作基准可以接受，但不是严格当时口径）；③调用方给的 T×N 预期收益（例如风险模型的因子部分）。**风险模型的特质收益没有做**：`ashare.risk` 目前没有公开的逐日残差接口，见第 9 节。
- **缺失**（默认 `complete=True`）：
  - 基准缺失不当 0：该事件该日记缺失，和个股缺失一样处理。原来把缺失的同行业同市值基准当 0，等于那天的异常收益取个股原始收益，抬高了例一的结果（[1,20] 原来报 +0.68%，现在 +0.41%）。
  - 窗口起点早于上市（首个有效收益）的事件剔除，计入 `listed_too_short`。原来这些事件上市前的格子记 0，相当于把新股前几天的走势掺进来。
  - 窗口内有其他缺失的事件剔除，计入 `incomplete_window`。
  - 只有**退市之后**的格子记 0（退市后持有现金），不剔除：否则只留下活下来的股票，造成幸存者偏差。
  - 停牌不算缺失：停牌日个股收益记 0；同行业同市值分组沿用停牌前最后一个市值（只看过去），停牌股票仍有基准，但不计入同组别人的基准（`group_benchmark(member=has_quote)`）。只做完整窗口、不处理停牌时，例一会剔除 2,350 条窗口不完整的事件（连同上市不足的一起，92% 的窗口里有停牌：停牌日没有市值、分不了组）、买不进的事件从 607 条剩 128 条，样本明显偏向交易连续的股票；处理后例一只剔除 288 条，剩下的是行业缺失或所在行业市值组不足 5 只。`complete=False` 回到「缺失记 0」的旧口径，用来对照。
  - 窗口必须完整落在面板内（`window_outside_panel`）。
- **检验**：
  - **首选：日历时间组合检验** `calendar_time(a, b)`。每个交易日 τ，把相对日落在 [a, b]、当天有数据的事件等权成一个组合，得到组合日异常收益 r_τ（只用组合非空的日子）；检验 r_τ 的均值，标准误用 Newey–West（Bartlett 权，滞后默认 floor(4·(T/100)^(2/9))）。它不假设事件之间独立：同日扎堆、同行业相邻几天的共同冲击、窗口重叠的事件共享同一段市场走势，都体现在 r_τ 的时间序列里。报告里给 `t_nw` 和 `implied_car` = 日均 × 区间天数。
  - 两种口径（`weight`）：默认 `"days"` 每个交易日权重相同，检验的是「按日等权」的漂移，事件只有一两个的日子和几十个事件的日子一样重；`"events"` 按当天事件数加权，检验的量与按事件平均的 CAR（`test` 的 `mean`）完全相同（窗口完整时 `implied_car` 逐位相等），标准误仍然按日历时间序列用 NW 算，所以同样不假设事件独立。两者检验的不是同一个量，结果可以相反（见例二 [1,5]）。
  - 适用条件：NW 只修正有限阶的自相关。共同因子高度持续时（例如行业因子日自相关 0.9、单行业的事件在一个月里陆续发生）它偏宽松，见 5.1 的场景 f；另外去掉没有事件的日子后，自相关的滞后按「有事件的日子」计数，跨过空档的两天被当成相邻，事件稀疏时更要注意。
  - 并排给出的按事件检验 `test(a, b)`：朴素 t；聚类标准误（CR1，t 分布自由度 = 聚类数 − 1），**默认按可成交日所在自然月聚类**，`cluster="date"` 或 `"quarter"` 可换；按聚类整块重抽的自助法。聚类数少于 30 时发警告：这时聚类标准误和自助法都偏宽松。
- 其他输出：`by_year()`、`caar(mask)`（含事件前走势；`n` 是每个相对日有真实数据的事件数）、`split(mask, a, b)`（例子里按第 0 天开盘能否买入分开统计）。
- 输入检查：`returns` 必须是 (交易日数, 证券数) 并与 `dates`、`symbols` 一致，`benchmark` 长度 T 或 T×N，`can_buy` 同形状，`mask`、聚类标签长度等于事件数；不一致时报出期望和实际形状。

### 5.1 哪种检验在什么情况下可信（合成数据，名义水平 5%）

T = 500、N = 300、个股噪声 N(0, 0.02)，每个场景 500 次模拟（± 后面是 95% 抽样误差）。场景 c、d 是审查给的两个扎堆场景：c 是 10 个行业 × 30 只，行业因子 AR(1) φ = 0.3、扰动 1%，25 个「行业-周」每组 8 只、事件日落在相邻 5 天内，看 CAR[1,20]；d 是 200 个 β = 1.5 的事件挤在连续 40 个交易日、基准是市场，看 CAR[1,60]。

|场景|朴素|按日聚类|按月聚类|按月自助法|**日历时间 NW**|
|---|---:|---:|---:|---:|---:|
|a 事件独立|3.6%|3.2%|5.2%|7.2%|**4.2%**|
|b 同一天 10 只共享冲击|41.8%|4.4%|5.4%|7.6%|**5.4%**|
|c 同行业相邻几天扎堆|23.8%|18.4%|6.8%|9.0%|**8.2% ± 2.4%**|
|d 窗口重叠 + β ≠ 1|61.0%|58.8%|29.6%|56.2%|**5.0%**|

- 按日聚类只挡得住「同一天」的共同冲击（b）；c、d 里的相关跨越了不同的日子。
- 按月聚类在 c 里回到名义水平附近，但 d 里事件只跨两三个月、聚类太少，仍然拒绝 30%（这时会发警告）。
- 日历时间检验四个场景都在名义水平附近；c 略偏高（8.2%，误差 ±2.4%），是行业因子的自相关加上每天只有十几只事件的小样本造成的。
- **场景 f（因子高度持续）是日历时间检验的失效区**：10 个行业 × 30 只，行业因子 AR(1) φ = 0.9、扰动 0.4%，10 个行业各 20 只事件分散在 20 天里，CAR[1,20]，400 次模拟（误差约 ±4%）：日历时间默认滞后拒绝 25%，滞后 20 阶 13%，滞后 60 阶 15.5%；按月聚类 9.2%，按季聚类 7.5%。加大滞后能减轻但消除不了。日收益里出现 0.9 的自相关并不现实，所以这是适用条件而不是常态；怀疑存在持续的共同因子时，用按季聚类和加大滞后的日历时间 t 一起看。真实例子上把滞后加到 20、60 阶，结论不变（例一减行业市值 [1,20] 按日等权 t 1.41 → 1.37 / 1.26，[1,60] 3.18 → 3.14 / 3.27；例二减行业市值 [1,20] −1.38 → −1.41 / −1.35）。
- 测试守住的容差（`test_review_scenarios_rejection_rates`，每个场景 200 次模拟，抽样误差约 ±3 个百分点）：日历时间 ≤ 10%；按日聚类 > 12%（证明场景确实扎堆）；按月聚类在 c 里 ≤ 11%、在 d 里 > 15%（记录它的已知失效）。

## 6. 两个真实例子

代码：`src/ashare/events/examples.py`（`python -m ashare.events.examples --root … --out report.json`）。窗口、检验区间、持有期、名额、单只上限、成本这些参数在第一版运行前定好，写在 `PARAMS` 里，没有按结果改过。返工时改了口径（完整窗口、检验方法、费用改用公共费率表），**也改了回测的两条规则**：名额不够时的先后从「按代码顺序」改成按 `priority`（例一按预告同比下限、例二按快报同比，再相同按 `tie_key`），名额从计划卖出日改到实际卖出日释放。改的理由是上一轮复核发现按代码顺序有板块偏差，回测数字因此有变化（例一扣成本年化 14.1% → 14.3%，例二 5.4% → 5.7%）。另外两项是事后补做的敏感性，不是主口径：日历时间检验加大滞后、缺失记 0 的宽松口径（`complete=False`）。

- 样本 2010-01-04 至 2026-11-12；窗口 [−20, 60]；检验区间 [−20,−1]、[0,0]、[1,5]、[1,20]、[1,60]、[0,20]；市值分 5 组；自助法 1000 次。
- 回测：可成交日开盘买入（`entry_lag=0`），持有 20 个交易日，重叠延长，买不进放弃（`defer=0`），当日持仓等权，最多 50 只、单只不超过 5%（不到 20 只时有现金）；名额不够时例一按预告同比下限、例二按快报同比从大到小，再相同按 `tie_key`；名额在实际卖出日释放。佣金万 2.5 最低 5 元、滑点 5 个基点；印花税、过户费用 `panelbt` 的 A 股历史费率档案（`docs/ASHARE_FEES.md`）；初始 1000 万；完整 A 股规则（开盘可买可卖掩码、按板块的整手、公司行为、退市）。比较基准是中证全指（价格指数），另报相对等权全 A（逐日等权平均收益，不含成本，是偏高的基准）。

下面的表里，「CAR 均值」按事件平均；后三列来自日历时间组合检验：「按日等权」是默认口径，每个交易日权重相同；「按事件加权」按当天事件数加权，检验的量就是左边的 CAR 均值（第 5 节）。**显著性以按日等权的 t 为主**，两种 t 方向不一致或一个显著一个不显著时，说明结论取决于事件稀少的日子还是事件密集的日子，下面逐条写明。

2. **能买到的那部分几乎没有漂移**：第 0 天开盘可买的 10,190 个事件 [1,20] +0.32%（日历时间 t 0.47）；买不进的 580 个有 +2.06%（t 3.66）。全样本的漂移里相当一部分来自买不到的股票，这正是 A 股事件策略最常见的虚高。
3. 信息大多在可成交日之前已经进了价格：事件前 20 天累计 +3.4%，其中公告日当天 +1.47%。按「收盘后可知」的默认口径吃不到公告日当天的反应；改成开盘前可知能多吃多少，需要每条公告的披露时刻，本地数据没有（没有用这个口径重跑，以免变成按结果挑口径）。
4. 回测相对中证全指的 +12.2% 年化超额**主要是等权与市值加权的风格差和价格指数不含分红**，不是事件本身：相对等权全 A 只有 +2.3%、信息比率 0.05，统计上和 0 分不开；收益又集中在 2015 年。结论：在默认口径和这组参数下，这个事件**不构成一个可交易的超额来源**。

### 6.3 检验口径对结论的影响（两个例子共同）

- **朴素 t 全面高估**：按月聚类的标准误是朴素的 1.3–3.2 倍；减市场时差距更大，因为市场调整去不掉行业和风格的共同冲击。
- **按月聚类仍然偏乐观**：例一减行业市值 [1,20]，按日聚类 t 2.98、按月 1.76、日历时间 1.41；例二减行业市值 [1,20]，按日 −2.84、按月 −2.53、日历时间 −1.38。两个例子里，按事件的检验显著而日历时间检验不显著的区间都出在公告后的漂移上——事件按季报期集中在几个月里，窗口互相重叠，事件之间远不独立（第 5.1 节的场景 c、d）。
- **按事件平均与按日等权会分开**：例二减市场 [1,5] 按事件 +0.17%，按日等权 −0.31%。`weight="events"` 的日历时间检验与按事件的 CAR 是同一个量（例子表里最后一列），差别只在标准误；两种权重的 t 不一致时，说明结论靠事件密集或事件稀少的日子撑着。
- 所以本笔记的结论以日历时间 t 为准，并看两种权重和两种剔除口径是否一致：例一只有 [1,60] 的同行业同市值漂移（+1.2% 到 +1.6%）在所有组合下都显著，[1,20] 取决于剔除规则；例二只有公告后 5 天的小幅负漂移（−0.46%），而且只在完整窗口口径或按事件加权时显著，20 天、60 天都不显著。

需要决定或安排的事（每条附我的建议）：

1. **数据层公开列**：第 3 节表里列出的预告、利润表、指数权重列还没有公开，`extract.py` 经 `Data._store.scan` 读。**建议**：数据层把这些列加进公共表，之后 `extract.py` 全部改用 `Data.table`（快报、分红已经改了）。

3. **风险模型特质收益**：`ashare.risk` 没有逐日残差的公开接口。**建议**：风险模型接真实行情时顺便公开「第 t 天模型对第 t+1 天收益的残差」，事件研究直接当第三种口径（`event_study` 已经接受 T×N 基准）。
4. **以后的事件研究默认以日历时间 t 下结论**，按事件的检验只作参考；用名额上限的研究在预注册里写明 `priority` 和 `seed`，并报告换几个 `seed` 后结论是否不变。

我发现但没有解决的问题：

- 例一的结论对「收盘后可知」很敏感（公告日当天 +1.5%）。没有逐条披露时刻，无法确认多少公告其实盘前可交易。
- 分红预案日是代理，未实施的预案缺失造成的选择偏差无法用本地数据量化。
- 完整窗口规则下，同行业同市值口径仍会剔除行业缺失或所在行业市值组不足 5 只的事件（例一 288 条），`complete=False` 可以对照。
- 回测的比较基准：中证全指是价格指数；等权全 A 是逐日再平衡、不含成本的理论组合，两者都不是可投资基准。
- 事件研究的同行业同市值基准用的行业含 2014 年以前的回填分类（`industry_source = 3`），作为基准影响不大，但不是严格当时口径。
- 日历时间检验在「行业因子自相关 + 每天事件很少」的场景里略偏宽松（第 5.1 节场景 c 约 8%）。
