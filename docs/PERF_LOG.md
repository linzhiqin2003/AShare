# 性能优化记录

每一项优化一条：改了什么、手段、改动前后的配对计时、一致性结论、对应提交。试过放弃的也记。发现不合理时按提交回滚。计时条件写在每条里；忙机上的数字只看相对关系，正式数字等空闲机器上重测。

## 正式一轮开始之前已经合入的

### P-001 输入检查从 Python 挪进 Rust 内核，并行扫描

- 提交：`e6703b7`（合并步骤 1c）。
- 手段：硬件。逐格内容检查改在内核里按 16384 个元素一块多线程扫描；批量接口里多组目标并行检查；退市行和公司行为索引一并挪进内核。
- 计时（4000 × 5500）：

| 场景 | 之前 | 之后 | 条件 |
|---|---:|---:|---|
| 行情构建，9 个面板字段 | 110.5 ms | 21.3 ms | 实现者配对交替，负载约 7.5；复核人复现 |
| 行情构建，4 个面板字段 | 约 15 ms | 约 6 ms | 复核人，负载约 11 |
| 单次回测含行情和目标检查，4 个字段 | 19.7 ms | 8.0 ms | 我的脚本，前后不同时段，负载约 10 和 5 |
| 行情复用、每次检查目标再回测 | 3.6 ms | 2.0 ms | 同上 |
| 1000 组小面板：检查 | 276 ms | 14 ms | 同上 |
| 1000 组小面板：检查加多线程回测 | 347 ms | 61 ms | 同上 |

- 一致性：好输入的回测结果逐位不变（纯现货 65000 组与改动前全字段相同）；坏输入矩阵 220 组加复核人另造 590 组，旧构建拒绝而新构建放过的 0 组；新增一类拒绝（掩码字节不是 0/1）；多个错误同时存在时先报哪一个可能与以前不同。
- 易用性：接口不变，新增 `validate=False` 开关（默认检查），`Result.inputs_validated` 留痕。

### P-002 滑动算子的数据相关分支改成位选择

- 提交：`a5b2408`（合并因子算子库）。
- 手段：硬件（消除分支预测失败）。`sum/mean/count/sumif` 共用无分支的取值；`std` 的运行长度更新、`min/max/arg/idx`、`ema/ffill` 同样处理。
- 计时（4000 × 5500，窗口 20，缺失 5%，单线程；实现者同一时段新旧构建对比，负载 10–14）：`ts_sumif` 条件一半真 239.6 → 80.7 ms，`ts_sum` 80.0 → 63.8 ms，`ts_std` 105.9 → 75.3 ms，`ts_min` 167.6 → 77.2 ms。我自己的测量：`ts_sumif` 条件一半真 223 → 79 ms，`ts_sum` 79 → 62 ms。
- 一致性：2425 组快照逐位一致；精度保障一处未删，另加精确有理数参考的测试。
- 放弃的一步：`std` 的「样本不足」判断也改成位选择后，正态输入反而慢 30%，已撤回。

### P-003 回测内核：公司行为按日稀疏索引

- 提交：`e6703b7`。
- 手段：算法。公司行为从逐日扫整行改为按日的稀疏索引。
- 计时（完整现货规则 4000 × 5500，与上一步两个构建配对）：最小值比 0.64–0.76，中位约 2.6 → 1.7 ms。
- 一致性：与上一步在 40000 组以上逐位相同，例外是被过滤的零头成交（4e-13 股以下），逐组归因过。
