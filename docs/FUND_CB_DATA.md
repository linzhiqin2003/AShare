# 场内基金与可转债数据

股票数据层的一个独立分组：数据集登记在 `catalog.FUND_DATASETS`，不进股票的 `DATASETS`；版本号另算
（`Store.fund_version`，股票的 `Store._version` 不含这些数据集）；面板写在 `<root>/cn/fund_panel/{fund,cb}/`。
股票、期货的同步、面板、校验与有没有基金分区无关，逐位不变（`test/data/test_fund_isolation.py`）。

```
python -m ashare.data sync-funds  --root <root> [--start 20150105]   # 下载 / 增量更新
python -m ashare.data build-funds --root <root> --stock-root <股票数据 root>
python -m ashare.data verify-funds --root <root>                      # 报告写到 <root>/cn/reports/funds_verify.md
```

```python
import ashare.data as ad
f = ad.open(root).funds()
p = f.panel("cb", ["close", "conversion_premium", "call_announced"], start="2023-01-03")
f.field("cb", "remaining_size")        # 单位、时点
```

## 1. 接口权限探查

2026-11-12 用本机账号对 13 个接口各发一次小请求，全部返回 `code 0`、有数据：

| 接口 | 用途 | 结论与限制 |
|---|---|---|
| `fund_basic` | 基金表 | 可用；`market=E` 取场内。按状态 L/D/I 分区会漏约 51 只，改为一次取全部 |
| `fund_daily` | 场内日线 | 可用；每页上限 5000；`vol` 单位手（100 份），`amount` 千元 |
| `fund_adj` | 复权因子 | 可用；每页上限 2000 |
| `fund_nav` | 净值 | 可用；本轮没有用到（场内价格已够回测），留作以后算折溢价 |
| `fund_div` | 分红 | 可用；必须给 `ts_code`、`ex_date` 或 `ann_date` 之一，多代码请求返回 0 行，所以按除息日逐日取 |
| `fund_share` | 场内份额 | 可用；`fd_share` 单位万份；服务器每页约 3000；季末日会同时返回场外基金（行数暴涨，正常） |
| `cb_basic` | 可转债表 | 可用 |
| `cb_daily` | 可转债日线 | 可用；可选字段 `bond_value`、`bond_over_rate`、`cb_value`、`cb_over_rate` 要显式要；`vol` 单位手（10 张），`amount` 万元 |
| `cb_issue` | 发行 | 可用 |
| `cb_call` | 赎回 / 强赎公告 | 可用 |
| `cb_rate` | 票面利率 | 可用；默认字段只返回 `ts_code`，必须显式给 `fields` |
| `cb_share` | 转股结果 / 剩余规模 | 可用；不带代码时会超过 offset 100000 上限，改为逐只取 |
| `cb_price_chg` | 转股价调整 | 可用；必须给 `ts_code`，逗号分隔多只可以，按代码前缀分批 |

## 2. 数据集与下载

| 数据集 | 分区 | 说明 |
|---|---|---|
| `fund_calendar` | 上交所 | 交易日历，单独存一份，不碰股票的日历 |
| `fund_basic` | `all` | 场内基金表 |
| `fund_daily`、`fund_adj`、`fund_share`、`fund_div` | 交易日 | `fund_div` 按除息日；前三个空分区会被拒（`fund_share` 例外：最新一天常为空，季末前后行数跳动） |
| `cb_basic`、`cb_issue`、`cb_call`、`cb_rate` | 整表 | 静态表，每次同步刷新 |
| `cb_price_chg` | 代码前缀 + 交易所 | 每批一个请求 |
| `cb_share` | 单只 | 只刷新未摘牌或摘牌不满 60 天的 |
| `cb_daily` | 交易日 | 带上源的转股价值、纯债价值字段 |

下载区间 2015-01-05 至 2026-11-12：约 1.58 万次请求，每接口约 240 次/分钟、8 个并发，墙钟约 14 分钟；
原始库 268 MB，两个面板（各保留 2 个版本）约 2.2 GB。

2015 年以前没有下载。按各接口最早有数据的日期估算：`cb_daily` 从 1993-02 约 5300 个交易日、`fund_daily`
从 1998 年约 4100、`fund_adj` 从 2005 年约 2400、`fund_share` 从 2004 年约 2450、`fund_div` 从 1999 年约 3900，
合计约 1.8 万次请求、约 22 分钟（命令 `sync-funds --start 19930101` 即可补齐，已有分区跳过）。
2015 年前场内基金不到 300 只、可转债常年只有二三十只，对配置类研究意义有限，是否补齐留给负责人决定。

## 3. 字段

字段表见 `ashare/data/fund_schema.py`（`describe("fund")`、`describe("cb")` 打印）。同名字段与 A 股面板含义、
单位相同：价格元、成交量按最小计量单位（基金「份」、可转债「张」）、成交额元、`is_listed` 上市日含退市日不含、
`delist` 退市日或其后首个交易日为真、`split` 无事件为 1、`cash_dividend` 无事件为 0。

### 单位换算的实测依据

- 基金：`amount × 1000 / (vol × 100)` 落在当天 [最低, 最高] 里，283 万行中只有 22 行不在（已登记，见第 6 节）。
- 可转债：`amount × 10000 / (vol × 10)` 落在 [最低, 最高] 里（77 万行中 1 行例外）；`amount / (vol × close)`
  的中位数为 0.001（万元 / 手 / 元 → 1e4 / 10）；按此换算的全市场日成交额约 500 亿元量级，与公开报道一致。
  源文档写 `amount` 单位为「万元」，实测相符；`vol` 单位为「手」，1 手 = 10 张。

### 时点规则

| 字段 | 何时可知 |
|---|---|
| 基金 `split` | 前收盘缺口反推：G = 上一有效收盘 / 交易所前收盘，D = 上一有效收盘 /（上一有效收盘 − 当日分红），split = G / D；只在 \|复权因子变化 − 1\| 与 \|G − 1\| 都超过 0.5% 时认作拆分或折算 |
| 基金 `cash_dividend` | 除息日（分红表「实施」记录） |
| 基金上市日 | min(基金表上市日, 第一根行情)：分级基金转换后的 LOF 有早于表里上市日的行情（71 只，见诊断） |
| `conversion_price` | 上市时取初始转股价；每次调整自 max(生效日, 公告日的下一交易日) 起用新值 |
| `call_announced` | 「公告实施强赎」的公告日的下一交易日起为真，直到摘牌 |
| `remaining_size` | 转股结果公告日的下一交易日起；首次公告前取发行规模 |
| `conversion_value`、`conversion_premium`、`double_low` | 当日收盘后；`100 / conversion_price × stock_close`，正股收盘取自股票面板（不复权） |
| `days_to_maturity` | 盘前；到期日减当天（自然日） |
| `total_shares`（基金） | 交易所公布的份额，通常收盘后或次日公布；最后一天常为 NaN；严格回测请滞后一天用 |

源的 `cb_value` 按生效日换转股价（不管公告是否已发出），所以面板的 `conversion_value` 与源在 215 格不同，
全是「生效在前、公告在后」造成的；按同样口径重算时与源相差 1% 以上的为 0 格（中位相对差 2.6e-5）。

### 可转债的占位行

`cb_daily` 里有成交量为 0、开盘价为 0、收盘价为 0 或沿用旧价的行（上市前、停牌、摘牌后），共 9591 行。
面板里这些行的开、高、低置为 NaN，收盘价为 0 时置 NaN，`has_quote = 成交量 > 0 且收盘价有效`。
最后成交日之后仍有占位行的可转债 490 只、3674 行；它们不算行情，不影响 `is_listed`（按摘牌日）。

## 4. 回测规则（`fund_rules.py`、`cb_rules.py`）

费用表写在 `ashare` 一侧（`MarketProfile`），没有改动 `panelbt`。

| 规则 | 场内基金 | 可转债 | 依据 / 是否核实 |
|---|---|---|---|
| 印花税 | 无 | 无 | 基金、债券交易不征印花税。已核实 |
| 过户费 | 0 | 0 | 中国结算对 ETF、LOF、债券不按股票收过户费。LOF 历史收费未逐条核实 |
| 佣金 | 调用方给（默认万分之一、无最低） | 调用方给（默认万分之一、无最低） | 券商协议差别很大，请按实际 |
| 交易单位 | 100 份 | 10 张（1 手） | 交易所交易规则。已核实 |
| 最小价位 | 0.001 元 | 0.001 元 | 已核实 |
| 涨跌停 | ±10%；创业板、科创板类 ETF ±20%（深市 2020-08-24 起、沪市 2019-07-22 起）；REITs 首日 ±30% | 2022-08-01 起 ±20%，上市首日 +57.3% / −43.3%（按 100 元）；之前无涨跌停（只有临停） | 创业板 / 科创板按名称关键词认定，未逐只核实；实测见第 6 节 |
| 交收 | 股票类 T+1；跨境、债券、黄金、商品、货币 T+0 | T+0 | 日频回测每天只成交一次，只作元数据；分类按名称关键词，未逐只核实 |
| 卖出锁定 | 1 天 | 0 天 | 同上 |

`fund_market(funds, symbols, start, end, exec="open")`、`cb_market(...)` 返回 `market`（`panelbt.Market`）以及
`config()`、`costs()`。可买可卖按成交价是否在涨跌停价上判断；拆分、分红、退市直接用面板字段。

**强赎要提前卖出。** `panelbt` 对退市按「前收盘 × 回收率」处理，而可转债强赎价（面值加当期利息，约 100–101 元）
通常远低于最后市价（最后收盘 / 强赎价的中位数 1.42 倍）。在 `call_announced` 为真后卖出，或在摘牌前一交易日清仓。
可转债票息没有作为现金入账：可转债按全价交易，利息已含在价格里，付息日的价格下跳会让收益略为低估（年约 0.5%–2% 的票息量级）。

## 5. 校验（`verify-funds`）

独立实现，不调用面板构建代码：拆分、转股价都从原始表另写一遍再与面板逐格比；能失败（测试里改坏复权因子、
改坏判定都会失败）；已知例外逐条登记在 `fund_known_exceptions.json`，只含代码、日期、检查名和原因，不含任何
从行情算出的数值（测试守住）。

2026-11-12 的结论为 **pass**，121 条例外全部用到。各项见报告，要点：

| 问题 | 结论 |
|---|---|
| 基金拆分、折算是否进了复权因子 | 是。连续两日都有行情的除权事件中，155 次拆分或折算（154 次为非分级 ETF 拆分，多在 2025–26 年）复权因子变化与前收盘缺口一致；96 次不一致均已登记（见下） |
| 可转债最后几天价格与强赎价的关系 | 强赎的 537 只中，189 只最后交易日就是赎回登记日，348 只在登记日前 3 个交易日（2022 年新规后）；最后收盘 / 强赎价分位数：5% 1.07、中位 1.42、95% 2.58；11 只收在强赎价以下。到期赎回的最后收盘约为到期赎回价的 1.0 倍 |
| 到期、强赎后面板还有没有行 | 源在最后成交日后仍有占位行（490 只、3674 行），面板不当行情；摘牌日起 `is_listed` 为假、`delist` 为真 |
| 可转债成交额单位 | 万元（见第 3 节） |
| 代码复用 | 有：带 `!1` 的旧代码、七位代码、`161022A.SZ`、`158008.OF` 一类；日线里不在基金表的 2 个代码已登记 |

例外的原因分布：一字价（开高低收相同）造成的均价越界 21 条及其次日 17 条、2020-02-26 前后的集中缺口 63 条、
七位代码 11 条、其他缺口 4 条、REITs 分配 1 条、基金成交额差 10 倍 1 条、可转债成交额偏低 1 条、不在基金表的代码 2 条。
其中 100 条原因没有查明（`cause_unknown`），只是按现象登记。

涨跌停实测：有行情的基金格子里涨跌幅都不超过所在档位（上市首日除外）；涨跌超过 10.5% 的基金全部被分在 20% 档。
可转债新规后有 10 格越过规则价，作为提示列出（面板起点在区间首行时首日按前收盘计）。
