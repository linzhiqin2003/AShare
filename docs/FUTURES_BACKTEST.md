# 期货回测

把期货当独立的资产回测：纯期货组合（趋势、套利、展期收益），也可以和现货混在一个面板里。设计见 `docs/DESIGN.md` 4.14（纯期货）和 4.15（混合面板的退出规则），引擎的精确口径见 `packages/panelbt/SPEC.md` 的「Stand-alone futures portfolios」和「Exit rules in mixed panels」。

三层入口，按需要选：

| 入口 | 给什么 | 适合 |
|---|---|---|
| `ashare.backtest.futures.futures_portfolio` | 数据层 + 品种列表 + 品种层面的目标 | 境内期货：换月、个人持仓期限、交易单位分界都替你处理 |
| `ashare.backtest.futures.book_from_table` | 长表（字段名同 `ashare.data.futures_schema`） | 外部来源的行情（如石油研究项目的境外合约） |
| `panelbt.FuturesBook` | 逐合约、逐行的数组 | 不依赖本仓库的任何东西 |

## 最短例子

```python
import numpy as np
import ashare.data as ad
from ashare.backtest import execution_targets
from ashare.backtest.futures import futures_portfolio

fut = ad.open("/path/to/data").futures()
pf = futures_portfolio(fut, ["RB", "CU"], start="2021-01-04", end="2024-12-31")
p = pf.signal_prices                                   # 比例后复权连续价格，只算信号
sig = np.sign(np.log(p) - np.log(np.roll(p, 60, axis=0)))
sig[:60] = np.nan
w = np.full(sig.shape, np.nan)
w[60::21] = 0.5 * sig[60::21]                          # 每 21 行调仓，名义各占权益一半
result = pf.run(execution_targets(w), kind="notional")  # 收盘出信号，下一行开盘成交
result.equity, result.futures_margin, pf.rolls
```

2021 年以前上期所、能源中心的保证金和手续费源里没有，区间早于此要显式给 `missing=dict(margin_rate=..., fee_rate=..., fee_per_contract=...)`，否则报错（不会用以后的值回填）。

## 十条语义

原则同引擎的其他部分：宁可悲观。

1. **目标写法**：三种都支持，空头为负。`"lots"` 是整手数（复盘真实持仓、对账）；`"notional"` 是名义市值占交易前权益的比例（按波动率定仓位最自然）；`"margin"` 是保证金占用占权益的比例，按当行的实际保证金率（交易所 × 账户条款）折成名义。当行的保证金率在前一交易日结算时就已公布（交易所规则：新标准在执行前一日结算时生效），不算前视。手数一律向零取整。
2. **盯市与现金**：按当日结算价逐日结转盈亏；保证金 = 当日结算价 × 乘数 × 当日保证金率；可用资金 = 权益 − 占用保证金（纯期货账户的权益就是现金）。期货公司条款是账户参数 `panelbt.FuturesAccount(margin_add, margin_scale, fee_scale)`，引擎本身默认中性（交易所标准）；境内的预设 `CN_RETAIL` 是**估计**，不是实际条款：保证金加 5 个百分点、手续费 × 3。依据是规则调研里的期货公司公示标准（保证金加 4–7 个百分点、手续费约为交易所 3 倍），取悲观的一端；可覆盖，能谈到更低费率的账户传自己的 `FuturesAccount`（`futures_portfolio(account=...)`）。这组默认值待用户确认（见文末「待用户确认」）。
3. **手续费**：按金额和按手两部分逐合约逐日取（`fee_rate`、`fee_per_contract`，可同时非零），每笔成交都收。日频目标不会在同一天把同一个合约开了又平（反手是先平昨仓再开新仓），所以平今费不会出现，不建模；步进接口每天每列也只成交一次，同理。唯一例外：在个人持仓期限或到期的那一行新开的仓，收盘被强平时按普通费率收，平今费更高的交易所（中金所股指 10 倍）会被低估——这样做的策略本身就不合理。
4. **追保与强平**：沿用引擎现金账户的期货规则：收盘时占用保证金大于权益（可用资金为负）记追保，下一行按执行价（含滑点）同比例减仓到满足开仓保证金；权益 ≤ 0 记爆仓，平掉全部且不再开仓。诊断里有 `margin_call`（逐日）、`coverage["futures_margin_call"]`、`coverage["futures_liquidation"]`、`liquidation_events`、`bankruptcy_events`。
5. **涨跌停**：数据层没有涨跌停幅度。接口接受「不可买 / 不可卖」掩码或涨跌停价（成交价达到涨停价不能买、达到跌停价不能卖）。推断规则（`infer_locked`，境内默认开）：开盘 = 最高 = 最低且有成交的行，开盘价高于前一行结算价时禁止买入、低于时禁止卖出。全库实测（1995–2026，成交量 > 0 的 1,793,242 行）：这种「一字」行有 101,883 行，绝大多数是只成交一两手的冷门合约，对能交易的策略没有影响；成交量 ≥ 100 手的 2,454 行（其中相对前结算涨跌 ≥ 3% 的 669 行），2012 年以后成交量 ≥ 1000 手的 284 行（105 行涨跌 ≥ 3%，例如 2020-02-03 春节后开盘 P2005、TA2005、I2005 全天封在跌停）。数量少、真封板时影响大，所以默认开；它看不出「开在停板、盘中打开」的日子；反过来，它把「全天一字但其实可以成交」（封板不牢、排队成交）的日子也当成停板拒绝，偏保守。
6. **换月**：持有的是具体合约。`futures_portfolio` 按数据层的换月规则（默认 `open_interest`：第 t 行只用第 t−1 行的持仓量，即 T 日收盘判定、T+1 执行）决定每个品种每行持有哪个合约；`targets()` 把品种层面的目标展开成合约层面：换月当行即使没有新目标也写一行，旧合约降为 0、新合约沿用当前目标，平旧开新各付一次手续费和滑点。只向后换。调用方也可以直接给合约层面的目标（`pf.book.run(plan, kind)`）。连续价格只算信号，例：2024-04-01 螺纹钢主力从 RB2405 换到 RB2410，当天两者结算价 3405 和 3445；不复权的主力连续在这天涨 40 元/吨，每手 10 吨就是 +400 元，可持有者并没有赚到这笔钱（换月时卖出 3405 的旧合约、买入 3445 的新合约，持仓价值不变）。比例后复权消除了这个跳空，所以 `signal_prices` 用它算信号；盈亏只按具体合约的结算价算。
7. **到期与个人客户限制**：合约的结束行 = min(最后交易行, 最后持仓行 + 1)。结束行照常可以成交（策略可以在开盘先平掉），收盘仍持有的按当行结算价了结：中金所现金交割合约在自己的最后交易日按交割结算价了结、收交割费；其余（实物交割品种的最后交易日、个人持仓期限）按强平处理，收手续费并计一次滑点。之后的目标计入 `n_expired_target`。个人客户最后持仓日默认开启（`personal=True`），规则见下表；`futures_portfolio` 会在期限前把持仓换到下一个合约。

   | 交易所 / 品种 | 规则 | 依据 |
   |---|---|---|
   | INE SC | 最后交易日前第 8 个交易日收市后须为 0 | 官方（INE 风险控制管理细则第六十六条） |
   | INE LU、NR | 前第 5 个交易日收市后须为 0 | 官方（同上） |
   | 大商所、郑商所、广期所 | 不得持仓进入交割月 | **未核实**（旁证，未读到官方原文） |
   | 上期所 | 按「不得进入交割月」处理 | **未核实**（推断，品种细则未读到），偏保守 |
   | INE BC 等其他品种 | 按「不得进入交割月」处理 | 推断 |
   | INE EC、中金所 | 不限制 | EC 为现金交割指数（推断）；中金所没有这条 |

   数据层给不出个人客户最后持仓日（合约表没有这个字段），由上表按最后交易日和交割月推算；`delivery_month` 为空时用最后交易日所在月份。

8. **乘数中途变化的合约**：`panelbt_inputs(multiplier_change="split")` 拆成两列，前一列在分界日前一行按结算价强平（手续费 + 滑点），后一列从分界日起开仓（手续费 + 滑点）。`targets()` 在分界日把持仓从前一列搬到后一列：名义和保证金目标自然按新乘数换算；手数目标按「设目标时的乘数 / 新乘数」折算后向零取整（PB 25 吨 → 5 吨：2 手变 10 手）。交易所实际是按比例折算持仓、不收费，这里多付了一次往返成本，偏悲观。
9. **缺失的保证金或手续费**：默认报错。数据层用 `panelbt_inputs(missing=..., param_fill=...)`（`futures_portfolio` 原样转交）；引擎层 `FuturesBook(missing=...)` 可选 `"previous"`（合约内只用此前的值向前填）或一个数。
10. **夜盘**：有夜盘的品种，日线开盘价是前一晚夜盘的集合竞价价，最高最低价含夜盘。用 `exec_price = 开盘价` 时，第 t 行的成交时点是 t−1 日晚上 21:00。防前视的用法：信号只用到第 t−1 行收盘（结算价、收盘价、持仓量），经 `execution_targets`（错一行）在第 t 行开盘成交；第 t 行的开高低、成交量不能进信号。两者之间隔着 15:00 到 21:00，实盘来得及。没有夜盘的品种（中金所、EC）开盘就是当天日盘开盘。

## 常见的坑（对照规则调研的清单）

| 坑 | 这里怎么防 |
|---|---|
| 用主力连续价直接算收益 | 只按具体合约结算价算盈亏；下面的例子量化了差距 |
| 用收盘价代替结算价盯市 | 盯市、保证金只用 `settlement`；`close` 只是报表 |
| 忽略平今费 | 日频不会出现平今，见第 3 条的唯一例外 |
| 夜盘归属错日 | 第 10 条：信号到 t−1 收盘，t 行开盘成交 |
| 忽略涨跌停无法成交 | 第 5 条：掩码、涨跌停价或一字板推断 |
| 用今天的保证金和费率回测历史 | 逐合约逐日取数据层参数；缺值报错而不是回填 |
| 持仓进入个人不能持有的期间 | 第 7 条：默认在期限前换月，仍持有就强平 |
| 主力切换用了未来信息 | 换月只用前一行的持仓量 |
| 合约乘数用错 | 乘数取数据层逐日的 `multiplier`，中途改单位的合约拆列 |
| 忽略分阶段保证金提高 | 保证金率逐日取，提高后可开数量变少（有性质测试） |

## 手工核对（真实数据）

`bench/futures_hand_check.py`：RB2310（螺纹钢，每手 10 吨），2023-06-01 开盘买 10 手、06-05 开盘加 5 手、06-08 开盘全平；交易所当日的手续费率（万分之一）和投机保证金率（13%），不加期货公司条款、不计滑点，按上期所结算规则手算：

- 开仓、加仓：手续费 = 手数 × 10 × 开盘价 × 1e-4；持仓基准 = 数量加权的成交价；

|---|---:|---:|---:|---|---|---|
| 2023-06-01 | 3455 | 3507 | 10 | 34.55 / 34.55 | 1,005,165.45 / 同 | 45,591 / 同 |
| 2023-06-02 | 3539 | 3563 | 10 | 0 / 0 | 1,010,765.45 / 同 | 46,319 / 同 |
| 2023-06-05 | 3602 | 3638 | 15 | 18.01 / 18.01 | 1,020,047.44 / 同 | 70,941 / 同 |
| 2023-06-06 | 3638 | 3655 | 15 | 0 / 0 | 1,022,597.44 / 同 | 71,272.5 / 同 |

逐项完全相同（最大差 0）。合计也可以直接验：10 × 10 × (3630 − 3455) + 5 × 10 × (3630 − 3602) − 107.01 = 18,792.99。

## 例子：多品种时间序列动量

`bench/futures_momentum.py --root <data>`：2012-01-04 至 2026-11-12（3607 行）。品种池是全部商品品种（不含中金所），**按当时取**：每个调仓行只在当时有主力合约、且过去 60 行成交额（主力合约的成交量 × 结算价 × 乘数，当天收盘已知）最大的 20 个品种里建仓，其余品种目标为 0，不用全样本挑的固定名单。全期共有 57 个品种进过这个名单。60 行动量的符号 × 10% / (60 行年化波动率 × √20) 作名义权重（单品种上限 1），每 21 行调仓，持仓量主力合约、真实换月，收盘出信号、下一行开盘成交。账户 `CN_RETAIL`（保证金 +5 个百分点、手续费 × 3），滑点万分之二，打开一字板推断和个人持仓期限。2021 年以前缺的参数用假设值：保证金 15%、手续费万分之一。

| 做法 | 年化 | 最大回撤 | 夏普 |
|---|---:|---:|---:|
| 引擎：具体合约、真实换月、费用 | 4.81% | 49.2% | 0.35 |
| 错误：不复权主力连续价 × 同样的权重（不计费用） | 1.02% | 57.3% | 0.15 |
| 参照：比例后复权连续价 × 同样的权重（不计费用） | 6.75% | 48.5% | 0.45 |

- 用了 4188 个合约、4190 次换月，15,710 笔成交，没有追保和强平，平均保证金占用 40%。
- 费用（手续费 + 滑点）每年约占权益 3.3%，其中 48% 是换月产生的（换月当行旧合约和新合约的成交）。
- 不复权连续价把每次换月的价差（新合约 − 旧合约）当成了持仓的盈亏：在这个样本上年化少算约 3.8 个百分点、最大回撤多算 8 个百分点。方向和大小取决于策略的多空和当时的期限结构，没有一般规律，这正是它危险的地方。
- 比例后复权价不计费用时比引擎高约 1.9 个百分点；引擎每年多扣约 3.3% 的费用，其余差异来自整手取整和按具体合约价格换算名义，没有逐项拆分。结论：后复权价可以当信号，不能当净值。
- 早先用全样本成交额挑定 20 个品种的版本（有前视）是年化 8.21%、最大回撤 33.4%；按当时取品种后明显变差，说明那份名单本身带了不少事后信息。

## 外部行情的入口

`book_from_table(daily, contracts, params=None, ...)`，字段名与 `ashare.data.futures_schema` 一致，以后境外数据适配器的输出可以直接喂进来。

| 表 | 必填列 | 可选列 | 单位与时点 |
|---|---|---|---|
| `daily` | `date`、`symbol`、`settlement`、`close` | `open`、`high`、`low`、`volume` | 日期 `YYYYMMDD`，交易所交易日（CME 周日晚开盘归周一）；价格是报价单位（美元/桶）；`settlement` 是交易所公布的结算价（ICE Brent 伦敦 19:28–19:30 加权，CME 纽约 14:28–14:30），不要用收盘价；`volume` 手、单边。执行价默认取 `open`（`exec_field` 可改） |
| `contracts` | `symbol`、`multiplier`、`last_trade_date` | `settlement_type`（`"cash"` 为现金交割）、`last_hold_date` | 乘数是每手的报价单位数量（WTI 1000 桶）；最后交易日那行的结算价对现金交割合约应是交割结算价 |
| `params` | `date`、`symbol`、`margin_long`、`margin_short` | `fee_open_rate`、`fee_open_per_contract` | 比例；元（报价货币）/手。没有逐日参数时直接传标量 `margin_rate`、`fee_rate`、`fee_per_contract` |

行是 `daily` 里出现过的全部日期，列是 `contracts` 的顺序；某合约某天没有行就是没有行情、不成交，结算价在合约内向前填。合成的 WTI 式月度合约链（含换月）见 `bench/futures_wti_example.py`：

```python
import numpy as np
from bench.futures_wti_example import chain
from panelbt.futures import roll_targets
from ashare.backtest.futures import book_from_table

daily, contracts = chain()                       # 两个长表，字段名同统一字段
ext = book_from_table(daily, contracts, margin_rate=0.10, fee_per_contract=1.5,
                      slippage=1e-4, initial_cash=1e6)
keep = int(np.searchsorted(ext.expiry, len(ext.dates))) + 1
plan = roll_targets(ext.expiry[:keep], len(ext.dates), 5, 5.0)   # 到期前 5 行换月
result = ext.book.run(plan, kind="lots")         # 一直持有 5 手近月
```

数组层面直接用 `panelbt.FuturesBook`（见包内 README），不需要本仓库的任何东西。

## 混合面板里的退出规则

市场里有期货列时，`bt.Rules` 只作用于现货列：标量百分比和 `max_hold` 只施加给现货列；每只证券或 T×N 的百分比在期货列上必须是 NaN，否则报错。期货列不判断、不记成本和建仓日，期货的普通目标不受规则状态（冷却、待平）影响。保证金账户里规则平仓的「自有现金不得为负」削减扣掉了当时占用的期货保证金（`close`/`average` 时点用前一结算价和当日保证金率，`open` 时点用调仓之后的占用）。限价目标在有期货列的市场里继续拒绝：限价开仓的资金判断只算现货的现金和保证金，没有算期货保证金，会超买。

## 性能

本机 M5 Pro，负载 7–12（同时有十来个代理在编译和跑测试），各 5 次取中位数：

| 项目 | 耗时 |
|---|---:|
| 建期货组合（90 个商品品种，3607 行 × 4188 个合约，读数据 + 换月 + 建 `Market`） | 7.06 s |
| 品种目标展开成合约目标（一组） | 87 ms |
| 单次回测 `bt.run` | 4.7 ms |
| `run_batch` 100 组参数（10 个回看期 × 10 个风险水平，目标已展开） | 123 ms |
| 100 组参数的信号计算和展开（Python） | 22.5 s |

## 不模拟的规则

平今费；交易所跨期、跨品种保证金优惠和双向持仓按大边收保证金；单边市后的扩板和随之自动提高的保证金；停板时的排队成交和强制减仓；临时日内开仓上限、程序化交易申报费；实物交割过程（仓单、升贴水、交割库容）；交易所按比例折算交易单位（这里按平旧开新）；夜盘与日盘之间、日内的价格路径；汇率；持仓限额（个人和小资金一般碰不到，大资金要自己约束目标）。
