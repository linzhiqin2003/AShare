# 期货回测

把期货当独立的资产回测：纯期货组合（趋势、套利、展期收益），也可以和现货混在一个面板里。设计见 `docs/DESIGN.md` 4.14（纯期货）和 4.15（混合面板的退出规则），引擎的精确口径见 `packages/panelbt/SPEC.md` 的「Stand-alone futures portfolios」和「Exit rules in mixed panels」。

三层入口，按需要选：

| 入口 | 给什么 | 适合 |
|---|---|---|
| `ashare.backtest.futures.futures_portfolio` | 数据层 + 品种列表 + 品种层面的目标 | 境内期货：换月、个人持仓期限、交易单位分界都替你处理 |
| `ashare.backtest.futures.book_from_table` | 长表（字段名同 `ashare.data.futures_schema`） | 外部来源的行情（如石油研究项目的境外合约） |
| `panelbt.FuturesBook` | 逐合约、逐行的数组 | 不依赖本仓库的任何东西 |

## 最短例子

```python
import numpy as np
import ashare.data as ad
from ashare.backtest import execution_targets
from ashare.backtest.futures import futures_portfolio

fut = ad.open("/path/to/data").futures()
pf = futures_portfolio(fut, ["RB", "CU"], start="2021-01-04", end="2024-12-31")
p = pf.signal_prices                                   # 比例后复权连续价格，只算信号
sig = np.sign(np.log(p) - np.log(np.roll(p, 60, axis=0)))
sig[:60] = np.nan
w = np.full(sig.shape, np.nan)
w[60::21] = 0.5 * sig[60::21]                          # 每 21 行调仓，名义各占权益一半
result = pf.run(execution_targets(w), kind="notional")  # 收盘出信号，下一行开盘成交
result.equity, result.futures_margin, pf.rolls
```

2021 年以前上期所、能源中心的保证金和手续费源里没有，区间早于此要显式给 `missing=dict(margin_rate=..., fee_rate=..., fee_per_contract=...)`，否则报错（不会用以后的值回填）。

## 十条语义

原则同引擎的其他部分：宁可悲观。

1. **目标写法**：三种都支持，空头为负。`"lots"` 是整手数（复盘真实持仓、对账）；`"notional"` 是名义市值占交易前权益的比例（按波动率定仓位最自然）；`"margin"` 是保证金占用占权益的比例，按当行的实际保证金率（交易所 × 账户条款）折成名义。当行的保证金率在前一交易日结算时就已公布（交易所规则：新标准在执行前一日结算时生效），不算前视。手数一律向零取整。
2. **盯市与现金**：按当日结算价逐日结转盈亏；保证金 = 当日结算价 × 乘数 × 当日保证金率；可用资金 = 权益 − 占用保证金（纯期货账户的权益就是现金）。期货公司条款是账户参数 `panelbt.FuturesAccount(margin_add, margin_scale, fee_scale)`，引擎本身默认中性（交易所标准）；境内的预设 `CN_RETAIL` 是**估计**，不是实际条款：保证金加 5 个百分点、手续费 × 3。依据是规则调研里的期货公司公示标准（保证金加 4–7 个百分点、手续费约为交易所 3 倍），取悲观的一端；可覆盖，能谈到更低费率的账户传自己的 `FuturesAccount`（`futures_portfolio(account=...)`）。这组默认值待用户确认（见文末「待用户确认」）。
3. **手续费**：按金额和按手两部分逐合约逐日取（`fee_rate`、`fee_per_contract`，可同时非零），每笔成交都收。日频目标不会在同一天把同一个合约开了又平（反手是先平昨仓再开新仓），所以平今费不会出现，不建模；步进接口每天每列也只成交一次，同理。唯一例外：在个人持仓期限或到期的那一行新开的仓，收盘被强平时按普通费率收，平今费更高的交易所（中金所股指 10 倍）会被低估——这样做的策略本身就不合理。
4. **追保与强平**：沿用引擎现金账户的期货规则：收盘时占用保证金大于权益（可用资金为负）记追保，下一行按执行价（含滑点）同比例减仓到满足开仓保证金；权益 ≤ 0 记爆仓，平掉全部且不再开仓。诊断里有 `margin_call`（逐日）、`coverage["futures_margin_call"]`、`coverage["futures_liquidation"]`、`liquidation_events`、`bankruptcy_events`。
5. **涨跌停**：数据层没有涨跌停价（Tushare 没有这个字段，见文末「数据层缺的字段」）。接口接受两种显式写法，有就用它们：
   - 涨跌停价 `limit_up` / `limit_down`（T×N）：成交价达到涨停价不能买、达到跌停价不能卖。数据层补上交易所每日参数文件里的涨跌停价后，正确做法是传这两个数组，并把 `infer_locked` 关掉；
   - 掩码 `no_buy` / `no_sell`（T×N 布尔）：自己判定哪些格子不能买、不能卖。

   ```python
   up = prev_settle * (1 + limit_pct)              # 交易所公布的涨跌停幅度 × 上一结算价
   down = prev_settle * (1 - limit_pct)
   book = bt.FuturesBook(..., limit_up=up, limit_down=down, infer_locked=False)
   # 或：book = bt.FuturesBook(..., no_buy=open_at_limit_up, no_sell=open_at_limit_down)
   ```

   没有涨跌停价时的推断（`infer_locked`，`futures_portfolio` 默认开）：开盘 = 最高 = 最低且有成交的行，开盘价高于前一行结算价时禁止买入、低于时禁止卖出，等于时不禁止。它抓到的和漏掉的：
   - **抓到的**：全天一字的行。全库（1995–2026，成交量 > 0 的 1,793,242 行）有 101,883 行，但其中 89% 相对前结算的幅度不到 3%，绝大多数是冷门合约只成交一两笔的普通行情，不是停板；按「品种 × 年份 99.9% 分位的最大波幅」估计停板幅度，2012 年以后成交 ≥ 1000 手的一字行里只有 11 行真在停板上（例如 2020-02-03 春节后开盘 P2005、TA2005、I2005 封在跌停）。这些行被拒绝方向的成交，在冷门合约上**偏悲观**（其实能成交），在真封板的行上是对的；
   - **漏掉的**：开盘就在停板、盘中又打开的行。2012 年以后主力合约里约 173 行开在估计的涨停、151 行开在估计的跌停（例如 RM2505 2025-03-11 开在 +9.03%），推断全部放行。执行价是开盘价时，这些行在开盘时其实买不进（卖不出），所以在这类行上**偏乐观**——追涨杀跌的策略最容易撞上。动量例子的成交里只有 1 笔落在这类行上，对例子的数字没有影响。

   总的偏向不确定，取决于策略在哪类行上交易；需要可靠结果时给涨跌停价。
6. **换月**：持有的是具体合约。`futures_portfolio` 按数据层的换月规则（默认 `open_interest`：第 t 行只用第 t−1 行的持仓量，即 T 日收盘判定、T+1 执行）决定每个品种每行持有哪个合约；个人持仓期限前换月时，下一个合约要在前一行有行情（当行有没有行情不看，否则就是前视）。`pf.run` 逐行推进（`FuturesBook.simulator`），品种层面的目标这样落到合约上：
   - **调用方给了目标的行**整体调仓：目标落在当行持有的合约上，不在目标里的合约（含旧合约）平掉。`kind="lots"` 是当行持有合约的整手数。
   - **品种在目标行还没有可交易的合约**（样本第一行、刚上市、合约还没有第一笔成交价、换不到下一个合约）：三种写法都挂起，等它第一次落到可交易的合约上那一行开仓。手数照给的开（给 5 手就开 5 手）；名义和保证金按**落地那一行**的权益和价格定手数，这一行开盘前已知，不是前视。
   - **只有换月的行**只动正在换月的品种：平旧开新，**保持手数**（新合约乘数不同时保持「手数 × 乘数」，向零取整，丢掉的零头计入诊断），各付一次手续费和滑点；其他品种的持仓不动、不成交，引擎里还在顺延的单子原样带上。保持手数而不是保持名义，是因为真实换月就是把同样的手数移到下一个合约；名义随新旧合约的价差变化（升水时略多、贴水时略少）。
   - 换月当行**旧合约没有成交价**：新合约照开、旧合约的平仓由引擎顺延到下一个有价的行，这期间持仓加倍（通常一天），风险和保证金都多算，偏悲观，计入诊断。重叠期间保证金按新旧两份合约算，可能因此触发追保。**新合约没有成交价**：旧合约照平、新合约顺延，中间空仓，漏掉这段价格变动，偏向不确定。
   - 挂起的目标落地时，品种如果还留着上次没平掉的旧合约，按调用方的目标开新合约、同一行平掉旧合约。
   - **追保强平行**：引擎丢弃这一行的加仓、暂停原计划直到下一次调仓；逐行推进同样丢掉这一行之前就在等的开仓和接续（计入诊断），强平掉的仓位不会在之后被加回去。强平后剩下的仓位照常换月；如果这一行同时是旧合约的结束行，剩下的部分在收盘了结后照常接到下一个合约，和追保早一天发生的结果一样。
   - 品种有调用方挂起的目标时，不再按旧手数换月：等这个品种在途的单子（例如旧合约顺延中的平仓）做完再按目标落地；新合约上已有调用方顺延中的单子时，也不按旧手数换月盖掉它。
   - 逐行推进自己不记「发出过的单子」，每次都从引擎读当时还在顺延的单子（`State.pending_cols`），写目标的行把它们原样带上；所以已经成交或作废的单子不会被重发。不变量写在 `ashare/backtest/futures_step.py` 开头。
   - 诊断：`result.diagnostics["futures_portfolio"]` 有 `roll_rounding_events`（换月取整丢掉零头的次数）、`roll_rounding_notional`（零头的名义金额合计）、`roll_overlap_events`（换月当行旧合约没平掉的次数）、`landings`（挂起目标落地的次数）、`liquidation_rows`（追保强平行数）、`liquidation_dropped_waits`（强平时丢掉的等待中开仓和接续）、`liquidation_dropped_units`（其中接续部分的手数 × 乘数合计）。
   - 其余行不交易，持仓在两次调仓之间随价格漂移。

   只向后换。调用方也可以直接给合约层面的目标（`pf.book.run(plan, kind)`）。连续价格只算信号，例：2024-04-01 螺纹钢主力从 RB2405 换到 RB2410，当天两者结算价 3405 和 3445；不复权的主力连续在这天涨 40 元/吨，每手 10 吨就是 +400 元，可持有者并没有赚到这笔钱（换月时卖出 3405 的旧合约、买入 3445 的新合约，持仓价值不变）。比例后复权消除了这个跳空，所以 `signal_prices` 用它算信号；盈亏只按具体合约的结算价算。
7. **到期与个人客户限制**：合约的结束行 = min(最后交易行, 最后持仓行 + 1)。结束行照常可以成交（策略可以在开盘先平掉），收盘仍持有的按当行结算价了结：中金所现金交割合约在自己的最后交易日按交割结算价了结、收交割费；其余（实物交割品种的最后交易日、个人持仓期限）按强平处理，收手续费并计一次滑点。之后的目标计入 `n_expired_target`。个人客户最后持仓日默认开启（`personal=True`），规则见下表；`futures_portfolio` 会在期限前把持仓换到下一个合约。

   | 交易所 / 品种 | 规则 | 依据 |
   |---|---|---|
   | INE SC | 最后交易日前第 8 个交易日收市后须为 0 | 官方（INE 风险控制管理细则第六十六条） |
   | INE LU、NR | 前第 5 个交易日收市后须为 0 | 官方（同上） |
   | 大商所、郑商所、广期所 | 交割月前一个月最后一个交易日收市后须为 0（不得持仓进入交割月） | **未核实**（旁证，未读到官方原文） |
   | 上期所 | 按「不得进入交割月」处理 | **未核实**（推断，品种细则未读到），偏保守 |
   | INE BC 等其他品种 | 按「不得进入交割月」处理 | 推断 |
   | INE EC、中金所 | 不限制 | EC 为现金交割指数（推断）；中金所没有这条 |

   两类规则同一口径：「某天收市后须为 0」，最后一个可以持仓过夜的是那天的前一个交易日，引擎在那天按结算价强平仍有的持仓。交易日按数据层的交易所日历（`fut.calendar()`，含未来一年多）往回数；`last_hold_dates` 拿到的日历不够长时用周一到周五补齐并发出警告，节假日被当成交易日，算出的期限**偏晚、偏乐观**（例：日历截在 2019 年时 RB2002 算成 20200130，按真实日历是 20200122）。期货公司常比交易所规定更早要求平仓，`futures_portfolio(personal_lead=k)` 再提前 k 个交易日换月；默认 0，没有自己公司的规定时建议 2（未核实，取常见做法）。数据层给不出个人客户最后持仓日（合约表没有这个字段），由上表按最后交易日和交割月推算；`delivery_month` 为空时用最后交易日所在月份。

8. **乘数中途变化的合约**：`panelbt_inputs(multiplier_change="split")` 拆成两列，前一列在分界日前一行收盘按结算价强平（手续费 + 滑点），后一列从分界日开盘起开仓（手续费 + 滑点），手数按「旧乘数 / 新乘数」折算后向零取整（PB 25 吨 → 5 吨：2 手变 10 手）。交易所实际是按比例折算持仓、不收费、持仓不中断。这里和真实情况有两处不同：多付一次往返成本（偏悲观）；分界日前一晚到分界日开盘之间**空仓一夜**，这段价格变动不计入盈亏（偏向不确定，取决于那一夜的涨跌）。
9. **缺失的保证金或手续费**：默认报错。数据层用 `panelbt_inputs(missing=..., param_fill=...)`（`futures_portfolio` 原样转交）；引擎层 `FuturesBook(missing=...)` 可选 `"previous"`（合约内只用此前的值向前填）或一个数。
10. **夜盘**：有夜盘的品种，日线开盘价是前一晚夜盘的集合竞价价，最高最低价含夜盘。用 `exec_price = 开盘价` 时，第 t 行的成交时点是 t−1 日晚上 21:00。防前视的用法：信号只用到第 t−1 行收盘（结算价、收盘价、持仓量），经 `execution_targets`（错一行）在第 t 行开盘成交；第 t 行的开高低、成交量不能进信号。两者之间隔着 15:00 到 21:00，实盘来得及。没有夜盘的品种（中金所、EC）开盘就是当天日盘开盘。

11. **不支持负价**：结算价、成交价、收盘价、开盘价里有 0 或负数的期货列一律报错，与 `validate` 无关。原因：保证金按价格算，负价会让占用保证金变成负数、反而增加可用资金，亏损也不触发追保（关掉校验实测：结算价 −37.63 时占用保证金算成 −37,630）。WTI 2020-04-20 这类负价行情目前不能回测，要支持需要另定保证金和强平口径（交易所当时临时改了规则），列在后续工作里。这条检查在 `FuturesBook`（以及 `futures_portfolio`、`book_from_table`）这一层；绕过它直接构造 `bt.Market(futures=...)` 时，`validate=True` 由内核的输入检查拒绝非正结算价，`validate=False` 不受保护。

## 常见的坑（对照规则调研的清单）

| 坑 | 这里怎么防 |
|---|---|
| 用主力连续价直接算收益 | 只按具体合约结算价算盈亏；下面的例子量化了差距 |
| 用收盘价代替结算价盯市 | 盯市、保证金只用 `settlement`；`close` 只是报表 |
| 忽略平今费 | 日频不会出现平今，见第 3 条的唯一例外 |
| 夜盘归属错日 | 第 10 条：信号到 t−1 收盘，t 行开盘成交 |
| 忽略涨跌停无法成交 | 第 5 条：掩码、涨跌停价或一字板推断 |
| 用今天的保证金和费率回测历史 | 逐合约逐日取数据层参数；缺值报错而不是回填 |
| 持仓进入个人不能持有的期间 | 第 7 条：默认在期限前换月，仍持有就强平 |
| 主力切换用了未来信息 | 换月只用前一行的持仓量 |
| 合约乘数用错 | 乘数取数据层逐日的 `multiplier`，中途改单位的合约拆列 |
| 忽略分阶段保证金提高 | 保证金率逐日取，提高后可开数量变少（有性质测试） |

## 手工核对（真实数据）

`bench/futures_hand_check.py`：RB2310（螺纹钢，每手 10 吨），2023-06-01 开盘买 10 手、06-05 开盘加 5 手、06-08 开盘全平；交易所当日的手续费率（万分之一）和投机保证金率（13%），不加期货公司条款、不计滑点，按上期所结算规则手算：

- 开仓、加仓：手续费 = 手数 × 10 × 开盘价 × 1e-4；持仓基准 = 数量加权的成交价；

逐项完全相同（最大差 0）。合计也可以直接验：10 × 10 × (3630 − 3455) + 5 × 10 × (3630 − 3602) − 107.01 = 18,792.99。

## 例子：多品种时间序列动量

`bench/futures_momentum.py --root <data>`：2012-01-04 至 2026-11-12（3607 行）。品种池是全部商品品种（不含中金所），**按当时取**：每个调仓行只在当时有主力合约、且过去 60 行成交额（主力合约的成交量 × 结算价 × 乘数，当天收盘已知）最大的 20 个品种里建仓，其余品种目标为 0，不用全样本挑的固定名单。全期共有 57 个品种进过这个名单。60 行动量的符号 × 10% / (60 行年化波动率 × √20) 作名义权重（单品种上限 1），每 21 行调仓，持仓量主力合约、真实换月，收盘出信号、下一行开盘成交。账户 `CN_RETAIL`（保证金 +5 个百分点、手续费 × 3），滑点万分之二，打开一字板推断和个人持仓期限。2021 年以前缺的参数用假设值：保证金 15%、手续费万分之一。

仓位设定的后果：名义总杠杆（各品种名义市值绝对值之和 / 权益）平均 2.7 倍、最高 5.6 倍，平均保证金占用 40%。这是回撤接近一半的直接原因；目标波动按每品种 10% 年化、20 个品种等风险叠加，没有组合层面的波动控制。

| 做法 | 年化 | 最大回撤 | 夏普 |
|---|---:|---:|---:|
| 引擎：具体合约、真实换月、费用 | 5.11% | 47.7% | 0.37 |
| 错误：不复权主力连续价 × 同样的权重（不计费用） | 0.96% | 57.3% | 0.14 |
| 参照：比例后复权连续价 × 同样的权重（不计费用） | 6.69% | 48.5% | 0.45 |

- 用了 4231 个合约、4232 次换月（含没有持仓的品种），6,484 笔成交：调仓行 4,080 笔，换月行上换月品种的平旧开新 2,404 笔，其他 0 笔（换月行不动别的品种）。没有追保，也没有强平。
- 费用（手续费 + 滑点 + 强平费）每年约占**权益**的 1.9%（逐日费用 ÷ 前一日权益，按年累加；相对初始资金是 3.1%），其中 49% 来自换月。
- 不复权连续价把每次换月的价差（新合约 − 旧合约）当成了持仓的盈亏：在这个样本上年化少算约 4.2 个百分点、最大回撤多算 10 个百分点。方向和大小取决于策略的多空和当时的期限结构，没有一般规律，这正是它危险的地方。
- 比例后复权价不计费用时比引擎高约 1.6 个百分点，和引擎每年多扣的约 1.9% 费用大体相当；剩下约 0.3 个百分点来自整手取整、按具体合约价格换算名义和保持手数换月，没有逐项拆分。结论：后复权价可以当信号，不能当净值。
- 历史版本：用全样本成交额挑定 20 个品种（有前视）是年化 8.21%、最大回撤 33.4%；按当时取品种、但换月行把所有品种拉回目标名义（已修正）是 4.81%、49.2%、15,710 笔成交。

## 外部行情的入口

`book_from_table(daily, contracts, params=None, ...)`，字段名与 `ashare.data.futures_schema` 一致，以后境外数据适配器的输出可以直接喂进来。

| 表 | 必填列 | 可选列 | 单位与时点 |
|---|---|---|---|
| `daily` | `date`、`symbol`、`settlement`、`close` | `open`、`high`、`low`、`volume` | 日期 `YYYYMMDD`，交易所交易日（CME 周日晚开盘归周一）；价格是报价单位（美元/桶）；`settlement` 是交易所公布的结算价（ICE Brent 伦敦 19:28–19:30 加权，CME 纽约 14:28–14:30），不要用收盘价；`volume` 手、单边。执行价默认取 `open`（`exec_field` 可改） |
| `contracts` | `symbol`、`multiplier`、`last_trade_date` | `settlement_type`（`"cash"` 为现金交割）、`last_hold_date` | 乘数是每手的报价单位数量（WTI 1000 桶）；最后交易日那行的结算价对现金交割合约应是交割结算价 |
| `params` | `date`、`symbol`、`margin_long`、`margin_short` | `fee_open_rate`、`fee_open_per_contract` | 比例；元（报价货币）/手。没有逐日参数时直接传标量 `margin_rate`、`fee_rate`、`fee_per_contract` |

行是 `daily` 里出现过的全部日期，列是 `contracts` 的顺序；某合约某天没有行就是没有行情、不成交，结算价在合约内向前填。合成的 WTI 式月度合约链（含换月）见 `bench/futures_wti_example.py`：

```python
import numpy as np
from bench.futures_wti_example import chain
from panelbt.futures import roll_targets
from ashare.backtest.futures import book_from_table

daily, contracts = chain()                       # 两个长表，字段名同统一字段
ext = book_from_table(daily, contracts, margin_rate=0.10, fee_per_contract=1.5,
                      slippage=1e-4, initial_cash=1e6)
keep = int(np.searchsorted(ext.expiry, len(ext.dates))) + 1
plan = roll_targets(ext.expiry[:keep], len(ext.dates), 5, 5.0)   # 到期前 5 行换月
result = ext.book.run(plan, kind="lots")         # 一直持有 5 手近月
```

数组层面直接用 `panelbt.FuturesBook`（见包内 README），不需要本仓库的任何东西。

## 混合面板里的退出规则

市场里有期货列时，`bt.Rules` 只作用于现货列：标量百分比和 `max_hold` 只施加给现货列；每只证券或 T×N 的百分比在期货列上必须是 NaN，否则报错。期货列不判断、不记成本和建仓日，期货的普通目标不受规则状态（冷却、待平）影响。保证金账户里规则平仓的「自有现金不得为负」削减扣掉了当时占用的期货保证金（`close`/`average` 时点用前一结算价和当日保证金率，`open` 时点用调仓之后的占用）。限价目标在有期货列的市场里继续拒绝：限价开仓的资金判断只算现货的现金和保证金，没有算期货保证金，会超买。

## 性能

本机 M5 Pro，负载 7–12（同时有十来个代理在编译和跑测试），各 5 次取中位数：

| 项目 | 耗时 |
|---|---:|
| 建期货组合（90 个商品品种，3607 行 × 4231 个合约，读数据 + 换月 + 建 `Market`） | 5.1 s |
| 单次回测 `pf.run`（逐行推进，含换月处理） | 118 ms |
| 100 组参数的信号计算（Python） | 10.7 s |
| 100 组参数的回测 `pf.run_batch(threads=8)` | 13.7 s |

`pf.run` 逐行推进（`Simulator`），比把整份目标一次交给内核（同一市场约 5 ms）慢得多：换月行要按当时的持仓决定「其他品种保持手数」，而内核的目标行没有「这一列不动」的写法，只能逐行读持仓。慢在 Python 的逐行循环，线程并行受 GIL 限制。没有调仓、换月、结束、挂起和顺延的「安静行」直接推进、不读持仓；但这个例子有 90 个品种，几乎每行都有品种换月，所以只快了一点（同一份结果逐位相同，120 → 117 ms，机器负载 8–10 时的中位数）；品种少时省得多。合约层面的目标已经确定时（不需要按品种换月），直接用 `pf.book.run` / `bt.run_batch`。要再快，需要内核支持「保持这一列」的目标，属于以后改内核的事。

## 不模拟的规则

| 规则 | 偏向 | 说明 |
|---|---|---|
| 平今费 | 不确定 | 日频不出现平今（第 3 条）；唯一例外是结束行当天新开又被强平的仓按普通费：上期所部分品种平今是普通费的一半（偏悲观），中金所股指 10 倍（偏乐观） |
| 跨期、跨品种保证金优惠，双向持仓按大边收 | 偏悲观 | 这里按每个合约单独收全额 |
| 单边市后扩板和自动提高保证金 | 偏乐观 | 次日可开数量和追保都按原保证金率算 |
| 收于停板的单边市当日禁止在停板方向开仓 | 偏乐观 | 规则调研第三部分建议的规则，没做 |
| 停板时的排队成交 | 不确定 | 一字推断全拒，开在停板盘中打开的全放（第 5 条） |
| 交易所强制减仓 | 偏乐观 | 持仓不会被交易所按比例减掉 |
| 临时日内开仓上限、程序化交易申报费 | 偏乐观 | 不限开仓、不收申报费 |
| 实物交割过程（仓单、升贴水、交割库容） | 不确定 | 不进交割：期限前换月或强平 |
| 交易单位按比例折算 | 偏悲观为主 | 这里平旧开新，多付往返成本、空仓一夜（第 8 条） |
| 夜盘与日盘之间、日内的价格路径 | 不确定 | 只用日线；开盘价成交，止损类规则不作用于期货列 |
| 汇率 | 不确定 | 境外合约按报价货币记账 |
| 持仓限额 | 偏乐观 | 个人和小资金一般碰不到，大资金要自己约束目标 |
| 负价 | — | 不支持，报错（第 11 条） |

## 已知局限

- 强平发生在最后持仓日的下一行收盘、按当行结算价（交易所实际是在那天开盘后执行），偏向不确定。
- 现金账户的混合面板（股票 + 期货）里，股票市值计入权益，所以「股票多头 + 期货空头」在现金已经低于期货占用保证金时也不记追保（真实账户里期货保证金不能用股票市值抵）。这是 4.11 对冲腿的既有口径，偏乐观；纯期货组合不受影响。
- 换月按保持手数处理；想在换月时按名义重新定仓，在换月行自己给目标。
