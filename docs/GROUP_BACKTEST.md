# 分组回测（`ashare.factor.groupbt`）

把一个在全市场上算好的因子矩阵，按股票池分组、做多空，给出分组收益图、绩效表和风险暴露。权重和指标的口径参照 WorldQuant BRAIN。只做日频；不扣交易成本。

## 最短例子

```python
import ashare.data
from ashare.factor import groupbt

panel = ashare.data.open().panel(list(groupbt.FIELDS))
factor = ...  # (交易日, 股票) 的因子矩阵，行列与 panel 对齐，值越大越做多
res = groupbt.run(factor, panel, "TOP1800", n_groups=10)
print(res.text())                       # 多空、top 组两张绩效表和风险暴露
open("report.html", "w").write(res.html())   # 图和表，含嵌套的小池
```

## 参数

| 参数 | 取值 | 默认 | 含义 |
|---|---|---|---|
| `universe` | `TOP800` / `TOP1800` / `ALL` | 必填 | 股票池 |
| `trade_at` | `open` / `close` | `open` | 成交时点，同时决定收益口径 |
| `trade_limitation` | 布尔 | `True` | 涨跌停和停牌限制 |
| `n_groups` | 5 / 10 | 10 | 分组数 |
| `group_neutralize` | `None` / `"industry"` / `"cap"` / `"cap+industry"` | `None` | 全市场上的中性化 |
| `vector_neut` | 一个或一组 (T, N) 向量 | `None` | 对风险向量做截面正交 |
| `decay` | 非负整数 | 0 | 全池权重的线性衰减天数 |
| `rebalance` | 正整数 | 1 | 每 N 个交易日生成一次调仓信号，下一交易日成交 |
| `record_holdings` | 布尔 | `False` | 记录主池多空组合调仓后的稀疏实际持仓 |
| `by` | `year` / `quarter` | `year` | 绩效表的分段 |
| `weights_portfolio` | 布尔 | `False` | 另算按全池归一化权重持仓的多空组合 |
| `sub_universes` | 布尔 | `True` | 用大池时把嵌套的小池各跑一遍 |
| `window` | `(起, 止)` | `groupbt.IS` | 回测窗口，见下 |

## 回测窗口

- 回测只用样本内窗口：`groupbt.IS = ("20160101", "20250101")`，含起不含止，是 `window` 的默认值。
- 止日及以后的行情和因子一概不读（面板在止日处截断后才进入计算），哪怕手里有更晚的数据。
- 起日之前的数据只用来算滚动窗口（如 240 日动量），不产生持仓。第一个信号日是窗口内第一个交易日，下一个交易日成交。
- 这套日期定义在 `ashare.factor.windows`，因子挖掘的 `Split.standard()` 用的是同一套（训练 = 样本内，验证 = 2025 年，留出 = 2026 年起）。
- 2025-01-01 之后都是样本外：`groupbt.VALIDATION`（2025 年）做验证，`groupbt.TEST`（2026 年起）做测试。要用必须显式传 `window=`，平时研究不要碰。

## 股票池

- `TOP800`：沪深300 + 中证500 的成分股。`TOP1800`：再加中证1000。`ALL`：全部已上市股票。
- 成分逐日取。成分数据是月末快照，指数在 6 月、12 月调整时池子最多滞后到当月月末；没有用到未来信息。
- 涉及 `TOP1800` 的回测从 2015-01-01 起（中证1000 的成分数据 2014 年 11 月才有）：主池是 `TOP1800` 时，它和带的 `TOP800` 小池都从这一天起算；主池是 `ALL` 时，只有 `TOP1800` 这个小池从这一天起，`ALL` 和 `TOP800` 仍是全历史。
- 子池检测：`ALL` 带 `TOP1800` 和 `TOP800`，`TOP1800` 带 `TOP800`，结果在 `res.subs` 里，口径相同。

## 从因子到权重

1. 因子在全市场上算好后传入。
2. 全市场上做中性化：
   - `"industry"`：申万一级行业内减行业均值。
   - `"cap"`：把 `log(总市值)` 的截面排名切成 10 组，组内减组均值。
   - `"cap+industry"`：先行业内减均值，再对 `log(总市值)` 做 `vector_neut`。
   - `vector_neut=`：依次对给出的向量做 `vector_neut`。
3. 抽出股票池内的值，池外为空。
4. 池内截面去均值（多空中性化）。
5. 归一化：除以截面绝对值之和。多头合计 +0.5，空头合计 −0.5。
6. `decay = n` 时，对最近 n 天的归一化权重做线性加权平均（系数 n、n−1、…、1）。

`vector_neut(x, y)`：逐日在截面上回归 `x = 截距 + beta·y`，返回 x 的残差。只用当天两者都有效的股票，少于两只时当天为空；y 为常量时退化为去均值。

## 时点和收益

| `trade_at` | 因子用到的数据 | 成交 | 收益区间 |
|---|---|---|---|
| `open` | T 日收盘及以前 | T+1 开盘 | T+1 开盘 → T+2 开盘 |
| `close` | T 日收盘及以前 | T+1 收盘 | T+1 收盘 → T+2 收盘 |

- 复权价。默认每天调仓。结果按成交日记账。
- 持仓停牌期间收益为 0，复牌当天一次体现停牌前后的价差。
- 一年按 240 个交易日。

### 调仓周期与持仓

`rebalance=N` 的节奏从窗口内第一个交易日（信号日）开始，信号行 0、N、2N……
对应成交行 1、N+1、2N+1……；保留 T 日信号、T+1 成交，窗口首日仍不建仓。
IS、VALIDATION 和显式传入的其他窗口各自重新起算，不继承前一窗口的持仓或节奏。
子池沿用主窗口的节奏，不因某天股票数不足或暂时无成分而挪动调仓日。

非调仓日保持上一次成交后的**实际权重**，不追补冻结而未成交的目标、不因价格变化漂移，
也不因退市或收益缺失另外补仓。收益缺失仍按现有纯权重内核的清洗规则处理（NaN 计零）；
调仓日继续使用原有涨跌停、停牌冻结与剩余额度缩放规则。新信号只在调仓日触发分组有效性错误；
加权组合的衰减仍使用逐日信号历史。`N=1` 的所有既有输出保持逐位一致。
可记账的非调仓日换手为零；窗口首个未建仓日、最后一个无法确定收益的日期继续按原有口径
返回 NaN。仍不扣交易成本；margin 分母随实际换手变化，不虚构费用。

`record_holdings=True` 额外返回主池多空组合在调仓成交后的非零权重，正数是多头、负数是空头，
正常满仓时各侧绝对权重合计 0.5。冻结可能让旧股票留在持仓，即使它已不属于当天目标组。
只记录调仓日；非调仓日查最近一次快照即为实际持仓，不保存 (T,N) 稠密矩阵。
快照的因子值是生成该次目标的信号日原始表达式值；冻结股票也使用同一信号日的值，缺失则留空。
`res.holdings` 默认是 `None`；开启后为字典：`days` 是 `res.dates` 中的成交行号，`dates` / `signal_dates`
是成交日与信号日，`offsets[k]:offsets[k+1]` 切出第 k 次快照的 `columns` / `weights` / `factor` / `industry`。
`columns` 是 `symbols` 轴中的列号。所有嵌套子池仍不记录持仓，避免额外放大存储。

平台据实际正/负持仓分别统计连续持有区间：从成交后非零权重首次出现，到权重归零或变号前一天。
区间长度按交易日计，跨调仓但方向不变算同一区间，零持仓日不计；窗口两端截断的区间按窗口内
观察到的天数纳入，不外推完整寿命。平均持仓天数 = 所有持有区间的交易日数之和 / 区间个数。
末日即使收益未知，已经观察到的持仓日仍计入。平台主列只显示多头均值，空头均值另存摘要。

## 分组和多空

- 每天把池内有因子值的股票按因子值从高到低切成 `n_groups` 组，第 1 组（top）最高。并列的按股票在面板里的先后顺序。
- 每组是一个纯多头组合，组内等权，权重合计 1。
- 多空组合：top 组合计 +0.5，bottom 组合计 −0.5。
- 调仓信号日池内有因子值的股票少于 `n_groups` 只，或不同取值少于 `n_groups` 个，抛 `GroupingError`，`rows` 给出是哪些行。因子全空的日子跳过。
- 日盈亏 = Σ 权重 × 个股收益。

## 交易限制

按成交时点判断（开盘看开盘价是否在涨跌停价，收盘看收盘价）：

- 停牌：权重保持上一日的值。
- 涨停：只能卖。目标权重高于上一日就保持上一日的值，低于就照常成交。
- 跌停：只能买，与涨停相反。
- 没有持仓的股票遇到受限方向，当天不建仓。
- 被冻结的股票占着额度，其余股票用剩下的额度按比例缩放，多头、空头两边分别算；缩放后又有股票撞上受限方向的，再冻结、再缩放，直到稳定。
- 「上一日的权重」取上一日的持仓权重，不计入日内涨跌造成的漂移。

## 输出

- `res.chart()`：`n_groups` 条分组累计盈亏线加一条多空线的 SVG，逐日相加（cumsum）。`res.curves(name)` 同时给出 cumsum 和 cumprod。
- `res.table("long_short")`、`res.table("top")`：行是年份或季度，最后一行 `ALL`；列如下。

| 指标 | 定义 |
|---|---|
| return | 日盈亏均值 × 240 |
| sharpe | 日盈亏均值 ÷ 日盈亏标准差 × √240 |
| turnover | 每天 Σ｜今天权重 − 昨天权重｜，取日均 |
| maxdrawdown | 累计盈亏（cumsum，从 0 起）相对高点的最大回落；分段的行只看段内 |
| margin | 总盈亏 ÷ 总成交额 × 10000，单位 bps |

- `res.exposure`：多空组合对四个风险因子的逐日暴露，Σ 权重 × 池内去均值后的因子值；`res.exposure_mean()` 是全历史均值。风险因子（`close` 为复权收盘价）：
  - `size`：`log(总市值)`。参考：Barra 的市值暴露在全市场股票上的截面均值约 −1.8，这里的暴露是池内去均值后的，两者不是同一个量，不能直接比
  - `reversal_20`：`1 − close / ts_delay(close, 20)`
  - `reversal_60`：`1 − close / ts_delay(close, 60)`
  - `momentum`：`ts_delay(close, 20) / ts_delay(close, 240) − 1`
- `res.group_pnl`、`res.pnl`、`res.turnover`：原始日序列。`res.text()`、`res.to_dict()`、`res.html()`。

## 已知局限

- 不扣成本、不考虑融券能否借到，多空收益是纸面收益；`margin` 用来看每单位成交的盈利。
- 指数成分是月末快照。
- 停牌持仓的权重不随价格漂移。
- 盘中时点成交（9:30、13:00、14:50 等）没有做，需要全市场分钟线。
- 风险因子是自己算的四个，没有 Barra 官方数据。

## 验证和性能

组合推进使用 `panelbt` 的纯权重模式，单次原生调用批量处理各组、多空、可选权重组合
及子池。它与成交模式共用引擎，但没有现金、股数、费用、手数或价格权重漂移；每日
受限权重冻结，其余按多空剩余额度缩放。开盘直接复用数据层可买卖掩码，收盘复用
`panelbt.markets.ashare.price_permissions`；收盘口径不额外套用开盘的一字板规则。
信号到成交的错位仍由 `ashare` 显式指定，以上回测口径和公开参数保持不变。

逐日排名、中性化和暴露归约使用 `panelops-core` 的 NumPy 顺序内核，与权重模拟在
同一个释放 GIL 的调用中执行。每池只排序一次，各池共享全市场中性化结果和当天风险
向量。历史价格前填保留有限缓冲区，不缓存跨调用的可变输入；IS 与 VALIDATION
各自遵守止日隔离。NumPy 市值对数批量计算保留数学库结果，不改为另一种近似函数。
调用期间不要修改输入或其内存别名。有效窗口的因子独立复制，其他传入 Rust 的视图
临时设为只读，正常或异常结束后恢复原标志；重叠借用须等最后一个调用结束才恢复。
`panelbt` 导入时自检 NumPy 求和次序，不匹配就报错并要求更新内核。

`bench/groupbt/check.py` 以冻结的 main 实现为基准，覆盖 384 组参数和所有公开输出；
合成数据另加 32 组 193 行与 300 行长窗口，共 416 组，跨越多个 64 行工作块。
真实结果仅写本 worktree 忽略的 `.cache/`；报告只记录一致数量和耗时。

- 入口与一份逐日逐股循环的参考实现对拍（三个股票池 × 两种成交时点 × 有无交易限制 × 5/10 组），差异不超过 1e-12；另有前视检查（改动之后的因子或价格，之前的结果逐位不变）。
- 变异检查：去掉信号到成交的移位、收益错一天、分组方向反、不查能否卖、冻结不占额度、收盘用开盘的限制、停牌不沿用前价、`TOP1800` 不等成分数据、不抽池、回撤不从 0 起、市值与行业顺序反、多空账面翻倍，十二处都被测试抓到。
- 旧 NumPy 版的历史测量（忙机）：`TOP800` 约 7 秒，`ALL` 不带子池约 8 秒，`ALL` 带两个子池且市值+行业中性化约 17 秒；这些数值保留为旧版本记录。
- 当前批量权重模式正式交替测量：单组「IS TOP1800 带 TOP800 子池＋VALIDATION」后续中位 9.131 → 0.281 秒，峰值 RSS 8.117 → 1.982 GB。内存仍高于 1.5 GB 目标。合成、真实各 384/384 全输出逐位一致，不使用容差。完整阶段表、线程表及复跑方法见 [GROUPBT_PERF_REPORT.md](GROUPBT_PERF_REPORT.md)。
