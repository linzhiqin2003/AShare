# P-022 任务内共享市值、股票池和风格均值

- 提交：未提交（基于 `a5ea630`）。
- 手段：复用计算。`groupbt.run_many` 按窗口缓存对数市值，按窗口、股票池及池起点缓存
  掩码。`panelbt.GroupExposureCache` 用线程安全的 `OnceLock` 按日期、池缓存四个均值。
  不缓存整张风险面板，保留原风险历史与持仓加权归约。
- 基准：真实数据，TOP1800 样本内带子池，四种中性化；同进程交替 9 次，保持其余代码一致。

| 独立开关 | 之前 | 之后 |
|---|---:|---:|
| 四变体行情准备 | 169.7 ms | 42.5 ms |
| 准备期 tracemalloc 分配峰值 | 518.9 MiB | 148.3 MiB |
| 四次内核合计，仅开关均值缓存 | 768.0 ms | 744.1 ms |
| 同轮 profile 暴露阶段合计 | 85.5 ms | 60.6 ms |

前三项为交替中位；最后一行为单轮阶段计时，只解释收益来源。缓存只存活于本次调用，
不跨任务共享可变数组；复用时还检查风险数组的指针、类型、形状、步长和窗口身份。

放弃压缩零项后求和：`[1e16, 1, -1e16, 1, 0.0, -0.0, 0.0, -0.0]` 的全长 NumPy 和为 0，
删零后为 1，最大绝对误差为 1（合成反例）。零项位置改变八路求和树；不放宽容差。
实际持仓加权和继续全长归约，包含有符号零和 NaN 的测试。此处不宣称完成稀疏暴露内核。

验证：跨池、跨窗口、不同信号和中性化、并发调用均逐位对照；均值缓存拒绝错误的行情身份。
漏掉股票池键、窗口键、Rust 均值索引串池和压缩零项四种变异均被捕获。
复跑：`python -m bench.groupbt.ablation -o .cache/groupbt-fusion/ablation.json`。
