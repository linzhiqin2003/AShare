### P-018 panelbt 纯权重记账与批量模拟

- 提交：`4129258`。
- 内核：`crates/panelbt-core/src/weights.rs`；Python 入口为 `panelbt.run_weights` / `run_weights_batch`，紧凑目标共享分组标签，计算期间释放 GIL（本仓库 PyO3 的名称为 `py.detach`）。
- 原 NumPy 模拟保存在 `panelbt.reference_weights`；现金和股数记账不用于权重模式。
- 逐位实现保留稀疏列序和 NumPy 的成对求和顺序；点积调用当前环境中 NumPy 的 float64 内核，避免自行选另一套 BLAS 导致舍入变化。仅 NumPy C API 桥接模块允许 unsafe，其余绑定仍禁止 unsafe；调用点写明数据长度、生命周期和 GIL 前提。
- 首轮逐位检查暂停记录：24 个原生用例中，单列、不限交易的用例出现 `-0.0` 与 `+0.0` 不同，最大绝对误差 **0**。原因是 `np.dot` 对长度 1 的向量走标量乘法，而 dtype dot 内核带正零累加恒等元。修复为同样的单元素乘法，未放宽任何断言；复核结果待补。
- 正式交替测量（每版 3 个新进程，每进程 3 轮，后两轮汇总）：整组后续中位
  9.131 → 5.690 秒，最高 RSS 8.117 → 8.271 GB。仅替换模拟还保留了完整风险与移位矩阵，
  因此这个阶段没有实现内存目标。可重建的隔离版本为 `bench/groupbt/simulation.py`。
- 该隔离版本合成全输出 384/384 逐位通过，9.805 秒。单元素、7/8、127/128/129、
  5923 列等模拟对照通过；原始符号零差异已修复，没有放宽断言。
- 变异：将 Rust 换手乘 0.5，被冻结 main 的全输出对照抓到；恢复源码并重建后
  384 组通过，记录耗时 80.869 秒。测试捕获的是换手断言，不是构建或导入失败。
- GIL 在核心计算期间释放；最终 1/2/4/8 线程扩展性见 P-020 和总报告。
- 可买卖规则复用：交易方向调用 tradecore 的共用判断，开盘读已有权限掩码，
  收盘复用 panelbt 的 price_permissions。收盘不添加开盘的一字板判断，以保持原口径。
