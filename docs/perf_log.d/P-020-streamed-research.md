### P-020 截面计算与暴露在 Rust 中逐日融合

- 提交：未提交。
- 设计：`panelbt.run_group_weights` 复用权重记账内核；截面操作静态复用
  `panelops-core` 中的 NumPy 顺序归约与稳定排序。Python 包不互相依赖。
- 每日共享全市场中性化、风险向量，每池排序一次供所有组使用。价格前填保留有限历史，
  暴露即时归约，不再输出多空持仓的 (T,N) 面板。
- 重构暂停检查：受限组合持仓出现有符号零差异，最大绝对误差 0。
  原 NumPy 的 `prev` 会保留不再活跃列的负零，而当天 `held` 从正零初始化；
  不能把两者合并成一个缓冲区。修复为保留历史状态、另用一个日持仓缓冲区。
  没有放宽断言。后续全部逐位复核通过。
- 串行融合版已经完成真实数据 384/384 全输出逐位对照（314.149 秒，含读取基准及
  派生输出检查）；随后继续优化，最终结果另行复核。
- 64 行一个工作块：截面按行并行，模拟按组合并行（各组合内部仍严格逐日），
  暴露按行并行。所有归约仍由单个 worker 按原次序执行，不用并行归约树。
  共享 Rayon 线程池限制内部工作线程数量，外部 Python 线程不持 GIL 等待。
- 价格前填从窗口边界向前找每列最后一个有效值，之后只推进所需历史；不是截断历史，
  长期停牌仍能找到更早的有效价。窗口不读取止日及以后的值。
- 正式交替测量：相比只替换模拟的 5.690 秒 / 8.271 GB，最终为 **0.281 秒 / 1.982 GB**。
  未修改 main 为 9.131 秒 / 8.117 GB。各版 3 个独立进程、每进程 3 轮，后两轮汇总；
  最终首轮中位 0.296 秒，后续 0.260–0.287 秒。没有用剖析开销大的计时夸大加速比。
- 最终真实全输出 **384/384** 逐位一致，耗时 **155.238 秒**；合成 **384/384**，
  另测向量中性化、5 组、宽截面、长缺价、空窗口、F-order 和多线程输出。
  发现全负行业标签的长度转换边界后，增加直接返回全缺失的路径和回归用例；该输入与 main 一致。
