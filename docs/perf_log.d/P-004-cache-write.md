### P-004 风险模型缓存写入：后台线程、快速压缩、证券表只存一次

- 提交：见本文件所在提交（分支 `perf/risk`）。
- 手段：硬件 / 格式。
  - 每日快照改由一个后台线程写：调用方只复制数组并入队（约 0.15 ms/日），zlib 压缩（释放 GIL）和落盘在另一个核上做；队列上限 64，写不过来时调用方等待。读取、清理、`stats` 和 `model_series` 结束（含提前关闭生成器）前都会等它落盘；写失败保存下来，在下一次 `save`/`flush`/生成器结束时以 `RuntimeError("风险模型缓存写入失败")` 抛出，原异常在 `__cause__`；进程退出时 `atexit` 再等一次。
  - 压缩从 `savez_compressed`（deflate 6）改为 deflate 1，仍是 `np.load` 能读的 npz。
  - 证券表每代只写一次（`.symbols.npy`）；`prepare(generation, symbols)` 新增可选参数，`model_series` 总会传，证券表坏了就以它为准重写。
  - 最后一天的递推检查点（只写一次）保持 deflate 6。
- 缓存格式 4（`cache.FORMAT`），写在 `.generation.json` 的 `format` 字段；格式不符的目录在 `prepare` 时整体判为未命中并清空。模型内容的 `CACHE_SCHEMA`（参与 `parameter_hash`）不变，所以模型元数据逐位不变。
- 顺带修复上次复核遗留的 d 项（`docs/RISK_NOTES.md`）：
  - 快照里存自己的键，读取时核对；键不符、截断、不是 zip、缺字段一律当作未命中，删掉坏文件后重算并覆盖；
  - `python -m ashare.risk.cache stats|clear <目录>` 对不存在的目录直接返回 0，不再创建目录；`ModelCache.stats/clear` 对已被删掉的目录也直接返回。

#### 一致性

全历史 4824 日逐日核对 B、F、D 和元数据（含 `parameter_hash`）的 SHA-256：0 日不同（`bench/risk/perf_round.py diff`）。最近 300 日、800 日的配对运行同样逐位相同。

#### 测试与变异

新增 `test/risk/test_cache_format.py`（10 个）：证券表只存一次、快照带键；截断 / 换成另一份有效快照 / 非 zip / 证券表损坏四种损坏都当未命中并重算出与无缓存相同的模型；旧格式目录被清空；后台写失败被报出；提前关闭生成器也落盘；命令行不为不存在的目录建目录。原有测试不改断言全部通过。
变异（`bench/risk/perf_mutations.py --only P-004`，先跑不改动的对照）：不核对快照键、读失败不当未命中、后台写失败被吞掉、旧格式不判失效、命令行建目录、证券表坏了不重写——6 处全部被抓到。

#### 易用性

`ModelCache` 接口不变，新增 `flush()` 和 `prepare` 的可选 `symbols`；旧缓存目录第一次使用时自动重算。`ModelCache` 直接 `save` 后立刻用别的进程读同一目录，需要先 `flush()`（同一对象的 `load` 会自动等）。

#### 试过放弃的

- 不压缩：调用方加落盘 0.36 ms/日（最快），但全历史 1068 MB，是旧格式的 1.73 倍，超过 1.5 倍的上限。
- deflate 6 / bzip2 / lzma：同一批日模型 173 / 176 / 165 KB/日，压缩 5.7 / 17.7 / 31.9 ms/日，比 deflate 1（176 KB、3.7 ms）省不了多少空间。
