### P-006 特质风险：三个指数加权方差改为分块累加（允许相对误差 1e-12）

- 提交：见本文件所在提交（分支 `perf/risk`）。
- 手段：数学算法（少算：窗口每天只前进一天，按块复用已算好的加权矩）。
- 改了什么：`src/ashare/risk/specific.py`（`SpecificMoments`）、`window.py`（`WindowVariances`，可代替残差窗口传给 `specific_variance`，函数签名不变）、
  `series.py` 接入；`portopt` 新增 `ew_moments_segment`、`ew_moments_variance`（Rust 内核 `crates/portopt-core`）。
- 配置：`FundamentalConfig.specific_incremental`（默认 True；False 为从头算，与旧实现同一路径，作对照）和 `specific_reanchor_days`（默认 252，正整数），二者进入 `parameter_hash` 和缓存键。
- 容差（事先约定）：三个方差各自与从头算的相对误差 ≤ 1e-12；由 `test/risk/test_specific_incremental.py` 在随机面板和对抗输入上守住。
- 校验途径：`specific_incremental=False` 跑一遍逐位等于旧实现；`python bench/risk/perf_round.py run --scenario tolerance` 在同一进程里逐日并排跑两种模式，报告三个方差相对从头算的最大误差、D 的最大相对差、B/F 是否逐位相同和改用从头算的列数。


## 推导

记窗口为最近 T 行（T = min(已有天数, history)），第 i 行权重 w_i = 2^{-(T-1-i)/h}（未归一化，与 Rust `ew_variance` 一致），
有效标记 e_i = [x_i 有限]。对任意移位 s，令 y_i = x_i − s。从头计算的定义：

- S = Σ e_i w_i，均值 m = Σ e_i w_i x_i / S，z_i = e_i (x_i − m) √(w_i/S)；
- var = Σ z_i² + 2 Σ_{l=1}^{L} (1 − l/(L+1)) Σ_{i≥l} z_i z_{i−l}，L = min(lags, T−1)；S = 0 时为 0；最后取 max(·,0)。

把它展开成窗口上的加权矩（移位不改变方差，m̃ = m − s）：

- A1 = Σ e_i w_i y_i，A2 = Σ e_i w_i y_i²，m̃ = A1/S，Σ z_i² = A2/S − m̃²；
- 对滞后 l，记 e_i^{(l)} = e_i e_{i−l}，N_l = Σ e^{(l)} w_i，Q_l = Σ e^{(l)} w_i y_i，R_l = Σ e^{(l)} w_i y_{i−l}，P_l = Σ e^{(l)} w_i y_i y_{i−l}；
  因 √(w_i w_{i−l}) = w_i·2^{−l/(2h)}，Σ z_i z_{i−l} = 2^{−l/(2h)} (P_l − m̃(Q_l + R_l) + m̃² N_l) / S。

每个矩都是「窗口内按到窗口末端的距离指数衰减的和」E_t = Σ_{i∈窗口} 2^{−(t−i)/h} g_i（g 是该行的有效标记、移位值、平方或成对项）。
任何一段连续行 [a, b] 都可以从空开始逐行 `E = d·E + g_i`（d = 2^{−1/h}）累加出以 b 为参照的段和 E_[a,b]，
把它挪到参照 t 只需乘 2^{−(t−b)/h}。于是窗口 [s, t] 的矩 = 若干段和各乘一个正的衰减系数再相加。

- NaN：g 的每一项都乘有效标记，缺失行对任何矩没有贡献，与从头计算「按有效权重归一化」一致；成对项要求两端都有效。
- 截断窗口（前 history 天）：窗口就是 [0, t]，同样分段；方差合成时用 L = min(lags, T−1) 的 Bartlett 权重（矩对 l = 1..lags 都保留，T ≤ l 时这些对本来就不存在）。
- 滞后项：成对项 (i, i−l) 归到后一行 i 所在的段，权重 w_i；只有 i−l ≥ s 时才属于窗口。分段时让最老的残块一直延伸到覆盖 s + lags 所在块的末尾，之后各整块里所有成对项的前一行都 ≥ s；残块本身按「前一行 ≥ s」累加（Rust 内核的 `floor` 参数）。
- 两组半衰期：base 用 h=84 的一组，corr0 与 corrnw 共用 h=252 的一组（corr0 取滞后 0 部分）。每组 3 + 4×5 = 23 个矩/列。
- 有效天数 count 是整数，逐日 +新行 −出界行，精确。

## 为什么不用「加新减旧」的递推

最初按 E_t = d·E_{t−1} + g_t − 2^{−T/h} g_{t−T} 写（加入新行、减掉出界行），对抗测试里守不住：一只股票长期停牌、窗口里只剩最老的几天有值时，
权重和 S 的真实值只有约 2^{−12}，而它是从约 121 的量级一路减下来的，残差是 eps×121 量级，相对误差到 1e-11；窗口里有效值全部出界后 S 应为 0 却剩下
舍入残渣，方差变成 0.0024（应为 0）。这种误差来自减法本身，重锚周期再短也只能缓解。改成只加不减的分块累加后，每个结果都是正权重项之和，
误差与从头计算同量级（实测最大相对误差 8e-15）。

## 分块

- 窗口 [s, t] 切成：最老的残块 [s, e]（e 是 s+lags 所在块的末尾，每天现算，至多 BLOCK+lags 行）、中间的整块（按绝对日期对齐，每块 BLOCK=32 天；
  每块的矩只算一次并缓存，整块之和按「首块、末块」缓存，每 32 天重算一次）、当前未满的块 [c, t]（每天现算，至多 32 行）。
  窗口很短（预热期或 history 很小）时整段一次算完。
- 每天的工作量约 BLOCK + lags + BLOCK/2 行，从头计算是 history（1008）行 × 三次；另省掉每天三次把 48 MB 残差历史转成连续数组。
- 确定性：结果只是这一天的窗口和移位的函数（块边界按绝对日期对齐，块和整块之和的算法与路径无关），全量重建和追加一天逐位相同。

## 误差控制（容差：三个方差各自与从头算相对误差 ≤ 1e-12）

- 移位：按绝对日期每 P = min(`specific_reanchor_days`, history) 天（默认 252）重取一次移位（锚点日之前 history−P+1 天的等权均值），并清空所有缓存的块，
  相当于整体从头重算；移位避免均值远大于波动时 A2/S − m̃² 的抵消。P 进入配置，因而进入缓存键。
- 条件数闸：每列给出各项绝对值之和 M（A2/S + m̃² + Σ 2k_l c_l (|P_l| + |m̃|(|Q_l|+|R_l|) + m̃² N_l)/S），`var·32 < M` 或 `var ≤ 0` 的列改用从头算。
- 均值闸：|均值|/σ 越大，从头计算自己的舍入误差越大（x − m 的相对误差约 2eps·|m|/σ，均值 50、σ 1e-4 的列实测与 numpy 参考差 1.8e-11）；超过 64 倍的列跟从头算走，保证与它一致。
- 阈值闸：`specific_variance` 里 `corr0 > floor`、`base > floor` 两处分支；值与 floor 相对差在 1e-9 以内的列改用从头算，分支判断与从头算模式一致。
- 「改用从头算」调用与从头算模式同一个内核（N>64 时 Rust 逐列计算，只算这些列；N≤64 时 numpy 对整块窗口算再取列），结果逐位等于从头算模式。

## 一致性

- 从头算模式（`specific_incremental=False`）对 P-004 之前的全历史逐日摘要：4824 日 B、F、D 全部逐位相同；元数据只有 `parameter_hash` 不同（配置多了两个字段），其余字段逐位相同。
- 默认模式，全历史 4824 日（`--scenario tolerance`）：三个方差相对从头算最大误差 base 8.7e-15、corr0 5.3e-15、corrnw 9.6e-15；D 最大相对差 1.8e-14；B、F 每天逐位相同；
  2810 万个「列·日」里 45783 个（0.16%）走了从头算。最近 800 日：方差 ≤ 7.9e-15，D ≤ 8.8e-15，改用从头算 0.05%。
- 同一模式下，追加一天与全量重建逐位相同（测试 `test_model_series_modes_cache_key_and_append`；结果只依赖当天窗口和按绝对日期取的移位）。

## 测试与变异

新增 `test/risk/test_specific_incremental.py`（14 个）：随机面板加对抗列（停牌 25 天后复牌、整列缺失、常数、量级跳变 1e5 倍、均值远大于波动、
只有最后 7 天、只有一个有效值、锚点后均值漂到 1e6、强负自相关、NW 几乎抵消）在 N≤64（numpy）与 N>64（Rust）、窗口始终不满、窗口比滞后还短四种规模上逐日守 1e-12；
Rust 矩与 numpy 参考对照；隔几天才求一次与每天求逐位相同；缓冲越界报错；两种模式下 B、F 逐位相同、D 在 1e-10 内、`parameter_hash` 不同；追加逐位相同；
周期改变改缓存键；周期参数校验；`floor` 与切片窗口等价；方差贴着 `variance_floor` 时分支判断与从头算一致；移位失效时条件数闸兜底。
变异（`perf_mutations.py --only P-006`，先跑不改动的对照）：残块不延伸、去掉条件数闸、去掉均值闸、去掉阈值闸、重取移位时不清空块、有效天数出界行不减、
Rust 忽略滞后对下限、Rust Bartlett 权重用错滞后数——8 处全部被抓到（两处 Rust 变异先重建扩展并核对扩展哈希变了）。条件数闸最初没被抓到：
按设计，移位所用的行总在当前窗口内，均值闸又先拦下大均值，真实输入几乎到不了它；补了一个人为让移位失效的测试。

## 易用性

默认行为变为分块累加（用户同意的容差内）；`specific_incremental=False` 可回到旧算法。接口只加不减：`FundamentalConfig` 两个新字段、`portopt` 两个新函数。
旧缓存因 `parameter_hash` 变化自动判为未命中。

## 试过放弃的

- 「加新减旧」的逐日递推（见上「为什么不用」）：随机面板上 3e-15，但长期停牌、窗口只剩最老几天有值时到 1e-11，有效值全部出界后得到 0.0024（应为 0）。

## 复核后修补

- 复核人用 50 位 Decimal 独立参照，量到的最大相对误差是 1.47e-14，闸两侧扫描最差 3.6e-14，没有找到守不住 1e-12 的情形。
- 阈值闸的测试有空档：带宽从 1e-9 缩到 1e-15 时测试照样通过。原测试只把列放在 floor ±4 ulp 处，增量误差太小，不会翻转。补了一个测试：600 列在 floor 的 ±8e-10 以内均匀分布，要求带内的列三个方差都逐位等于从头算（即走了回退）。
- `specific_incremental` 必须是 bool，`specific_reanchor_days` 不接受 bool。
- 重新验证（复核修补之后）的结果见 P-008 记录的「复核后修补」。
