# P-024 平台多窗口表达式复用公共子式

- 提交：未提交（基于 `a5ea630`）。
- 手段：接通已有 `Evaluator.evaluate_many`，按表达式摘要去重后复用字段、收益等公共节点，
  逐个消费并保存结果。保持原算子和全部参数，包括 `exact=`，没有新增一套标准差算法。
- 优化前平台热运行求值（含保存信号）为四变体 116 ms、八变体 277 ms，分别约占工作进程
  总耗时的 10% 和 14%。因此先测现有求值器的共享能力。

| 纯求值基准 | 独立求值 | 公共子式共享 | tracemalloc 峰值 |
|---|---:|---:|---:|
| `ts_std(returns, [20, 60])` | 86.1 ms | 63.6 ms | 两边约 208.7 MiB |
| `ts_std(returns, [5, 20, 60, 120])` | 179.9 ms | 106.2 ms | 两边约 208.7 MiB |

真实输入、8 个算子线程，同进程交替 9 次，不含写文件。复用后少算公共输入，标准差的
每个窗口仍保有独立状态与原有更新次序。没有实现一次逐行遍历更新多个标准差窗口的
新内核：目前保留这项已证实有收益且无需改动数值状态机的方案；不能把本项描述成
标准差内核的多窗口扫描融合。

验证：每个保存信号与原独立求值逐字节相等；同表达式不同配置只求值一次，进度顺序不变。
把第二个窗口的结果替换成第一个窗口，新增的保存信号对照立即失败。平台最终全部落盘
数组及原始摘要 JSON 另行核对。复跑：`python -m bench.platform.evaluation -o .cache/groupbt-fusion/evaluation.json`。
