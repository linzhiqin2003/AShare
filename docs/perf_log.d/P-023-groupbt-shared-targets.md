# P-023 多变体共享逐日目标和共同账本

- 提交：未提交（基于 `a5ea630`）。
- 手段：批量计算。`panelbt.run_group_weights_batch` 在一次释放 GIL 的调用中完成多个
  调仓周期与权重组合配置。每个 64 行工作块只算一次中性化、排名、分组和价格历史。
  不同周期各有独立账本；相同周期复用共同组合，只在需要时额外算归一化权重组合。
  返回数组和可选持仓记录彼此独立。
- `groupbt.run_many` 的共享键保留信号身份、窗口、主池及子池、池起点、成交时点和限制、
  分组数、中性化、风险向量及 decay。`run` 公开签名不变。平台按同一信号文件复用输入，
  完成一个变体后就让统计与剩余回测重叠执行，不等待全部回测再做统计。

| 基准 | 分别调用 | 批量调用 |
|---|---:|---:|
| 同一信号，调仓 1/3 日 × 是否权重组合，IS 带子池，记录持仓 | 911.5 ms | 338.8 ms |

真实输入，同进程交替 9 次；两边均已共享风险均值，所以此项收益不重复计入 P-022。
计时为内核与绑定，Python 已准备的输入相同；不含表达式、统计和落盘。

验证：跨多个 64 行块和 193 行窗口，不同周期、权重组合、持仓标志逐位比较；手算均值、
独立调仓日序列和 Rust 单测共同覆盖。变异为所有账本沿用第一个周期时，对照立即失败。
平台原始 series、holdings 数组和摘要 JSON 另作端到端对照。

IS 与验证的活动因子区间不重叠，仍分别计算；价格历史分别截止于各自止日。不引入
跨窗口完整排名缓存，避免额外的大面板和未来数据越界。
复跑：`python -m bench.groupbt.ablation -o .cache/groupbt-fusion/ablation.json`。
