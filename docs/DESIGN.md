# AShare 量化研究框架 · 方案

版本 0.2（2026-11-12）。本文是实现的依据：改设计先改本文，再改代码。

## 本地研究平台（第一期）

可选的 `ashare.platform` 提供研究台和因子库，前端在 `web/`；框架不反向依赖平台。
表达式经过有资源上限的 AST 白名单解释，构造现有 DSL 节点。每个研究 tab 使用独立的
spawn 工作进程，只读、按需缓存数据字段；只开放 IS 和 VALIDATION，不开放 TEST。
tab 身份由浏览器保存并幂等恢复，数量不受进程预算限制；工作进程只在运行时创建，空闲超时回收。
运行模式可切换线程或子进程，父协调进程与子进程一起受总预算约束。同次运行按表达式摘要
只求值一次，使用验证期末截断面板，IS 取因果前缀；子进程通过只读临时 mmap 共享信号。
库内相关排除同批和扫描参数同族条目。基准指数来自本地日线，只作用于绘图和相对指标，
不进入回测配置与条目身份。界面分栏使用持久化比例，边界可拖动、双击复位。
基准目录只使用数据层公开 `Data.indexes()`（由 `catalog.BENCHMARKS` 提供名单和中文名），
不兼容旧数据层。目录保留搜索，不分页；默认上证指数缺失时回退目录首项并标示。
研究台口径下拉框提供累加、复利及各自的相对基准模式；相对模式可选多空、第 1 组或两者。
累加超额为逐日差的和，复利超额为策略净值除以基准净值再减一；时间窗内重新起算，
基准缺失日按零收益处理。回撤由展示曲线重算，基准虚线在相对模式隐藏；原始结果不变。
第 1 组序列按需独立读取，不为一条多头线下载全部分组。抽屉小图隐藏回撤轴刻度，悬停给出数值。
散点标签测量文字尺寸，避让所有点和已放置标签；没有空位时只保留悬停名称。
相对指标仅在参数组表分成「年化超额」「信息比率」两列；检验名完整换行。
收益轴下限贴近数据范围，不补整档空刻度；收益和回撤两块之间保留独立间距。
结果以 SQLite WAL 记录条目及试验，以每次试验一个 NPZ 保存原始 float64 序列。
前端传输采用按列打包的 float32 序列；计算和存档精度不降低。运行进度以有序 SSE 续传。
服务只监听回环地址，校验 Host 和写请求 Origin；视觉遵循用户指定的第二版亮色设计稿。
具体接口、语法、取舍和性能验证见 `docs/PLATFORM.md`。

第五轮增加 `rebalance=1`（逐 N 个信号日、下一日成交），非调仓日保持实际固定权重，验证窗口
独立起算；默认所有旧输出逐位不变。内核可选记录主池多空的稀疏调仓快照，平台单独存文件、
按日期读取，避免曲线接口加载持仓；以快照推导两侧连续持仓天数。调仓周期参与条目身份并支持
设置列表扫描、服务端筛选和分组。持仓页仅开放 IS/VALIDATION 的实际持仓日，支持前次调仓比较。

## 1. 目标

个人做 A 股日频/周频、纯多头的选股研究：因子挖掘与检验、多因子合成、组合回测，之后接模拟盘和实盘。

三条原则：

1. **时点正确**。任何一天用到的数据，都必须是那天真实能看到的。
2. **性能优先，用基准测试决定用什么写**。numpy 和 polars 的向量化运算已经很快，不重复造。每个计算模块先用 numpy / polars 写出向量化基线并测速；只要 Rust 实测更快，就用 Rust 写。对比数字留在仓库里，作为以后每次迭代的基线。目标是一次因子检验在百毫秒级，上千个因子的批量回测在秒级。
3. **解耦**。回测引擎和因子算子是两个独立的包，只通过数组接口被调用，不认识数据源，也不认识本项目。包里某个函数用 numpy 还是 Rust 实现，对调用方不可见。

整体结构图见 `docs/architecture.svg`。依赖方向只有一个：`ashare → panelbt, paperbroker, panelops`。三个包互不依赖，也不 import `ashare`，之间只用 numpy 数组交换数据。回测和模拟盘在 Rust 层共用 `tradecore`，保证两边的费用和规则口径一致。

统一的数据形状是**面板**：T 行（交易日，升序）× N 列（证券，含已退市），C 连续的 `float64` 或 `bool` 数组。行情、因子、掩码、权重都是这个形状，行列含义由一份主日历和一份主证券表决定。

## 3. 选型

| 环节 | 选择 | 依据 |
|---|---|---|
| 数据 | Tushare Pro 为主，BaoStock 对账 | 现有密钥实测 26 个接口通过 25 个，覆盖所需全部数据；BaoStock 免费，独立来源，用来核对 ST、停牌、退市 |
| 存储 | 原始数据 Parquet，面板 `.npy` 内存映射 | 日频数据量小，不需要数据库服务；内存映射的矩阵可以零拷贝交给 Rust |
| 表处理 | polars | Rust 内核，多线程，as-of 连接快 |
| 回测引擎 | 自研 `panelbt`（Rust 内核） | 摸底实测 Rust 比最快的 numpy 写法快 3–16 倍，见 4.5；完整的选型对比见 `SELECTION.md` |
| 模拟盘 | 自研 `paperbroker`（Rust 内核） | 与回测共用规则代码；行情用 Tushare 实时日线接口 `rt_k`，现有密钥实测三次请求取全市场，带买一卖一价量 |
| 因子算子 | 自研 `panelops` | 统一接口；逐个算子与 polars / numpy 对比，Rust 更快的就写 Rust，其余直接包一层 |
| 因子合成 | 自研滚动训练 + LightGBM | Qlib 没有 Python 3.13 的安装包，对 pandas 3 的修复未合并 |
| 组合优化 | Clarabel 直接调用（默认）；cvxpy 只作后备和参考 | 问题先换成标准锥形式再交给 Clarabel 的 Python 接口，同结构问题复用；Clarabel 报数值失败时退到 cvxpy + Clarabel 重解；`backend="rust"` 走 `portopt`（Rust 里调 Clarabel，可批量并行）；`backend="cvxpy_*"` 是用来对拍的参考实现。见 6.4 |
| 对照与对账 | alphalens-reloaded、rqalpha（仅开发依赖） | 用独立实现核对自研代码的结果 |
| 报告 | quantstats，加自己的统计检验 | 实测可用 |

没有选的，以及原因：

- **backtrader**：2023 年后停更。它是事件驱动的，每只股票每根 K 线都走一遍 Python 回调，适合单标的或几个标的的择时；5000 只股票的截面选股跑一次要按分钟到小时计。不带 A 股规则。
- **backtesting.py**：设计上一次只回测一个标的，没有组合的概念，做不了截面选股。
- **rqalpha 当主引擎**：A 股规则最全，但同样是事件驱动，批量试因子太慢；许可仅限个人非商业使用。所以只拿来对账。
- **Qlib、vnpy.alpha、zipline-reloaded**：Qlib 见上；vnpy.alpha 把涨跌停写死成 ±10%，没有最低佣金和分红，还带 1.1 GB 的界面库；zipline 不支持 pandas 3。

## 4. panelbt：回测引擎

### 4.1 定位

市场无关的截面组合模拟器，会长期使用：现在服务 A 股，以后扩展到港股和美股。输入是对齐好的面板数组和配置，输出净值、持仓和成交。不读文件，不联网。任何市场的规则都不写进内核，而是由「市场档案」换算成数组和参数传进来（见 4.7）。

它是一个独立的 Python 原生扩展包，运行依赖只有 numpy，将来可能单独开源发布，所以包里不能出现本项目的路径和假设，代码注释和文档用英文（另附中文 README）。

### 4.2 接口

```python
import panelbt as bt

market = bt.Market(
    exec_price=...,   # T×N 成交价。NaN = 当日无行情，不可交易
    close=...,        # T×N 估值价。NaN 时用最近一个有效值
    can_buy=...,      # T×N bool
    can_sell=...,     # T×N bool
    volume=None,      # T×N 成交量（股），用于成交量占比上限
    split=None,       # T×N 除权日的股数乘数（10 送 5 = 1.5），无则为 1
    cash_div=None,    # T×N 除息日每股派现
    delist=None,      # T×N bool，退市处理日
)
costs = bt.Costs(commission_rate=2.5e-4, commission_min=5.0,
                 tax_sell=..., tax_buy=0.0,   # 标量或长度 T 的数组
                 fee_rate_buy=1e-5, fee_rate_sell=1e-5, slippage=5e-4)
config = bt.Config(initial_cash=1e7, min_qty=..., qty_step=...,   # 标量或长度 N
                   max_participation=0.1, carry_blocked=True,
                   delist_recovery=1.0, cash_buffer=0.0, record_trades=False)

targets = bt.Targets.from_dense(weights)       # 稀疏的目标权重
result = bt.run(market, targets, costs, config)
results = bt.run_batch(market, [targets_1, targets_2, ...], costs, config, threads=0)
```

目标权重用稀疏结构传入：调仓日下标、每个调仓日的（列号，权重）列表。原因是批量回测时，一千组稠密的 T×N 权重矩阵放不进内存。`Targets.from_dense` 约定：整行 NaN 表示当日不调仓，其余行里的 NaN 当作 0。支持 `kind="shares"` 直接给目标股数。负目标需要 `Config(margin=MarginModel(allow_short=True, ...))`；只做多现金账户仍拒绝负目标和权重和超过 1 的计划。

`result` 包含逐日的净值、现金、换手、分项成本（佣金、税、其他费用、滑点、冲击）、受限未成交的笔数，以及可选的持仓和成交明细。

### 4.3 时间约定

`targets` 里第 t 行是**第 t 日成交时**要达到的目标。引擎不做任何移位。用 t−1 日收盘的信息算信号、在 t 日成交，这个错位由调用方负责，项目里只在 `ashare.backtest` 做一次：

```python
from ashare.backtest import execution_targets, execution_days
plan = execution_targets(signal)                 # 稠密 T×N，行 = 信号日
plan = execution_targets(picks, t=T)             # panelops.targets 等稀疏目标，行 = 信号日
days = execution_days(signal_days, T)            # 只要成交日行号（如交给 optimize_sequence）
```

- 行号就是交易日：周末、节假日不在面板里，周五收盘的信号落到下一个交易日那一行。`lag` 默认 1，必须是正整数；信号只用开盘前已知信息、本来就不需要错位的，直接构造 `panelbt.Targets`。
- 末尾 `lag` 行的信号在面板里没有成交日：默认丢掉，`tail="error"` 时报错。
- 成交日停牌或涨跌停：错位不管，引擎按 `can_buy`/`can_sell` 拦下，`carry_blocked=True`（默认）在之后每天重试直到下一个调仓行。

第 t 日的处理顺序：

第二轮增加了最先入账的外部资金流、税后分红、收盘借券/融资费用和自有闲置现金利息；多空账户先减风险，再同比例缩放开仓篮子。收盘追保在下一行强平，详见包内 SPEC。以下是默认现金账户的基础顺序：

1. 公司行为：先按除权前股数派现，再按 `split` 调整股数。
2. 退市：持仓按最近有效收盘价 × `delist_recovery` 变现，并记录。
3. 确定目标：当日有新目标就采用，并清掉之前没完成的；没有新目标且 `carry_blocked` 打开时，只对之前因受限没成交的证券继续尝试。
4. 用成交价给组合估值，算出每只证券的目标股数（向下取整到申报单位）。
5. 先卖后买。卖出受 `can_sell` 和成交量占比限制；目标为 0 时可以把零股一次卖完。
6. 买入受 `can_buy`、成交量占比和现金限制。现金不够时所有买单同比例缩减，再向下取整，保证现金不为负。
7. 用收盘价估值，得到当日净值。

日频下每天只成交一次，当天买入的不会当天卖出，T+1 自然满足。

### 4.4 A 股规则（`panelbt.markets.ASHARE`）

- 可买可卖：停牌不可买卖；成交价等于涨停价不可买；成交价等于跌停价不可卖；全天一字板按最高价等于最低价判断。
- 印花税和过户费：`ASHARE.costs(dates)` 按日期展开，覆盖 2005-01-24 起的全部历史（面板从 2007-01-04 开始），不用再手填。每一条的生效日期和依据见 [ASHARE_FEES.md](ASHARE_FEES.md)：印花税 2005-01-24 双边 0.1%、2007-05-30 双边 0.3%、2008-04-24 双边 0.1%、2008-09-19 起卖出单边 0.1%、2023-08-28 起 0.05%；过户费 2015-08-01 起两市按成交金额 0.02‰、2022-04-29 起 0.01‰。2015 年以前沪市按面值、深市按金额，引擎的费率只能按日期不能按证券区分，所以两种同时计入（保守，偏高），这几条标「未核实」。
- 全区间固定费率要显式写：`panelbt.Costs(tax_sell=0.001, fee_rate_buy=1e-5, fee_rate_sell=1e-5, …)`，或在 `ASHARE.costs` 里把四个分量都覆盖。覆盖某个方向的过户费（按金额或按股）时，同方向的另一种写法自动清零，同一笔费用不会算两次。佣金由券商定，调用方给。
- 申报单位：主板和创业板 100 股的整数倍；科创板 200 股起、1 股递增；北交所 100 股起、1 股递增。
- 佣金最低 5 元；过户费双边。
- 从面板一步建行情：`ashare.backtest.market_from_panel(data, start, end, exec="open")`（见 6.1）。

### 4.5 性能目标与实现语言

动手前先做摸底：把「估值 + 调仓成交 + 费用」这段核心循环分别用三种方式写出最小版本，在同样的输入上确认结果一致后测速。

- numpy 全截面向量化：每天对整行做向量运算。
- numpy 稀疏：每天只处理有持仓或有目标的下标。
- Rust。

判定规则：摸底时事先定的是「单次回测或批量吞吐有一项快 3 倍以上才用 Rust」；2026-11-12 起放宽为只要 Rust 实测更快就用 Rust。规则换算、输入校验、稀疏转换和结果后处理是整块的逐元素运算，先用 numpy 写，实测 Rust 更快再换。摸底的数字和脚本留档。

目标值：在本机（M5 Pro，15 核）上，T = 4000、N = 5500：

- 单次回测（持仓约 100 只，月度调仓）：30 ms 以内。
- 1000 组目标批量并行：5 秒以内。
- 结果与线程数无关，逐位一致。

这些是目标值，实现后用基准测试实测，把实测数字写回本节。

#### 步骤 1 实测（2026-11-12）

测试条件：macOS 26.6 / M5 Pro 15 核，Python 3.13.13、NumPy 2.5.4（Accelerate）、Rust 1.95.0，release + LTO + codegen-units=1。T=4000、N=5500，月度为每 21 日。下表单次与批量均三次中位数；批量 K=1000，numpy 用筛选后最快的 15 进程 spawn+mmap，Rust 用 rayon。全部版本先逐日净值对拍，最大单次差 8.44e-15。

| 持仓目标/调仓 | numpy 全截面 ms | numpy 稀疏 ms | Rust ms | 单次加速 | numpy 批量 s | Rust 批量 s | 批量加速 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 100/月度（21 日） | 16.106 | 8.733 | 0.539 | 16.21× | 0.906 | 0.115 | 7.84× |
| 1000/月度（21 日） | 16.182 | 27.386 | 5.523 | 2.93× | 1.846 | 0.490 | 3.77× |
| 100/每日 | 238.454 | 86.383 | 5.683 | 15.20× | 9.480 | 0.584 | 16.22× |
| 1000/每日 | 246.743 | 311.035 | 60.951 | 4.05× | 27.057 | 6.009 | 4.50× |

判定：使用 Rust 内核。单次最快 numpy 在 100/月度与 100/每日是稀疏版，在 1000/月度与 1000/每日是全截面版。1000/月度单次只有 2.93×，没有夸报成 >3×；该场景批量仍为 3.77×。总体严格满足“任一单次或批量超过 3×”规则。

NumPy 全截面的连续 dot 很高效，H=1000 时比高级索引/union1d 的稀疏版更快；H=100 时稀疏减少访存。Rust 省掉逐日 Python 调度、临时数组与索引构造，活动列循环在寄存器/缓存中完成。线程池的众多小 numpy 调用争抢 GIL，增加线程反而变慢；进程池共享只读 mmap、避免复制市场，15 进程胜出。Rayon 共享借用市场且无进程 IPC，策略内部运算顺序不变。

### 4.8 做空与保证金账户

持仓带正负号，负数是空头。只做多的现金账户是保证金账户的一个特例，默认行为不变。

- 账户量：现金（含融券卖出所得）、多头市值、空头市值，权益 = 现金 + 多头市值 − 空头市值。
- 保证金模型：多头和空头各有开仓保证金率和维持保证金率，可以随日期变化；是否允许借钱买入；融券所得能否挪用；融资利率和融券费率。
- 可融券标的用一张掩码面板给出。新开空头需要标的可融且可卖，平空需要可买。
- 先成交降低风险的订单，再成交增加风险的订单；保证金或现金不够时，增加风险的订单同比例缩减。
- 空头在除息日付出分红；送转同样作用在空头股数上。
- 收盘后不满足维持保证金即为追保。默认在下一个交易日把全部仓位同比例缩减到满足开仓保证金；权益小于等于 0 记为爆仓，平掉全部仓位后停止交易。也可以设成只记录不干预。
- A 股融券的监管参数（保证金比例、维持担保比例、折算率）调整过多次，默认值必须有公开规则作依据并注明生效日期，核实不了的由调用方显式传入。融券卖出的报价限制在日频下无法模拟。

### 4.11 期货对冲腿

A 股个股融券很受限，实际对冲靠股指期货，所以内核要支持期货这类品种。放在步骤 1c。

- 每只证券有一个品种类型：现货（全额交收）或期货（逐日结算），期货另有合约乘数和保证金率（可随日期变化，用来表达交割月上调保证金）。
- 期货开仓不付本金，只付费用并占用保证金；每天按结算价把盈亏计入现金。
- 到期按交割结算价平仓。每个合约是面板里的一列，换月由目标给出（近月权重降为 0，远月建仓）；另提供一个按规则生成换月目标的辅助函数。
- 对冲的用法：目标里给期货列一个负的名义权重；另提供辅助函数，按股票组合的市值或贝塔算出对冲手数。
- 期货的保证金占用并入 4.8 的保证金约束；追保和强平沿用同一套处理。
- 数据来自 Tushare 的期货合约信息和日线（含结算价、合约乘数、到期日）。贴水成本不需要单独建模，它体现在合约价格向现货收敛的过程里。

实现说明（步骤 1c，2026-11-12；完整口径见 `packages/panelbt/SPEC.md` 的 Futures 一节）：

- 只有一个逐日账户循环，按「现金特化 / 保证金账户」×「有无期货列」编译成四份；现货规则在两种构建里是同一段源码。**加一列从不交易的期货，现货结果逐位不变**，是常驻性质测试（`test/test_futures_invariance.py`）。现金特化只由账户条款决定，挂期货不会把现金账户换成保证金路径。
- 目标按名义权重换手数：`权重 × 交易前权益 × (1 − 现金缓冲) / (执行价 × 乘数)` 向零取整；非零权重取整为 0 手只计数（`futures_rounded_to_zero`）。期货空头不需要融券权限。未持有且当天无执行价的合约用上一行已公布的结算价定手数（与现货用上一收盘价对称）。
- 逐日结算：成交时只按成交价对结算基准实现已平部分的盈亏并扣手续费；收盘按 `手数 × 乘数 × (今结 − 基准)` 入现金，基准换成今结。期货不计入现货市值，权益仍是现金 + 现货多头 − 现货空头。
- 保证金占用 `|手数| × 乘数 × 价 × 当日保证金率`，并入开仓与维持约束；可用自有现金 = 现金 − 受限空头 − 占用，提款、闲置利息、融资利息都用它。
- 先减仓后开仓，期货减仓在前。**期货减仓和平仓不受「自有现金不得转负」截断**，也不受现金账户卖出检查限制：减仓只释放保证金，亏损无论平不平都会在收盘入账；手续费造成的负现金按欠款保留并计融资利息。开仓和加仓受资金与保证金约束：保证金账户里期货与现货开仓同一个缩放因子（期货在前做前缀检查）；现金账户先按「占用 ≤ 现金」缩放期货开仓，现货再用「现金 − 占用」走原来的现金账户算法。现金账户持有过合约之后才记追保、强平和破产，追保条件是占用 > 权益。
- 到期行的 `settlement` 必须是交割结算价（中金所股指期货为最后两小时指数算术平均）；到期当天可以先按目标成交（含开仓），收盘按交割结算价现金交割并收交割费，停牌也照常交割。次日起非零目标只计入 `n_expired_target`，强平日被强平方案替换的请求行里的过期目标同样计数。
- 辅助函数：`roll_targets` 在 `到期 − roll_days` 行换到下一合约，只向后换，合约间隔小于 roll_days 时持有最远的未到期合约到期；`hedge_contracts` 向零取整（与内核一致），正敞口取整为 0 手时发出 `HedgeRoundingWarning`。期货费率只接受标量、(1, N)、(T, 1) 和 T×N，一维数组在 T=N 时有歧义，直接报错。

### 4.12 逐日步进接口

`bt.run` 只吃预先算好的目标，表达不了「目标取决于账户走到今天的状态」的策略。`bt.Simulator` 把同一个逐日循环拆成「状态 + 推进一天」，由调用方一天一天推：

```python
sim = bt.Simulator(market, costs, config)          # kind="weights" 或 "shares"
for t in range(sim.n_days):
    target = strategy(t, sim.state)                # None / 长度 N 的一行 / (列号, 值)
    sim.step(target)                               # 返回当日指标（DayRecord）
result = sim.result()                              # 与 bt.run 同一种 Result
```

实现：内核的逐日循环拆成两段，`Core::open`（当日外部资金流、公司行为、退市）和 `Core::trade`（确定目标、成交、收盘估值）。`bt.run` 就是对每一行依次调用这两段，编译器内联后与原来的单一循环等价；`Simulator.step` 调用 `trade(t)` 后立刻调用 `open(t+1)`。持仓成本、入场日这些只有步进接口需要的记账由编译期开关 `T` 打开，`bt.run` 的构建里不存在。改动前后的 `bt.run` 在随机输入（现金、保证金、两种期货）上结果逐位相同；配对计时（新旧两份 LTO 构建交替跑）新版不慢。

时间约定不变：第 t 步给的目标是第 t 日成交时要达到的目标，引擎不移位。第 t 步之前读到的 `sim.state` 只含第 t 日成交前就知道的东西：

| 字段 | 什么时点可知 |
|---|---|
| `day` | 下一步要执行的行号 |
| `equity` | 第 t−1 日收盘权益（第 0 行为初始资金） |
| `cash` | 第 t−1 日收盘现金，加上第 t 日开盘前入账的外部资金流、税后分红、退市变现 |
| `shares` | 第 t−1 日收盘持仓，按第 t 日的送转调整、扣掉第 t 日退市的列 |
| `cost` | 持仓的数量加权原始成交价（不含滑点、冲击和费用），按送转调整，分红不调整；空仓为 0 |
| `entry_day` | 当前持仓的建仓行号（加仓不变，反手重置）；空仓为 −1 |
| `last` | 持有列的估值价：截至 t−1 的最近有效收盘价，按第 t 日分红、送转调整 |
| `futures_basis` | 期货持仓的结算基准（上一结算价） |
| `pending_cols/pending_targets` | 因价格、掩码或成交量受限、仍在顺延的订单 |
| `margin_call` / `bankrupt` | 第 t−1 日收盘追保（第 t 日为强平日）/ 已爆仓 |

第 t 日的公司行为、外部资金流和退市属于开盘前已公布的信息，所以已经反映在第 t 步之前的状态里；第 t 日的价格、掩码、成交量、结算价不会进入。防前视测试改动第 t 日及以后的全部行情（以及 t 日以后的公司行为和退市），断言第 0 到 t 步之前的状态逐位不变。

数组是零拷贝的实时视图，随步进变化，要保留历史就自己 `copy()`。视图建在只读缓冲区上，numpy 不允许把它改回可写，经由公开接口改不了模拟状态；绕过只读保护（例如顺着视图的 `.base` 链拿到底层数组）写入属于未定义行为。期货列不维护 `cost` 和 `entry_day`：不论持仓多少，读出来恒为 0 和 −1，期货持仓看 `shares`。每一步：行情面板按引用重新借用（不拷贝），状态数组放在 numpy 里由内核直接写；没有与证券数成正比的 Python 层拷贝。传稠密的一行目标本身是 O(N)，大截面建议传 `(列号, 值)`。

存档与恢复：`sim.snapshot()` 返回字节串（版本化的二进制格式，第 2 版，不用 pickle），`bt.Simulator.restore(blob, market, costs, config, kind=...)` 恢复后继续跑与不中断逐位相同。字节串末尾是前面全部字节的 CRC-32，恢复时先校验，截断、多出字节、任何一位被改都报错。字节串里还带指纹：行列数、账户类型、目标类型、全部费用和配置向量与标量、规则的全部标量项，以及止损、止盈、移动止损参数数组的每一格；不一致就拒绝。行情面板（价格、掩码、成交量、公司行为、开高低、期货面板）也进指纹：默认 `fingerprint="sample"` 对每张面板取形状、dtype、首行、末行和固定步长抽样的约 64K 格做摘要，在 `Simulator` 构造时算一次（4000×5500 的行情约 5–7 ms，负载约 10），只改了大面板里没被抽到的格子查不出来；`fingerprint="full"` 对每一格做哈希（同样的行情约 0.8–1.2 s）。恢复时要用存档时同样的选项。`bt.run` 不算摘要。第 1 版格式的存档直接报「format version 1 is no longer supported」。恢复失败不会留下加载到一半的对象。

多线程：`step` 期间释放 GIL，多个 `Simulator` 可以各自在不同线程里推进，结果与顺序执行逐位相同。同一个 `Simulator` 不能被两个线程同时操作：另一个线程在 `step` 进行时再调 `step` 或读 `state`，会抛 `RuntimeError`（状态不受影响）。不提供「批量 + Python 回调」入口：回调要拿 GIL，并行不起来。

每步固定开销（`bench/step_overhead.py`，T=4000，机器负载约 7，各五次取中位数）：

| 场景 | 每行 µs |
|---|---:|
| `Simulator`，每步读一次 `state`、每 21 行换一次目标，N=1 | 4.5 |
| 同上，N=5500 | 4.6 |
| 只调 `step()`，N=1 / N=5500 | 3.1 / 3.3 |
| `bt.run` 跑同一个计划，N=1 | 0.04 |
| backtrader 1.9.78，preload + runonce、无 observer，`next` 里读现金和持仓、每 21 根 K 线 `order_target_percent` | 29.5 |

开销与证券数无关，约为 backtrader 每根 K 线开销的六分之一；主要花在 Python 调用和每步重新借用行情面板上。能写成固定规则的状态逻辑用 4.13 的声明式规则，在内核里跑，`bt.run` 和 `bt.run_batch` 也能用。

### 4.13 声明式退出规则与限价目标

止损、止盈、移动止损、最长持有期和限价目标是固定模式，不值得每天回到 Python。它们写成配置，由内核执行，`bt.run`、`bt.run_batch`、`bt.Simulator` 都能用：

```python
market = bt.Market(exec_price, close, can_buy, can_sell, ..., open=o, high=h, low=l)
rules = bt.Rules(fill_time="open", stop_loss=0.08, take_profit=0.3,
                 trailing_stop=0.12, max_hold=20)        # 百分比可为标量、长度 N、T×N
result = bt.run(market, bt.Targets.from_dense(w, limits=lim), costs,
                bt.Config(rules=rules, record_trades=True))
result.diagnostics["stop_loss"]; result.trades[k].reason   # TradeReason
```

精确规格在 `packages/panelbt/SPEC.md` 的「Declarative exit rules and limit targets」一节，纯 Python 参考实现是 `panelbt/reference_rules.py`。原则是**宁可悲观**：日线只给开高低收，凡是取决于日内先后顺序的情形，都按对策略不利的一边算。

参考实现在原参考实现上派生，规则部分与 `rules.rs` 结构相近（同样的判断顺序和二分），不是独立写的，所以两边对拍不能排除两边一起错。兜底是 `test/test_exit_rules_hand.py`：独立复核时照 SPEC 手算的一组小例子（多空止损、跳空、双触、移动止损、入场当天、卖出锁定、受限重试、两种冷却、限价各情形、持有期），内核、参考实现、手算期望值三方逐项比成交行、价格、原因、数量和计数。

**十个语义问题的答案与理由**

1. **触发与成交价**：多头当日最低价触及止损线（空头最高价）即触发；开盘就已越过（跳空）按开盘价成交，否则按触发线成交，再叠加滑点和冲击。理由：开盘价是当天第一个价，跳空时不可能在线上成交；不跳空时线价是最好情况下能拿到的价，滑点照常扣。由此触发成交的原始价一定落在 [最低, 最高] 内（有性质测试）。
2. **同一根 K 线止损止盈都触及**：默认 `both_hit="stop"`，按止损线成交；`"target"` 可切到止盈。理由：先后不可知，取不利一边。跳空优先于此：开盘已过止盈线就按开盘价止盈（开盘价是确定发生的）。
3. **移动止损的最高价**：触发线 = 截至上一交易日收盘的最高价（空头最低价）×(1 ∓ 回撤)。当日最高价在收盘后才并入。建仓当天（「新仓」，见下）的价格区间不并入，起点是建仓原始价。理由：当日最高价可能出现在最低价之后，用它抬高当日触发线等于日内前视；建仓当天买入之前的那段区间不属于持仓。
4. **持仓成本**：数量加权的原始成交价（不含滑点、冲击、费用）；加仓重新加权，减仓不变，新开或反手重置；送转按比例除；现金分红默认不调整（除息造成的下跌会推近多头止损线，这是有意的），`dividend_adjusts_cost=True` 时成本和最高价都减去每股分红（下限 0）。
5. **与交易限制的关系**：规则平仓是一笔普通成交：卖出要 `can_sell`、买回要 `can_buy`；成交量占比上限把当天该列已成交的数量算进去；按平仓口径取整（零股可一次清掉）；`sell_lock=True`（默认，A 股 T+1）时当天买入的股份当天不能被规则或限价卖出；现金账户沿用原有的费用检查，保证金账户（无融资时）把平仓削到自有现金不为负。没做完的平仓记为「待平」，之后每一行在一切新判断之前按当天的 `exec_price`（不是原触发价）重试，原因不变，直到仓位归零（包括被强平、退市等其他途径归零）。每个仍待平的行计一次 `rule_deferred`。`sell_lock` 对所有市场默认开启（偏悲观）；没有当日卖出限制的市场要显式设为 False。默认值没有改成跟随市场档案：档案在 `panelbt.markets` 里，不在这次改动范围内，`Market` 也不带档案。
6. **与当天调仓的先后**：必填 `fill_time` 说明 `exec_price` 在一天中的位置。`"open"`：先按开盘价调仓，再看当天区间（开盘价成交的新仓看到了整天的区间，当天就参与判断）。`"close"`：先判规则再按收盘价调仓。`"average"`（均价、VWAP 一类）按 `"close"` 处理，并且当天以均价买入的仓位当天不参与判断：买入之前那段区间分不出来，若参与判断，止盈可能用到买入之前出现的最高价。强平日（追保、爆仓）跳过日内阶段：待平的等着，限价单不成交。当天有规则成交、待平或限价目标的列，当天的普通调仓跳过这一列（规则或限价优先）。
7. **规则退出之后**：默认（`cooldown=None`）在之后某一行给出新目标行之前，不再开仓这一列（普通、顺延、限价、做多做空都算）；退出当天的目标行不算。`cooldown=k` 改为退出后 k 行之内不开仓，期间的目标行也不解除。每次被挡计 `reentry_blocked`。理由：现行目标仍然要求持有，不挡的话第二天就买回来了，止损形同虚设。
8. **限价目标**：`Targets(..., limits=...)` 给每个条目一个限价（NaN 是普通目标），需要配 `Rules`（至少给 `fill_time`）。默认 `limit_fill="cross"`：买单要求当天最低价**严格低于**限价才成交，卖单要求最高价严格高于限价；`"touch"`（最低价等于限价也算）是显式选项。成交价：买 min(开盘, 限价)，卖 max(开盘, 限价)（跳空穿过按开盘价）。理由是独立复核在沪深 300 成分 2007–2026 上的实测：限价取前收 ×(1∓1%~3%)，只碰到、没穿过的日子只占限价成交的 4%–6%，却贡献了限价买入当日收益（收盘 / 成交价 − 1）的 55%–65%，平均 +1.4%–1.8%，穿过的只有约 +0.06%；挂在当天极值上的单很可能没成交，算成交会明显高估低吸类策略。面板没有最小报价单位，所以用严格不等号代替「穿过至少一个价位」。下单量按日内阶段开始时的 `E = 现金 + Σ持仓 × 估值价`（不用当天价格）和限价换算。现金不够（含佣金）时和普通买入一样削到买得起为止，计 `cash_scaled`（保证金账户计 `margin_scaled`）。削完缺口不超过一手（分数股时不超过这张单自己的滑点、冲击和费用折合的数量）才算完成，这样不会出现「只差佣金的零头天天去补」；缺口更大或一股没买到就不算完成。默认当天有效（`limit_valid="day"`），可选 `"until_next"` 一直有效到成交或被下一个目标行替换；没做满（资金缺口超过上面的额度，或掩码、成交量上限、阻挡）时计 `limit_blocked`，`until_next` 保留剩余部分、之后各行照同样的规则再试（等现金进账是常见用法），当天有效的单丢弃剩余。计数 `limit_filled`（按成交笔数，先减仓再反向开仓算两笔）、`limit_unfilled`（价格没到）、`limit_blocked`（到了但超出上述额度没做满）。`cash_scaled` 按行计：同一行里普通买入、限价单或两者都被现金削减，只计一次；没有限价单时与原来的计数相同。`margin_scaled` 上，限价单只在这一行还没计过时计一次，普通保证金篮子的计数不变。限价开的仓当天是新仓。
9. **空头和期货**：空头完全对称（止损线在成本之上、止盈线在成本之下，`take_profit >= 1` 时空头没有止盈）。期货列暂不支持，配了规则或限价且市场里有期货列时输入检查直接拒绝（`run`、`run_batch`、`Simulator` 都是）。理由：期货的成本口径要换成结算价、保证金和到期移仓也要一并定义，留作后续。
10. **诊断**：`Result.diagnostics` 多出 `stop_loss`、`take_profit`、`trailing_stop`、`max_hold`（触发次数）、`rule_deferred`、`reentry_blocked`、`limit_filled`、`limit_unfilled`、`limit_blocked`；`record_trades=True` 时 `Trade.reason` 是 `TradeReason`（`REBALANCE`、`STOP_LOSS`、`TAKE_PROFIT`、`TRAILING_STOP`、`MAX_HOLD`、`LIMIT`）。它是 `IntEnum`，`astuple(trade)` 仍是纯数字。

**实现**：内核加第三个编译期开关 `T`（持仓记账 + 规则），与 `CLASSIC`、`FUT` 并列。不配规则也没有限价目标时，`run` 走 `T=false` 的特化，规则代码和成本、最高价、建仓日这些数组都不存在。规则逻辑在 `crates/panelbt-core/src/rules.rs`；`Simulator` 一直用 `T=true`，配规则时与 `run` 逐位相同（常驻测试，含中途存档恢复）。

**期货列**（2026-11-13 起退出规则已放开，只作用于现货列，见 4.15；以下是当时的记录）：市场里有期货列时，规则和限价目标整体拒绝（`run`、`run_batch`、`Simulator` 都是）。「规则只作用于现货列」暂未做，卡在两处：限价开仓和平仓削减的资金判断（`rules.rs` 的 `marked_account`/`projected_at`）只算现货的现金和保证金，不含期货占用的保证金，混合账户里会超买；参考实现的规则部分也没有期货路径，要一起补并对拍。留作下一步。

**近似在哪里，什么时候偏差大**

日线只知道开、高、低、收四个价，不知道它们在日内出现的先后。所有规则回测都是在上面那套悲观假设下的近似：

- 同一天碰到两条线（止损和止盈、或限价和止损）时，真实结果取决于先碰哪条，这里一律取不利的；日内振幅大于两条线间距的日子越多，回测越偏保守。
- 触发线按线价成交，假设触及时能在线上成交到；真实盘中触及后的成交价往往更差（尤其是快速下跌、流动性差时），只有滑点和冲击参数在兜。触发线贴着价格（止损比例小于日内正常波动）时，日线回测会把大量「盘中刺穿又收回」的日子都算成止损，并按线价成交，与分钟级回测差别很大。
- 移动止损只用到前一天的最高价，比盘中逐笔跟踪的移动止损反应慢一天，单日大涨后回落的情形会少触发。
- `fill_time="average"` 当天新买的仓位不判断，真实盘中如果在买入之后跌破止损线，会晚一天才处理。
- 限价单默认要求价格穿过限价；即使穿过，真实盘中也可能因排队没成交，这一点没有模拟。改用 `limit_fill="touch"` 会明显偏乐观（见第 8 条的数字）。
- 同一天里的资金先后有两处轻微偏乐观：日内阶段先规则平仓、后限价单，止损回笼的现金可以给同一天的限价买入用，而真实盘中限价单可能比止损先成交；`fill_time="average"`（以及 `"close"`）时，规则平仓回笼的现金可以给当天按均价（收盘价）成交的调仓用，而均价成交贯穿全天、平仓可能在尾盘。资金紧的账户上影响才明显。
- `Market(validate=False)` 不检查 `low <= open <= high`；违反的行上「触发成交价在 [最低, 最高] 内」不再成立。

日内波动大的品种（小盘股、题材股、高波动期）和止损线设得很紧的策略，近似误差最大；需要精确时应改用分钟级数据。

### 4.14 纯期货组合回测

4.11 的期货是「股票组合上的一条对冲腿」。这一节把期货当成独立的资产：面板里全部是期货列（也可以混现货列），按具体合约持仓、按结算价逐日盯市，保证金和费用逐合约逐日取自输入，结果是同一种 `Result`。面向使用者的说明、手工核对和例子见 [FUTURES_BACKTEST.md](FUTURES_BACKTEST.md)，引擎口径见 SPEC 的「Stand-alone futures portfolios」。

**内核不改**。4.11 的逐日账户循环已经能跑全是期货列的市场（现金账户特化下：期货开仓先按「占用 ≤ 现金」缩放，收盘「占用 > 权益」追保，下一行同比例强平）。缺的都是输入层面的事，所以做成 `panelbt.FuturesBook`（纯 NumPy）：

- 账户条款 `FuturesAccount(margin_add, margin_scale, fee_scale)`：实际保证金率 = 交易所 × margin_scale + margin_add，手续费 × fee_scale；引擎默认中性，境内预设 `ashare.backtest.futures.CN_RETAIL`（+5 个百分点、× 3，估计值，取期货公司公示标准的悲观端，可覆盖，待用户确认）。
- 三种目标：手数、名义 / 权益、保证金 / 权益（按当行实际保证金率折成名义）。
- 合约的结束行 = min(最后交易行, 个人最后持仓行 + 1)。结束行照常可以成交，收盘仍持有的由内核的到期步骤了结：现金交割合约在自己的最后交易日按交割结算价、收交割费；其余（实物交割的最后交易日、个人持仓期限、交易单位分界）按当行结算价强平，「交割费」一栏填成手续费率 + 滑点，等于按结算价平仓并计一次滑点。
- 涨跌停：涨跌停价 `limit_up`/`limit_down` 或掩码 `no_buy`/`no_sell`；数据层没有涨跌停价时用一字板推断（`futures_portfolio` 默认开：开 = 高 = 低且有成交，按相对前结算的方向拒绝买或卖，等于前结算不拒绝）。全库成交量 > 0 的 1,793,242 行里一字行 101,883 行，89% 幅度不到 3%，多是冷门合约的普通成交，拒绝它们偏悲观；而开在停板、盘中又打开的主力合约行（2012 年后约 173 行涨停、151 行跌停）推断全部放行，在这类行上偏乐观。总的偏向取决于策略，可靠的做法是数据层补上涨跌停价后传价格、关掉推断（FUTURES_BACKTEST 第 5 条）。个人客户持仓期限里大商所、郑商所、广期所、上期所的规则未核实。
- 负价：期货列的结算价、成交价、收盘价、开盘价为 0 或负数一律报错，与 `validate` 无关（否则保证金变负、亏损不触发追保）；WTI 2020-04-20 这类行情列为后续工作。
- 缺失的保证金、手续费：交易窗口内的缺值默认报错，`missing="previous"`（只向前填）或给一个数。

`ashare.backtest.futures`：

- `futures_portfolio(fut, products, ...)`：用数据层的换月规则（第 t 行只用第 t−1 行的指标）定每个品种每行持有的合约，个人持仓期限前提前换到下一个合约（只向后换），只用这些合约建 `FuturesBook`；`signal_prices` 是同一规则下的比例后复权连续价格，只算信号。`run()` 用步进接口逐行推进：调用方给目标的行整体调仓；品种在目标行还没有合约时目标挂起，落到合约上那一行按原目标开仓；只有换月的行只动换月的品种（平旧开新、保持手数，乘数不同时保持手数 × 乘数），其他品种不成交；被结束行了结的持仓（交易单位分界）按同一规则接到下一个合约；追保强平行丢掉所有等待中的开仓。实现在 `ashare/backtest/futures_step.py`，自己不记发出过的单子，每次从引擎读还在顺延的单子，不变量写在文件开头并有随机性质测试守住。内核的目标行没有「这一列不动」的写法，所以逐行读持仓，单次约 120 ms（整份目标交给内核约 5 ms）。个人持仓期限按数据层的交易所日历（含未来日期）推算，可设提前量。
- 个人客户最后持仓日：SC 最后交易日前第 8 个交易日收市后为 0，LU/NR 前第 5 个（官方）；大商所、郑商所、广期所交割月前一个月最后一个交易日收市后为 0（旁证，未核实）；上期所和能源中心其他品种按同一条处理（推断，未核实）；两类规则同一口径（「某天收市后为 0」，最后过夜日是它的前一个交易日）；样本截在合约到期之前时日历用工作日补齐；EC、中金所不限制。
- `book_from_table(daily, contracts, params)`：外部行情的入口，列名同 `futures_schema`（第二件，见 FUTURES_BACKTEST「外部行情的入口」）。

### 4.15 混合面板里的退出规则

4.13 原来在市场里有期货列时整体拒绝规则，「股票多头 + 股指期货对冲」的组合用不了止损。现在放开**退出规则**（止损、止盈、移动止损、最长持有期，只减仓），限价目标继续拒绝。口径见 SPEC「Exit rules in mixed panels」。

- **只作用于现货列**：标量百分比和 `max_hold` 只施加给现货列；每只证券或 T×N 的百分比在期货列上必须是 NaN（「不设」），否则输入检查报错。规则阶段只遍历现货持仓（`st.held`），期货持仓在 `book.held`，从不判断，也不记成本、建仓日、最高价。
- **资金**：保证金账户里规则平仓（主要是止损平空）的「自有现金不得转负」削减改为扣掉当时占用的期货保证金：`close`/`average` 时点（调仓之前）用开盘前的占用（前一结算价 × 当日保证金率），`open` 时点（调仓之后）用调仓后的占用（当行成交的合约按成交价）。现金账户的规则卖出沿用原来的费用检查，与普通现货卖出一致。
- **内核**：`run` 多了「有期货 + 记账」的两份特化（现金 / 保证金账户），只在既有期货列又配了规则时使用；`rules::intraday`、`reduce` 多一个参数 `fm`（期货占用，没有期货时为 0，`x − 0.0` 逐位不变）。不配规则或没有期货列时走的还是原来的四份构建。`Simulator` 一直是记账构建，本来就能编译这条路径。
- **限价目标继续拒绝**：限价开仓的资金判断（`rules.rs` 的 `marked_account`/`projected_at`）只算现货的现金和保证金，没有算期货保证金，混合账户里会超买。`run`、`run_batch`（Python 检查和绑定层双重检查）、`Simulator.step` 都拒绝。
- **参考实现**：`panelbt/reference_rules_futures.py` 把规则参考实现（`reference_rules.RulesEngine`）和混合账户参考实现（`reference_futures.MixedEngine`）组合起来，日内顺序照内核：开盘前事项 → 规则（close/average）→ 期货减仓 → 现货 → 开仓 → 规则（open）→ 现货收盘 → 期货结算与到期。

**验证**：随机对拍 500 组（规则语料加 1–2 个期货列，对冲权重最大到 6 倍名义，现金和保证金账户、三种时点），断言四种规则、待平、冷却、期货成交、期货强平都出现过，且规则从不碰期货列；步进（含中途存档恢复）与 `run` 逐位相同；加一列从不交易的期货后，现货规则结果逐位不变；两个手算例子：保证金账户止损平空被期货保证金削减（`close` 时点用开盘前占用、`open` 时点用调仓后的占用，后者对拍时开盘前占用会给出完全平仓）；输入错误。现有测试里只改了一条：`test_exit_rules.py::test_input_errors` 原来断言「有期货列就拒绝规则」，改为断言限价目标和期货列上的规则百分比被拒绝。变异检查（`bench/mutations_rules_futures.py`，结果在 `bench/results/mutations_rules_futures.json`）：削减不扣期货保证金、`close` 时点看不到保证金、`open` 时点用交易前保证金、期货加规则走不记账的构建、期货列上的百分比不报错、步进接口接受限价，六处都被测试抓到。

**性能**：新旧两份 LTO 构建交替计时（`bench/pair.py` 与新增的 `bench/pair_futures.py`，基准为主干 d791a69，负载 8–11），结果逐位相同，比值见下（多轮；单轮中位数比值波动很大，同时列出各轮最小值比值的中位数）：

### 分组研究的纯权重记账

`panelbt` 增加独立的纯权重入口 `run_weights` / `run_weights_batch`，内核位于
`crates/panelbt-core`。它按给定持有期收益计算盈亏，不模拟现金、股数、费用或价格漂移。
买卖权限仍由行情层给出，冻结方向与成交引擎共用判断；冻结权重占用对应多空预算。
目标行就是成交行，信号错位仍只在 `ashare` 完成。批量入口支持共享分组标签的紧凑目标，
避免为每个组展开整张权重面板；计算期间释放 GIL。旧 NumPy 权重模拟冻结在
`panelbt.reference_weights`，逐位对照包括浮点归约顺序。`groupbt` 的公开参数和口径不变。

批量研究入口 `run_group_weights` 在一个释放 GIL 的调用中协调截面算子、权重记账和暴露。
截面算子复用 `panelops-core` 的排序键，并增加显式保留 NumPy 归约顺序的内核；不改变
现有补偿求和算子的数值口径。Python 包之间仍不互相 import，Rust crate 静态复用代码。
调用方明确给出信号和成交的起始行，不在引擎中隐含移位。每天复用全市场中性化结果，
每池只排一次名供全部组合使用；各池减均值可能产生不同的舍入并列，不能直接过滤主池排名。
价格前填、风险历史和持仓采用有限工作缓冲区；不输出每组完整持仓面板。市值对数继续由
NumPy ufunc 批量计算，保留所用数学库的逐位结果，其余逐日工作在 Rust 中完成。

权重入口在 Rust 借用期间将传入数组视图设为只读，结束或异常时恢复原有标志；同一数组
被重叠调用借用时，最后一个调用结束才恢复。`groupbt` 另复制有效窗口的可变因子，隔离
调用方对原因子的后续写入；底层缓冲区不可写的连续输入可免拷贝。只读标志不能锁住预先
存在的其他别名，调用期间仍禁止修改输入。
归约顺序依赖 NumPy 的内部实现，并非 NumPy 的兼容性承诺；`panelbt` 导入时用跨越
8/128 元素边界、含负零和 NaN 的探针逐位核对，不匹配就报错，要求更新内核。

本轮分组研究优化先以当前版本保存平台端到端基准，再逐项测量。共享数据只存活于一次
任务，键必须包含股票池、窗口和影响计算的参数；不同调仓周期共用每日目标，分别记账。
风险均值可以跨信号复用，持仓加权归约仍须保留原 NumPy 求和树（不能直接压缩零项）。
因子仅在底层缓冲区确实不可写且布局连续时免拷贝，普通只读视图继续隔离潜在可写别名。
样本内和验证保持各自截断边界；所有共享、融合都以逐位对照和独立性能测量决定是否保留。

### 4.17 加密货币：现货、U 本位永续、季度交割（设计稿 v3.1，2026-11-15）

用户 2026-11-15 定：扩展 `panelbt`，不另接引擎（NautilusTrader 是事件驱动、不是面板接口，和因子、组合、平台接不上）；日频和小时级的策略都支持；做币安的现货、U 本位永续、U 本位季度交割合约，以及按成交额取前 N 个币的横截面（含已下架的币）。币本位合约、现货杠杆借币、期权、组合保证金账户不做。设计经 Codex 三轮对抗审查（v1 10 条 P0，v2 剩 4 条，v3 无 P0、5 条 P1 已改），规则事实见 [markets/BINANCE.md](markets/BINANCE.md)。

**分两批**：第一批是现货账户和合约账户**各自独立**回测（永续、季度、跨期基差都在合约账户里）。现货腿 + 合约腿的组合（现货对永续的基差、资金费套利）要两个钱包同步推进、钱包间按真实余额划转，需要内核新增「行边界阶段」和独立的钱包账，放第二批（C4），这一节末尾记了它要满足的条件。

**时间轴：引擎一律逐小时推进。** 资金费结算（00/08/16 UTC，部分币 4 小时或 1 小时）、季度交割（08:00 UTC）都在整点，一行一小时时每个事件正好落在行边界上。约定 **第 t 行 = [s_t, s_t + 1h)**，第 t 行在 s_t 按开盘价成交；结算时刻等于 s_{t+1} 的资金费归第 t 行收盘时的持仓（结算先于 s_{t+1} 的成交）。币安对结算时刻前后几秒的成交没有确定规则，这个约定的误差是边界上的那一笔，文档写明。8 年小时线约 7 万行，前 100 个币约 700 万格，内核一次跑完。

**日频策略**：日线 d 覆盖 [d 日 trade_hour, d+1 日 trade_hour)，收盘后出信号，在下一根日线的第一个小时（`trade_hour` 那一行）成交，信号只错位一次。只在 `trade_hour` 的行给目标；日频模式下 `carry_blocked=False`，受阻的单子不在其他小时重试，等下一个 `trade_hour`。季度换月也放在到期前最后一个 `trade_hour`（换月提前量按时间长度 `roll_before="3D"`，落到它之前最近的 `trade_hour`）。交易所强平、交割、下架结算照常在发生的小时处理。结果按日汇总出日频净值和报表。

**现货账户**：只有现货列，现金账户，只做多，小数数量用 `qty_step`。手续费从现金扣（币安实际从买到的币里扣，持币量少 0.1%，账户里的持仓是未扣费的数量；差别写进报告）。费用只能按日期分段、不能按交易对分（内核限制），所以 BTCUSDT 2022-07-08 至 2023-03-22 的零费率不体现，按 0.1% 收（偏悲观）。下单规则（步长、最小数量）用每个交易对的一份快照（N 向量），标「假设」；现货的最小名义过滤第一批不实现，写进限制。

**合约账户**（U 本位单资产全仓）：只有期货列，按标记价格盯市、按下面的规则强平。

**数量单位**：期货列仍是整数「张」。**乘数 = 这个交易对固定的内部计量单位**：取数据版本里出现过的所有步长的最大公约单位（十进制下取最小的那个 10 的负幂），随数据版本冻结，追加历史后不重选；价格是每个币的报价。交易所的下单规则作为随时间变化的输入另给（内核第 5 条）。成交量换成张：`volume_engine = 币数量 / 乘数`；期货手续费只用按金额费率（公式里已含乘数），按张收费为 0。`1000PEPE` 这类合约在数据层统一换算成「每个 1000PEPE」的价格、数量、成交量和资金费，USDT 成交额和最小名义不乘 1000，映射到币只用于选币和对照。

**内核要补的能力**（都是可选输入；不开启时与现在逐位相同。逐位不变不仅用「加一列不交易的期货」证明，还要让现有的现金账户、保证金账户、持有期货的全部测试和 `run` / `run_batch` / `step` / `snapshot` 在新构建上逐位不变）：

1. **资金费** `Futures(funding=...)`，T×N，单位是「每张的 USDT」：`funding[t, n] = rate × p_f × multiplier`，`rate` 是结算时刻 s_{t+1} 的费率，`p_f` 是这笔结算的标记价格——2023-10-31 以后用资金费历史接口给的结算标记价，之前用下一根标记价格小时线的开盘价，标「近似」；没有结算的格子为 0（数据层区分「没有结算」和「缺数据」，后者报错）。第 t 行收盘时按收盘仍持有的张数收付，`现金 −= contracts × funding[t, n]`（费率为正多头付）；本行被强平的张数不收付。结果单列 `funding`，计入贡献，现金守恒式多一项。资金费率事后才知道：信号用的费率序列只到上一次结算。
2. **初始与维持保证金分开** `Futures(maint_rate=...)`：`margin_rate`（= 1 / 杠杆）继续约束开仓和可用现金；`maint_rate` 只用于强平判断。不给时等于 `margin_rate`。杠杆不能超过交易所当时第一档允许的最大杠杆（数据层给的规则表，超出报错）。
3. **交易所强平** `Futures(liquidation=Liquidation(mark_open, mark_high, mark_low, clearance_fee_rate, tier_cap))`，只允许在全是期货列的市场上开启，要求成交价是本行开盘价（声明 `exec_at_open=True`）。开启后原来的「收盘占用 > 权益、下一行同比例减仓」不再使用。记号：成交后的现金 C'、带符号的币数量 Q_i = 张数 × 乘数、记账基准 B_i、维持保证金率 r_i、标记价 M_i。逐行顺序：
   1. **开盘检查**：已有仓位按 `mark_open` 估值，`D_open = C + Σ Q_i (M_i0 − B_i) − Σ r_i |Q_i| M_i0`。D_open ≤ 容差（相对名义 1e-12）且持有期货时，在开盘按 `mark_open` 全部强平（成交规则见 4），本行不再交易。这一步只估值、不改现金和基准，盈亏仍在平仓或收盘结转时只算一次。
   2. **成交**：可开仓量和权重换算用按 `mark_open` 估值后的权益；候选成交的资金检查包括成交价相对 `mark_open` 的浮亏、费用和成交后全部持仓的初始保证金。
   3. **成交后检查**：用成交后的 C'、Q、B' 重算 `D0 = C' + Σ Q_i (M_i0 − B_i') − Σ r_i |Q_i| M_i0`，D0 ≤ 容差且持有期货时立即按 `mark_open` 全部强平。
   4. **盘中检查**：每个持仓列的标记价格从 `mark_open` 线性走到不利极值（多头到 `mark_low`、空头到 `mark_high`），ΔM_i = 极值 − M_i0。`D(λ) = D0 + λ·D1`，`D1 = Σ (Q_i − r_i |Q_i|) ΔM_i`。D1 ≥ 0 不触发；否则 λ* = −D0 / D1，λ* ≤ 1 时在各列 M_i0 + λ*·ΔM_i 上全部强平。各列同时走向极值是一种**联合压力情景**，不是收益的下界（多列时真实先后顺序可能让强平价更高或更低）；单列时它准确判断「有没有触及强平线」，成交价仍是近似。
   5. **强平成交与费用**：按触发标记价成交，再加正常的滑点、冲击和普通吃单手续费（与普通成交同一套）；平仓后剩余权益 R。清算费按全部被平的列先合计再受下面的上限约束。清算费 = min(`clearance_fee_rate` × 平仓名义, max(R, 0))（穿仓的仓位不收清算费，币安规则；收不足额时按剩余收，这是简化，标出）。R < 0 时余额记为 0，差额单列为「穿仓缺口」并计入守恒式（简化：币安对普通用户的负余额按条件、延时自动清偿，这里立即清零），账户记爆仓，之后不再开仓；清算费扣完余额恰好为 0 不算爆仓（权益为 0 也开不了仓）。强平后清掉**全部**顺延中的单子和挂起目标（不只是这一列），之后的目标照常生效（除非已爆仓）。
   6. **收盘**：按 `settlement`（= 本行标记价收盘，到期行 = 交割价，见第 4 条）结转浮动盈亏；到期了结；收资金费；再按 `settlement` 做一次维持保证金检查，不足就在 `settlement` 价位按 5 全部强平。资金费价格 p_f 和 `settlement` 相差的只是结算时刻前后几秒的价格变动，用同一个 `settlement` 估值是写明的近似。
   7. **分档**：只用第一档维持保证金率。`tier_cap[T, N]` 是第一档的名义上限，在开盘、成交后、收盘按持仓名义检查，盘中按 `|Q| × mark_high`（多空一样，不用强平路径的不利极值）检查；本行盘中有平仓、无法确定最高价出现在平仓前还是后的，按超限计（保守）。超过的行数计入 `coverage["tier_cap_exceeded"]`；`ashare` 侧默认判为无效并报错，研究时可以显式放开。
4. **交割与下架结算**：用已有的到期了结，到期行 = 结束于结算时刻的那一行（交割 08:00 UTC → 07:00 那一行），这一行的 `settlement` 直接给交易所公布的交割价 / 结算价（不再先结转到标记收盘价），收交割费（= 吃单费率）。下架结算价查不到时用结算时刻的标记价格并在诊断里标出。
5. **随时间变化的下单规则** `Futures(qty_step, min_qty, min_notional)`，T×N（张、张、USDT）：开仓和加仓按当行步长向零取整；资金或成交量参与率缩放之后，按缩放后的数量重新取整、重新检查最小数量和最小名义（视为重新提交一笔更小的市价单），不满足就不成交，计入 `futures_rounded_to_zero`。最小名义按 `mark_open` 计（币安市价单按标记价检查）。减仓豁免最小名义、仍受步长和最小数量约束；**平掉全部持仓不受步长和最小数量约束**（模型约定：规则变化后留下的零头可以一次清掉）；反手拆成「平旧」和「开新」两段，只有平旧部分豁免。`kind="shares"` 的目标同样按这些规则取整。
6. **非整点生效的规则**（例如某次维持保证金调整 09:35 生效）：从下一个整点起生效，文档写明；公告里「已有仓位不受影响」一类的条款不建模（影响可能持续到这批旧仓平掉为止），在规则表里标出，回测诊断列出实际用到这类近似的交易对和时间段。

**C1 / C2 / C3 之间的输入约定**（三条线共用，C2 的测试夹具里放一份两合约的小面板：一个永续中途上市、一个季度合约中途到期）：

- 期货列每行的 `settlement` 必须为正（SPEC 现有要求）：上市前的行填上市后第一个标记价收盘（只用于「目标被拒还是取整为 0」的计数，不参与记账，现有约定），到期或下架之后的行填了结价；`mark_open/high/low` 和 `funding` 在生命周期外为 NaN / 0，内核只在**持有**时读它们，持有时遇到 NaN 报错。
- 生命周期内缺数据（交易所停机、归档缺口）由数据层标出，`ashare` 侧默认报错并列出交易对和时段，显式允许时按「不可交易、不估值变动」处理并计入诊断。
- 最后一行的资金费需要右边界 s_T 的结算；数据到 s_T 为止没有这笔结算就是 0，有结算但拿不到价格就截掉最后一行，不补造。
- 「没有这个输入」（不开启）、「这一格没有事件」（0）、「缺数据」（NaN + 质量标记）三者分开，不互相代替。

**第二批（C4，两钱包）要满足的条件**（Codex 第二轮 N3、N4）：内核提供行边界阶段（上一行收盘之后、下一行开盘之前），能动态注入划转，并返回实际划出的金额，再给另一钱包入同样的数；合约账户要分开维护钱包余额 W 和未实现盈亏 U（E = W + U），可划转额按币安规则算，不能用内核逐小时结转后的现金；划转在开盘检查之前，不能在盘中强平之后补钱撤销强平；两个模拟器的快照、划转日志和合计净值同步，内部划转不算收益也不算外部入金。

**C4 设计细节（2026-11-15，C1–C3 合入后写；Codex 对抗审查一轮后改，6 条 P1 已改进下文）**：

- **范围**：一个现货钱包（现金账户，只做多）加一个 U 本位合约钱包（单资产全仓），同一套小时时间轴同步推进，钱包间可以划转。用途是现货腿 + 合约腿的组合：资金费套利（现货多 + 永续空）、现货对永续或季度的基差。两边各自的规则、费用、强平、下架、交割照第一批不变；不做现货借币、币本位、逐仓。
- **行边界阶段 = 动态外部资金流**：`Simulator.step(target, flow=x)`（x > 0 入金、x < 0 出金，缺省 0）。现有模拟器在上一次 `step` 结束时已经做完下一行的静态盘前阶段（`Config.cash_flow`、公司行为、下架），动态流在**本次 `step` 开始时、开盘检查之前**应用，每行只能给一次，记进同样的 `flow` 和「请求与实际之差」两列，不算收益。`State` 在两次 `step` 之间读到的是「静态盘前阶段之后、动态流之前」的状态，文档写明各金额的时点。静态 `cash_flow` 不为 0 的模拟器不能再用 `flow=`（报错）；旧 `cash_flow` 的提取上限保持原样（逐位不变），下面的可划转额只约束动态流。上一行收盘（含收盘强平）已经结束，划转不能撤销已发生的强平。`run` / `run_batch` 不变。
- **合约钱包分开记 W 和 U**：每列维护币安口径的开仓均价 e_i（用含滑点、冲击的实际成交价，不含手续费，和 `State.cost` 分开；加仓按数量加权，减仓不变，全部平掉清零，反手按反手成交价重开）。钱包余额 W 的完整守恒式：W = 初始 + 外部与划转流量 + 已实现盈亏 − 手续费 − 资金费 − 清算费 − 交割费 + 穿仓缺口补记；已实现盈亏在减仓、强平、交割、下架了结时都按 (了结价 − e_i) × 了结数量算。U = Σ Q_i (M_i − e_i)，M_i 是和内核权益同一时点的标记价。**不变式 W + U = 内核权益**（相对名义 1e-12）由性质测试守住，含爆仓行；穿仓缺口补记单列，不当外部入金。开启 W/U 记账不改变任何已有输出（逐位）。`State` 加 `wallet_balance`、`unrealized`、`transferable` 和每列 `entry_price`；结果加逐行 `wallet_balance`、`unrealized`（只在开启交易所强平的合约市场上有）；快照带上每列开仓均价。
- **可划转额（模型假设，未查到币安原文）**：合约钱包 `transferable = max(0, W + min(U, 0) − IM)`，IM = Σ |Q_i| × 上一行 `settlement` × 本行（动态流所在行）已生效的 `margin_rate_i`；浮盈不能划走、浮亏要扣、初始保证金要留。它和币安 `maxWithdrawAmount` 的大小关系没有证据，**不声称偏保守**，标「未验证的划转模型假设」，例子里对它做敏感性（例如 IM 放大 1.5 倍）。现货钱包可划转额 = 现金（不能为负）。已爆仓的合约钱包不能入金也不能出金。
- **协调器** `ashare.backtest.crypto.two_wallet(spot, usdm, targets, *, transfer=..., hedge=..., trade_hour=None, initial=(现货, 合约))`，逐步版本 `TwoWallet`。两个 `CryptoMarket` 必须是同一段小时时间轴。每行：
  1. **先冻结决策**：在任何一边 `step` 之前，读两边状态（复制需要的数组，`State` 是活视图）、算出两边目标和划转；
  2. **划转金额在入账前定好**：请求 → 付款方可划转额截断 → 接收方资格（已爆仓拒收）→ 得到一个双方都接受的金额 a（可能为 0），两边分别 `step(…, flow=∓a)`。内核实际流量和 a 不一致就整个协调器报错失效（不产生半行状态）；第二个 `step` 抛错同样整体失效；
  3. 记划转日志（行、方向、请求、实际、截断原因）。
- **目标语义**：目标按**币**给（每个币一个现货数量和一个合约数量，单位是币，不是两边各自的权重），也可以按合计权益的权重给，协调器用**同一个参考价**（这个币上一根已完成的现货收盘；没有现货腿的用标记收盘）换成币数量，两条腿用同一个币数量，再各自换成现货数量和合约张数（含乘数、`1000PEPE` 这类单位换算）。首行和新上市列没有上一根收盘时拒绝非零目标（不回退到本行价格）。日频模式下非 `trade_hour` 的行目标为 `None`、两边 `carry_blocked=False`，划转每小时都跑；下架退出等第一批的例外照常。
- **对冲成交（`hedge`）**：两腿独立成交会因资金、成交量、交易掩码、强平而失配，单腿暴露会把方向收益算成套利收益。`hedge="follow_spot"`（例子用这个）：现货腿先成交，合约腿的目标改为「−对冲比例 × 现货实际持有的币数量」（取整到张），本行就对齐；合约腿再成交不足的部分记为残余暴露。`hedge="independent"`：两腿各按目标成交。两种都逐行输出残余暴露（币数量和按参考价的 USDT 名义），诊断给出最大值、持续行数，超过阈值默认报错、可显式放开。
- **现货按数量下单的取整**：现有现货内核在 `kind="shares"` 下资金或成交量缩放后不再按步长取整（会买出 0.909… 个币）。C4 给加密货币现货市场补上：缩放后按 `qty_step` 向零取整、再查最小数量，全部卖出不受步长约束（同合约第 5 条）；只在加密货币现货市场（档案标记）开启，A 股等现有市场逐位不变。
- **划转策略**：内置 `MarginBand(target, low, high)`：合约钱包保证金率 = (W + U) / Σ|Q_i|M_i（上一行 `settlement`），低于 `low` 时从现货划入补到 `target`，高于 `high` 时把超出 `target` 的部分（受可划转额限制）划回现货；不持仓时不动。也可以传函数 `transfer(t, spot_state, usdm_state) -> float`（正数 = 现货到合约）。现货没有现金时不为划转而卖币（模型约定）：救援失败（请求被截断）逐行记下，诊断给次数、金额和随后是否被强平。
- **结果**：两边各自的 `Result` 照旧（划转在各自的结果里是外部流量，不算收益）；合计净值 = 现货权益 + 合约 W + U，合计收益不含内部划转（两边流量之和逐行为 0，测试守住）；合计诊断 = 两边诊断合并 + 划转次数、请求与实际总额、被截断的次数和金额、被拒的入金、救援失败、残余暴露。
- **快照**：只在两边都完成同一行后可取。一份快照含两边模拟器的快照（含每列开仓均价）、划转日志、目标语义、`hedge`、`trade_hour`、策略的类名和参数；指纹覆盖时间轴、列与币单位映射和上述配置。内置策略可快照；自定义函数策略要实现 `state()` / `restore(state)` 才能快照，否则 `snapshot()` 报错。恢复先建两个临时模拟器和策略、全部成功后再整体替换。
- **验证**：参考实现另写（不和内核、不和第一批参考实现共用记账代码），确定性反例：①浮盈不能划走（多头浮盈 50、W 100、IM 30 → 可划 70）；②浮亏要扣（浮亏 20 → 可划 50）；③盘前入金救下本行开盘检查（不入金时开盘强平、入金后不强平）；④上一行收盘已强平，下一行入金不改变强平记录；⑤两边都不交易时合计收益为 0、两边流量之和为 0；⑥接收方已爆仓时付款方也不出金（两边流量都是 0）；⑦开仓均价：加仓、部分减仓、反手、全部平仓后重开；⑧资金费、手续费进 W 不进 U；⑨穿仓行 W + U = 0、缺口补记单列；⑩保证金率在边界上调时用新率算 IM；⑪`follow_spot` 下现货因资金只成交一半时合约也只开一半；⑫现货 `shares` 缩放后按步长取整；⑬首行非零目标报错；⑭W + U = 权益的随机性质测试。对拍语料要覆盖：两个方向的划转、截断、被拒、救援成功与失败、强平后入金被拒、反手、交割、下架、残余暴露。变异检查覆盖：动态流放在开盘检查之后、浮盈可划、IM 用错标记价或错行的保证金率、减仓时改均价、反手不重置均价、漏记穿仓补记、内部划转算进收益、两边划转金额不相等、已爆仓仍可入金、`follow_spot` 用目标而不是实际成交量。
- **例子**：BTC 资金费套利（现货多 + 永续空，`hedge="follow_spot"`），每腿名义 = 合计权益 × h，h = 1 / (1 + 目标保证金率 + 现金储备率)，固定并写明初始分配、现金储备、`MarginBand(0.5, 0.25, 1.0)`、再平衡频率；2020-01 起，报年化、资金费收入、费用、最大回撤、划转次数、救援失败次数、强平次数、残余暴露；手算核对一次救援划转和一次资金费日。结论只代表「现金储备式救援、不兑现现货利润」这一种做法，文档写明。

**验证**：混合账户参考实现 `reference_futures.py` 照第 1–6 条独立扩展（不和内核共用代码）。先写**确定性反例**及期望值（来自两轮审查）：资金检查拒绝开仓（乘数和步长 1、初始保证金率 10%、零费用、现金 10、成交价 100、标记开盘 90：开 1 单位后权益 0、初始保证金 9，必须拒绝，整数张时成交量为 0）；成交后才失守（现金 3、已有多头 2 单位、基准和标记开盘都是 100、维持率 1%、零费用：开盘 D = 1；按 98 平掉 1 单位后现金 1、维持保证金 1、D = 0，立即强平）；分档上限看最高价（持有多头 1 单位，标记开高低收 100 / 200 / 99 / 100，上限 150，应计超限）；边界跳价；资金费先付后触发强平；交割价低于标记收盘（基准 100、标记收盘 101、交割价 99，多头合计亏 1）；穿仓时不收清算费；受阻目标不在非 `trade_hour` 重试；强平后其他列的挂起开仓被清掉。再做随机对拍，语料断言这些分支都出现过：资金费付和收、开盘强平、成交后强平、盘中强平（单列、多列、多空混合、λ* = 1 边界、D1 ≥ 0 不触发）、收盘强平、清算费部分收取和穿仓缺口、强平后再开仓、交割、下架结算、缩放后重新取整、最小名义拦下与减仓豁免、全部平仓不受步长约束、反手拆分、分档超限计数。手算例子：2021-05-19 BTC 永续 10 倍多头（按标记价格最低点手算强平价和清算费）、一个资金费结算日、一次季度交割。变异检查覆盖资金费方向和边界归属、强平前后的资金费、λ 公式里维持保证金随价格变、成交后检查、清算费上限、交割价结转、只减仓豁免、维持与初始保证金混用。与 `~/Codespace/Quant` 的 `account.py` 只做对照解释，不以对齐它为目标。

### 4.18 加密货币因子：资金费率与基差（设计稿 v5.1，2026-11-15；Codex 对抗审查四轮，各轮 P1 已改进下文；推断方案在第三轮后整体重写；v5.1 按真实归档改了交割核对）

用户 2026-11-15 定：把资金费率和基差因子做进来。本地币池目前只有 BTC、ETH，所以第一步是**时序因子**（每个币一列，用来择时），检验按时序做；因子按「时间 × 币」输出，币池扩大后横截面工具可以直接用，横截面检验到时再做。

**时点约定**（全部因子和标签共用）：

- 面板 `time` 是小时左端 s_t；第 t 行的收盘数据在 `available_at = s_{t+1}` 可知。因子值都按 `available_at` 标时间。
- 资金费：结算时刻 s 的费率归 s 之前的持仓，数据层放在以 s 为右边界的行，所以同样在 `available_at = s` 可知。沿用 4.17「结算先于同一时刻成交」的零延迟模型：在 s 成交时已经知道 s 的费率（币安实际有约 15 秒偏差，文档写明这是近似）。
- 日频：成交时刻 τ = 某日的 `trade_hour` 整点。τ 时可用的是 `available_at ≤ τ` 的因子值，即结束于 τ 的那一行。按现有 `daily_targets` 的口径，日线 d 覆盖 [d 日 trade_hour, d+1 日 trade_hour)，它的收盘就是 τ = d+1 日 trade_hour，所以 `available_at = τ` 的值标成**日线标签 d**，交给 `daily_targets` 做唯一一次移位（在 τ 成交）。这个映射由一个函数 `daily_factor(values, trade_hour)` 给出，检验的标签和策略例子都用它，不另写。
- 截断检验按 `available_at` 截断原始事件（结算记录按结算时刻、K 线按收盘时刻），不是按行号截断面板。

**质量掩码**（不能只看 NaN：数据层会把允许的缺口按持平补值，半截线也有数值）：每个价格输入在一个小时上可用，要求这一小时是「正常 K 线」——不是缺口占位、不是停机半截线、没有时间戳异常、在生命周期内（用数据层的质量标记判断）。季度合约另外排除零成交、价格连续冻结的小时（这两类质量位也算不正常；季度只作信号，成交稀少时收盘价是陈旧的）。永续溢价、标记溢价、季度基差要求**两边**这一小时都正常，否则这一小时的值是 NaN；窗口均值在掩码之后数有效小时，不足窗口的 2/3 为 NaN。资金费记录的完整性由数据层保证（严格构建缺一笔就报错，不放宽），因子层不再补。

**资金费率口径**：只用无量纲的 `funding_rate`（不是面板里每张的 USDT 现金 `funding`）。

- `funding_last` = 最近一笔已结算费率 r × 8760 ÷ h，h 是**这一笔自己的**结算间隔（数据层与该笔一起记录的间隔，不是当前行的间隔）。
- `funding_mean_W`（W = 3、7、30 天）= **日历时间里的资金费强度**：8760 × Σ r_i ÷ (W × 24)，求和取结算时刻在 (τ − W, τ] 内的全部结算。含义：按窗口里实际发生的结算事件累计费率，除以固定的日历时长，不按名义间隔重新加权；临时改成 1 小时结算而费率不变时，强度确实变大（多付了钱），这是要的口径。左端的结算不算、右端的算，跨窗口边界不按小时摊分。注意它是费率之和，不是现金：固定一个币实际付出的是 Σ r_i × 结算标记价。窗口必须落在数据覆盖之内，否则 NaN。
- `funding_z_90d` = (M − 均值) ÷ 标准差，M = `funding_mean_7d(τ)`，参考值为 M(τ − 24k 小时)，k = 1…90（同一钟点、只用过去），ddof = 1，有效参考值少于 60 个或标准差为 0 时为 NaN。

**基差口径**：

- `premium_{1d,7d}` = 永续成交收盘 ÷ 同小时现货收盘 − 1，窗口内有效小时的平均；`mark_premium_{1d,7d}` = 标记价收盘 ÷ 指数收盘 − 1，作对照。
- `basis_q` = (季度收盘 ÷ 同小时现货收盘 − 1) × 8760 ÷ 剩余小时数。剩余小时数按**这一小时的收盘时刻**（`available_at`）到交割时刻计算。选约只看元数据：候选是上市满 7 天、剩余时间**严格大于** 336 小时（14 天）的季度合约，取剩余时间最短的一期；所选合约这一小时 K 线不正常时这一小时为 NaN，不改用更远的一期（避免「近月→远月→近月」来回跳），所以换期只会向远月走。没有候选为 NaN。同时输出所选合约代码和是否换期。
- `basis_q_chg_7d` = **同一合约**的 `basis_q` 现在与 7 天前之差（7 天前用同一合约当时的值）；那一期 7 天前还没有值就是 NaN。不把换期造成的跳变当成基差变化。
- `carry_spread` = `funding_mean_7d` − `basis_q`。

**季度合约的「仅信号」数据集**：季度合约只用来算基差，不交易，因此不需要官方交割价（交割价接口只回到 2022-03）。单独一个数据集：从 `data.binance.vision` 同步 BTC、ETH 历次 U 本位季度合约的 1h K 线（核对 CHECKSUM），合约元数据两个时刻分开取：**交割时刻**由代码里的交割日加 08:00 UTC 得出，再与交易所接口的 `deliveryDate`（有的话）和归档核对：**最后一根有成交的 K 线，开盘时刻必须落在 [交割 − 24 小时, 交割]**，否则构建失败（2026-11-15 实测：官方归档在交割整点那根 K 线里仍有少量成交，之后用交割价补出几周到几个月成交量为 0 的平线；46/50 期都有）。信号表只收收盘不晚于交割时刻的 K 线；交割之后的行原样保留在原始归档里，在信号表中登记为质量例外 `post_delivery` 并剔除，逐期计数进入版本哈希；**上市时刻**优先取有出处的 `onboardDate` 或上新公告，缺失时用这一期合约**全部归档里的最早一根 K 线**作保守代理并标明来源（`listed_source`）。为此同步时每期合约都要列出归档的全部月份、取最早一个月，不能用本次查询的起点；两种来源都没有的合约不进候选，并记进构建报告。它有自己的内容版本：哈希覆盖原始归档、解析结果、**规范化后的合约元数据（上市与交割时刻及各自来源）、质量例外**和定义版本，随版本冻结，读取时校验；元数据修正就生成新版本。独立校验（CHECKSUM、解析、连续性、合约元数据），不走可交易季度的交割价校验。因子的输入身份 = 面板版本 + 信号数据集版本 + 因子定义版本，因子缓存按这三者识别。

**标签（未来收益）**：

- 日频，计划入场时刻 τ_in = 信号所在日线之后的 `trade_hour`（与 `daily_targets` 的成交时刻一致），退出时刻 τ_out = τ_in + h 天（h = 1、7、30）。入场或退出那一行不可成交（掩码、缺数据、不在生命周期）时，这个标签为 NaN，不顺延（与日频策略不在其他小时重试一致）。
- 现货收益 = τ_out 行开盘 ÷ τ_in 行开盘 − 1。
- 永续多头收益（固定一个币、一倍、不含手续费和强平）= [P_out − P_in − Σ r_s × p_f,s] ÷ P_in，P 是永续成交开盘价，求和取结算时刻 s ∈ (τ_in, τ_out] 的全部结算，p_f,s 是该笔的结算标记价（与 4.17 第 1 条同一来源）。这两种是**描述用标签**（分位表、Spearman、策略对照）。
- **推断用标签**另定，要求跨期严格可加：日收益 g_d = ln(1 + 当天的单日收益)，单日收益按上面两条在 [τ_d, τ_{d+1}) 上算（永续含当天的资金费现金、按当天入场价归一）；h 天推断收益 = Σ_{j=1..h} g_{d+j}。它和描述标签不是同一个数（复利、按日重新归一），报告里分开写。任一天缺失则这一 h 天和为 NaN。

**检验**：

- 描述统计量：日频样本上的时序 Spearman 相关系数（因子值与未来收益），只做描述。
- 推断检验的是「因子 x_d 对未来 h 天推断收益 R_{d,h} = Σ_{j=1..h} g_{d+j} 的预测斜率为零」。估计：R_{d,h} = α + β x_d + u 的 OLS，样本索引为 x_d 与 R_{d,h} 都有效的 d。标准误用**正向回归形式的 Hodrick（1992）1B**：Var(β̂) = (Z'Z)⁻¹ S (Z'Z)⁻¹，Z = [1, x]，S = Σ_t e_{t+1}² · q_t q_t'（求和，不除以 T），q_t = Σ_{k=0..h−1} z_{t−k}，e_{t+1} = g_{t+1} − ḡ 是**零假设下**去均值的单日推断收益（不是回归残差）；q_t 里任一 z 缺失，这一项不进 S。t = β̂ ÷ se。不做反向回归，不与 White 对拍；正确性用独立的逐项展开实现对拍，并用手算的小样本（3–5 个点）核对。
- **p 值用模拟的保守上界**（Berger–Boos 形式），不用正态表。工作模型：g_d = μ + ε_d，x_d = c + φ x_{d−1} + η_d，(ε_d, η_d) 跨日独立、同日相关系数 δ；ε 从样本内去均值后的 g **独立重抽**（单个抽样，不分块，保证收益不可预测、斜率严格为零），η = δ·标准化 ε × sd(η) + √(1−δ²)·独立正态 × sd(η)；平稳初值，套用样本外真实的缺失位置，每次模拟用与观察相同的 T 和掩码。参数处理：
  - **φ 不用区间**，在整个允许范围 [0, 0.999] 上取上确界，网格为 0–0.9 每隔 0.05、0.9–0.99 每隔 0.01、0.991–0.999 每隔 0.001（共 37 点）；
  - **δ 用区间**：在**样本内**（2024-01-01 之前）估计 δ，取 Fisher z 的 99.9% 区间（γ = 0.001）后冻结，区间内取 11 个等距点，含两端；
  - 每格用公共随机数模拟 4,000 次 |t|，格内 p_θ = (1 + #{|t*| ≥ |t|}) ÷ 4,001；
  - 网格最大值若落在内点，在相邻格之间再加密一次（各维 5 点）取最大；报告 p 值曲面在 φ、|δ| 方向是否单调，不单调要在报告里写明；
  - 这一项的 p 值 = min(1, 网格上确界 + γ)。最小可达值约 0.00125，低于 Holm 首个门槛 0.00625。
  网格最大值近似连续上确界，这一近似连同「独立重抽丢掉波动聚集」一起写进报告的局限一节。模拟前在 φ = 0、δ = 0 格上核对拒绝率在 5% 附近，作为程序自检。
- **确认族只有 8 项**，事先定死：`funding_mean_7d`、`funding_z_90d`、`premium_7d`、`basis_q` × 7 天 × BTC、ETH × 永续推断收益；只用样本外，双侧，Holm 校正；**8 个名额始终保留**，算不出来（样本不足、样本内估不出 δ）的项 p 值为 NaN，沿用 `stats.adjust` 的约定，不缩小分母。只有这一族的结果可以说「显著」。
- **探索**：其余因子、期限 1 / 30 天、现货收益、样本内结果，只报告同样方法得到的保守 p 值和 Spearman，不做多重校正，明确标「探索，不作推断」。
- **功效**：目标功效 80%。备择从逐日过程生成再聚合（保持可加）：g_{d+1} = μ + b·x_d + ε_{d+1}，其余同零假设模型；对每个确认项，在 b 的网格上（正负分开）用**完整检验规则**（上面的保守 p 值 ≤ Holm 首个门槛 0.00625）算拒绝率，取 φ、δ 网格上最低的那个功效；最小可检出效应 = 最低功效达到 80% 的最小 |b|，换算成「因子增加一个样本内标准差、7 天推断收益变动多少」。搜索范围内达不到 80% 就写「不可检出」。
- 样本切分：边界 2024-01-01 00:00 UTC。样本内只收入场和退出都早于边界的标签；样本外只收入场不早于边界的标签；跨边界的标签两边都不收。样本外的因子可以用边界之前的历史做预热。
- 分位描述：每个日期用**过去 365 天、不含当天**的因子值定 5 个分位边界（有效历史少于 180 天为 NaN），并列值按「≤ 边界归下组」；报告每组实际日期数、平均未来收益和标签重叠情况；分位结果只做描述，不做显著性。

**策略例子**：第一批日频趋势策略加一层「资金费过热减仓」：`funding_z_90d > 2` 时把多头目标减半，`< −2` 时把空头目标减半，缺因子值时不调整；和不加这层的版本在同一区间、同一预热下比较。趋势策略的历史表现已经公开在 C3 / C5 的记录里，这个例子是**回溯探索**，不是确认；规则在这里冻结（阈值 ±2、减半、不调参），确认只能用 2026-11-15 之后的新数据。

**入口**：`ashare.factor.crypto`：`crypto_factors(ds, signals, symbols, start, end, *, names=None)` 返回 {名字: (available_at, 时间 × 币)}，内部先读足预热历史，`start` / `end` 只裁剪输出；`daily_factor(values, trade_hour)` 给日频标签。这一步不注册进表达式因子库（现有 `FactorSet` 只收 `Expr`），横截面检验时再加面板适配器。检验在 `ashare.factor.crypto_eval`（描述与推断两套标签、Hodrick 1B 检验、模拟保守 p 值、Holm、功效、分位描述），报告写成 Markdown 和 JSON 摘要。

**验证**：每个因子在合成数据上手算核对（含 1 / 4 / 8 小时间隔混用、临时 1 小时结算、缺口占位与半截线被掩码、换期、到期前后、恰好 336 小时）；**前视检验**：在若干历史时点按 `available_at` 截断原始事件，因子值必须与全量数据算出的一致；永续溢价、季度基差、资金费均值在一段真实数据上从原始归档独立复算；Hodrick 1B 标准误与独立的逐项展开实现对拍并用手算小样本核对，推断标签逐日相加等于 h 天和，零假设世界的斜率严格为零（大样本模拟回归斜率均值接近 0），模拟 p 值的计数公式；变异检查覆盖年化用错间隔、窗口含未结算的一笔、日频标签多移或少移一次、z 分数用到当天或未来、换期提前或滞后、剩余小时数用行左端、标签收了跨边界样本、掩码漏掉补值占位、1B 漏掉过去窗口的缺失、1B 用了回归残差而不是零假设下的去均值收益、校准参数用了样本外数据、Holm 缩小分母、选约在近月缺一小时时退回远月、上市时刻用了查询起点。

### 4.19 单标的择时因子的评估入口（C8，2026-11-15）

用于 BTC 择时研究（研究计划私有）。要防的是三件事：用到决策时刻之后的数据；在验证期和封存期反复试；同一个因子换个写法重复计数。代码通用、公开，研究的设定、名单和台账放私有目录 `data/mining/`。

- **研究设定**是一份私有 JSON：规范台账位置 `ledger`（计入设定哈希，显式传入其他路径拒绝）、标的、调仓时点 `trade_hour`、主目标持有期，以及挖掘期、验证期、确认期三段 `[开始, 结束)`、验证名单的哈希、最终名单的哈希。台账每一行都记录设定的哈希。一旦已有验证或确认记录，就拒绝修改三段日期。
- **数据防火墙**：`study.view(阶段)` 返回的小时面板、分钟线、metrics 读取器都截在该阶段的结束时刻（`available_at` 或区间结束 ≥ 结束时刻的行一律看不到）。因子函数只能从 view 取数。
- **前视自检**：同一个因子函数分别在完整 view 和「截到更早随机日期」的 view 上算一遍，重叠日期的值必须逐位相同，否则判为前视并拒绝。截断日期由定义哈希决定，可重复。
- **标签与推断沿用 4.18 / C6**：`crypto_labels`（永续开盘价加资金费的可加对数收益）、正向 Hodrick 1B、Berger–Boos 保守 p 值。只计入「入场 ≥ 阶段开始，且入场 + 持有期 ≤ 阶段结束」的样本，跨界的标签丢掉。C6 写死的 `BOUNDARY` 改为参数，C6 原有结果逐位不变。
- **台账**：公式身份来自实际执行代码和参数；检验身份再加入标的、调仓钟点、持有期、标签口径，以及挖掘、验证、确认三段日期。尝试数、BH 和名单均按检验身份计。相同检验、数据版本及完整设定直接使用通过结构及内外身份核对的缓存，不算新尝试或本次复算；只有同检验数据版本实际改变才标记复算，不增加名额。缓存不一致则告警并重新计算；台账是私有文件，不做抵抗主动篡改的加密认证。每行保留公式、检验、设定和数据身份及阶段；已有验证/确认记录后不能改日期。
- **验证期**：候选必须出现在已登记哈希的验证名单里（不超过 10 个），每个候选只能评估一次，第二次调用拒绝。
- **确认期**：最终名单（不超过 5 个）的文件哈希必须与设定一致；整份名单只跑一次：Holm 校正（名额固定），加上事先写死的组合策略。组合策略为各因子按挖掘期参数标准化后等权打分，仓位截到 [−1, 1]，杠杆 1，`panelbt` 加密货币永续、费率按档案。组合与永续持有和 `bench/crypto_examples.py` 的第一批趋势策略比较。第二次运行拒绝。
- 这些限制只能通过修改私有设定来绕过，而设定的哈希每一行都留在台账里，改动有据可查。

## 5. panelops：因子算子



对面板做运算的函数库，接口统一，全部正确处理缺失值，可以传入股票池掩码。

实现方式逐个算子决定：先用 polars 表达式、numpy（必要时加 bottleneck）写出基线，在 T = 4000、N = 5500 的面板上测速和内存。Rust 实测更快、或基线内存放不下的，用 Rust 写（按列或按行并行）；其余包一层直接用。预计滚动排名、滚动相关、带缺失值的截面排名和 IC 这几类会需要 Rust，逐元素运算和简单滚动统计不需要，以实测为准。每个算子的基准数字留档。

- 时间序列算子：`delay`、`delta`、滚动的均值、标准差、求和、最大、最小、排名、相关、协方差、线性衰减加权、指数平均、回归的斜率和残差。
- 截面算子：排名、标准化、去极值、分组去均值、对行业和对数市值回归取残差（中性化）。
- 评估核：IC 和秩 IC、分组收益、分组换手、因子自相关、由分数生成前 q 分位的稀疏目标（直接交给 panelbt）。

每个算子都与 numpy / pandas 的直白实现对拍；IC 和分组收益再与 alphalens 对拍。

## 6. ashare：研究项目本体

### 6.1 数据层

**封装**：数据层对项目的其余部分隐藏「数据从哪来、怎么存」。分四层，依赖只能从上往下。

| 层 | 模块 | 负责什么 | 谁可以用 |
|---|---|---|---|
| 读取接口 | `ashare.data` 顶层 | 按统一的字段名和单位取面板、长表、日历、证券表；给出每个字段的单位、来源和「当天何时可知」；给出数据版本 | 研究代码、回测、模拟盘的唯一入口 |
| 存储与构建 | `ashare.data.store`、`ashare.data.panel`、`ashare.data.verify` | 原始库（Parquet 分区加清单）、稠密面板的构建和增量更新、校验 | 数据层内部 |
| 数据集目录 | `ashare.data.catalog` | 每个数据集一条声明：来自哪个源的哪个接口、分区方式、主键、字段和原始单位、行数上限、重抓窗口 | 数据层内部 |
| 源适配 | `ashare.data.sources` | 每个数据源一个模块，接口相同；限速、重试、翻页、密钥、错误分类只在这里 | 数据层内部；模拟盘的实时行情复用其中的 Tushare 客户端 |

```python
import ashare.data as ad

ds = ad.open()                                   # 数据根目录：ASHARE_DATA_DIR，默认是仓库下的 data/
p = ds.panel(["close", "adj_factor", "volume", "is_suspended"], start="2015-01-05")
p.dates, p.symbols, p["close"]                   # T×N 只读内存映射，可以直接交给 panelbt
ds.table("income", start="2015-01-01")           # 长表（财务、事件），polars LazyFrame
ds.calendar(); ds.securities(); ds.field("close")
ds.version                                       # 进因子缓存和试验账本的键
```

接到回测和风险模型的转接只有两处，都在 `ashare` 里：

```python
from ashare.backtest import market_from_panel
bm = market_from_panel(ds, start="2015-01-05", exec="open", fields=["adj_factor"])
bm.market, bm.config(initial_cash=1e7), bm.costs(commission_rate=2.5e-4)

from ashare.risk import from_panel
source, config = from_panel(ds, start="2023-06-01")   # 交给 model_series
```

- `market_from_panel`：成交价 `exec` 取 `open`（默认，直接用面板的 `can_buy_open`/`can_sell_open`）、`close` 或 `vwap`（按同一条涨跌停、一字板、停牌规则现算）；`split`、`cash_dividend` 的「缺失 = 无事件」换成 1 和 0；板块取证券表的板块列，为空时按代码前缀推断（如 `T600018.SH`），都认不出就报错列出证券；`delist` 原样交给引擎。
- `from_panel`：`total_market_cap`/`float_market_cap`/`turnover` 改名为风险模型的 `total_mv`/`circ_mv`/`turnover_rate`；区间里出现过的申万一级代码按升序编成 0..K−1，行业因子用申万名称命名（`industry_银行`，代码两版都有时取 SW2021 名称）。

- 数据层以外的代码不出现 Tushare 的接口名、字段名、原始单位和文件路径。
- 同一个 Tushare 账号的限速和「单 IP」规则由同一个客户端管，历史采集和模拟盘的实时轮询共用它。
- 换数据源或加数据源（BaoStock 核对、以后的港股美股）只加一个源适配模块和几条数据集声明，读取接口不变。
- **现在不拆成独立的包**：它是 A 股和 Tushare 专用的胶水代码，字段会随研究频繁变动，也不是性能内核，单独发版只会多出版本对齐的成本。`sources` 不依赖 `ashare` 的其他模块（只用 httpx、polars 和标准库），以后要拆随时可以拆。

- **采集**：httpx 异步客户端，令牌桶限速，识别限频错误后退避重试，按接口和分区断点续传。原始响应原样存成 Parquet，字段保留 Tushare 原名，记录抓取时间。
- **范围**：2007-01-01 至今（涨跌停价从 2007 年才有）。
- **数据集**：交易日历；证券列表（含退市）；日线；复权因子；每日指标（市值、换手、估值、股息率）；涨跌停价；停复牌；ST 名单与曾用名；指数成分权重；基准指数日线（主流指数名单 `BENCHMARKS`，默认上证指数，见 `docs/DATA_NOTES.md`「基准指数」）；申万行业成分（含历史）；三张报表与财务指标；业绩预告与快报；分红送转；之后再加增减持、回购、研报预测。
- **面板构建**：主日历 × 主证券表，把长表转成稠密矩阵落盘，附一份元数据（日历、证券表、数据版本）。
- **公司行为**：`split`、`cash_dividend` 以复权因子为准对账，`action_source` 记每格的来源：0 无事件，1 分红表原样，2 经济去重、候选裁决或日期对齐后，3 按因子合成（等效参考价再投资，不扣红利税、没有现金流），4 分红表事件被否决（因子没变），5 差异化分红。5 记的是持有人实得的公告值；回购专户股份不参与分配，交易所按摊薄比例 k 算参考价，所以按复权因子算的收益比按面板事件算的低 `(1 − k)` 乘以分配比例；`panelbt` 按面板事件记账。k 的下限默认 0.85，与对账容差一样进入数据版本。
- **时点财务**：每条记录按「实际公告日的下一个交易日」生效，保留所有版本，构建面板时按当天可见的最新版本取值。
- **校验**：与 BaoStock 抽样核对价格、ST、停牌；检查不变量（复权价连续、涨跌停价与规则公式的一致率、停牌日无成交）；输出覆盖率报告。

已知缺口：指数权重只有月末快照；中证 1000 从 2014-10 起、中证 2000 从 2023-08 起才有成分；财务更正的历史版本不完整；没有现成的一致预期，只有逐篇研报的预测。

#### 6.1.1 境内期货（全部交易所，2026-11-13 第 1 批）

给纯期货回测（趋势、期限结构、跨品种）和石油研究项目用。口径、校验结果和已知问题见 `docs/FUTURES_DATA.md`。

- **统一字段**（`ashare.data.futures_schema`）：与来源无关的几张表——合约表、日线、逐日结算参数（保证金、按金额和按手的开仓 / 平昨 / 平今手续费、交割费、涨跌停幅度）、交易所日历，可选的来源主力映射和**合约乘数分段表**（`multipliers`：合约 × 生效日 → 乘数、来源、依据）。合约标识写成「品种 + 四位年月 + . + 交易所全称」（`SC2612.INE`、`TA2611.CZCE`）。一个来源的适配器只要交出这几张表（`conform` 检查必填列），面板、连续合约、校验都不用改；Tushare 的代码、字段名和单位只出现在 `futures_tushare.py`。境外期货（WTI、布伦特）以后用 Databento / Bloomberg 适配器接入同一套字段。
  - 统一字段里的日线、参数、映射都只在合约上市期内，并且对得上合约表；源代码对不上的（郑商所年份补错、交易所后缀写错）由适配器按「当天上市且唯一」找回，找不回的计数并逐条进校验，不静默丢弃。
  - 合约乘数按日期取值：来源优先级是成交额反查 → 人工修正表（每行写依据，推断的标「未核实」）→ 合约表现值。
  - 价格为 0、负手续费、整交易所整天为 0 的手续费都是源错误或源的写法，统一字段置空，不当作真值。
- **原始库**：五个数据集 `futures_calendar`、`futures_contracts`（按交易所分区）、`futures_daily`、`futures_mapping`、`futures_settle`（按交易日分区，交易日取六个期货交易所日历的并集）。沿用股票的存储、清单、断点续跑和按接口限速，日分区有同样的刷新保护（重抓返回空表或行数骤降时保留旧修订）。期货数据集登记在 `FUTURES_DATASETS`，**不并入 `DATASETS`**：股票的同步计划、状态、校验、内容版本只看 `DATASETS`，与期货共用一份清单时股票侧输出逐位不变；期货有自己的内容版本 `Store.futures_version` 和校验。中金所对冲腿原有的 `fut_basic`、`fut_daily` 不动。命令：`python -m ashare.data --root <根> sync-futures`、`build-futures`、`verify-futures`。
- **面板**：「交易日 × 合约」，存储写法与股票面板相同（代次目录 + `current.json`），但按「交易所_品种」分块，每块只覆盖该品种合约存续的日子（全历史一万多个合约存成一个稠密矩阵每字段约 1 GB 且几乎全空）。字段含按日的 `multiplier`。读取入口 `ashare.data.open(root).futures()`：`panel`、`contracts`、`calendar`、`table`、`continuous`、`roll_schedule`；`futures_panelbt.panelbt_inputs` 直接给出 `panelbt.Market` 和 `panelbt.Futures` 的输入：参数只向前填补、不用以后的值回填，缺值由调用方用 `missing` 显式给；区间内改过交易单位的合约默认报错，可选在分界日拆列（返回 `splits` 列出同一合约的前后两列和分界日，供调用方挪仓）。
- **连续合约**：换月规则三种（来源映射、按持仓量、按成交量；后两种只用前一交易日的数据，粘住、只向后、严格大于才换），主力和次主力；复权三种（不调整、差值后复权、比例后复权）；另给换月日程表。连续价格只用于信号，回测按合约逐个持有。
- **校验**（`futures_verify`，原始库部分与同步、适配器不共用代码）：每项判 pass / explained / fail，「已解释」只认已知例外清单（`futures_known_exceptions.json`，逐条写合约、日期、原因）里的条目，清单外的不符一律 fail，命令行以非零状态退出。清单只放匹配键和原因（不放由行情算出的数值，测试按白名单核对键集合）；「不符已确认、原因未查明」的原因单列在 `cause_unknown`，报告里单独计数。检查项：清单对文件、日分区覆盖与截断、主键唯一、日历对照与「休市日有日线」、合约覆盖、前结算连续、日线取值范围（价格为正、最高 ≥ 最低等）、结算参数取值范围、整天零手续费、单双边奇偶（含单边以后的双边复发）、合约表单位对成交额、代码对齐、按日乘数逐行核对成交额；面板部分（不允许例外）：统一参数取值范围、引用完整性。
- 只做日频；分钟线、涨跌停幅度（Tushare 没有，以后取交易所每日交易参数文件）、交割结算价（商品期货）不在这一批。

- **分钟线**：统一字段新增分钟线表（`futures_foreign.MINUTE`：K 线开始时刻 UTC、所属交易日、合约、开高低收、成交量），暂时定义在 `futures_foreign` 里；境内以后加分钟线时挪进 `futures_schema`。

- **完整性**：结算价缺失不往下传（整个品种没有结算价总是报错；有成交的合约日缺结算价默认报错，`require_settlement=False` 放行）；Bloomberg 的 `fieldExceptions`、合约表必需字段缺失都报错，不回退到品种表。负价格按真实值保留，`ratio` 复权遇到非正价格报错（改用 `difference`）。

#### 6.1.3 港股、美股（第 2 批）

口径、权限实测、校验结果、已知问题和全历史估算见 `docs/HKUS_DATA.md`。**美股面板是试验性的**（价格收益加拆并股，不含现金分红；正式回测还缺分红来源和退市原因）。**两地面板都是事后清洗过的数据，不是严格的时点数据**：事件执不执行、是否拆列、`delist` 都可能用到以后的数据（截断不变性测试守住的例外清单见 `LOOKAHEAD_FIELDS`）。

- **按市场分目录**：`Store(root, "hk")`、`Store(root, "us")` 写在 `<root>/hk`、`<root>/us`，各有一份清单，与 A 股的 `<root>/cn` 互不相干；数据集登记在 `OVERSEAS_DATASETS`（不并入 `DATASETS`）。A 股侧同步计划、状态、校验、内容版本与面板版本在同一个根下加入港美股前后逐位相同；A 股、期货子命令和 `reader.Data` 拒绝 `hk`、`us`。
- **原始库**：日历、证券表、日线与复权因子（按交易日，全部证券）、样本的按证券历史（2010 年起）、港股通名单与南向持股（港股）、汇率（FXCM 日线和人民币中间价，读取时给出可用时刻）。原始字段保留源名。两地复权因子都是前复权快照，因子数据集每次同步整段重抓并记同一个快照编号，构建要求快照唯一；正式同步前改为「新日子与旧值比较，有变化的证券单独重抓」。
- **面板**：两套代次 `all`（按交易日的全部证券）与 `sample`（2010 年起按当前市值分层抽的 200 只，有幸存者偏差，只用于开发抽查）。美股只放三大交易所的普通股与存托凭证（因子表交易所判断，含已退市的），长缺口或可疑事件处价格不连续的列拆成 `代码#2`：旧列从新列开始那天起不再上市并在那天退市，按 min(停牌前收盘, 复牌收盘 × 缺口里执行了的倍数) 偏悲观地清算（`delist_recovery`）。没有执行了的事件、价格上跳超过 3 倍而成交股数没有放大（≤ 前 10 个成交日中位数 1.5 倍，基准各天的股数按其后执行了的拆并股换算成跳变日的单位；不看成交额，它会随当天活跃度放大）的（疑似源漏记的合股），也按同样办法拆列；阈值是模块常量、进版本键。同一代码几条交易所因子序列时，每天取开始日最早的、再按纽交所、纳斯达克、美交所，不看序列哪天结束；行情从第一次有三大交易所因子起取到日线自身的范围；当天有成交却没有三大交易所因子的格不可交易（行情留作参考），还在上市时连续 5 个这样的成交日在第 5 个那天退市，按与拆段相同的口径清算，因子恢复就恢复可交易。字段与 A 股同名同义，另有 `adj_factor`（只累乘执行了的事件）、`split`、`equivalent_cash`、`action_source`、`action_suspect`、`action_check`（印证方式）、`has_quote`、`tradable`、`is_listed`、`delist`（美股只用当时可知的信息），港股另有港股通四个字段（南向持股错位一天）和 `price_rounded`，美股另有 `total_market_cap`。读取入口 `ashare.data.open(root, market="hk"|"us", universe=...)`。版本键含全部输入内容、样本名单、四个模块的源码和常量。
- **公司行为**（`overseas_actions`）：源没有事件明细，由相邻因子比推出，同一停牌窗口的事件合起来印证：港股先看交易所前收（前收 / 上一收盘与 1/R 相对差 ≤ 0.5%，合计比值 ≥ 1.25 倍的窗口 1%，再放宽半个价位），对不上或缺失再看价格；美股看价格（开盘或收盘，只靠收盘的逐格记出来）。印证不了的、最后一次成交之后的不执行并逐格标记。执行的：整数比拆并股；分不出现金与股数的，小比值（r < 1.10）港股按等效现金（参考价随同窗口前面的事件换算）、美股不执行，大比值按股数调整（不扣税）；美股合计比值不到 1.25 倍的窗口里非整数的股数调整还要开盘价走到一半以上（只认开盘），否则不执行。
- **校验**（`overseas_verify`，与同步、构建不共用代码）：沿用 6.1.1 的 pass / explained / fail 与例外清单写法，面板部分不允许例外，按字段定义独立核对公司行为（持有者价值不变式、因子账目、字段约束、港股前收印证了却没执行、缺口之后和没有上一成交日的等效现金）、美股可交易必须当天有因子、相邻可交易日价格跳出 [1/3, 3] 而无事件解释的：交易明显放大（上跳看成交股数、下跳看成交额，达到前 10 日中位数 5 倍）的算真实行情，其余必须按代码和日期逐条登记（不许整类豁免），疑似漏记合股的上跳必须已拆列、上市退市（含拆段两列不重叠、无因子退市、清算回收率）、港股通字段；港股前收每对相邻交易日都核；坏数据不让校验崩溃。
- 不在这一批：全历史正式同步、历史每手、卖空名单、分红明细、分钟线。

#### 6.1.5 筹码（D3，2026-11-15 用户定）

用户要把筹码数据接进来做 alpha。Tushare `cyq_perf`（每日筹码及胜率）从 2018-01-02 起，原始字段有 `his_low/his_high`、5/15/50/85/95 分位成本、加权平均成本、胜率（%）。2026-11-16 独立全量复核覆盖 9,786,688 行、2,150 个交易日，结论及分层数字见 `docs/D3_NOTES.md`。

- **当前只接原始数据，不发布任何 `chip_*` 字段**。`his_low/his_high` 不是截至当日上市以来的历史极值，原来用它们核实复权基准的判据作废；第 7 节 D3 行中该项旧判据由本节修订取代。源边界可能来自算法价格范围或网格，但尚不能解释为当日非零筹码分布的支撑边界，不能靠放宽误差阈值通过验收。
- **候选分母与尚未证明的基准**：`close_t × adj_t / adj_F` 是目前证据最支持的分母，其中本地候选 `adj_F` 取各分区 `_fetched_at` 当时最新有效因子。4,910 对因子增加超过 5% 的相邻交易日，中位成本比值的 `100 × |Δln R|` 中位数为 1.794，不复权分母为 31.994。但固定 `adj_F` 在时间差分中完全抵消，连续性无法识别整段常数倍偏差，也不能证明源实际采用抓取日基准。
  - 获得充分证据后，拟建 `chip_cost_05/15/50/85/95`、`chip_avg_cost` = 对应成本 ÷ 同基准收盘；`chip_winner` = 胜率 / 100。均为无量纲、收盘后可知，2018-01-02 前缺失。这是待验收设计，尚未登记或发布。
  - 成本有网格离散，部分低价股约 0.1 元一格；网格量化须经分布核对，不能解释所有偏差。胜率与中位成本方向矛盾 19,046 条，600165.SH 等存在整段尺度偏差；2026-05-21 有 1,405 只股票边界收缩。另有胜率 >100 的 7,286 条、非正成本 138 条，需明确异常隔离规则，不能直接发布胜率字段。
- **发布前证据**：少量正常和异常证券的 `cyq_chips` 分布、特殊公司行为处理口径，以及跨实际除权的同一证券日两份抓取快照。须解释尺度偏差并证明跨抓取基准换算后的比值不变；现有 54,079 条重合记录的 9 个数值字段完全一致，但没有覆盖不同基准，不能替代该证明。未满足前继续停留在原始层。本轮不联网，不下载全历史分布。
- **同步与版本**：`cyq_perf` 进股票数据集，按交易日分区，`coverage_start=20180102`。每晚同步任务自动增量抓；面板重建后版本变化。
- **刷新**：源可能重算历史，保留不可变快照；只替换内容哈希变化的分区。未来换算须按各分区自己的 `_fetched_at` 找候选因子，跨真实除权快照不变性仍待证，不能仅以合成测试宣称成立。
- **平台**：证据满足、字段验收后再登记字段表和 `guide`；当前没有筹码字段入口。

### 6.2 因子与检验

- 因子用算子组合定义，登记名字、所需字段和说明；结果按「定义的哈希 + 数据版本」缓存。
- 第一批：市值、短期反转、动量、波动率、换手率、估值（EP、BP）、股息率，以及 Alpha158 的量价部分。
- 单因子报告：IC 与 ICIR、分组收益、**多头组扣成本后相对基准的超额**（调用 panelbt）、换手、分年度、分市值段、与已有因子的相关性。评价以多头端为准，因为做不了空。
- 算子精度：滑动求和一族（`ts_sum`、`ts_mean`、`ts_sumif`）在退化窗口上给精确值（窗口有效值全为 0 时恰为正零，全相等时均值恰为该值）；窗口不超过 3 行时逐窗口直接求和并正确舍入，结果只取决于窗口内容；更长的窗口默认仍是增量算法，最后一位可能随窗口之外的历史变化。逐格核对因子、或因子里拿两个窗口和比相等（例如对窗口和求相关）时用 `exact=True`：每格是窗口内数值的正确舍入和（均值是这个和除以个数），与顺序和历史无关，代价约为默认的 8–17 倍，窗口到 20 行后不再随窗口变长。细节与测量见 `docs/PANELOPS_BENCHMARKS.md`「滑动求和的退化窗口与历史无关」。

#### 6.2.1 外部因子包

三套公开的公式型因子（Qlib Alpha158、WorldQuant Alpha101、国泰君安 191）随仓库提供，在 `ashare.factor.alphas`：逐条翻译、独立参考实现、约定文件和核对结果（文档在 `docs/factors/`，原文出处与许可见 `docs/factors/sources/README.md`），作为内置因子集注册（2026-11-14 起公开，此前放在本地私有包）。别的成套因子仍可写成单独的 Python 包，经入口点组 `ashare.factors` 挂上来。机制在 `ashare.factor.formula`：

- `dsl`：WorldQuant 式、国君式公式的翻译用语言（口径集中在这一个文件）；`qlib`：Qlib 表达式字符串到 `Expr` 的确定性转换；`ops`：用现有算子精确组合出的算子。
- `registry_from_module(模块, 前缀, 条数, notes=..., excluded=...)`：从「一个函数一条因子」的模块构造注册表，按名字挂元数据标记 `notes`（`(标记, 编号)`），`registry.with_note(标记)` 筛选。
- `inputs`：取数（`load_inputs`）与参考实现的输入（`reference_frames`）；`verify`：候选对独立参考实现逐格核对，支持「已知例外」（`KnownException`：只对条件成立、按正常规则不过关、候选恰为声明值的格子生效，单独计数）。
- `plugins`：`discover()` 列出全部因子集，`load_registry(名字, **选项)` 取注册表。内置的有示例集 `example`（两条自编因子和它们的参考实现）和 `alpha158`、`alpha101`、`gtja191`。

外部包的最小写法：

```toml
# 外部包的 pyproject.toml
[project]
name = "my_factors"
version = "0.1"
dependencies = ["ashare"]

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project.entry-points."ashare.factors"]
my_factors = "my_factors.plugin:register"
```

```python
# my_factors/plugin.py
from ashare.factor.formula import FactorSet, dsl as d
from ashare.factor.library import Registry


def build(window="7"):
    registry = Registry()
    registry.register(
        "my_range", d.ts_mean(d.high - d.low, int(window)), "mean(high - low, window)",
        notes=[("自编", "M-1")],
    )
    return registry


def register(hub):
    hub.add(FactorSet("mine", build, reference="my_factors.reference", options=("window",)))
```

```python
# my_factors/reference.py：独立参考实现（pandas），选项以字符串原样传入
def my_range(frames, window="7"):
    return (frames["high"] - frames["low"]).rolling(int(window)).mean()


REFERENCES = {"my_range": my_range}
```

装进同一个环境（`uv pip install -e 路径`）后：`load_registry("mine", window="9")` 取注册表，`python -m ashare.factor.formula.verify mine --option window=9` 核对。约定：

- `register(hub)` 只有一个参数；入口点导入失败、`register` 报错、两个包登记同名因子集，都会直接报错并指明入口点，不静默跳过。
- `FactorSet` 的 `build(**选项)` 返回 `Registry`，只接受 `options` 里声明的选项（命令行传进来的值是字符串）；`reference` 是参考实现模块（`REFERENCES = {名字: 函数}` 或 `compute_many(frames, names, **选项)`），选项同样传给它；参考实现只有时序运算时可以给 `chunk`（按证券分块并行）；`exceptions = {因子名: (KnownException, ...)}`。
- 参考实现要独立：照约定文件自己写 pandas，不调用 `ashare.factor` 的表达式和 `panelops`。
- 外部包的测试可以用 `ashare.factor.formula.testing.synthetic_source` 造合成面板。

#### 6.2.2 单因子评估与因子挖掘（`ashare.factor.evaluate`、`ashare.factor.stats`、`ashare.factor.mining`）

本仓库只放机制：评估、搜索器、台账、统计检验和用自编玩具表达式写的例子。挖出来的任何因子、试验记录、台账文件都不进仓库，台账默认写到数据根目录下不入库的 `mining/`（`ASHARE_MINING_DIR` 或 `root=` 可指到私有仓库）。口径、出处、模拟与性能见 `docs/MINING_NOTES.md`。

- **单因子评估**（`FactorEvaluator`、`evaluate_factor`）：收益标签用 `ashare.labels`（不依赖 ml 依赖组，`ashare.ml.labels` 从这里转出；t+1 按 `exec` 成交价买、t+1+h 卖，买入日不可买的样本不进 IC），Rank IC 多个持有期（默认 1、5、20），t 值取重叠持有期下均值方差的上界 s²·h/n、自由度为不重叠的块数减一，不重叠的块少于 10 个时不给 p 值；分组收益与单调性；**多头端**为准：前 10%（或前 N 只）等权、在固定的调仓日表（第 0、5、10…行）上调仓，T 日收盘出信号、`execution_targets` 错到 T+1 成交，`panelbt.run_batch` 一次跑一批；默认基准是同一套成交机制（同样的调仓日、成交错位、可交易规则、费用）持有信号日股票池全体等权，零假设下超额才接近 0（旧的「收盘到收盘」基准留作 `benchmark="close"` 对照）；默认初始资金 100 亿元（`capital=`），让最低佣金在持有全体的基准上不起作用，小账户下基准多扣成本、超额偏正；从第一次成交起算超额、信息比率、夏普、回撤、换手、成本，以及超额日序列的方差比（序列相关，Bartlett 默认 20 阶）；分年度、分市值段、因子自相关、与已有因子的截面秩相关。段（训练、验证……）内的 IC 只用标签完整落在段内的信号日。`to_dict()` 只含基本类型，`text()` 给终端。
- **统计检验**（`ashare.factor.stats`，不依赖搜索器）：概率夏普、折算夏普（Bailey & López de Prado 2012/2014，可按方差比修正序列相关，Lo 2002）、Bonferroni / Holm / Benjamini–Hochberg / Benjamini–Yekutieli、CSCV 回测过拟合概率（Bailey 等 2017）、有效试验数（平均相关、Nyholt、Li–Ji）、HAC t 值、重叠持有期的保守 t 值。
- **搜索空间**（`Space`）：用户声明字段（带量纲）、算子与参数取值、最大深度与节点数、截面算子位置；量纲规则在生成时排除价格加成交量这类组合，根节点要求无量纲，截面算子的参数默认也要求无量纲（价格、成交量水平的截面排名不作候选，`allow_level_ranks=True` 放开）；去重键：可交换算子排序、`ts_corr` 按对称处理、非负量上的 `abs` 去掉、根上的截面单调变换剥掉。
- **策略**：`Enumerate`（穷举）、`Random`（随机采样）、`Evolution`（变异、交叉、锦标赛、(μ+λ) 截断），同一接口 `run(space, evaluate)`，全部确定性（种子决定，与线程数无关）。
- **大模型研究循环**（`ashare.factor.mining.llm.LLMResearch`，第四种策略，同一接口）：参考微软 RD-Agent 的「假设 → 因子 → 评估反馈 → 笔记」循环，在本框架里重写、不依赖它。模型只写本仓库的表达式语言，每个表达式评估前按空间校验（不合法的不评估、不算试验，错误反馈给模型），跨轮按去重键去重；只有训练段的适应度与训练段指标（经 `mine` 的只读入口 `evaluate.train_feedback` 和策略侧白名单）进入提示词，不含日期；按轮数、费用或 token 预算、连续无效轮数停止；模板哈希进 `describe()`；每轮写转写记录到台账目录下的 `llm/`（私有，不许写进仓库）。默认接 DeepSeek 官方接口（OpenAI 兼容、只用 httpx、密钥读 `DEEPSEEK_API_KEY`）。不是确定性的。说明见 `docs/LLM_MINING.md`。
- **搜索**（`mine`）：`split`（`Split`）必填；搜索只在截掉留出段的面板视图（`Truncated`）上进行，训练段算适应度（默认多头端超额的信息比率，可换、可加复杂度惩罚），验证段只用来挑选；两段式（训练段 IC 的 t 值过门槛才回测，筛掉的照样记账）；数值去重（与已入选因子的截面秩相关 ≥ 0.9 标为重复，照样计入试验数）；断点续跑（从台账接着跑，结果与一次跑完相同）；留出段只能 `unlock_holdout` 显式解锁一次，解锁记进台账。
- **GPU 粗筛**（`ashare.factor.mining.gpu`，可选依赖 `gpu`，`mine(screen="gpu")`）：两阶段，GPU（MLX，Metal 或 CUDA，内核正文同一份）按 float32 整代粗筛，只决定送不送 CPU；GPU t 值不低于 min(screen_t, z₁₋α) − 0.3 的、GPU 算不了的（不支持的算子、超出 float32 安全范围、排序主要由舍入决定）送 CPU 按 float64 复算并照常判定，进台账、统计检验和结果的数字全部来自 CPU；没送的记一次阶段为 `gpu_screen`、不带指标的试验。默认 `screen="cpu"` 与原做法逐位相同；GPU 不可用时报错不退回。说明与测量见 `docs/GPU_MINING.md`。
- **台账**：`ashare.ledger.Ledger`（与 `ashare.ml` 共用，同一 JSONL 格式、文件锁、失败也留痕，末尾是半行时先补换行、读时跳过坏行）；`trial_id` = 去重键 + 数据版本 + 评估定义（含成交价、基准口径、费用），不含搜索策略和粗筛门槛，同一候选在不同搜索里只算一次；复用时按这次的门槛重判，过了的才复用回测结果，没过的降回粗筛结果（仍是一次试验）；`Ledger.trials()` 跨搜索、跨手工（`record_trial`）累计。折算夏普的试验数用台账累计数；IC 的 Holm / BH / BY 把之前的试验补成无效检验占分母。留出段只能解锁一次是纪律而不是技术锁（换台账即可再解锁），台账只负责留下看过的记录。
- **折算夏普的方差 V**：默认取零假设下单个夏普估计量的方差 q/(T−1)，q 是该候选超额日序列的方差比（`autocorr=False` 时 q = 1）；原文的「各试验夏普的截面方差」在候选池里有真信号时被撑大、几乎什么都过不了（模拟见 MINING_NOTES），作为 `sr_var="empirical"` 保留，`"max"` 两者取大。

### 6.3 合成、组合与研究纪律

- 滚动训练：按时间切分，训练集和测试集之间留隔离期；LightGBM；各折并行。
- 组合：前 N 等权；或用 `ashare.portfolio` 约束相对基准的行业和市值偏离、个股上限、换手（6.4）。
- 纪律：先写假设和判定规则再跑；每个试验记账；最近两年的数据留作最终检验；用试验次数折算显著性。统计检验从 Quant 项目移植。

### 6.4 风险模型与组合优化

**风险模型 `ashare.risk`**，两种实现，对外是同一个形状：某一天的暴露矩阵 B（N × K）、因子协方差 F（K × K）、特质方差 D（长度 N）。组合方差按 `‖F^½ Bᵀ w‖² + wᵀ D w` 算，任何地方都不展开成 N × N 的稠密矩阵。

- **统计型**（先做，当基线和对照）：指数加权的样本协方差加 Ledoit–Wolf 收缩，以及主成分因子模型。只需要收益率。
- **基本面因子型**（Barra 式）：国家因子 + 申万一级行业 + 风格因子。每天做一次截面加权回归得到因子收益（权重取市值的平方根，行业因子收益按市值加权和为零）；因子协方差用指数加权加 Newey–West 调整；特质风险用指数加权、对历史短的股票用结构化估计并做收缩。第一期的风格只用行情和每日指标能算的：市值、贝塔、动量、残差波动、非线性市值、流动性、账面市值比、盈利市值比；成长、杠杆等要等时点财务数据。
- **时点**：第 t 天的模型只用第 t 天收盘前已知的数据；暴露用第 t 天的值解释第 t+1 天的收益。
- **检验**：在已知因子结构的合成数据上要能还原参数；用偏差统计量（预测波动与实现波动之比）检验预测是否准确，两种模型互相对照。

**组合优化 `ashare.portfolio`**：不自己写求解器。实测后的默认路径（`backend="auto"`）是把问题换成标准锥形式、直接调 Clarabel 的 Python 接口，同结构的问题复用；Clarabel 报数值失败时退到 cvxpy + Clarabel 重解。`backend="rust"` 走 `portopt`（Rust 里调 Clarabel，可批量并行），`backend="osqp"` 和 `backend="cvxpy_*"` 留作对照和参考实现，不在默认路径上。

- 接真实面板：`ashare.risk.from_panel(data, start=...)` 返回交给 `model_series` 的 `(source, config)`（见 6.1）。`PortfolioProblem` 的 `industry_factors`、`style_factors` 可以给因子列号，也可以给因子名（`"industry_银行"`、`"size"`，可混用），风格因子名的全集是 `ashare.risk.STYLE_NAMES`。

- 目标：预期收益 − 风险厌恶 × 主动风险 − 交易成本。
- 约束：满仓或留现金比例、只做多和个股上限、相对基准的个股 / 行业 / 风格偏离上限、换手上限、跟踪误差上限；停牌和涨跌停买卖不了的股票权重冻结。
- 无解时按事先定好的顺序放松约束并记录，不静默返回一个不满足约束的解。
- 每次求解后都核对约束是否满足；结果与第二个求解器对拍。
- 输出目标权重，按 `panelbt.Targets` 的稀疏布局交给回测。

### 6.5 归因与容量（`ashare.analysis`）

回测之后回答三个问题：收益从哪来、风险押在哪、能装多少钱。输出一律是普通数据对象
（`Table`：数组 + 行名 + 列名，可转列式 dict 和 pandas 表），以后由报告模块 `ashare.report`
作为可选小节接入。细节、口径和验证记录见 `docs/ANALYSIS_NOTES.md`。

- **时间约定**：`weights[t]` 是第 t 日收盘后的权重，赚第 t+1 日的收益；风险模型 `B_t` 解释
  `r_{t+1}`。第 t 日的归因一律用 t-1 收盘的持仓、暴露、行业分类和基准权重。
- **收益与估值**：个股收益 = 后复权价（close × adj_factor 作为整体沿用最近有效值）之比，停牌期间
  含停牌中除权都为 0；持仓估值与 panelbt 相同，缺价时用最近收盘价逐次除权的参考价。
- **接主干**：行情、账户规则、费用表、信号错位用 `ashare.backtest`，风险模型输入用
  `ashare.risk.risk_inputs`；本包的 `adapters` 只在「只有面板、没有数据句柄」时转发。
- **收益归因** `attribute`：主动收益 = 市场 + 行业 + 风格 + 特质 + 交易 + 成本，逐日恒等。
  因子收益由 `FactorHistory` 在遍历 `model_series` 时按风险模型自己的截面回归补算（同一内核、
  同一估计池，逐位一致）；全市场暴露放不下内存，只保存组合与基准出现过的证券。
  多期链接默认 GRAP（不取对数、无奇点、递推一次得到逐日累计值），可选 Carino。
- **风险归因** `decompose_risk` / `risk_series`：Euler 拆分到因子与特质，给边际贡献和占比；
  逐日预测与次日实现比较（偏差统计量，区间默认用 20 日块自助法）。
- **Brinson** `brinson`：按申万一级行业，Brinson-Fachler 为默认、BHB 可选；现金单列一个行业。
- **容量** `capacity`：冲击模型与 `panelbt` 同口径（`impact_k·(q/V)^e`，默认 e=0.5、k=系数×此前日波动率）。
  解析模拟按股数记现金账户，规则与 panelbt 相同但不取整、不设成交量上限，毫秒级，可在规模上
  求两种容量（成本吃掉一半毛超额，取成本曲线上升段的交点，下降段的交点另报为最小可行规模；
  超过 10% 成交量占比的成交额超过 5%），求不到时给 NaN/inf 和状态，不拿搜索边界充数；`rerun=True`
  对每个规模真跑 `panelbt.run_batch`（同宽松规则用来对账、真实 A 股规则看实际净值）。
- **成本拆解** `cost_breakdown`：按年列佣金、印花税、其他费用、滑点、冲击、融券费、红利税、融资利息
  和换手（双边，与报告一致）。
- **性能**：先用 NumPy 向量化；十五年全市场逐日归因的数值部分在秒级以内，主要时间在生成风险模型本身，
  暂不写 Rust 内核（对比数字见 `docs/ANALYSIS_NOTES.md`）。

### 6.6 事件驱动（`ashare.events`）

截面因子之外的另一类策略：信号是「某只股票在某天发生了某件事」。提供四样东西：事件表、内置事件提取、事件转目标持仓、事件研究。细节、真实例子和变异清单见 `docs/EVENTS_NOTES.md`。

- **事件表**：polars 表，必需列 `symbol`、`date`（公告日历日 YYYYMMDD）、`kind`、`timing`，其余是数值字段。`timing` 默认 `after_close`：公告日只到天，按收盘后才可知处理，最早在公告日之后的第一个交易日成交；`pre_open` 表示公告日开盘前已知。公告日不是交易日时顺延。按类型覆盖用 `with_timing`。对齐后的「可成交日」`avail` 是事件研究的第 0 天、事件转持仓的起点。错位用公共的 `ashare.backtest.timing.execution_days`（信号日 + 1，末尾丢弃）。
- **内置事件**：业绩预告（首次与修正按同一条规则区分）、业绩快报（相对上年同期与相对最近一次预告的超预期）、分红（年报期的预案日用年报公告日近似，其他报告期用股东大会决议日；另有决议日、实施公告日两种进度）、指数成分调整（沪深 300、中证 500、中证 1000；只有月末快照，只能用生效之后的快照日，推不出公告日）。快报、分红走公共的 `Data.table`；预告、利润表、指数权重的部分列数据层尚未公开，经数据层内部接口读原始表，源字段名只出现在 `extract.py`。
- **事件转目标**：可成交日 + `entry_lag` 开盘买入，持有 `holding` 个交易日；买不进时放弃或顺延至多 `defer` 天；重叠时延长、忽略或叠加；权重等权、按数值或每份固定；持仓数上限、单只上限。只在持仓集合变化的日子写一行 `panelbt.Targets`。所有决定按时间顺序只用当时已知的信息：名额在决策日占用、不看之后能否买到，给了可卖掩码时在实际卖出日释放；按数值加权时延长事件只改它之后的权重。名额不够时按 `priority`，再相同时按只由事件自身决定的固定哈希，不按代码顺序。
- **事件研究**：异常收益 = 个股收益 − 基准（指数，或同行业 × 市值分位组的留一等权组合，或调用方给的 T×N 预期收益，例如风险模型的因子部分）；基准缺失不当 0，窗口不完整和上市不足的事件默认剔除并计数，退市后的格子记 0；同股同日同类事件合并。**首选的显著性口径是日历时间组合检验**（每个交易日等权持有窗口内的事件，对组合日超额做 Newey–West t）；另并排给出朴素 t、按月聚类（可选按日、按季度）的标准误和按聚类整块重抽的自助法，聚类少于 30 个时警告。事件数按年、事件前走势、开盘可买与买不进（涨停、停牌）分开统计。风险模型的特质收益尚无公开接口，留待接入。

### 6.7 回测报告（`ashare.report`）

一次回测出一份报告数据（`build_tearsheet`，口径见 `docs/REPORT_NOTES.md`），同一份数据有两种看法：自包含的 HTML 页面（给人看），以及给终端和 AI 代理看的文本版。

- **文本版**：`Tearsheet.text(sections, fmt, lang, start, end)`、`print(tearsheet)`，命令行 `python -m ashare.report show / html`，报告数据用 `save_json` / `load` 存取。默认摘要一屏（40 行内），其余按小节取；`text`（等宽、行宽 ≤ 100 列、中文按两列）、`markdown`、`json` 三种格式；`--lang en` 表头用 JSON 键名。文本版不另算指标：每个数取自报告数据，格式与页面相同；自选区间的指标用页面「切换区间」的同一套公式（Python 逐行照搬页面的 JS，测试里用 node 跑页面那段 JS 对拍）。
- **提醒**：把看图能看出、只读数字容易漏的问题（基准不含分红、首末月年不完整、未成交多、现金高、持仓不足、回撤未修复、历史太短等）按保守阈值写成带数字的句子。
- **补充内容**：对比指数、胜率（按年、滚动 1/3/5 年）、个股贡献（用持仓和价格重建，与引擎的 `result.contribution` 和权益恒等式核对）、收益分布与尾部、集中度；`compare()` 把几份报告放在共同区间上并排。这些只进数据层和文本版，页面先出设计稿、经用户选定后再改；在那之前不嵌入页面，HTML 逐字节不变。

### 6.8 资产配置（`ashare.allocation`）

几个到几十个大类资产怎么分配权重，口径与结果见 `docs/ALLOCATION_NOTES.md`。

- **方法**：固定权重（配再平衡带）、等权、倒波动、带预算的风险平价、目标波动叠加（杠杆上限）、最小方差与均值方差（经 `ashare.portfolio`）、趋势过滤叠加；协方差复用 `ashare.risk` 的收缩估计。
- **时点**：调仓行就是成交行，第 t 个调仓日只用 t−1 日收盘及以前的收益；月度调仓与 `ashare.backtest.timing` 的信号 → 成交错位一致；有对所有方法参数化的前视测试。
- **风险平价**：牛顿法解 Spinu 凸目标，残差作诊断；无解（存在方差为 0 的长仓组合）时依次加 ridge，诊断分开报「原协方差上收敛」与「靠 ridge 解到」，`allocate` 汇总并对未收敛发警告；独立的坐标下降参考实现对拍。
- **输出**：`Allocation`（行号、日期、权重、是否下单、诊断），可转 `panelbt.Targets`、`to_dict()` 只含内置类型，可交给 `ashare.report.tearsheet`。真实数据例子 `bench/allocation/etf_example.py`（四只 ETF），性能基线 `bench/allocation/perf.py`。
### 6.9 机器学习（`ashare.ml`）

把「因子当特征 → 滚动训练 → 预测值当新因子」这一圈封装好；模型本身用成熟的库（树模型 LightGBM，线性模型 NumPy 正规方程 + scikit-learn），框架负责模型外面那一圈：样本对齐、间隔、滚动重训、特征库、留痕。细节与实测见 `docs/ML_NOTES.md`。

- **依赖**：可选依赖组 `ml`（`lightgbm`、`scikit-learn`），只有 `import ashare.ml` 时才需要，缺了报出中文的安装方法；框架其余部分不受影响（不装这个组时其余测试照常通过，`test/ml` 整体跳过）。`make dev` 默认装上它，`make check` 会跑 `test/ml`。神经网络（PyTorch）这一轮不做，以后走单独的可选组 `nn`，默认不装；`mlp`、`lstm`、`gru`、`transformer` 这几个名字预留给它，没装时用到会提示装 `nn` 组。不引入 Qlib。
- **标签**（`Label`）：按回测的成交约定实际拿得到的未来收益。信号日 t 收盘后算特征，t+lag 行按成交价买入、再过 h 行按成交价卖出，`label[t] = P[t+lag+h]/P[t+lag] − 1`（P = 成交价 × 复权因子），与 `ashare.backtest.execution_days` 同一口径；可买可卖与 `market_from_panel` 同一口径。预设 `ret1/ret5/ret10/ret20`，可扣市场或行业均值；训练目标默认是原始收益，可选截面排名（`rank=True`）或截面标准分（`zscore=True`），评估始终用原始收益。买入日不可买的样本默认不进训练集但照样给预测值。卖出日不可卖默认仍按当日价算（`sell_blocked="price"`），可选 `"drop"`（置缺失）或 `"carry"`（顺延到第一个可卖日、最多 `max_carry` 天；标签跨度随之加 `max_carry`，最小间隔一起变大，防前视按逐样本的实际卖出日核对）。默认值以后要改，必须作为新的一组入账并注明是看过结果之后改的。
- **截面预处理**（`Preprocess`）：去极值 → 行业/市值中性化 → 标准化或排名化 → 缺失值处理，全用 `panelops` 截面算子、按日在股票池内做；预处理结果存在特征库里，训练和预测读同一份。
- **特征库**（`FeatureStore`）：只存股票池内的样本，float32，按特征列存成磁盘映射文件，样本按（信号日，证券）排序、`day_ptr` 索引，一折取一段连续样本。缓存键 = 特征表达式哈希 + 预处理 + 股票池 + 面板版本 + 代码哈希 + 求值依赖版本（numpy、panelops 构建号、因子求值器代码哈希）；建库时某个特征在股票池内全部缺失直接报错；新特征只算新列；`incremental=True` 时新日期只追加尾部（追加前重算最后几天逐位核对）。
- **切分**（`schedule`）：滚动或扩展窗口，按月/季/半年/年或每 k 个交易日重训；训练 → 间隔 → 验证 → 间隔 → 预测。间隔 `gap` 默认等于标签跨度 `lag + h`，只能加大，保证任一训练/验证样本的标签结束日严格早于下一段第一天；`describe()` 打印日程表。
- **防前视**：特征表达式只看信号日及以前；标签结束日 < 预测期首日由 `check_lookahead` 逐折核对（最晚信号日 + 跨度，以及训练样本的实际卖出日两道）；LightGBM 跨折复用的分箱边界只用第一折训练集定（第一折训练集早于所有预测期）。测试：改动第 D 日及以后的全部数据，D 之前的预测逐位不变；D 取在第一折中间、第二折中间（不在任何折边界上）和折边界三处，前两处才抓得到「分箱用了较晚一折的训练集」。
- **模型协议**：`fit(train, valid)`、`predict(batch)`、`save(path)`、`load(path)`，可选 `feature_importance()`、`get_params()`；`Batch` 带 X（用时才读盘）、y、日、列。内置 `ridge`、`lasso`、`elasticnet`、`lgbm`、`lgbm_rank`（lambdarank，按日分组）、`ensemble`（多模型多种子，平均或按截面排名平均）。提前停止看验证集逐日 Rank IC 均值。第三方模型 `register_model("名字", 类或 "模块:属性", group=...)` 或入口点组 `ashare.ml.models` 登记后即可 `model="名字"`，不改核心代码。
- **预测即因子**：`walk_forward(...)` 返回 `WalkResult`，`.pred` 是 T×N 面板，直接交给 `panelops.rank_ic` / `group_returns`、合成或组合构建；`to_targets(res, top=50)` 按标签持有期调仓、经 `execution_targets` 错位后交给 `panelbt.run`。
- **留痕**：每次训练往 JSONL 账本追加一行（数据版本、特征与哈希、标签、预处理、股票池、切分日程、模型参数、种子、代码版本、库版本、各折与汇总指标、耗时），失败的训练也记（`status: failed`，只记异常类型）。同样的定义重跑命中运行缓存直接返回，记一条 `cache_hit`，不算新试验；`Ledger.trials()` 数不同定义的组数，含失败的。定义的规范形式：种子只认实际传给模型的那个（`seed=7` 与 `params={"seed": 7}` 是同一组，不接受 seed 的模型记 None）；自定义模型按类的 qualname + 类源码哈希识别，不看模块路径，取不到源码时只用 qualname 并标 `unavailable`。定义不含框架代码版本、库版本和线程数；运行缓存按这三者区分。某折没有可训练样本、或预测是常数时报错；被跳过的折打日志。默认目录 `ASHARE_ML_DIR`，否则数据根目录下的 `ml/`（不入库）。
- **超参搜索**：网格或随机，同一套切分评估，每组都入账；`end` 必填，留出最后一段作最终检验；结果给 Bonferroni 折算（门槛 α / 账本累计组数）。更精细的多重检验校正留到因子挖掘那条线。
- **解释**：各折特征重要性（及随时间变化）、验证集上按 Rank IC 的截面内置换重要性。不做 SHAP。
- **性能**：逐日运算用 `panelops` 或 NumPy 向量化；训练线程数可配，默认核数的一半；各折可并行（`fold_workers`）。LightGBM 默认 `bins="shared"`（全部样本按第一折的分箱边界分一次，各折取子集）；`bins="per_fold"` 每折重新分箱，与最直白的写法逐位一致。

### 6.10 加密货币数据（`ashare.data.crypto`，设计稿 v3，2026-11-15）

只接币安。数据放在 `data/crypto/`（不入库），和 A 股的 `data/cn` 分开，有自己的清单和内容版本，不进 `DATASETS`。规则事实和出处见 [markets/BINANCE.md](markets/BINANCE.md)。

- **来源与覆盖**（每个数据集单独列来源和起止，不统一假定）：
  - `data.binance.vision` 公开归档，下载后核对 `.CHECKSUM`：现货 1h K 线；U 本位永续和交割合约的 1h K 线、标记价格 1h K 线（`markPriceKlines`，和普通 K 线同名，放不同目录）、价格指数 1h K 线；资金费率（只有月度文件，字段 `calc_time, funding_interval_hours, last_funding_rate`，**没有标记价格**）。归档包含已下架的交易对。
  - 公开 REST 接口（只读、不用密钥）：归档没覆盖到的最近几天；资金费历史接口的结算标记价（2023-10-31 以后才有值，作为资金费的结算标记价，原样保留）；季度合约交割价接口（`deliveryTime`、`deliveryPrice`）；`exchangeInfo` 快照。
  - REST 补的部分标记来源；归档出来后替换，**替换产生新的内容版本**，旧回测可以按旧版本复现。
- **格式**：时间戳单位按市场和数据集判断，不按日期猜——现货自 2025-01-01 起是微秒，U 本位至今是毫秒，每个文件读完后检查时间范围合理；表头按文件内容判断（U 本位月度 K 线 2022-01 起带表头，现货不带）；资金费时间戳带几毫秒抖动，取整到结算整点后再对齐，取整距离超过 1 秒报错。
- **交易对档案**：`exchangeInfo` 每次同步存一份带日期的快照。只收 `contractType` 为永续或季度、`underlyingType = COIN`、`quoteAsset = marginAsset = USDT` 的合约，`TRADIFI_PERPETUAL` 等按字段剔除，不靠手写名单。今天的快照推不出历史上的全集：历史交易对的全集取自归档的目录列表，档案里查不到的交易对，下单规则按 4.17 的「假设」处理并列入诊断，不按价格量级猜步长。另维护一张币的映射表：交易对 → 币（`1000PEPEUSDT` → PEPE × 1000）、代币更名和转换（MATIC → POL，带生效时间和换算比例），出处逐条写明。
- **下架与暂停**：区分五种情况：数据疑似僵尸（fapi 对已下架合约返回成交额为 0、价格冻结的 K 线，见 `~/.claude/experience/binance_delisted_zombie_klines.md`；以归档为准）、交易暂停后恢复、正式下架、结算事件、代币转换。「末尾连续多少小时零成交」只产生数据质量标记，不生成历史退出。下架和代币转换来自**事件表**：从币安公开公告列表（下架、合约下线、代币迁移三类，只读、不用登录）抓取，每条事件分版本保存：`known_at`（这一版内容可知的时间：首发时间或页面注明的更新时间）、`effective_at`（停止交易、结算时间）、结算价（合约）、出处网址、原文，以及被哪一版替代（延期、撤销）。追加新公告不覆盖旧版本；查不到历史版本的只有最终内容，`known_at` 记为页面能证明的最晚时间并标「版本未知」，不把最终内容倒填到首发时间。抓不到的人工补并标出。要有测试：追加未来的数据和事件版本不改变已有历史的事件和回测结果，截断测试连事件版本一起截断（例：OMGUSDT 2024-12-14 公告原定 12-30 下架，12-20 改到 2025-01-31，12-14 到 12-20 之间回测只能看到原定日期）。
- **面板**：「小时 × 交易对」，按月分块存储。字段：开高低收、成交量（币）、成交额、主动买入成交额、标记价格的开高低收、价格指数收盘、资金费率（结算时刻对齐，其余为空）、资金费现金 `funding`（4.17 第 1 条的口径：每张的 USDT = 结算费率 × 结算标记价 × 乘数，放在以该结算时刻为右边界的行上；结算标记价 2023-10-31 起取资金费历史接口，之前取下一根标记价格小时线的开盘价并标「近似」）、`settlement`（标记价收盘，到期行换成交割价 / 下架结算价）、资金费间隔、是否可交易、下单规则（步长、最小数量、最小名义，标来源：公告 / 快照 / 假设）。同一个币的现货、永续、各期交割合约是不同的列，档案里记它们对应的币。日线由小时线按 `trade_hour` 切分聚合，只用于信号和报表。
- **缺失**：资金费记录缺一笔不当 0、不用之后的价格补，按「缺失」报错；只凭相邻记录间距不判断结算频率改变，以归档里的 `funding_interval_hours` 字段为准，并和记录连续性交叉核对。
- **最近一个月的资金费**（C5，2026-11-15 加；Codex 审查后改为显式启用的「推断延伸」）：月度资金费归档要到下月初才出，之前只有 REST 记录、没有间隔字段。REST 漏一笔、中间临时改过间隔又改回来，都无法从 REST 和当前 `fundingInfo` 快照排除，所以**严格构建不变**（仍停在最后一个归档间隔的右边界）；另加显式选项 `allow_inferred_funding=True` 构建「推断延伸」版本（单独的数据版本，元数据写明），归档之后的 REST 记录满足下面**全部**条件才延伸：①从最后一条归档记录起，相邻 REST 记录（取整到整点后）间距全部等于最后归档间隔、都落在该间隔的整点网格上；②同步时抓取的 `fundingInfo` 快照（原样存档：抓取时间、内容哈希）里这个交易对要么不在列表里（只适用于最后归档间隔为 8 小时），要么列出的间隔等于最后归档间隔；`updateTime` 的含义官方没写，只记录、不当证据；③每条 REST 记录都有结算标记价。终点 = min（各必需数据集日度归档覆盖到的最后一个完整小时，第一笔不满足条件或缺失的结算之前），按现有 `funding_schedule` 的末笔覆盖检查（构建终点之前该有的结算都要有）；不满足就停在出问题之前那笔结算的右边界。延伸段的记录标「间隔由延续推断」，回测诊断列出用到的交易对和时段。下月归档出来后严格构建自然覆盖这一段；同时比较推断版本与归档的经济字段（结算时刻、间隔、费率、结算标记价），不一致时写差异报告并在 `verify` 里列出，旧推断版本保留可复现，新版本以归档为准（来源标签从「推断」变成「归档」本身不算差异）。K 线用 `data.binance.vision` 的日度归档（核对 CHECKSUM）补到最近一个完整的日度归档；日度归档还没有的最近几小时不补。
- **校验**（独立实现）：zip 校验和；小时线连续性（缺口要么是交易所公告的维护窗口，要么列入已知例外，其余报错）；资金费结算时刻落在当时间隔的整点上；结算标记价与下一根标记价格小时线开盘价的差异作为**诊断**（官方价格原样保留，不做相等断言，偏离超过阈值的列出来人工看；落在哪根 K 线的高低区间内也只是诊断，边界采样会有差异）；交割价只用交割价接口的官方值，与价格指数小时收盘价偏离过大的列出来人工看（不补分钟数据做 30 分钟均值复算）；同一个币现货和永续价格的偏离超过阈值的时刻列出来人工看；截断数据和全量数据算出的历史前 N 名单一致。
- **命令**：`python -m ashare.data.crypto --root data/crypto sync | build | verify`，断点续跑、按接口限速，下载走本机代理环境变量（Node 以外的 Python 客户端照常读 `HTTPS_PROXY`）。


### 6.10.1 分钟线（C7，2026-11-15 用户定）

- **独立数据集** `crypto_minute`（6.11 登记为冷数据，放外置盘），不并入小时面板，不改现有小时数据的任何版本。只存原始字段，不做 46 个字段的宽面板。
- **原始层**：归档原样存（内容寻址 + 清单，复用 `ashare.data.crypto` 现有的存储与 CHECKSUM 核对），断点续传、只下缺的。
- **整理层**：按「市场 / 交易对 / 种类 / 月」各一个 parquet，列为 `open_time`（毫秒，UTC）、开高低收、成交量、成交额、笔数、主动买入量和额（标记价、指数价只有开高低收）。时间戳单位按数值量级判断（币安 2025 年起的部分现货归档是微秒），统一成毫秒，判断不了就报错。
- **校验**（独立实现，不和整理代码共用判据）：CHECKSUM；时间严格递增、在 1 分钟网格上；每月行数等于该月分钟数，缺口逐段记成质量例外（不补值）；**聚合对账**：把 1m 聚合成 1h，与已有小时面板的同一品种逐小时比较开高低收和成交量，差异逐条列出（小时面板来自另一份官方归档，是独立来源）。
- **内容版本**：哈希覆盖原始归档、整理结果、质量例外和定义版本；读取校验。
- **读取**：`ashare.data.crypto.minute.bars(symbol, market, kind, start, end, *, root=None)` 返回 Polars（按需读月文件，不整表载入）；`python -m ashare.data.crypto.minute sync | build | verify | status`。

### 6.10.2 合约指标 metrics（C8，2026-11-15 用户定：BTC 择时开工）

币安 U 本位 `metrics` 日度归档（`data.binance.vision/data/futures/um/daily/metrics/<交易对>/`，只有日度，没有月度；BTCUSDT 从 2020-09-01 起，5 分钟一行）。第一批 BTCUSDT、ETHUSDT。

- **字段**（改名，单位按 DATA_SPEC 第 5 节）：`open_interest`（币）、`open_interest_value`（USDT）、`top_account_ratio`（原 `count_toptrader_long_short_ratio`，大户账户多空比）、`top_position_ratio`（原 `sum_toptrader_long_short_ratio`，大户持仓多空比）、`global_account_ratio`（原 `count_long_short_ratio`，全市场账户多空比）、`taker_buy_sell_ratio`（原 `sum_taker_long_short_vol_ratio`，主动买量 / 主动卖量）。
- **实测发现（2026-11-15，逐月抽样 + 2024-02/03 逐日）**：
  1. **`create_time` 的含义在 2024-03-04 变了**：之前标 5 分钟窗口的**结束**，之后标窗口的**开始**。判据：用永续 1m K 线的主动买入量复算每行的主动买卖比，对得上的一种对齐误差 1e-9～1e-3，另一种 0.3～0.5。按新规则直接把 `create_time` 当可知时刻，2024-03 以后每行都提前 5 分钟看到数据。
  2. 2020-09 至 2021-05 每行出现两次。
  3. 2022-01 至 2022-04 三个多空比和主动买卖比是空字符串（2022-04 起全市场账户多空比先恢复）。
  4. 有些天不满 288 行（例如 277、287）。
- **切换时刻登记为常量，证据只负责核对（2026-11-16 第二次复核改）**：逐行误差有长尾；日中位数虽能区分两种含义，却会掩盖 23:55、00:05 的边界偏移，逐日 K 检查还会漏掉跨午夜反向段。因此不再从数据推断切换点。每个合约必须先登记切换时刻，当前 BTCUSDT、ETHUSDT 均为 `2024-03-04T00:00:00Z`；未登记的合约拒绝 build，不能套用其他合约的日期。
  - 每行按登记时刻赋值：`create_time < switch_at` 为窗口结束（alignment=0），其余为窗口开始（alignment=1）。登记值必须落在 UTC 日界；改登记需要人工复核并发布新内容版本。
  - 每个 UTC 日只用两边都可比的行计算两种误差中位数。至少 120 行，一种中位数 < 0.01 且另一种 > 0.1 才形成明确证据；明确证据必须与登记值一致。无法判定的日子按登记值处理，不再用前后日推断；保留 `INHERITED_ALIGNMENT` 位表示当日证据不足、采用登记对齐（兼容旧字段），报告此类天数。
  - 明确反向行指登记对齐误差 > 0.1 且另一种 < 0.01、两边均有限。连续 K=2 行明确反向就报错，**跨 UTC 日累计，不在午夜清零**；缺失、灰区、同向行打断连续证据。登记时刻前后各 24 小时的闭区间内，任何一行明确反向都报错，灰区行可保留。所有矛盾均提示可能出现新切换，需要人工复核登记。
  - 逐行对账：按登记对齐复算，误差 > 0.05 的行打 `TAKER_MISMATCH` 并保留，按日、年、全历史报告比例；此质量位不能豁免上述证据矛盾。
  - 归一后 `time` = 窗口开始、`available_at` = 窗口结束，另存 `alignment`。**全部字段都按窗口结束才可知**，包括未平仓量快照。
- 重复行完全相同才去重，内容不同就报错；空字符串转成 null，并打质量位；缺行不补，按 C7 的写法记成缺口。
- **存储与校验同 C7**：独立冷数据集 `crypto_metrics`（6.11 登记，放外置盘）；归档原样内容寻址存储，核对 CHECKSUM；按月一个 parquet；内容版本；断点续传、只下缺的。校验独立实现：时间网格、重复、缺口；用另一份代码独立按登记常量赋值并核对每日中位数、跨日连续反向段和切换前后 24 小时窗口；逐行对账主动买卖比与 1m K 线（误差超过 0.05 标记 `TAKER_MISMATCH` 并保留，按日、年和全历史报告比例）。
- **读取** `ashare.data.crypto.metrics.read(symbol, start, end, *, root=None, version=None)` 返回 Polars；命令行 `python -m ashare.data.crypto.metrics sync | build | verify | status`。

### 6.11 数据存放位置（2026-11-15 用户定）

内置盘空间紧，冷数据放外置盘（PCIe 固态）。

- **热数据留在仓库 `data/`（内置盘）**：`cn`（每晚同步写）、`live`（实时录制）、`paper`、`platform`、`mining`、`research`。后台定时任务只碰这些，避免 launchd 写外置盘被系统权限拦下、拔盘时任务失败。
- **冷数据放外置盘**：`dev`、`crypto`、`crypto_minute`（6.10.1）。
- **指针文件，不用软链接**：数据集搬走后，原位置只留 `data/<名字>/LOCATION.json`（`{"path": 外置盘绝对路径, "moved_at": …, "files": 文件数, "bytes": 字节数}`），`data/` 不入库，所以本机路径不会进仓库。
- **统一入口** `ashare.paths.dataset_dir(name)`：显式传入的路径 > 环境变量 `ASHARE_DATA_DIR`（沿用现有约定：整根替换 `data/`）> 根下 `<name>/LOCATION.json` 指向的位置 > 根下 `<name>/`。指针指向的目录不存在（外置盘没挂）时抛 `DataLocationError`，写明数据集名和期望路径，**不退回内置盘的空目录**。`src/` 和 `bench/` 里所有数据路径（含命令行参数默认值、`CRYPTO_DATA_ROOT` 之类的旧变量）都改走这个入口；静态测试守住：`ashare.paths` 以外不再出现 `"data/<名字>"` 字面路径（测试夹具除外）。
- **搬迁工具** `python -m ashare.paths status | move <名字> <目标目录>`：`status` 列出每个数据集的位置、大小、是否可读；`move` 复制 → 逐文件核对大小和 SHA-256 → 原子写指针 → 默认保留原目录，加 `--delete-source` 才删。热数据集（`cn`、`live`、`paper`）拒绝搬迁，除非 `--force`。

### 6.12 数据源规范（D2，2026-11-15 用户定）

用户要求：数据源定一个规范，写进文档，让别人自己的数据也能接进来。全文见 `docs/DATA_SPEC.md`，这里只记设计取舍。

- **只规定标准层**：外部数据统一整理成「数据包」——按表、按时间分区的长表 parquet，加一份 `datapackage.json` 清单。来源层（各家原始下载）和面板层（内部 T×N 数组）不受约束。现有数据族的内部格式为性能保留不改，各配一个导出器产出标准层视图。
- **清单用现成标准**：采用 Data Package v2（`resources`、Table Schema `fields`/`primaryKey`），本项目要求的东西用扩展属性加上（`unit`、`knownAt`、`symbology`、`calendar`、`gaps`、`frequency`、`kind`）。运行时不依赖 frictionless 库，严格检查由我们自己的校验器做。
- **时间**：日频用 `date32` 交易日，日内和 24 小时市场用带 UTC 时区的 `timestamp`；拒收无时区时间戳、整数 epoch（毫秒/微秒歧义，币安归档 2025 年改过单位）和 `YYYYMMDD` 字符串。区间左闭右开、写左端。
- **防前视放在字段级**：每个字段声明 `knownAt`（`start`、`end`、`end+<时长>`、`column:available_at`、`unknown`）；unknown 表示来源不能保证时点，校验报警告。非行情时间序列必须有 `available_at`，允许公告早于事件日期；只有行情表要求可知时刻不早于区间开始。
- **单位换成基本单位**：股、张、合约、币；金额用元不用千元万元；比例用小数。缺失写 null，不得用 NaN/0/-1；行情不补行、不前向填充；来源缺口写进清单 `gaps`。
- **版本**：每个文件记字节数、SHA-256、行数，包版本 = 规范化清单的 SHA-256；`seal` 计算、`check` 校验、读取时核对被读到的文件。
- **接入**：直接写文件后 `seal` + `check`，或实现三方法的 `Adapter` 协议交给 `build()`（临时目录写好、校验通过才发布）。包放 `data/ext/<名字>/`，经 `dataset_dir("ext")` 解析；`open()` 给出 `read()` 长表和与数据层 `Panel` 同接口的 `panel()`，可直接交给因子引擎。
- **数字枚举不进标准层**：各族 `action_source` 枚举互不兼容，标准层用 `corporate_actions.kind` 加自由文本 `source`。

### 6.13 统一命令行 `ashare`（CL1，2026-11-15 用户定）

用户要求：把 CLI 做好，让 agent 能非常方便地辅助研究员完成任务，功能做全；做好后装成本机全局命令。

**原则（面向 agent，也照顾人）**

- 一个入口 `ashare`，按任务分组的子命令，参数写法统一（`--universe`、`--neutralize`、`--start/--end`、`--json`）。现有的 `python -m ashare.data / report / paths / paper / platform / data.crypto / factor.mining.llm` 继续可用；`ashare` 调它们的函数，不复制逻辑。
- **每条命令都支持 `--json`**：输出带 `"schema": "ashare.cli/1"` 的稳定结构，只含基本类型；默认输出给人看的简短文本。错误也结构化（`--json` 时写到 stderr：`{"error": 类别, "message": 人能读的说明, "hint": 下一步}`），不吐 Python 堆栈（`--debug` 才给）。
- **退出码固定**：0 成功；1 用法或表达式错误；2 数据不可用（外置盘没挂、面板没建）；3 被规则拒绝（例如测试期已看过）；4 计算失败。
- **可发现**：`ashare help --json` 列出全部命令、参数、默认值和一个例子；`ashare guide <主题>` 给 agent 的速查（字段、算子、时间窗口与只看一次的规矩、股票池、中性化、费用口径、常见坑），内容从代码里的登记表生成，不手写第二份。
- **长任务可续可查**：耗时超过几秒的命令打印任务 id，`ashare jobs list/show/cancel`；结果落在平台结果库，和网页看到的是同一份。
- **资源可调**：计算类命令都接受 `--workers N`（同时跑几个变体或任务，进程或线程池大小）和 `--threads N`（单个任务内算子用的线程数）。不传时沿用平台现有的自动值（`parallel_budget` / `ops_threads`），实际取值打印在输出和 `--json` 里。默认低优先级运行（`nice` + 后台 QoS），`--foreground` 才不降；同一时间只跑一个重任务，第二个排队。
- **入库默认开**（用户 2026-11-16 定）：`alpha run` 默认写进因子库，`--no-save` 不写。

## 8. paperbroker：实时模拟盘引擎

### 8.1 定位

一个模拟券商：接收订单，按实时行情快照撮合，维护账户，逐日结算。用途是把研究里选出的组合放到真实行情上向前跑，检验回测的结论，并为以后接实盘做准备。

和 `panelbt` 一样做成独立的包：Rust 内核加 Python 原生扩展，不依赖 `ashare`。行情从哪来、策略怎么下单、进程怎么常驻，都在 `ashare.paper` 里。

说明一点：模拟盘的瓶颈是行情轮询的网络延迟（秒级），撮合的计算量很小。这里用 Rust 的主要收益是确定性、类型安全，以及和回测共用同一份规则代码，速度不是主要理由。基准照样测（回放一整天全市场快照的吞吐）。

### 8.2 内核是一个确定性的状态机

内核不读系统时间，不做网络和文件读写。它只接收事件、更新状态、吐出事件。同样的输入序列必然得到同样的输出，所以可以录制后回放、崩溃后从日志恢复，也便于测试。

输入事件：

- 行情快照：证券、时间、最新价、开高低、昨收、累计成交量和成交额、买一卖一（有就用）、涨跌停价、是否停牌。
- 订单请求：下单、撤单。
- 时段变化：盘前、开盘集合竞价、连续竞价、午休、收盘集合竞价、收盘。
- 日终结算：公司行为、T+1 解锁、未成交订单过期、利息和费用计提。
- 资金进出。

输出事件：订单被接受或拒绝（带原因）、成交（价格、数量、分项费用）、订单结束、持仓和资金变化。

### 8.3 撮合规则

没有逐笔委托簿，只能按快照撮合，所以规则偏保守：

- **连续竞价**：买单的限价不低于卖一价（没有盘口时用最新价）就成交，成交价取卖一价；卖单对称。Tushare `rt_k` 实测返回买一卖一的价和量（`bid_price1`、`bid_volume1`、`ask_price1`、`ask_volume1`），没有更深的档位。
- **成交量上限**：一次快照能成交的数量，不超过上一次快照以来市场成交量的增量 × 参与率上限。剩下的继续挂着等下一次快照。这是为了防止在市场只成交了 100 股的时候「成交」一万股。
- **涨跌停**：最新价等于涨停价且没有卖盘时，买单不成交；跌停时卖单同理。集合竞价同样适用：封死涨停时挂在涨停价的买单不在竞价中成交。
- **集合竞价**：集合竞价时段收到的订单，在竞价结束时按开盘价或收盘价统一撮合，数量受竞价成交量 × 参与率限制。
- **停牌**：不接受订单。
- **废单检查**：资金不足、可卖数量不足（T+1）、价格超出涨跌停范围、数量不符合申报单位、价格不是最小报价单位的整数倍。
- **滑点**：可配置，按最小报价单位的个数或按比例加在成交价上。

订单类型：限价单、市价单（按对手方最优价成交，带保护价）、当日有效。「调到目标仓位」由 Python 层拆成普通订单。

### 8.4 账户与结算

- 账户：现金、挂单冻结的资金、持仓（总量、可卖、冻结）、成本价。
- 费用、申报单位、保证金这些按笔计算的规则，和 `panelbt` 用同一份 Rust 代码（`crates/tradecore`），保证回测和模拟盘的口径一致。
- 日终结算：未成交订单过期；当天买入的股票解锁为可卖；按 Tushare 的分红送转数据做除权除息；生成当日快照（净值、持仓、现金、成交、费用）。
- 第一版是只做多的现金账户。做空和保证金等 `tradecore` 里的保证金模型就绪后再接入，接口先留好。

### 8.5 持久化与恢复

- 每个会改变状态的输入事件先追加写进事件日志，再交给内核处理。日志是追加式的文本行，启动时如果发现最后一行不完整就截掉。
- 定期存状态快照。启动时读最近的快照，再重放它之后的日志。
- 全量行情不进事件日志，另存成 Parquet 录制文件，用于事后回放和复盘。

### 8.6 `ashare.paper`：行情、调度与策略对接

- **行情**：轮询 Tushare 的实时日线接口取全市场或关注列表的快照，标准化后喂给内核并录制。行情源抽象成接口，以后可以换成券商终端的行情。
- **限额**（2026-11-12 实测与官方文档）：Tushare 的限额按接口分开计；常规接口这个账号是每分钟 500 次（超限返回 `code 40203`），`rt_k` 官方说法是每分钟 50 次；全市场一轮要 3 次请求，所以连续竞价时段约 6 秒一轮。同一账号不能在多个 IP 同时取数。
- **原始录制**：另有一个独立的录制任务（`data/live/tools/rt_recorder.py`，launchd 在交易日 9:05 启动），只把接口的原始响应按时间存盘（`data/live/raw/<日期>/<接口>/`），不依赖本项目的任何代码。模拟盘的回放输入由导入器从这些原始文件生成。
- **调度**：按交易日历和交易时段运行，午休和节假日不轮询；进程常驻，崩溃后自动拉起并从日志恢复。
- **策略对接**：每天读取研究框架给出的目标组合，在开盘后下单；可选简单的分时拆单。
- **每日自动运行**（2026-11-14）：`python -m ashare.paper daily after-close|signal|nightly|run`，账户目录里的 `strategy.json` 绑定「表达式 + 回测页设置」，选股与回测页同一套函数；调度模板（launchd / systemd）在 `deploy/paper/`。见 `docs/PAPER_OPS.md`。
- **日终**：结算，出日报，并与 `panelbt` 对账（见 8.7）。
- **监控**：心跳、行情中断和轮询失败的告警。

### 8.7 验证

- 内核的性质测试：资金守恒；可卖数量不为负；冻结资金与挂单一致；成交量不超过市场成交量增量 × 参与率；涨停不买入、跌停不卖出。
- 回放：同一份事件日志重放两次，状态逐字节一致；在日志任意位置截断后恢复，状态等于截断前的状态。
- 与回测一致：把一天的成交按实际成交均价交给 `panelbt` 回放，费用、持仓、现金必须一致。
- 实盘时段联调：开盘后录制真实快照，核对撮合行为。开发阶段先用历史分钟线合成快照流。

### 8.8 与真实成交的差异

- 不知道自己在委托队列里的位置，也不知道两次快照之间的价格路径。
- 只有买一卖一，没有更深的档位，快照间隔约 6 秒；吃穿一档之后的价格只能靠成交量上限和滑点参数做保守处理。个别证券没有盘口时只能用最新价撮合，结果偏乐观。
- 因此模拟盘的结果是「在这些假设下的估计」，不能当成实盘成绩。

## 9. 券商接口与 miniQMT 适配

状态：设计稿。实盘权限要向券商申请（用户的待办），这一节只做系统这一侧；真实下单的开关始终由人掌握，默认关闭。

### 9.1 目的

策略这一侧（每天的目标组合 → 订单 → 跟踪成交 → 对账）不应该知道对面是模拟盘还是真实券商。定一个统一的券商接口，模拟盘和 miniQMT 各写一个适配器，上层代码只面向接口。这样研究里验证过的下单逻辑搬到实盘时不用改。

### 9.2 接口（`ashare.broker`）

- `connect()`、`close()`、`status()`：连接状态是显式的，断开不会自动恢复（miniQMT 的 `connect()` 是一次性的），由上层的监督循环重连。
- `submit(order) → 本地单号`：本地单号由我们生成（不超过 24 个 ASCII 字符，写进券商的备注字段），重复提交同一个本地单号不会下两次单。
- `cancel(本地单号)`：返回只代表撤单请求已发出，是否撤掉以订单状态为准。
- `orders()`、`trades()`、`positions()`、`cash()`：查询当前状态。查询失败和结果为空必须区分（miniQMT 两种情况都返回 `None`，适配器里要处理）。
- `events()`：订单状态变化、成交、连接状态的事件流，事件类型与 `paperbroker` 的输出事件一致。
- 订单状态统一成一个状态机：待报、已报、部成、已成、待撤、已撤、部撤、废单、未知；miniQMT 的状态码 48–57、255 映射到它。

原则：**以查询为准，推送只用来触发查询**。回调线程里只做入队，不做业务处理，不发同步查询（miniQMT 在回调里同步查询会卡死）。

| 适配器 | 对面 | 说明 |
|---|---|---|
| `PaperBroker` | `paperbroker` 内核 | 现有模拟盘包一层，作为接口的参考实现 |
| `QmtBroker` | Windows 上的 miniQMT 客户端 + `xtquant` | `xtquant` 只有 Windows 版，交易通道是客户端目录下的本地队列文件，所以必须和客户端在同一台机器；本机（macOS）通过一个桥接服务访问 |

运行拓扑：研究、信号、目标组合在 macOS；Windows 机器上跑 miniQMT 客户端和一个薄的桥接服务（只做转发、鉴权和审计，不含策略逻辑）；两边走局域网。行情可以继续用 Tushare，也可以换成 `xtdata` 的全推快照。

桥接服务有三条路线，**实现前由用户选定**：

| 路线 | 许可证 | 特点 |
|---|---|---|
| `qmtserver` / `qmtclient` | MIT | 交易接口默认关闭且默认只演练不下单，令牌鉴权，有审计日志；版本 0.8，标注 Alpha |
| `qmt-bridge` | MIT | HTTP 100 多个接口加 WebSocket 回报，客户端不依赖 `xtquant`；功能多，需要自己收紧 |
| 自己写一个最小的 | — | 只暴露 9.2 的十来个调用，代码量小、可控；要自己维护 |

（`xqshare` 是 GPL-3.0，不采用。）

### 9.4 风控与合规（都在我们这一侧，适配器之前）

- **真实下单开关**：配置里默认是演练模式（只记录将要发出的委托，不发出）；打开它只能由人改配置。
- **预交易检查**：单笔金额上限、单只证券持仓上限、单日委托笔数上限、每秒委托速率上限、价格偏离上限、可卖数量、禁止交易名单。速率和笔数上限取向券商报告的数值——程序化交易要先向券商报告策略类型、最高申报速率、单日最高申报笔数和软件信息，确认后才能交易，实际行为与报告不一致会被限制。
- **人工干预**：一键全撤、暂停申报（交易所实施细则对程序化交易系统的要求）。
- **对账**：日终三方核对——本地账本、券商查询结果、`paperbroker` 影子账户；不一致就停止次日下单并告警。
- **每日流程**：按「每个交易日开盘前重启并登录客户端、用新的会话号重连」设计；重连次数有上限（每次连接都会在客户端目录生成文件）。

### 9.5 验证

- 一套契约测试同时跑两个适配器：下单、部分成交、撤单、废单、断线重连、重复提交、查询失败与空结果。
- `QmtBroker` 在没有账号的情况下用假的 `xtquant` 模块测试：按官方文档实现回调、状态码和已知的行为（撤单返回成功但未真正撤掉、查询返回 `None` 的两种含义、回调里同步查询卡死、断线不自动重连）。
- 拿到模拟账号或实盘权限后的联调清单（各时段下单的实际行为、订单号跨日是否有效、流控数值、五档行情的实际档数）记在 `docs/` 里逐项核对；这些在官方文档里没有写明。

### 9.6 需要用户决定或去办的事

1. 向券商申请 miniQMT 和程序化交易权限（各家门槛不同，网上的说法互相矛盾，以客户经理的书面答复为准；开户时问清是否要求实体机和固定网卡地址，这决定 Windows 机器放哪）。
2. 桥接服务走 9.3 的哪条路线。
3. 向券商报告的最高申报速率和单日最高笔数（低频组合调仓，建议报得保守，例如每秒不超过 5 笔、每日不超过 2000 笔，远低于高频标准的每秒 300 笔、每日 20000 笔）。
