# AShare 量化研究框架 · 方案

版本 0.2（2026-11-12）。本文是实现的依据：改设计先改本文，再改代码。

## 1. 目标

个人做 A 股日频/周频、纯多头的选股研究：因子挖掘与检验、多因子合成、组合回测，之后接模拟盘和实盘。

三条原则：

1. **时点正确**。任何一天用到的数据，都必须是那天真实能看到的。
2. **性能优先，用基准测试决定用什么写**。numpy 和 polars 的向量化运算已经很快，不重复造。每个计算模块先用 numpy / polars 写出向量化基线并测速；只要 Rust 实测更快，就用 Rust 写。对比数字留在仓库里，作为以后每次迭代的基线。目标是一次因子检验在百毫秒级，上千个因子的批量回测在秒级。
3. **解耦**。回测引擎和因子算子是两个独立的包，只通过数组接口被调用，不认识数据源，也不认识本项目。包里某个函数用 numpy 还是 Rust 实现，对调用方不可见。

整体结构图见 `docs/architecture.svg`。依赖方向只有一个：`ashare → panelbt, paperbroker, panelops`。三个包互不依赖，也不 import `ashare`，之间只用 numpy 数组交换数据。回测和模拟盘在 Rust 层共用 `tradecore`，保证两边的费用和规则口径一致。

统一的数据形状是**面板**：T 行（交易日，升序）× N 列（证券，含已退市），C 连续的 `float64` 或 `bool` 数组。行情、因子、掩码、权重都是这个形状，行列含义由一份主日历和一份主证券表决定。

## 3. 选型

| 环节 | 选择 | 依据 |
|---|---|---|
| 数据 | Tushare Pro 为主，BaoStock 对账 | 现有密钥实测 26 个接口通过 25 个，覆盖所需全部数据；BaoStock 免费，独立来源，用来核对 ST、停牌、退市 |
| 存储 | 原始数据 Parquet，面板 `.npy` 内存映射 | 日频数据量小，不需要数据库服务；内存映射的矩阵可以零拷贝交给 Rust |
| 表处理 | polars | Rust 内核，多线程，as-of 连接快 |
| 回测引擎 | 自研 `panelbt`（Rust 内核） | 摸底实测 Rust 比最快的 numpy 写法快 3–16 倍，见 4.5；完整的选型对比见 `SELECTION.md` |
| 模拟盘 | 自研 `paperbroker`（Rust 内核） | 与回测共用规则代码；行情用 Tushare 实时日线接口 `rt_k`，现有密钥实测三次请求取全市场，带买一卖一价量 |
| 因子算子 | 自研 `panelops` | 统一接口；逐个算子与 polars / numpy 对比，Rust 更快的就写 Rust，其余直接包一层 |
| 因子合成 | 自研滚动训练 + LightGBM | Qlib 没有 Python 3.13 的安装包，对 pandas 3 的修复未合并 |
| 组合优化 | Clarabel 直接调用（默认）；cvxpy 只作后备和参考 | 问题先换成标准锥形式再交给 Clarabel 的 Python 接口，同结构问题复用；Clarabel 报数值失败时退到 cvxpy + Clarabel 重解；`backend="rust"` 走 `portopt`（Rust 里调 Clarabel，可批量并行）；`backend="cvxpy_*"` 是用来对拍的参考实现。见 6.4 |
| 对照与对账 | alphalens-reloaded、rqalpha（仅开发依赖） | 用独立实现核对自研代码的结果 |
| 报告 | quantstats，加自己的统计检验 | 实测可用 |

没有选的，以及原因：

- **backtrader**：2023 年后停更。它是事件驱动的，每只股票每根 K 线都走一遍 Python 回调，适合单标的或几个标的的择时；5000 只股票的截面选股跑一次要按分钟到小时计。不带 A 股规则。
- **backtesting.py**：设计上一次只回测一个标的，没有组合的概念，做不了截面选股。
- **rqalpha 当主引擎**：A 股规则最全，但同样是事件驱动，批量试因子太慢；许可仅限个人非商业使用。所以只拿来对账。
- **Qlib、vnpy.alpha、zipline-reloaded**：Qlib 见上；vnpy.alpha 把涨跌停写死成 ±10%，没有最低佣金和分红，还带 1.1 GB 的界面库；zipline 不支持 pandas 3。

## 4. panelbt：回测引擎

### 4.1 定位

市场无关的截面组合模拟器，会长期使用：现在服务 A 股，以后扩展到港股和美股。输入是对齐好的面板数组和配置，输出净值、持仓和成交。不读文件，不联网。任何市场的规则都不写进内核，而是由「市场档案」换算成数组和参数传进来（见 4.7）。

它是一个独立的 Python 原生扩展包，运行依赖只有 numpy，将来可能单独开源发布，所以包里不能出现本项目的路径和假设，代码注释和文档用英文（另附中文 README）。

### 4.2 接口

```python
import panelbt as bt

market = bt.Market(
    exec_price=...,   # T×N 成交价。NaN = 当日无行情，不可交易
    close=...,        # T×N 估值价。NaN 时用最近一个有效值
    can_buy=...,      # T×N bool
    can_sell=...,     # T×N bool
    volume=None,      # T×N 成交量（股），用于成交量占比上限
    split=None,       # T×N 除权日的股数乘数（10 送 5 = 1.5），无则为 1
    cash_div=None,    # T×N 除息日每股派现
    delist=None,      # T×N bool，退市处理日
)
costs = bt.Costs(commission_rate=2.5e-4, commission_min=5.0,
                 tax_sell=..., tax_buy=0.0,   # 标量或长度 T 的数组
                 fee_rate_buy=1e-5, fee_rate_sell=1e-5, slippage=5e-4)
config = bt.Config(initial_cash=1e7, min_qty=..., qty_step=...,   # 标量或长度 N
                   max_participation=0.1, carry_blocked=True,
                   delist_recovery=1.0, cash_buffer=0.0, record_trades=False)

targets = bt.Targets.from_dense(weights)       # 稀疏的目标权重
result = bt.run(market, targets, costs, config)
results = bt.run_batch(market, [targets_1, targets_2, ...], costs, config, threads=0)
```

目标权重用稀疏结构传入：调仓日下标、每个调仓日的（列号，权重）列表。原因是批量回测时，一千组稠密的 T×N 权重矩阵放不进内存。`Targets.from_dense` 约定：整行 NaN 表示当日不调仓，其余行里的 NaN 当作 0。支持 `kind="shares"` 直接给目标股数。负目标需要 `Config(margin=MarginModel(allow_short=True, ...))`；只做多现金账户仍拒绝负目标和权重和超过 1 的计划。

`result` 包含逐日的净值、现金、换手、分项成本（佣金、税、其他费用、滑点、冲击）、受限未成交的笔数，以及可选的持仓和成交明细。

### 4.3 时间约定

`targets` 里第 t 行是**第 t 日成交时**要达到的目标。引擎不做任何移位。用 t−1 日收盘的信息算信号、在 t 日成交，这个错位由调用方负责，项目里只在 `ashare.backtest` 做一次：

```python
from ashare.backtest import execution_targets, execution_days
plan = execution_targets(signal)                 # 稠密 T×N，行 = 信号日
plan = execution_targets(picks, t=T)             # panelops.targets 等稀疏目标，行 = 信号日
days = execution_days(signal_days, T)            # 只要成交日行号（如交给 optimize_sequence）
```

- 行号就是交易日：周末、节假日不在面板里，周五收盘的信号落到下一个交易日那一行。`lag` 默认 1，必须是正整数；信号只用开盘前已知信息、本来就不需要错位的，直接构造 `panelbt.Targets`。
- 末尾 `lag` 行的信号在面板里没有成交日：默认丢掉，`tail="error"` 时报错。
- 成交日停牌或涨跌停：错位不管，引擎按 `can_buy`/`can_sell` 拦下，`carry_blocked=True`（默认）在之后每天重试直到下一个调仓行。

第 t 日的处理顺序：

第二轮增加了最先入账的外部资金流、税后分红、收盘借券/融资费用和自有闲置现金利息；多空账户先减风险，再同比例缩放开仓篮子。收盘追保在下一行强平，详见包内 SPEC。以下是默认现金账户的基础顺序：

1. 公司行为：先按除权前股数派现，再按 `split` 调整股数。
2. 退市：持仓按最近有效收盘价 × `delist_recovery` 变现，并记录。
3. 确定目标：当日有新目标就采用，并清掉之前没完成的；没有新目标且 `carry_blocked` 打开时，只对之前因受限没成交的证券继续尝试。
4. 用成交价给组合估值，算出每只证券的目标股数（向下取整到申报单位）。
5. 先卖后买。卖出受 `can_sell` 和成交量占比限制；目标为 0 时可以把零股一次卖完。
6. 买入受 `can_buy`、成交量占比和现金限制。现金不够时所有买单同比例缩减，再向下取整，保证现金不为负。
7. 用收盘价估值，得到当日净值。

日频下每天只成交一次，当天买入的不会当天卖出，T+1 自然满足。

### 4.4 A 股规则（`panelbt.markets.ASHARE`）

- 可买可卖：停牌不可买卖；成交价等于涨停价不可买；成交价等于跌停价不可卖；全天一字板按最高价等于最低价判断。
- 印花税和过户费：`ASHARE.costs(dates)` 按日期展开，覆盖 2005-01-24 起的全部历史（面板从 2007-01-04 开始），不用再手填。每一条的生效日期和依据见 [ASHARE_FEES.md](ASHARE_FEES.md)：印花税 2005-01-24 双边 0.1%、2007-05-30 双边 0.3%、2008-04-24 双边 0.1%、2008-09-19 起卖出单边 0.1%、2023-08-28 起 0.05%；过户费 2015-08-01 起两市按成交金额 0.02‰、2022-04-29 起 0.01‰。2015 年以前沪市按面值、深市按金额，引擎的费率只能按日期不能按证券区分，所以两种同时计入（保守，偏高），这几条标「未核实」。
- 全区间固定费率要显式写：`panelbt.Costs(tax_sell=0.001, fee_rate_buy=1e-5, fee_rate_sell=1e-5, …)`，或在 `ASHARE.costs` 里把四个分量都覆盖。覆盖某个方向的过户费（按金额或按股）时，同方向的另一种写法自动清零，同一笔费用不会算两次。佣金由券商定，调用方给。
- 申报单位：主板和创业板 100 股的整数倍；科创板 200 股起、1 股递增；北交所 100 股起、1 股递增。
- 佣金最低 5 元；过户费双边。
- 从面板一步建行情：`ashare.backtest.market_from_panel(data, start, end, exec="open")`（见 6.1）。

### 4.5 性能目标与实现语言

动手前先做摸底：把「估值 + 调仓成交 + 费用」这段核心循环分别用三种方式写出最小版本，在同样的输入上确认结果一致后测速。

- numpy 全截面向量化：每天对整行做向量运算。
- numpy 稀疏：每天只处理有持仓或有目标的下标。
- Rust。

判定规则：摸底时事先定的是「单次回测或批量吞吐有一项快 3 倍以上才用 Rust」；2026-11-12 起放宽为只要 Rust 实测更快就用 Rust。规则换算、输入校验、稀疏转换和结果后处理是整块的逐元素运算，先用 numpy 写，实测 Rust 更快再换。摸底的数字和脚本留档。

目标值：在本机（M5 Pro，15 核）上，T = 4000、N = 5500：

- 单次回测（持仓约 100 只，月度调仓）：30 ms 以内。
- 1000 组目标批量并行：5 秒以内。
- 结果与线程数无关，逐位一致。

这些是目标值，实现后用基准测试实测，把实测数字写回本节。

#### 步骤 1 实测（2026-11-12）

测试条件：macOS 26.6 / M5 Pro 15 核，Python 3.13.13、NumPy 2.5.4（Accelerate）、Rust 1.95.0，release + LTO + codegen-units=1。T=4000、N=5500，月度为每 21 日。下表单次与批量均三次中位数；批量 K=1000，numpy 用筛选后最快的 15 进程 spawn+mmap，Rust 用 rayon。全部版本先逐日净值对拍，最大单次差 8.44e-15。

| 持仓目标/调仓 | numpy 全截面 ms | numpy 稀疏 ms | Rust ms | 单次加速 | numpy 批量 s | Rust 批量 s | 批量加速 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 100/月度（21 日） | 16.106 | 8.733 | 0.539 | 16.21× | 0.906 | 0.115 | 7.84× |
| 1000/月度（21 日） | 16.182 | 27.386 | 5.523 | 2.93× | 1.846 | 0.490 | 3.77× |
| 100/每日 | 238.454 | 86.383 | 5.683 | 15.20× | 9.480 | 0.584 | 16.22× |
| 1000/每日 | 246.743 | 311.035 | 60.951 | 4.05× | 27.057 | 6.009 | 4.50× |

判定：使用 Rust 内核。单次最快 numpy 在 100/月度与 100/每日是稀疏版，在 1000/月度与 1000/每日是全截面版。1000/月度单次只有 2.93×，没有夸报成 >3×；该场景批量仍为 3.77×。总体严格满足“任一单次或批量超过 3×”规则。

NumPy 全截面的连续 dot 很高效，H=1000 时比高级索引/union1d 的稀疏版更快；H=100 时稀疏减少访存。Rust 省掉逐日 Python 调度、临时数组与索引构造，活动列循环在寄存器/缓存中完成。线程池的众多小 numpy 调用争抢 GIL，增加线程反而变慢；进程池共享只读 mmap、避免复制市场，15 进程胜出。Rayon 共享借用市场且无进程 IPC，策略内部运算顺序不变。

完整实现（包含全部可选面板、约 100 持仓目标、月度调仓，三次中位数）：

| 场景 | API 总耗时 ms | 准备 ms / 占比 | 内核+绑定 ms / 占比 | 后处理 ms / 占比 |
|---|---:|---:|---:|---:|
| 整手单次 | 9.805 | 0.029 / 0.31% | 9.525 / 99.58% | 0.011 / 0.12% |
| 小数股单次 | 9.487 | 0.029 / 0.30% | 9.655 / 99.64% | 0.006 / 0.06% |
| 1000 组 batch | 959.170 | 2.895 / 0.31% | 913.375 / 96.32% | 32.017 / 3.38% |

复用 Market：整手 9.805 ms、小数股 9.487 ms；1000 组 0.959 s，达到 30 ms / 5 s。首次 Market 全量校验另需 38.000 ms；冷启动构造市场再单次回测约 47.805 ms，按冷启动口径未达 30 ms。外围每次准备和后处理不是主瓶颈，一次性全量校验受内存扫描成本限制。阶段百分比按三项之和计算，独立中位数不要求精确相加为总耗时。

小市场 T=120、N=80、记录成交持仓：Python 参考实现 2.902 ms，Rust 0.143 ms。

Claude 独立复测（同一台机器，五次中位数）：四个场景的单次加速为 16.5×、3.0×、15.9×、4.1×，完整实现单次 9.6 ms、1000 组批量 0.95 s，与上表一致。

已知的改进点：完整实现在「100 只、月度调仓」上是 9.6 ms，同一场景的最小摸底版本是 0.5 ms，差距要在第二轮查清并消除。

### 4.6 正确性

性能排在正确性之后。验证分四层：

1. **参考实现**：`panelbt.reference` 用纯 Python 逐日逐股循环实现同一份规则，写得越直白越好，它就是可执行的规格。
2. **随机对拍**：随机生成市场（含涨跌停、停牌、退市、分红送转、缺失值）和目标，Rust 与参考实现逐日比对净值、现金和持仓。测试要断言用例确实覆盖到了成交、受限、现金不足、退市这些分支，防止「两边都没成交所以一致」。
3. **性质测试**：成本为零时净值等于无摩擦净值；扣成本后的净值不高于不扣的；不可买卖时持仓不变；股数符合申报单位；现金不为负；逐日的资产变化等于盈亏减成本。
4. **变异检查**：故意改坏内核里的 8–10 处（比如去掉印花税、先买后卖、忽略 `can_sell`），每一处都必须有测试失败。

之后在真实数据上再与 rqalpha 对账（见步骤 4）。

### 4.7 市场参数化

- **市场档案** `MarketProfile`：名字、货币、每年交易期数、分段生效的费用表、申报单位规则、涨跌停规则、卖出锁定（T+0 或 T+1）。档案负责把行情面板和日期换算成内核要的数组：可买可卖掩码、逐日的税费率、每只证券的最小申报量和步长。
- **费用模型一般化**：佣金由比例、按股、下限、上限四个参数组成；税和其他费用买卖两个方向分开，各自可以随日期变化，其他费用同时支持按金额和按股收取。这样 A 股（卖出单边印花税、最低 5 元）、港股（双边印花税、各种征费）、美股（按股计佣金、卖出按股收监管费）都能表达。
- **内置档案只有 A 股**。港股和美股的费率没有核实过，不内置；用测试证明参数化足以表达它们，文档里给出示意。（2026-11-13 起已内置港股、美股档案，见 4.16。）
- 一天内多次成交和多币种需要改内核，目前不支持，写在规格里。期货见 4.11。

### 4.8 做空与保证金账户

持仓带正负号，负数是空头。只做多的现金账户是保证金账户的一个特例，默认行为不变。

- 账户量：现金（含融券卖出所得）、多头市值、空头市值，权益 = 现金 + 多头市值 − 空头市值。
- 保证金模型：多头和空头各有开仓保证金率和维持保证金率，可以随日期变化；是否允许借钱买入；融券所得能否挪用；融资利率和融券费率。
- 可融券标的用一张掩码面板给出。新开空头需要标的可融且可卖，平空需要可买。
- 先成交降低风险的订单，再成交增加风险的订单；保证金或现金不够时，增加风险的订单同比例缩减。
- 空头在除息日付出分红；送转同样作用在空头股数上。
- 收盘后不满足维持保证金即为追保。默认在下一个交易日把全部仓位同比例缩减到满足开仓保证金；权益小于等于 0 记为爆仓，平掉全部仓位后停止交易。也可以设成只记录不干预。
- A 股融券的监管参数（保证金比例、维持担保比例、折算率）调整过多次，默认值必须有公开规则作依据并注明生效日期，核实不了的由调用方显式传入。融券卖出的报价限制在日频下无法模拟。

### 4.11 期货对冲腿

A 股个股融券很受限，实际对冲靠股指期货，所以内核要支持期货这类品种。放在步骤 1c。

- 每只证券有一个品种类型：现货（全额交收）或期货（逐日结算），期货另有合约乘数和保证金率（可随日期变化，用来表达交割月上调保证金）。
- 期货开仓不付本金，只付费用并占用保证金；每天按结算价把盈亏计入现金。
- 到期按交割结算价平仓。每个合约是面板里的一列，换月由目标给出（近月权重降为 0，远月建仓）；另提供一个按规则生成换月目标的辅助函数。
- 对冲的用法：目标里给期货列一个负的名义权重；另提供辅助函数，按股票组合的市值或贝塔算出对冲手数。
- 期货的保证金占用并入 4.8 的保证金约束；追保和强平沿用同一套处理。
- 数据来自 Tushare 的期货合约信息和日线（含结算价、合约乘数、到期日）。贴水成本不需要单独建模，它体现在合约价格向现货收敛的过程里。

实现说明（步骤 1c，2026-11-12；完整口径见 `packages/panelbt/SPEC.md` 的 Futures 一节）：

- 只有一个逐日账户循环，按「现金特化 / 保证金账户」×「有无期货列」编译成四份；现货规则在两种构建里是同一段源码。**加一列从不交易的期货，现货结果逐位不变**，是常驻性质测试（`test/test_futures_invariance.py`）。现金特化只由账户条款决定，挂期货不会把现金账户换成保证金路径。
- 目标按名义权重换手数：`权重 × 交易前权益 × (1 − 现金缓冲) / (执行价 × 乘数)` 向零取整；非零权重取整为 0 手只计数（`futures_rounded_to_zero`）。期货空头不需要融券权限。未持有且当天无执行价的合约用上一行已公布的结算价定手数（与现货用上一收盘价对称）。
- 逐日结算：成交时只按成交价对结算基准实现已平部分的盈亏并扣手续费；收盘按 `手数 × 乘数 × (今结 − 基准)` 入现金，基准换成今结。期货不计入现货市值，权益仍是现金 + 现货多头 − 现货空头。
- 保证金占用 `|手数| × 乘数 × 价 × 当日保证金率`，并入开仓与维持约束；可用自有现金 = 现金 − 受限空头 − 占用，提款、闲置利息、融资利息都用它。
- 先减仓后开仓，期货减仓在前。**期货减仓和平仓不受「自有现金不得转负」截断**，也不受现金账户卖出检查限制：减仓只释放保证金，亏损无论平不平都会在收盘入账；手续费造成的负现金按欠款保留并计融资利息。开仓和加仓受资金与保证金约束：保证金账户里期货与现货开仓同一个缩放因子（期货在前做前缀检查）；现金账户先按「占用 ≤ 现金」缩放期货开仓，现货再用「现金 − 占用」走原来的现金账户算法。现金账户持有过合约之后才记追保、强平和破产，追保条件是占用 > 权益。
- 到期行的 `settlement` 必须是交割结算价（中金所股指期货为最后两小时指数算术平均）；到期当天可以先按目标成交（含开仓），收盘按交割结算价现金交割并收交割费，停牌也照常交割。次日起非零目标只计入 `n_expired_target`，强平日被强平方案替换的请求行里的过期目标同样计数。
- 辅助函数：`roll_targets` 在 `到期 − roll_days` 行换到下一合约，只向后换，合约间隔小于 roll_days 时持有最远的未到期合约到期；`hedge_contracts` 向零取整（与内核一致），正敞口取整为 0 手时发出 `HedgeRoundingWarning`。期货费率只接受标量、(1, N)、(T, 1) 和 T×N，一维数组在 T=N 时有歧义，直接报错。

### 4.12 逐日步进接口

`bt.run` 只吃预先算好的目标，表达不了「目标取决于账户走到今天的状态」的策略。`bt.Simulator` 把同一个逐日循环拆成「状态 + 推进一天」，由调用方一天一天推：

```python
sim = bt.Simulator(market, costs, config)          # kind="weights" 或 "shares"
for t in range(sim.n_days):
    target = strategy(t, sim.state)                # None / 长度 N 的一行 / (列号, 值)
    sim.step(target)                               # 返回当日指标（DayRecord）
result = sim.result()                              # 与 bt.run 同一种 Result
```

实现：内核的逐日循环拆成两段，`Core::open`（当日外部资金流、公司行为、退市）和 `Core::trade`（确定目标、成交、收盘估值）。`bt.run` 就是对每一行依次调用这两段，编译器内联后与原来的单一循环等价；`Simulator.step` 调用 `trade(t)` 后立刻调用 `open(t+1)`。持仓成本、入场日这些只有步进接口需要的记账由编译期开关 `T` 打开，`bt.run` 的构建里不存在。改动前后的 `bt.run` 在随机输入（现金、保证金、两种期货）上结果逐位相同；配对计时（新旧两份 LTO 构建交替跑）新版不慢。

时间约定不变：第 t 步给的目标是第 t 日成交时要达到的目标，引擎不移位。第 t 步之前读到的 `sim.state` 只含第 t 日成交前就知道的东西：

| 字段 | 什么时点可知 |
|---|---|
| `day` | 下一步要执行的行号 |
| `equity` | 第 t−1 日收盘权益（第 0 行为初始资金） |
| `cash` | 第 t−1 日收盘现金，加上第 t 日开盘前入账的外部资金流、税后分红、退市变现 |
| `shares` | 第 t−1 日收盘持仓，按第 t 日的送转调整、扣掉第 t 日退市的列 |
| `cost` | 持仓的数量加权原始成交价（不含滑点、冲击和费用），按送转调整，分红不调整；空仓为 0 |
| `entry_day` | 当前持仓的建仓行号（加仓不变，反手重置）；空仓为 −1 |
| `last` | 持有列的估值价：截至 t−1 的最近有效收盘价，按第 t 日分红、送转调整 |
| `futures_basis` | 期货持仓的结算基准（上一结算价） |
| `pending_cols/pending_targets` | 因价格、掩码或成交量受限、仍在顺延的订单 |
| `margin_call` / `bankrupt` | 第 t−1 日收盘追保（第 t 日为强平日）/ 已爆仓 |

第 t 日的公司行为、外部资金流和退市属于开盘前已公布的信息，所以已经反映在第 t 步之前的状态里；第 t 日的价格、掩码、成交量、结算价不会进入。防前视测试改动第 t 日及以后的全部行情（以及 t 日以后的公司行为和退市），断言第 0 到 t 步之前的状态逐位不变。

数组是零拷贝的实时视图，随步进变化，要保留历史就自己 `copy()`。视图建在只读缓冲区上，numpy 不允许把它改回可写，经由公开接口改不了模拟状态；绕过只读保护（例如顺着视图的 `.base` 链拿到底层数组）写入属于未定义行为。期货列不维护 `cost` 和 `entry_day`：不论持仓多少，读出来恒为 0 和 −1，期货持仓看 `shares`。每一步：行情面板按引用重新借用（不拷贝），状态数组放在 numpy 里由内核直接写；没有与证券数成正比的 Python 层拷贝。传稠密的一行目标本身是 O(N)，大截面建议传 `(列号, 值)`。

存档与恢复：`sim.snapshot()` 返回字节串（版本化的二进制格式，第 2 版，不用 pickle），`bt.Simulator.restore(blob, market, costs, config, kind=...)` 恢复后继续跑与不中断逐位相同。字节串末尾是前面全部字节的 CRC-32，恢复时先校验，截断、多出字节、任何一位被改都报错。字节串里还带指纹：行列数、账户类型、目标类型、全部费用和配置向量与标量、规则的全部标量项，以及止损、止盈、移动止损参数数组的每一格；不一致就拒绝。行情面板（价格、掩码、成交量、公司行为、开高低、期货面板）也进指纹：默认 `fingerprint="sample"` 对每张面板取形状、dtype、首行、末行和固定步长抽样的约 64K 格做摘要，在 `Simulator` 构造时算一次（4000×5500 的行情约 5–7 ms，负载约 10），只改了大面板里没被抽到的格子查不出来；`fingerprint="full"` 对每一格做哈希（同样的行情约 0.8–1.2 s）。恢复时要用存档时同样的选项。`bt.run` 不算摘要。第 1 版格式的存档直接报「format version 1 is no longer supported」。恢复失败不会留下加载到一半的对象。

多线程：`step` 期间释放 GIL，多个 `Simulator` 可以各自在不同线程里推进，结果与顺序执行逐位相同。同一个 `Simulator` 不能被两个线程同时操作：另一个线程在 `step` 进行时再调 `step` 或读 `state`，会抛 `RuntimeError`（状态不受影响）。不提供「批量 + Python 回调」入口：回调要拿 GIL，并行不起来。

每步固定开销（`bench/step_overhead.py`，T=4000，机器负载约 7，各五次取中位数）：

| 场景 | 每行 µs |
|---|---:|
| `Simulator`，每步读一次 `state`、每 21 行换一次目标，N=1 | 4.5 |
| 同上，N=5500 | 4.6 |
| 只调 `step()`，N=1 / N=5500 | 3.1 / 3.3 |
| `bt.run` 跑同一个计划，N=1 | 0.04 |
| backtrader 1.9.78，preload + runonce、无 observer，`next` 里读现金和持仓、每 21 根 K 线 `order_target_percent` | 29.5 |

开销与证券数无关，约为 backtrader 每根 K 线开销的六分之一；主要花在 Python 调用和每步重新借用行情面板上。能写成固定规则的状态逻辑用 4.13 的声明式规则，在内核里跑，`bt.run` 和 `bt.run_batch` 也能用。

### 4.13 声明式退出规则与限价目标

止损、止盈、移动止损、最长持有期和限价目标是固定模式，不值得每天回到 Python。它们写成配置，由内核执行，`bt.run`、`bt.run_batch`、`bt.Simulator` 都能用：

```python
market = bt.Market(exec_price, close, can_buy, can_sell, ..., open=o, high=h, low=l)
rules = bt.Rules(fill_time="open", stop_loss=0.08, take_profit=0.3,
                 trailing_stop=0.12, max_hold=20)        # 百分比可为标量、长度 N、T×N
result = bt.run(market, bt.Targets.from_dense(w, limits=lim), costs,
                bt.Config(rules=rules, record_trades=True))
result.diagnostics["stop_loss"]; result.trades[k].reason   # TradeReason
```

精确规格在 `packages/panelbt/SPEC.md` 的「Declarative exit rules and limit targets」一节，纯 Python 参考实现是 `panelbt/reference_rules.py`。原则是**宁可悲观**：日线只给开高低收，凡是取决于日内先后顺序的情形，都按对策略不利的一边算。

参考实现在原参考实现上派生，规则部分与 `rules.rs` 结构相近（同样的判断顺序和二分），不是独立写的，所以两边对拍不能排除两边一起错。兜底是 `test/test_exit_rules_hand.py`：独立复核时照 SPEC 手算的一组小例子（多空止损、跳空、双触、移动止损、入场当天、卖出锁定、受限重试、两种冷却、限价各情形、持有期），内核、参考实现、手算期望值三方逐项比成交行、价格、原因、数量和计数。

**十个语义问题的答案与理由**

1. **触发与成交价**：多头当日最低价触及止损线（空头最高价）即触发；开盘就已越过（跳空）按开盘价成交，否则按触发线成交，再叠加滑点和冲击。理由：开盘价是当天第一个价，跳空时不可能在线上成交；不跳空时线价是最好情况下能拿到的价，滑点照常扣。由此触发成交的原始价一定落在 [最低, 最高] 内（有性质测试）。
2. **同一根 K 线止损止盈都触及**：默认 `both_hit="stop"`，按止损线成交；`"target"` 可切到止盈。理由：先后不可知，取不利一边。跳空优先于此：开盘已过止盈线就按开盘价止盈（开盘价是确定发生的）。
3. **移动止损的最高价**：触发线 = 截至上一交易日收盘的最高价（空头最低价）×(1 ∓ 回撤)。当日最高价在收盘后才并入。建仓当天（「新仓」，见下）的价格区间不并入，起点是建仓原始价。理由：当日最高价可能出现在最低价之后，用它抬高当日触发线等于日内前视；建仓当天买入之前的那段区间不属于持仓。
4. **持仓成本**：数量加权的原始成交价（不含滑点、冲击、费用）；加仓重新加权，减仓不变，新开或反手重置；送转按比例除；现金分红默认不调整（除息造成的下跌会推近多头止损线，这是有意的），`dividend_adjusts_cost=True` 时成本和最高价都减去每股分红（下限 0）。
5. **与交易限制的关系**：规则平仓是一笔普通成交：卖出要 `can_sell`、买回要 `can_buy`；成交量占比上限把当天该列已成交的数量算进去；按平仓口径取整（零股可一次清掉）；`sell_lock=True`（默认，A 股 T+1）时当天买入的股份当天不能被规则或限价卖出；现金账户沿用原有的费用检查，保证金账户（无融资时）把平仓削到自有现金不为负。没做完的平仓记为「待平」，之后每一行在一切新判断之前按当天的 `exec_price`（不是原触发价）重试，原因不变，直到仓位归零（包括被强平、退市等其他途径归零）。每个仍待平的行计一次 `rule_deferred`。`sell_lock` 对所有市场默认开启（偏悲观）；没有当日卖出限制的市场要显式设为 False。默认值没有改成跟随市场档案：档案在 `panelbt.markets` 里，不在这次改动范围内，`Market` 也不带档案。
6. **与当天调仓的先后**：必填 `fill_time` 说明 `exec_price` 在一天中的位置。`"open"`：先按开盘价调仓，再看当天区间（开盘价成交的新仓看到了整天的区间，当天就参与判断）。`"close"`：先判规则再按收盘价调仓。`"average"`（均价、VWAP 一类）按 `"close"` 处理，并且当天以均价买入的仓位当天不参与判断：买入之前那段区间分不出来，若参与判断，止盈可能用到买入之前出现的最高价。强平日（追保、爆仓）跳过日内阶段：待平的等着，限价单不成交。当天有规则成交、待平或限价目标的列，当天的普通调仓跳过这一列（规则或限价优先）。
7. **规则退出之后**：默认（`cooldown=None`）在之后某一行给出新目标行之前，不再开仓这一列（普通、顺延、限价、做多做空都算）；退出当天的目标行不算。`cooldown=k` 改为退出后 k 行之内不开仓，期间的目标行也不解除。每次被挡计 `reentry_blocked`。理由：现行目标仍然要求持有，不挡的话第二天就买回来了，止损形同虚设。
8. **限价目标**：`Targets(..., limits=...)` 给每个条目一个限价（NaN 是普通目标），需要配 `Rules`（至少给 `fill_time`）。默认 `limit_fill="cross"`：买单要求当天最低价**严格低于**限价才成交，卖单要求最高价严格高于限价；`"touch"`（最低价等于限价也算）是显式选项。成交价：买 min(开盘, 限价)，卖 max(开盘, 限价)（跳空穿过按开盘价）。理由是独立复核在沪深 300 成分 2007–2026 上的实测：限价取前收 ×(1∓1%~3%)，只碰到、没穿过的日子只占限价成交的 4%–6%，却贡献了限价买入当日收益（收盘 / 成交价 − 1）的 55%–65%，平均 +1.4%–1.8%，穿过的只有约 +0.06%；挂在当天极值上的单很可能没成交，算成交会明显高估低吸类策略。面板没有最小报价单位，所以用严格不等号代替「穿过至少一个价位」。下单量按日内阶段开始时的 `E = 现金 + Σ持仓 × 估值价`（不用当天价格）和限价换算。现金不够（含佣金）时和普通买入一样削到买得起为止，计 `cash_scaled`（保证金账户计 `margin_scaled`）。削完缺口不超过一手（分数股时不超过这张单自己的滑点、冲击和费用折合的数量）才算完成，这样不会出现「只差佣金的零头天天去补」；缺口更大或一股没买到就不算完成。默认当天有效（`limit_valid="day"`），可选 `"until_next"` 一直有效到成交或被下一个目标行替换；没做满（资金缺口超过上面的额度，或掩码、成交量上限、阻挡）时计 `limit_blocked`，`until_next` 保留剩余部分、之后各行照同样的规则再试（等现金进账是常见用法），当天有效的单丢弃剩余。计数 `limit_filled`（按成交笔数，先减仓再反向开仓算两笔）、`limit_unfilled`（价格没到）、`limit_blocked`（到了但超出上述额度没做满）。`cash_scaled` 按行计：同一行里普通买入、限价单或两者都被现金削减，只计一次；没有限价单时与原来的计数相同。`margin_scaled` 上，限价单只在这一行还没计过时计一次，普通保证金篮子的计数不变。限价开的仓当天是新仓。
9. **空头和期货**：空头完全对称（止损线在成本之上、止盈线在成本之下，`take_profit >= 1` 时空头没有止盈）。期货列暂不支持，配了规则或限价且市场里有期货列时输入检查直接拒绝（`run`、`run_batch`、`Simulator` 都是）。理由：期货的成本口径要换成结算价、保证金和到期移仓也要一并定义，留作后续。
10. **诊断**：`Result.diagnostics` 多出 `stop_loss`、`take_profit`、`trailing_stop`、`max_hold`（触发次数）、`rule_deferred`、`reentry_blocked`、`limit_filled`、`limit_unfilled`、`limit_blocked`；`record_trades=True` 时 `Trade.reason` 是 `TradeReason`（`REBALANCE`、`STOP_LOSS`、`TAKE_PROFIT`、`TRAILING_STOP`、`MAX_HOLD`、`LIMIT`）。它是 `IntEnum`，`astuple(trade)` 仍是纯数字。

**实现**：内核加第三个编译期开关 `T`（持仓记账 + 规则），与 `CLASSIC`、`FUT` 并列。不配规则也没有限价目标时，`run` 走 `T=false` 的特化，规则代码和成本、最高价、建仓日这些数组都不存在。规则逻辑在 `crates/panelbt-core/src/rules.rs`；`Simulator` 一直用 `T=true`，配规则时与 `run` 逐位相同（常驻测试，含中途存档恢复）。

**期货列**（2026-11-13 起退出规则已放开，只作用于现货列，见 4.15；以下是当时的记录）：市场里有期货列时，规则和限价目标整体拒绝（`run`、`run_batch`、`Simulator` 都是）。「规则只作用于现货列」暂未做，卡在两处：限价开仓和平仓削减的资金判断（`rules.rs` 的 `marked_account`/`projected_at`）只算现货的现金和保证金，不含期货占用的保证金，混合账户里会超买；参考实现的规则部分也没有期货路径，要一起补并对拍。留作下一步。

**近似在哪里，什么时候偏差大**

日线只知道开、高、低、收四个价，不知道它们在日内出现的先后。所有规则回测都是在上面那套悲观假设下的近似：

- 同一天碰到两条线（止损和止盈、或限价和止损）时，真实结果取决于先碰哪条，这里一律取不利的；日内振幅大于两条线间距的日子越多，回测越偏保守。
- 触发线按线价成交，假设触及时能在线上成交到；真实盘中触及后的成交价往往更差（尤其是快速下跌、流动性差时），只有滑点和冲击参数在兜。触发线贴着价格（止损比例小于日内正常波动）时，日线回测会把大量「盘中刺穿又收回」的日子都算成止损，并按线价成交，与分钟级回测差别很大。
- 移动止损只用到前一天的最高价，比盘中逐笔跟踪的移动止损反应慢一天，单日大涨后回落的情形会少触发。
- `fill_time="average"` 当天新买的仓位不判断，真实盘中如果在买入之后跌破止损线，会晚一天才处理。
- 限价单默认要求价格穿过限价；即使穿过，真实盘中也可能因排队没成交，这一点没有模拟。改用 `limit_fill="touch"` 会明显偏乐观（见第 8 条的数字）。
- 同一天里的资金先后有两处轻微偏乐观：日内阶段先规则平仓、后限价单，止损回笼的现金可以给同一天的限价买入用，而真实盘中限价单可能比止损先成交；`fill_time="average"`（以及 `"close"`）时，规则平仓回笼的现金可以给当天按均价（收盘价）成交的调仓用，而均价成交贯穿全天、平仓可能在尾盘。资金紧的账户上影响才明显。
- `Market(validate=False)` 不检查 `low <= open <= high`；违反的行上「触发成交价在 [最低, 最高] 内」不再成立。

日内波动大的品种（小盘股、题材股、高波动期）和止损线设得很紧的策略，近似误差最大；需要精确时应改用分钟级数据。

### 4.14 纯期货组合回测

4.11 的期货是「股票组合上的一条对冲腿」。这一节把期货当成独立的资产：面板里全部是期货列（也可以混现货列），按具体合约持仓、按结算价逐日盯市，保证金和费用逐合约逐日取自输入，结果是同一种 `Result`。面向使用者的说明、手工核对和例子见 [FUTURES_BACKTEST.md](FUTURES_BACKTEST.md)，引擎口径见 SPEC 的「Stand-alone futures portfolios」。

**内核不改**。4.11 的逐日账户循环已经能跑全是期货列的市场（现金账户特化下：期货开仓先按「占用 ≤ 现金」缩放，收盘「占用 > 权益」追保，下一行同比例强平）。缺的都是输入层面的事，所以做成 `panelbt.FuturesBook`（纯 NumPy）：

- 账户条款 `FuturesAccount(margin_add, margin_scale, fee_scale)`：实际保证金率 = 交易所 × margin_scale + margin_add，手续费 × fee_scale；引擎默认中性，境内预设 `ashare.backtest.futures.CN_RETAIL`（+5 个百分点、× 3，估计值，取期货公司公示标准的悲观端，可覆盖，待用户确认）。
- 三种目标：手数、名义 / 权益、保证金 / 权益（按当行实际保证金率折成名义）。
- 合约的结束行 = min(最后交易行, 个人最后持仓行 + 1)。结束行照常可以成交，收盘仍持有的由内核的到期步骤了结：现金交割合约在自己的最后交易日按交割结算价、收交割费；其余（实物交割的最后交易日、个人持仓期限、交易单位分界）按当行结算价强平，「交割费」一栏填成手续费率 + 滑点，等于按结算价平仓并计一次滑点。
- 涨跌停：涨跌停价 `limit_up`/`limit_down` 或掩码 `no_buy`/`no_sell`；数据层没有涨跌停价时用一字板推断（`futures_portfolio` 默认开：开 = 高 = 低且有成交，按相对前结算的方向拒绝买或卖，等于前结算不拒绝）。全库成交量 > 0 的 1,793,242 行里一字行 101,883 行，89% 幅度不到 3%，多是冷门合约的普通成交，拒绝它们偏悲观；而开在停板、盘中又打开的主力合约行（2012 年后约 173 行涨停、151 行跌停）推断全部放行，在这类行上偏乐观。总的偏向取决于策略，可靠的做法是数据层补上涨跌停价后传价格、关掉推断（FUTURES_BACKTEST 第 5 条）。个人客户持仓期限里大商所、郑商所、广期所、上期所的规则未核实。
- 负价：期货列的结算价、成交价、收盘价、开盘价为 0 或负数一律报错，与 `validate` 无关（否则保证金变负、亏损不触发追保）；WTI 2020-04-20 这类行情列为后续工作。
- 缺失的保证金、手续费：交易窗口内的缺值默认报错，`missing="previous"`（只向前填）或给一个数。

`ashare.backtest.futures`：

- `futures_portfolio(fut, products, ...)`：用数据层的换月规则（第 t 行只用第 t−1 行的指标）定每个品种每行持有的合约，个人持仓期限前提前换到下一个合约（只向后换），只用这些合约建 `FuturesBook`；`signal_prices` 是同一规则下的比例后复权连续价格，只算信号。`run()` 用步进接口逐行推进：调用方给目标的行整体调仓；品种在目标行还没有合约时目标挂起，落到合约上那一行按原目标开仓；只有换月的行只动换月的品种（平旧开新、保持手数，乘数不同时保持手数 × 乘数），其他品种不成交；被结束行了结的持仓（交易单位分界）按同一规则接到下一个合约；追保强平行丢掉所有等待中的开仓。实现在 `ashare/backtest/futures_step.py`，自己不记发出过的单子，每次从引擎读还在顺延的单子，不变量写在文件开头并有随机性质测试守住。内核的目标行没有「这一列不动」的写法，所以逐行读持仓，单次约 120 ms（整份目标交给内核约 5 ms）。个人持仓期限按数据层的交易所日历（含未来日期）推算，可设提前量。
- 个人客户最后持仓日：SC 最后交易日前第 8 个交易日收市后为 0，LU/NR 前第 5 个（官方）；大商所、郑商所、广期所交割月前一个月最后一个交易日收市后为 0（旁证，未核实）；上期所和能源中心其他品种按同一条处理（推断，未核实）；两类规则同一口径（「某天收市后为 0」，最后过夜日是它的前一个交易日）；样本截在合约到期之前时日历用工作日补齐；EC、中金所不限制。
- `book_from_table(daily, contracts, params)`：外部行情的入口，列名同 `futures_schema`（第二件，见 FUTURES_BACKTEST「外部行情的入口」）。

**十个语义问题**的答案与理由逐条写在 SPEC 和 FUTURES_BACKTEST 里，这里只记结论：三种目标都支持；结算价盯市，可用 = 权益 − 占用；按金额和按手两部分手续费，平今不会出现（日频每列每行只成交一次）；追保沿用现金账户的期货规则；涨跌停用掩码、价格或一字板推断；持有具体合约，换月 T 日收盘判定 T+1 开盘平旧开新；到期按交割结算价（现金交割）或强平加滑点；交易单位分界平旧开新；缺值报错；夜盘开盘价是前一晚的集合竞价，信号只用到前一行收盘。

**验证**：独立的朴素参考实现 `panelbt/reference_book.py`（从原始输入逐日逐合约自己做全部换算和账户，与 `futures_book.py`、内核不共用代码）随机对拍，断言每个分支（三种目标、追保、强平、爆仓、三种结束方式、一字板、顺延、过期目标、取整为 0、开仓缩放）都出现过；与 `Simulator` 逐位等价；性质测试（逐日权益变化 = 期货盈亏 − 费用、空仓权益不变、保证金率调高可开手数不增）；手算例子；25 处变异全部抓到（`bench/mutations_futures_book.py`，含复核补的换月看当行行情、多空保证金取小、一字板平盘边界）。真实数据手工核对：RB2310 三笔开平仓按上期所规则手算的手续费、权益、占用保证金与引擎逐项相同（差 0）。

### 4.15 混合面板里的退出规则

4.13 原来在市场里有期货列时整体拒绝规则，「股票多头 + 股指期货对冲」的组合用不了止损。现在放开**退出规则**（止损、止盈、移动止损、最长持有期，只减仓），限价目标继续拒绝。口径见 SPEC「Exit rules in mixed panels」。

- **只作用于现货列**：标量百分比和 `max_hold` 只施加给现货列；每只证券或 T×N 的百分比在期货列上必须是 NaN（「不设」），否则输入检查报错。规则阶段只遍历现货持仓（`st.held`），期货持仓在 `book.held`，从不判断，也不记成本、建仓日、最高价。
- **资金**：保证金账户里规则平仓（主要是止损平空）的「自有现金不得转负」削减改为扣掉当时占用的期货保证金：`close`/`average` 时点（调仓之前）用开盘前的占用（前一结算价 × 当日保证金率），`open` 时点（调仓之后）用调仓后的占用（当行成交的合约按成交价）。现金账户的规则卖出沿用原来的费用检查，与普通现货卖出一致。
- **内核**：`run` 多了「有期货 + 记账」的两份特化（现金 / 保证金账户），只在既有期货列又配了规则时使用；`rules::intraday`、`reduce` 多一个参数 `fm`（期货占用，没有期货时为 0，`x − 0.0` 逐位不变）。不配规则或没有期货列时走的还是原来的四份构建。`Simulator` 一直是记账构建，本来就能编译这条路径。
- **限价目标继续拒绝**：限价开仓的资金判断（`rules.rs` 的 `marked_account`/`projected_at`）只算现货的现金和保证金，没有算期货保证金，混合账户里会超买。`run`、`run_batch`（Python 检查和绑定层双重检查）、`Simulator.step` 都拒绝。
- **参考实现**：`panelbt/reference_rules_futures.py` 把规则参考实现（`reference_rules.RulesEngine`）和混合账户参考实现（`reference_futures.MixedEngine`）组合起来，日内顺序照内核：开盘前事项 → 规则（close/average）→ 期货减仓 → 现货 → 开仓 → 规则（open）→ 现货收盘 → 期货结算与到期。

**验证**：随机对拍 500 组（规则语料加 1–2 个期货列，对冲权重最大到 6 倍名义，现金和保证金账户、三种时点），断言四种规则、待平、冷却、期货成交、期货强平都出现过，且规则从不碰期货列；步进（含中途存档恢复）与 `run` 逐位相同；加一列从不交易的期货后，现货规则结果逐位不变；两个手算例子：保证金账户止损平空被期货保证金削减（`close` 时点用开盘前占用、`open` 时点用调仓后的占用，后者对拍时开盘前占用会给出完全平仓）；输入错误。现有测试里只改了一条：`test_exit_rules.py::test_input_errors` 原来断言「有期货列就拒绝规则」，改为断言限价目标和期货列上的规则百分比被拒绝。变异检查（`bench/mutations_rules_futures.py`，结果在 `bench/results/mutations_rules_futures.json`）：削减不扣期货保证金、`close` 时点看不到保证金、`open` 时点用交易前保证金、期货加规则走不记账的构建、期货列上的百分比不报错、步进接口接受限价，六处都被测试抓到。

**性能**：新旧两份 LTO 构建交替计时（`bench/pair.py` 与新增的 `bench/pair_futures.py`，基准为主干 d791a69，负载 8–11），结果逐位相同，比值见下（多轮；单轮中位数比值波动很大，同时列出各轮最小值比值的中位数）：

## 5. panelops：因子算子

对面板做运算的函数库，接口统一，全部正确处理缺失值，可以传入股票池掩码。

实现方式逐个算子决定：先用 polars 表达式、numpy（必要时加 bottleneck）写出基线，在 T = 4000、N = 5500 的面板上测速和内存。Rust 实测更快、或基线内存放不下的，用 Rust 写（按列或按行并行）；其余包一层直接用。预计滚动排名、滚动相关、带缺失值的截面排名和 IC 这几类会需要 Rust，逐元素运算和简单滚动统计不需要，以实测为准。每个算子的基准数字留档。

- 时间序列算子：`delay`、`delta`、滚动的均值、标准差、求和、最大、最小、排名、相关、协方差、线性衰减加权、指数平均、回归的斜率和残差。
- 截面算子：排名、标准化、去极值、分组去均值、对行业和对数市值回归取残差（中性化）。
- 评估核：IC 和秩 IC、分组收益、分组换手、因子自相关、由分数生成前 q 分位的稀疏目标（直接交给 panelbt）。

每个算子都与 numpy / pandas 的直白实现对拍；IC 和分组收益再与 alphalens 对拍。

### 6.1 数据层

**封装**：数据层对项目的其余部分隐藏「数据从哪来、怎么存」。分四层，依赖只能从上往下。

| 层 | 模块 | 负责什么 | 谁可以用 |
|---|---|---|---|
| 读取接口 | `ashare.data` 顶层 | 按统一的字段名和单位取面板、长表、日历、证券表；给出每个字段的单位、来源和「当天何时可知」；给出数据版本 | 研究代码、回测、模拟盘的唯一入口 |
| 存储与构建 | `ashare.data.store`、`ashare.data.panel`、`ashare.data.verify` | 原始库（Parquet 分区加清单）、稠密面板的构建和增量更新、校验 | 数据层内部 |

| 源适配 | `ashare.data.sources` | 每个数据源一个模块，接口相同；限速、重试、翻页、密钥、错误分类只在这里 | 数据层内部；模拟盘的实时行情复用其中的 Tushare 客户端 |

```python
import ashare.data as ad

ds = ad.open()                                   # 数据根目录：ASHARE_DATA_DIR，默认是仓库下的 data/

ds.table("income", start="2015-01-01")           # 长表（财务、事件），polars LazyFrame
ds.calendar(); ds.securities(); ds.field("close")
ds.version                                       # 进因子缓存和试验账本的键
```

接到回测和风险模型的转接只有两处，都在 `ashare` 里：

```python

bm = market_from_panel(ds, start="2015-01-05", exec="open", fields=["adj_factor"])
bm.market, bm.config(initial_cash=1e7), bm.costs(commission_rate=2.5e-4)

from ashare.risk import from_panel
source, config = from_panel(ds, start="2023-06-01")   # 交给 model_series
```

- `market_from_panel`：成交价 `exec` 取 `open`（默认，直接用面板的 `can_buy_open`/`can_sell_open`）、`close` 或 `vwap`（按同一条涨跌停、一字板、停牌规则现算）；`split`、`cash_dividend` 的「缺失 = 无事件」换成 1 和 0；板块取证券表的板块列，为空时按代码前缀推断（如 `T600018.SH`），都认不出就报错列出证券；`delist` 原样交给引擎。

- 数据层以外的代码不出现 Tushare 的接口名、字段名、原始单位和文件路径。
- 同一个 Tushare 账号的限速和「单 IP」规则由同一个客户端管，历史采集和模拟盘的实时轮询共用它。
- 换数据源或加数据源（BaoStock 核对、以后的港股美股）只加一个源适配模块和几条数据集声明，读取接口不变。
- **现在不拆成独立的包**：它是 A 股和 Tushare 专用的胶水代码，字段会随研究频繁变动，也不是性能内核，单独发版只会多出版本对齐的成本。`sources` 不依赖 `ashare` 的其他模块（只用 httpx、polars 和标准库），以后要拆随时可以拆。

- **采集**：httpx 异步客户端，令牌桶限速，识别限频错误后退避重试，按接口和分区断点续传。原始响应原样存成 Parquet，字段保留 Tushare 原名，记录抓取时间。
- **范围**：2007-01-01 至今（涨跌停价从 2007 年才有）。
- **数据集**：交易日历；证券列表（含退市）；日线；复权因子；每日指标（市值、换手、估值、股息率）；涨跌停价；停复牌；ST 名单与曾用名；指数成分权重；申万行业成分（含历史）；三张报表与财务指标；业绩预告与快报；分红送转；之后再加增减持、回购、研报预测。
- **面板构建**：主日历 × 主证券表，把长表转成稠密矩阵落盘，附一份元数据（日历、证券表、数据版本）。
- **公司行为**：`split`、`cash_dividend` 以复权因子为准对账，`action_source` 记每格的来源：0 无事件，1 分红表原样，2 经济去重、候选裁决或日期对齐后，3 按因子合成（等效参考价再投资，不扣红利税、没有现金流），4 分红表事件被否决（因子没变），5 差异化分红。5 记的是持有人实得的公告值；回购专户股份不参与分配，交易所按摊薄比例 k 算参考价，所以按复权因子算的收益比按面板事件算的低 `(1 − k)` 乘以分配比例；`panelbt` 按面板事件记账。k 的下限默认 0.85，与对账容差一样进入数据版本。
- **时点财务**：每条记录按「实际公告日的下一个交易日」生效，保留所有版本，构建面板时按当天可见的最新版本取值。
- **校验**：与 BaoStock 抽样核对价格、ST、停牌；检查不变量（复权价连续、涨跌停价与规则公式的一致率、停牌日无成交）；输出覆盖率报告。

已知缺口：指数权重只有月末快照；中证 1000 从 2014-10 起、中证 2000 从 2023-08 起才有成分；财务更正的历史版本不完整；没有现成的一致预期，只有逐篇研报的预测。

- **面板**：`fund_panel/{fund,cb}/` 两份稠密「交易日 × 代码」面板，存储写法与股票面板相同；同名字段与 A 股面板含义和单位相同（价格元、成交量份 / 张、成交额元）。基金的拆分、折算、分红**以复权因子为准**裁决（`fund_actions`）：只在有行情的日子之间比较、停牌期间的事件落在复牌第一天，分红按「代码 + 登记日 + 金额」去重，对不上的以因子为准，来源记在 `action_source`；复用代码（`!1`）的旧证券同一只就并列、两只就拆成两列（旧证券存续期内的行情全归七位代码），同一天逐元相同、在证券表存续期外的副本行情去掉；开高低收相同而成交均价不在这个价上的沿用价不算行情；深市 2020-02-25 基金收盘整天有误，用次日交易所前收盘修补（`close_corrected` 逐格标记）。证券表带类别 `fund_class`（ETF / LOF / 分级 / REITs / 其他）：ETF 可用于回测，LOF 谨慎使用，分级基金不可用（`fund_market` 默认不让买，`graded=True` 才放行并告警）。可转债派生字段（转股价值、转股溢价率、双低、剩余规模、强赎已公告、剩余期限、票面利率）全部按当时可知：转股价自 max(生效日, 公告次日) 起、强赎和转股结果自公告次日起。可转债的占位行（零成交）不算行情。读取入口 `ashare.data.open(root).funds()`。
- **回测规则**：费用表写在 `ashare` 一侧（`fund_rules.FUND`、`cb_rules.CB`，免印花税和过户费），交易单位、涨跌停（基金 10% / 20% / REITs 首日 30%，可转债 2022-08-01 起 20%、首日 57.3% / −43.3%）；`fund_market`、`cb_market` 直接给出 `panelbt.Market` 和 `config()`、`costs()`。T+0 / T+1 按名称推断、未逐只核实。可转债的强赎与到期在 `cb_market` 里处理（不改 `panelbt`）：没卖掉的按赎回价了结（最后交易日后的估值价设为赎回价）、强赎公告可知后不能买、`targets()` 默认在最后交易日前 1 个交易日正常卖出（`exit_days` 可调）；票息不单独入账。
- **校验**（`fund_verify`，与构建代码独立）：分区覆盖、主键、单位（成交额折算均价落在最高最低之间）、代码复用、上市期、转股价独立重算、涨跌停；基金事件走两条跨停牌、覆盖全部有行情日的路径——面板事件推出的参考价对交易所前收盘、持有收益对复权因子收益；只认已知例外清单（逐条、只含键和原因），清单外不符一律 fail；分级基金整类不进判定。两条路径都查不出代码映射错误，另设硬不变量：任意两列不许有同一段相同行情、七位与六位代码的有行情日不许重叠，不允许例外。

### 6.2 因子与检验

- 因子用算子组合定义，登记名字、所需字段和说明；结果按「定义的哈希 + 数据版本」缓存。
- 第一批：市值、短期反转、动量、波动率、换手率、估值（EP、BP）、股息率，以及 Alpha158 的量价部分。
- 单因子报告：IC 与 ICIR、分组收益、**多头组扣成本后相对基准的超额**（调用 panelbt）、换手、分年度、分市值段、与已有因子的相关性。评价以多头端为准，因为做不了空。
- 算子精度：滑动求和一族（`ts_sum`、`ts_mean`、`ts_sumif`）在退化窗口上给精确值（窗口有效值全为 0 时恰为正零，全相等时均值恰为该值）；窗口不超过 3 行时逐窗口直接求和并正确舍入，结果只取决于窗口内容；更长的窗口默认仍是增量算法，最后一位可能随窗口之外的历史变化。逐格核对因子、或因子里拿两个窗口和比相等（例如对窗口和求相关）时用 `exact=True`：每格是窗口内数值的正确舍入和（均值是这个和除以个数），与顺序和历史无关，代价约为默认的 8–17 倍，窗口到 20 行后不再随窗口变长。细节与测量见 `docs/PANELOPS_BENCHMARKS.md`「滑动求和的退化窗口与历史无关」。

#### 6.2.1 外部因子包

成套的公式型因子（公式、独立参考实现、约定文件、核对结果）不放在本仓库，写成单独的 Python 包，经入口点组 `ashare.factors` 被发现。本仓库的 `ashare.factor.formula` 只提供机制：

- `dsl`：WorldQuant 式、国君式公式的翻译用语言（口径集中在这一个文件）；`qlib`：Qlib 表达式字符串到 `Expr` 的确定性转换；`ops`：用现有算子精确组合出的算子。
- `registry_from_module(模块, 前缀, 条数, notes=..., excluded=...)`：从「一个函数一条因子」的模块构造注册表，按名字挂元数据标记 `notes`（`(标记, 编号)`），`registry.with_note(标记)` 筛选。
- `inputs`：取数（`load_inputs`）与参考实现的输入（`reference_frames`）；`verify`：候选对独立参考实现逐格核对，支持「已知例外」（`KnownException`：只对条件成立、按正常规则不过关、候选恰为声明值的格子生效，单独计数）。
- `plugins`：`discover()` 列出全部因子集，`load_registry(名字, **选项)` 取注册表。没装任何外部包时只有内置示例集 `example`（两条自编因子和它们的参考实现），一切功能照常。

外部包的最小写法：

```toml
# 外部包的 pyproject.toml
[project]
name = "my_factors"
version = "0.1"
dependencies = ["ashare"]

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project.entry-points."ashare.factors"]
my_factors = "my_factors.plugin:register"
```

```python
# my_factors/plugin.py
from ashare.factor.formula import FactorSet, dsl as d
from ashare.factor.library import Registry


def build(window="7"):
    registry = Registry()
    registry.register(
        "my_range", d.ts_mean(d.high - d.low, int(window)), "mean(high - low, window)",
        notes=[("自编", "M-1")],
    )
    return registry


def register(hub):
    hub.add(FactorSet("mine", build, reference="my_factors.reference", options=("window",)))
```

```python
# my_factors/reference.py：独立参考实现（pandas），选项以字符串原样传入
def my_range(frames, window="7"):
    return (frames["high"] - frames["low"]).rolling(int(window)).mean()


REFERENCES = {"my_range": my_range}
```

装进同一个环境（`uv pip install -e 路径`）后：`load_registry("mine", window="9")` 取注册表，`python -m ashare.factor.formula.verify mine --option window=9` 核对。约定：

- `register(hub)` 只有一个参数；入口点导入失败、`register` 报错、两个包登记同名因子集，都会直接报错并指明入口点，不静默跳过。
- `FactorSet` 的 `build(**选项)` 返回 `Registry`，只接受 `options` 里声明的选项（命令行传进来的值是字符串）；`reference` 是参考实现模块（`REFERENCES = {名字: 函数}` 或 `compute_many(frames, names, **选项)`），选项同样传给它；参考实现只有时序运算时可以给 `chunk`（按证券分块并行）；`exceptions = {因子名: (KnownException, ...)}`。
- 参考实现要独立：照约定文件自己写 pandas，不调用 `ashare.factor` 的表达式和 `panelops`。
- 外部包的测试可以用 `ashare.factor.formula.testing.synthetic_source` 造合成面板。

### 6.3 合成、组合与研究纪律

- 滚动训练：按时间切分，训练集和测试集之间留隔离期；LightGBM；各折并行。
- 组合：前 N 等权；或用 `ashare.portfolio` 约束相对基准的行业和市值偏离、个股上限、换手（6.4）。
- 纪律：先写假设和判定规则再跑；每个试验记账；最近两年的数据留作最终检验；用试验次数折算显著性。统计检验从 Quant 项目移植。

### 6.4 风险模型与组合优化

**风险模型 `ashare.risk`**，两种实现，对外是同一个形状：某一天的暴露矩阵 B（N × K）、因子协方差 F（K × K）、特质方差 D（长度 N）。组合方差按 `‖F^½ Bᵀ w‖² + wᵀ D w` 算，任何地方都不展开成 N × N 的稠密矩阵。

- **统计型**（先做，当基线和对照）：指数加权的样本协方差加 Ledoit–Wolf 收缩，以及主成分因子模型。只需要收益率。
- **基本面因子型**（Barra 式）：国家因子 + 申万一级行业 + 风格因子。每天做一次截面加权回归得到因子收益（权重取市值的平方根，行业因子收益按市值加权和为零）；因子协方差用指数加权加 Newey–West 调整；特质风险用指数加权、对历史短的股票用结构化估计并做收缩。第一期的风格只用行情和每日指标能算的：市值、贝塔、动量、残差波动、非线性市值、流动性、账面市值比、盈利市值比；成长、杠杆等要等时点财务数据。
- **时点**：第 t 天的模型只用第 t 天收盘前已知的数据；暴露用第 t 天的值解释第 t+1 天的收益。
- **检验**：在已知因子结构的合成数据上要能还原参数；用偏差统计量（预测波动与实现波动之比）检验预测是否准确，两种模型互相对照。

**组合优化 `ashare.portfolio`**：不自己写求解器。实测后的默认路径（`backend="auto"`）是把问题换成标准锥形式、直接调 Clarabel 的 Python 接口，同结构的问题复用；Clarabel 报数值失败时退到 cvxpy + Clarabel 重解。`backend="rust"` 走 `portopt`（Rust 里调 Clarabel，可批量并行），`backend="osqp"` 和 `backend="cvxpy_*"` 留作对照和参考实现，不在默认路径上。

- 接真实面板：`ashare.risk.from_panel(data, start=...)` 返回交给 `model_series` 的 `(source, config)`（见 6.1）。`PortfolioProblem` 的 `industry_factors`、`style_factors` 可以给因子列号，也可以给因子名（`"industry_银行"`、`"size"`，可混用），风格因子名的全集是 `ashare.risk.STYLE_NAMES`。

- 目标：预期收益 − 风险厌恶 × 主动风险 − 交易成本。
- 约束：满仓或留现金比例、只做多和个股上限、相对基准的个股 / 行业 / 风格偏离上限、换手上限、跟踪误差上限；停牌和涨跌停买卖不了的股票权重冻结。
- 无解时按事先定好的顺序放松约束并记录，不静默返回一个不满足约束的解。
- 每次求解后都核对约束是否满足；结果与第二个求解器对拍。
- 输出目标权重，按 `panelbt.Targets` 的稀疏布局交给回测。

### 6.5 归因与容量（`ashare.analysis`）

回测之后回答三个问题：收益从哪来、风险押在哪、能装多少钱。输出一律是普通数据对象
（`Table`：数组 + 行名 + 列名，可转列式 dict 和 pandas 表），以后由报告模块 `ashare.report`
作为可选小节接入。细节、口径和验证记录见 `docs/ANALYSIS_NOTES.md`。

- **时间约定**：`weights[t]` 是第 t 日收盘后的权重，赚第 t+1 日的收益；风险模型 `B_t` 解释
  `r_{t+1}`。第 t 日的归因一律用 t-1 收盘的持仓、暴露、行业分类和基准权重。
- **收益与估值**：个股收益 = 后复权价（close × adj_factor 作为整体沿用最近有效值）之比，停牌期间
  含停牌中除权都为 0；持仓估值与 panelbt 相同，缺价时用最近收盘价逐次除权的参考价。
- **接主干**：行情、账户规则、费用表、信号错位用 `ashare.backtest`，风险模型输入用
  `ashare.risk.risk_inputs`；本包的 `adapters` 只在「只有面板、没有数据句柄」时转发。
- **收益归因** `attribute`：主动收益 = 市场 + 行业 + 风格 + 特质 + 交易 + 成本，逐日恒等。
  因子收益由 `FactorHistory` 在遍历 `model_series` 时按风险模型自己的截面回归补算（同一内核、
  同一估计池，逐位一致）；全市场暴露放不下内存，只保存组合与基准出现过的证券。
  多期链接默认 GRAP（不取对数、无奇点、递推一次得到逐日累计值），可选 Carino。
- **风险归因** `decompose_risk` / `risk_series`：Euler 拆分到因子与特质，给边际贡献和占比；
  逐日预测与次日实现比较（偏差统计量，区间默认用 20 日块自助法）。
- **Brinson** `brinson`：按申万一级行业，Brinson-Fachler 为默认、BHB 可选；现金单列一个行业。
- **容量** `capacity`：冲击模型与 `panelbt` 同口径（`impact_k·(q/V)^e`，默认 e=0.5、k=系数×此前日波动率）。
  解析模拟按股数记现金账户，规则与 panelbt 相同但不取整、不设成交量上限，毫秒级，可在规模上
  求两种容量（成本吃掉一半毛超额，取成本曲线上升段的交点，下降段的交点另报为最小可行规模；
  超过 10% 成交量占比的成交额超过 5%），求不到时给 NaN/inf 和状态，不拿搜索边界充数；`rerun=True`
  对每个规模真跑 `panelbt.run_batch`（同宽松规则用来对账、真实 A 股规则看实际净值）。
- **成本拆解** `cost_breakdown`：按年列佣金、印花税、其他费用、滑点、冲击、融券费、红利税、融资利息
  和换手（双边，与报告一致）。
- **性能**：先用 NumPy 向量化；十五年全市场逐日归因的数值部分在秒级以内，主要时间在生成风险模型本身，
  暂不写 Rust 内核（对比数字见 `docs/ANALYSIS_NOTES.md`）。

### 6.6 事件驱动（`ashare.events`）

截面因子之外的另一类策略：信号是「某只股票在某天发生了某件事」。提供四样东西：事件表、内置事件提取、事件转目标持仓、事件研究。细节、真实例子和变异清单见 `docs/EVENTS_NOTES.md`。

- **事件表**：polars 表，必需列 `symbol`、`date`（公告日历日 YYYYMMDD）、`kind`、`timing`，其余是数值字段。`timing` 默认 `after_close`：公告日只到天，按收盘后才可知处理，最早在公告日之后的第一个交易日成交；`pre_open` 表示公告日开盘前已知。公告日不是交易日时顺延。按类型覆盖用 `with_timing`。对齐后的「可成交日」`avail` 是事件研究的第 0 天、事件转持仓的起点。错位用公共的 `ashare.backtest.timing.execution_days`（信号日 + 1，末尾丢弃）。
- **内置事件**：业绩预告（首次与修正按同一条规则区分）、业绩快报（相对上年同期与相对最近一次预告的超预期）、分红（年报期的预案日用年报公告日近似，其他报告期用股东大会决议日；另有决议日、实施公告日两种进度）、指数成分调整（沪深 300、中证 500、中证 1000；只有月末快照，只能用生效之后的快照日，推不出公告日）。快报、分红走公共的 `Data.table`；预告、利润表、指数权重的部分列数据层尚未公开，经数据层内部接口读原始表，源字段名只出现在 `extract.py`。
- **事件转目标**：可成交日 + `entry_lag` 开盘买入，持有 `holding` 个交易日；买不进时放弃或顺延至多 `defer` 天；重叠时延长、忽略或叠加；权重等权、按数值或每份固定；持仓数上限、单只上限。只在持仓集合变化的日子写一行 `panelbt.Targets`。所有决定按时间顺序只用当时已知的信息：名额在决策日占用、不看之后能否买到，给了可卖掩码时在实际卖出日释放；按数值加权时延长事件只改它之后的权重。名额不够时按 `priority`，再相同时按只由事件自身决定的固定哈希，不按代码顺序。
- **事件研究**：异常收益 = 个股收益 − 基准（指数，或同行业 × 市值分位组的留一等权组合，或调用方给的 T×N 预期收益，例如风险模型的因子部分）；基准缺失不当 0，窗口不完整和上市不足的事件默认剔除并计数，退市后的格子记 0；同股同日同类事件合并。**首选的显著性口径是日历时间组合检验**（每个交易日等权持有窗口内的事件，对组合日超额做 Newey–West t）；另并排给出朴素 t、按月聚类（可选按日、按季度）的标准误和按聚类整块重抽的自助法，聚类少于 30 个时警告。事件数按年、事件前走势、开盘可买与买不进（涨停、停牌）分开统计。风险模型的特质收益尚无公开接口，留待接入。

### 6.7 回测报告（`ashare.report`）

一次回测出一份报告数据（`build_tearsheet`，口径见 `docs/REPORT_NOTES.md`），同一份数据有两种看法：自包含的 HTML 页面（给人看），以及给终端和 AI 代理看的文本版。

- **文本版**：`Tearsheet.text(sections, fmt, lang, start, end)`、`print(tearsheet)`，命令行 `python -m ashare.report show / html`，报告数据用 `save_json` / `load` 存取。默认摘要一屏（40 行内），其余按小节取；`text`（等宽、行宽 ≤ 100 列、中文按两列）、`markdown`、`json` 三种格式；`--lang en` 表头用 JSON 键名。文本版不另算指标：每个数取自报告数据，格式与页面相同；自选区间的指标用页面「切换区间」的同一套公式（Python 逐行照搬页面的 JS，测试里用 node 跑页面那段 JS 对拍）。
- **提醒**：把看图能看出、只读数字容易漏的问题（基准不含分红、首末月年不完整、未成交多、现金高、持仓不足、回撤未修复、历史太短等）按保守阈值写成带数字的句子。
- **补充内容**：对比指数、胜率（按年、滚动 1/3/5 年）、个股贡献（用持仓和价格重建，与引擎的 `result.contribution` 和权益恒等式核对）、收益分布与尾部、集中度；`compare()` 把几份报告放在共同区间上并排。这些只进数据层和文本版，页面先出设计稿、经用户选定后再改；在那之前不嵌入页面，HTML 逐字节不变。

### 6.8 资产配置（`ashare.allocation`）

几个到几十个大类资产怎么分配权重，口径与结果见 `docs/ALLOCATION_NOTES.md`。

- **方法**：固定权重（配再平衡带）、等权、倒波动、带预算的风险平价、目标波动叠加（杠杆上限）、最小方差与均值方差（经 `ashare.portfolio`）、趋势过滤叠加；协方差复用 `ashare.risk` 的收缩估计。
- **时点**：调仓行就是成交行，第 t 个调仓日只用 t−1 日收盘及以前的收益；月度调仓与 `ashare.backtest.timing` 的信号 → 成交错位一致；有对所有方法参数化的前视测试。
- **风险平价**：牛顿法解 Spinu 凸目标，残差作诊断；无解（存在方差为 0 的长仓组合）时依次加 ridge，诊断分开报「原协方差上收敛」与「靠 ridge 解到」，`allocate` 汇总并对未收敛发警告；独立的坐标下降参考实现对拍。
- **输出**：`Allocation`（行号、日期、权重、是否下单、诊断），可转 `panelbt.Targets`、`to_dict()` 只含内置类型，可交给 `ashare.report.tearsheet`。真实数据例子 `bench/allocation/etf_example.py`（四只 ETF），性能基线 `bench/allocation/perf.py`。
### 6.9 机器学习（`ashare.ml`）

把「因子当特征 → 滚动训练 → 预测值当新因子」这一圈封装好；模型本身用成熟的库（树模型 LightGBM，线性模型 NumPy 正规方程 + scikit-learn），框架负责模型外面那一圈：样本对齐、间隔、滚动重训、特征库、留痕。细节与实测见 `docs/ML_NOTES.md`。

- **依赖**：可选依赖组 `ml`（`lightgbm`、`scikit-learn`），只有 `import ashare.ml` 时才需要，缺了报出中文的安装方法；框架其余部分不受影响（不装这个组时其余测试照常通过，`test/ml` 整体跳过）。`make dev` 默认装上它，`make check` 会跑 `test/ml`。神经网络（PyTorch）这一轮不做，以后走单独的可选组 `nn`，默认不装；`mlp`、`lstm`、`gru`、`transformer` 这几个名字预留给它，没装时用到会提示装 `nn` 组。不引入 Qlib。
- **标签**（`Label`）：按回测的成交约定实际拿得到的未来收益。信号日 t 收盘后算特征，t+lag 行按成交价买入、再过 h 行按成交价卖出，`label[t] = P[t+lag+h]/P[t+lag] − 1`（P = 成交价 × 复权因子），与 `ashare.backtest.execution_days` 同一口径；可买可卖与 `market_from_panel` 同一口径。预设 `ret1/ret5/ret10/ret20`，可扣市场或行业均值；训练目标默认是原始收益，可选截面排名（`rank=True`）或截面标准分（`zscore=True`），评估始终用原始收益。买入日不可买的样本默认不进训练集但照样给预测值。卖出日不可卖默认仍按当日价算（`sell_blocked="price"`），可选 `"drop"`（置缺失）或 `"carry"`（顺延到第一个可卖日、最多 `max_carry` 天；标签跨度随之加 `max_carry`，最小间隔一起变大，防前视按逐样本的实际卖出日核对）。默认值以后要改，必须作为新的一组入账并注明是看过结果之后改的。
- **截面预处理**（`Preprocess`）：去极值 → 行业/市值中性化 → 标准化或排名化 → 缺失值处理，全用 `panelops` 截面算子、按日在股票池内做；预处理结果存在特征库里，训练和预测读同一份。
- **特征库**（`FeatureStore`）：只存股票池内的样本，float32，按特征列存成磁盘映射文件，样本按（信号日，证券）排序、`day_ptr` 索引，一折取一段连续样本。缓存键 = 特征表达式哈希 + 预处理 + 股票池 + 面板版本 + 代码哈希 + 求值依赖版本（numpy、panelops 构建号、因子求值器代码哈希）；建库时某个特征在股票池内全部缺失直接报错；新特征只算新列；`incremental=True` 时新日期只追加尾部（追加前重算最后几天逐位核对）。
- **切分**（`schedule`）：滚动或扩展窗口，按月/季/半年/年或每 k 个交易日重训；训练 → 间隔 → 验证 → 间隔 → 预测。间隔 `gap` 默认等于标签跨度 `lag + h`，只能加大，保证任一训练/验证样本的标签结束日严格早于下一段第一天；`describe()` 打印日程表。
- **防前视**：特征表达式只看信号日及以前；标签结束日 < 预测期首日由 `check_lookahead` 逐折核对（最晚信号日 + 跨度，以及训练样本的实际卖出日两道）；LightGBM 跨折复用的分箱边界只用第一折训练集定（第一折训练集早于所有预测期）。测试：改动第 D 日及以后的全部数据，D 之前的预测逐位不变；D 取在第一折中间、第二折中间（不在任何折边界上）和折边界三处，前两处才抓得到「分箱用了较晚一折的训练集」。
- **模型协议**：`fit(train, valid)`、`predict(batch)`、`save(path)`、`load(path)`，可选 `feature_importance()`、`get_params()`；`Batch` 带 X（用时才读盘）、y、日、列。内置 `ridge`、`lasso`、`elasticnet`、`lgbm`、`lgbm_rank`（lambdarank，按日分组）、`ensemble`（多模型多种子，平均或按截面排名平均）。提前停止看验证集逐日 Rank IC 均值。第三方模型 `register_model("名字", 类或 "模块:属性", group=...)` 或入口点组 `ashare.ml.models` 登记后即可 `model="名字"`，不改核心代码。
- **预测即因子**：`walk_forward(...)` 返回 `WalkResult`，`.pred` 是 T×N 面板，直接交给 `panelops.rank_ic` / `group_returns`、合成或组合构建；`to_targets(res, top=50)` 按标签持有期调仓、经 `execution_targets` 错位后交给 `panelbt.run`。
- **留痕**：每次训练往 JSONL 账本追加一行（数据版本、特征与哈希、标签、预处理、股票池、切分日程、模型参数、种子、代码版本、库版本、各折与汇总指标、耗时），失败的训练也记（`status: failed`，只记异常类型）。同样的定义重跑命中运行缓存直接返回，记一条 `cache_hit`，不算新试验；`Ledger.trials()` 数不同定义的组数，含失败的。定义的规范形式：种子只认实际传给模型的那个（`seed=7` 与 `params={"seed": 7}` 是同一组，不接受 seed 的模型记 None）；自定义模型按类的 qualname + 类源码哈希识别，不看模块路径，取不到源码时只用 qualname 并标 `unavailable`。定义不含框架代码版本、库版本和线程数；运行缓存按这三者区分。某折没有可训练样本、或预测是常数时报错；被跳过的折打日志。默认目录 `ASHARE_ML_DIR`，否则数据根目录下的 `ml/`（不入库）。
- **超参搜索**：网格或随机，同一套切分评估，每组都入账；`end` 必填，留出最后一段作最终检验；结果给 Bonferroni 折算（门槛 α / 账本累计组数）。更精细的多重检验校正留到因子挖掘那条线。
- **解释**：各折特征重要性（及随时间变化）、验证集上按 Rank IC 的截面内置换重要性。不做 SHAP。
- **性能**：逐日运算用 `panelops` 或 NumPy 向量化；训练线程数可配，默认核数的一半；各折可并行（`fold_workers`）。LightGBM 默认 `bins="shared"`（全部样本按第一折的分箱边界分一次，各折取子集）；`bins="per_fold"` 每折重新分箱，与最直白的写法逐位一致。

## 8. paperbroker：实时模拟盘引擎

### 8.1 定位

一个模拟券商：接收订单，按实时行情快照撮合，维护账户，逐日结算。用途是把研究里选出的组合放到真实行情上向前跑，检验回测的结论，并为以后接实盘做准备。

和 `panelbt` 一样做成独立的包：Rust 内核加 Python 原生扩展，不依赖 `ashare`。行情从哪来、策略怎么下单、进程怎么常驻，都在 `ashare.paper` 里。

说明一点：模拟盘的瓶颈是行情轮询的网络延迟（秒级），撮合的计算量很小。这里用 Rust 的主要收益是确定性、类型安全，以及和回测共用同一份规则代码，速度不是主要理由。基准照样测（回放一整天全市场快照的吞吐）。

### 8.2 内核是一个确定性的状态机

内核不读系统时间，不做网络和文件读写。它只接收事件、更新状态、吐出事件。同样的输入序列必然得到同样的输出，所以可以录制后回放、崩溃后从日志恢复，也便于测试。

输入事件：

- 行情快照：证券、时间、最新价、开高低、昨收、累计成交量和成交额、买一卖一（有就用）、涨跌停价、是否停牌。
- 订单请求：下单、撤单。
- 时段变化：盘前、开盘集合竞价、连续竞价、午休、收盘集合竞价、收盘。
- 日终结算：公司行为、T+1 解锁、未成交订单过期、利息和费用计提。
- 资金进出。

输出事件：订单被接受或拒绝（带原因）、成交（价格、数量、分项费用）、订单结束、持仓和资金变化。

### 8.3 撮合规则

没有逐笔委托簿，只能按快照撮合，所以规则偏保守：

- **连续竞价**：买单的限价不低于卖一价（没有盘口时用最新价）就成交，成交价取卖一价；卖单对称。Tushare `rt_k` 实测返回买一卖一的价和量（`bid_price1`、`bid_volume1`、`ask_price1`、`ask_volume1`），没有更深的档位。
- **成交量上限**：一次快照能成交的数量，不超过上一次快照以来市场成交量的增量 × 参与率上限。剩下的继续挂着等下一次快照。这是为了防止在市场只成交了 100 股的时候「成交」一万股。
- **涨跌停**：最新价等于涨停价且没有卖盘时，买单不成交；跌停时卖单同理。集合竞价同样适用：封死涨停时挂在涨停价的买单不在竞价中成交。
- **集合竞价**：集合竞价时段收到的订单，在竞价结束时按开盘价或收盘价统一撮合，数量受竞价成交量 × 参与率限制。
- **停牌**：不接受订单。
- **废单检查**：资金不足、可卖数量不足（T+1）、价格超出涨跌停范围、数量不符合申报单位、价格不是最小报价单位的整数倍。
- **滑点**：可配置，按最小报价单位的个数或按比例加在成交价上。

订单类型：限价单、市价单（按对手方最优价成交，带保护价）、当日有效。「调到目标仓位」由 Python 层拆成普通订单。

### 8.4 账户与结算

- 账户：现金、挂单冻结的资金、持仓（总量、可卖、冻结）、成本价。
- 费用、申报单位、保证金这些按笔计算的规则，和 `panelbt` 用同一份 Rust 代码（`crates/tradecore`），保证回测和模拟盘的口径一致。
- 日终结算：未成交订单过期；当天买入的股票解锁为可卖；按 Tushare 的分红送转数据做除权除息；生成当日快照（净值、持仓、现金、成交、费用）。
- 第一版是只做多的现金账户。做空和保证金等 `tradecore` 里的保证金模型就绪后再接入，接口先留好。

### 8.5 持久化与恢复

- 每个会改变状态的输入事件先追加写进事件日志，再交给内核处理。日志是追加式的文本行，启动时如果发现最后一行不完整就截掉。
- 定期存状态快照。启动时读最近的快照，再重放它之后的日志。
- 全量行情不进事件日志，另存成 Parquet 录制文件，用于事后回放和复盘。

### 8.6 `ashare.paper`：行情、调度与策略对接

- **行情**：轮询 Tushare 的实时日线接口取全市场或关注列表的快照，标准化后喂给内核并录制。行情源抽象成接口，以后可以换成券商终端的行情。
- **限额**（2026-11-12 实测与官方文档）：Tushare 的限额按接口分开计；常规接口这个账号是每分钟 500 次（超限返回 `code 40203`），`rt_k` 官方说法是每分钟 50 次；全市场一轮要 3 次请求，所以连续竞价时段约 6 秒一轮。同一账号不能在多个 IP 同时取数。
- **原始录制**：另有一个独立的录制任务（`data/live/tools/rt_recorder.py`，launchd 在交易日 9:05 启动），只把接口的原始响应按时间存盘（`data/live/raw/<日期>/<接口>/`），不依赖本项目的任何代码。模拟盘的回放输入由导入器从这些原始文件生成。
- **调度**：按交易日历和交易时段运行，午休和节假日不轮询；进程常驻，崩溃后自动拉起并从日志恢复。
- **策略对接**：每天读取研究框架给出的目标组合，在开盘后下单；可选简单的分时拆单。
- **日终**：结算，出日报，并与 `panelbt` 对账（见 8.7）。
- **监控**：心跳、行情中断和轮询失败的告警。

### 8.7 验证

- 内核的性质测试：资金守恒；可卖数量不为负；冻结资金与挂单一致；成交量不超过市场成交量增量 × 参与率；涨停不买入、跌停不卖出。
- 回放：同一份事件日志重放两次，状态逐字节一致；在日志任意位置截断后恢复，状态等于截断前的状态。
- 与回测一致：把一天的成交按实际成交均价交给 `panelbt` 回放，费用、持仓、现金必须一致。
- 实盘时段联调：开盘后录制真实快照，核对撮合行为。开发阶段先用历史分钟线合成快照流。

### 8.8 与真实成交的差异

- 不知道自己在委托队列里的位置，也不知道两次快照之间的价格路径。
- 只有买一卖一，没有更深的档位，快照间隔约 6 秒；吃穿一档之后的价格只能靠成交量上限和滑点参数做保守处理。个别证券没有盘口时只能用最新价撮合，结果偏乐观。
- 因此模拟盘的结果是「在这些假设下的估计」，不能当成实盘成绩。

## 9. 券商接口与 miniQMT 适配

状态：设计稿。实盘权限要向券商申请（用户的待办），这一节只做系统这一侧；真实下单的开关始终由人掌握，默认关闭。

### 9.1 目的

策略这一侧（每天的目标组合 → 订单 → 跟踪成交 → 对账）不应该知道对面是模拟盘还是真实券商。定一个统一的券商接口，模拟盘和 miniQMT 各写一个适配器，上层代码只面向接口。这样研究里验证过的下单逻辑搬到实盘时不用改。

### 9.2 接口（`ashare.broker`）

- `connect()`、`close()`、`status()`：连接状态是显式的，断开不会自动恢复（miniQMT 的 `connect()` 是一次性的），由上层的监督循环重连。
- `submit(order) → 本地单号`：本地单号由我们生成（不超过 24 个 ASCII 字符，写进券商的备注字段），重复提交同一个本地单号不会下两次单。
- `cancel(本地单号)`：返回只代表撤单请求已发出，是否撤掉以订单状态为准。
- `orders()`、`trades()`、`positions()`、`cash()`：查询当前状态。查询失败和结果为空必须区分（miniQMT 两种情况都返回 `None`，适配器里要处理）。
- `events()`：订单状态变化、成交、连接状态的事件流，事件类型与 `paperbroker` 的输出事件一致。
- 订单状态统一成一个状态机：待报、已报、部成、已成、待撤、已撤、部撤、废单、未知；miniQMT 的状态码 48–57、255 映射到它。

原则：**以查询为准，推送只用来触发查询**。回调线程里只做入队，不做业务处理，不发同步查询（miniQMT 在回调里同步查询会卡死）。

### 9.3 两个适配器

| 适配器 | 对面 | 说明 |
|---|---|---|
| `PaperBroker` | `paperbroker` 内核 | 现有模拟盘包一层，作为接口的参考实现 |
| `QmtBroker` | Windows 上的 miniQMT 客户端 + `xtquant` | `xtquant` 只有 Windows 版，交易通道是客户端目录下的本地队列文件，所以必须和客户端在同一台机器；本机（macOS）通过一个桥接服务访问 |

运行拓扑：研究、信号、目标组合在 macOS；Windows 机器上跑 miniQMT 客户端和一个薄的桥接服务（只做转发、鉴权和审计，不含策略逻辑）；两边走局域网。行情可以继续用 Tushare，也可以换成 `xtdata` 的全推快照。

桥接服务有三条路线，**实现前由用户选定**：

| 路线 | 许可证 | 特点 |
|---|---|---|
| `qmtserver` / `qmtclient` | MIT | 交易接口默认关闭且默认只演练不下单，令牌鉴权，有审计日志；版本 0.8，标注 Alpha |
| `qmt-bridge` | MIT | HTTP 100 多个接口加 WebSocket 回报，客户端不依赖 `xtquant`；功能多，需要自己收紧 |
| 自己写一个最小的 | — | 只暴露 9.2 的十来个调用，代码量小、可控；要自己维护 |

（`xqshare` 是 GPL-3.0，不采用。）

### 9.4 风控与合规（都在我们这一侧，适配器之前）

- **真实下单开关**：配置里默认是演练模式（只记录将要发出的委托，不发出）；打开它只能由人改配置。
- **预交易检查**：单笔金额上限、单只证券持仓上限、单日委托笔数上限、每秒委托速率上限、价格偏离上限、可卖数量、禁止交易名单。速率和笔数上限取向券商报告的数值——程序化交易要先向券商报告策略类型、最高申报速率、单日最高申报笔数和软件信息，确认后才能交易，实际行为与报告不一致会被限制。
- **人工干预**：一键全撤、暂停申报（交易所实施细则对程序化交易系统的要求）。
- **对账**：日终三方核对——本地账本、券商查询结果、`paperbroker` 影子账户；不一致就停止次日下单并告警。
- **每日流程**：按「每个交易日开盘前重启并登录客户端、用新的会话号重连」设计；重连次数有上限（每次连接都会在客户端目录生成文件）。

### 9.5 验证

- 一套契约测试同时跑两个适配器：下单、部分成交、撤单、废单、断线重连、重复提交、查询失败与空结果。
- `QmtBroker` 在没有账号的情况下用假的 `xtquant` 模块测试：按官方文档实现回调、状态码和已知的行为（撤单返回成功但未真正撤掉、查询返回 `None` 的两种含义、回调里同步查询卡死、断线不自动重连）。
- 拿到模拟账号或实盘权限后的联调清单（各时段下单的实际行为、订单号跨日是否有效、流控数值、五档行情的实际档数）记在 `docs/` 里逐项核对；这些在官方文档里没有写明。

### 9.6 需要用户决定或去办的事

1. 向券商申请 miniQMT 和程序化交易权限（各家门槛不同，网上的说法互相矛盾，以客户经理的书面答复为准；开户时问清是否要求实体机和固定网卡地址，这决定 Windows 机器放哪）。
2. 桥接服务走 9.3 的哪条路线。
3. 向券商报告的最高申报速率和单日最高笔数（低频组合调仓，建议报得保守，例如每秒不超过 5 笔、每日不超过 2000 笔，远低于高频标准的每秒 300 笔、每日 20000 笔）。
